# 基础资料生命周期需求计划

本文档承接 `three-client-requirements-analysis.md`、`flutter-pc-local-api-plan.md`、`dotnet-sync-api-plan.md`、`mobile-offline-queue-plan.md`、`amount-currency-exchange-rate-plan.md` 和 `runtime-accounts-and-master-data-contract.md`，定义 Finance Own 第一版基础资料在 PC、Web 和手机端的创建、修改、停用、同步、冲突和权限边界。

## 1. 范围

第一版基础资料包括：

1. 币种和账本本位币。
2. 账户组。
3. 账户。
4. 收入分类和支出分类。
5. 标签。
6. 往来方。
7. 汇率快照。

以下内容不在第一版主线中完成：

1. 复杂投资品种主数据。
2. 证券、基金、债券和收益率公式校准。
3. 外部银行或券商自动同步。
4. 跨账本共享同一套基础资料。
5. Web 或手机端读取旧 MoneyHome8 原始库。

## 2. 数据归属

基础资料必须归属于单个账本，不能跨账本复用同一个对象 ID。

| 对象 | 归属 | 第一版同步 |
| --- | --- | --- |
| 币种 | 账本 | PC/Web 可管理，手机读取 |
| 账户组 | 账本 | PC/Web 可管理，手机读取 |
| 账户 | 账本 | PC/Web 可管理，手机读取和选择 |
| 分类 | 账本 | PC/Web 可管理，手机读取和选择 |
| 标签 | 账本 | PC/Web 可管理，手机可使用，轻量新增后置 |
| 往来方 | 账本 | PC/Web 可管理，手机读取和选择 |
| 汇率快照 | 账本 | PC/Web 可管理，手机读取 |

PC 本地未开启同步的账本只保存本机基础资料。开启同步后，只同步新系统基础资料对象；旧 MoneyHome8 原始文件、旧字段值、旧原始行、迁移审计、迁移报告、脱敏摘要和旧路径仍只保存在 PC 本地，不进入云端。

## 3. 通用字段

所有基础资料对象至少需要以下字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `object_id` | 是 | 新系统稳定对象 ID |
| `ledger_id` | 是 | 所属账本 ID |
| `name` | 是 | 账本内展示名称 |
| `code` | 否 | 账本内可选业务代码；币种使用 `currency_code` |
| `sort_order` | 否 | 同级排序 |
| `is_archived` | 是 | 停用状态 |
| `version` | 是 | 对象版本 |
| `created_at` | 是 | 创建时间 |
| `updated_at` | 是 | 最后更新时间 |
| `deleted_at` | 否 | 软删除或墓碑时间 |

名称可以重复与否需要按对象定义：

| 对象 | 名称规则 |
| --- | --- |
| 币种 | `currency_code` 在账本内唯一 |
| 账户组 | 同一父级下名称不建议重复；重复时 UI 必须展示路径 |
| 账户 | 同一账本内允许重名，但 UI 必须展示分组、币种和关闭状态 |
| 分类 | 同一父级同方向下名称不建议重复；重复时 UI 必须展示路径 |
| 标签 | 同一账本内名称不建议重复；颜色不能作为唯一身份 |
| 往来方 | 同一账本内允许重名，需通过备注或联系方式辅助区分 |

## 4. 账户组

账户组用于组织账户树，不直接承载余额。

字段要求：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `group_id` | 是 | 账户组 ID |
| `parent_group_id` | 否 | 父组 ID；为空表示根级 |
| `group_kind` | 否 | 资产、负债、净值或自定义分组 |
| `name_path` | 否 | 服务端或本地查询可返回的展示路径 |

规则：

1. 禁止形成循环父子关系。
2. 父组停用后，子组和账户不能在常规选择器中丢失。
3. 删除有子组或账户的组时，必须改为停用或要求先迁移子项。
4. PC/Web 提供完整管理；手机第一版只读取账户树摘要。
5. 账户组归属解除、批量迁移或组失效必须固定账户版本和组版本；提交前组被删除、归档或跨账本失效时拒绝并保留草稿。
6. 删除组合账户或账户组详情前必须返回成员、子账户、历史交易、附件、计划和同步影响预览。

## 5. 账户

账户是交易和余额的核心引用对象。

字段要求：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `account_id` | 是 | 账户 ID |
| `group_id` | 否 | 账户组 ID；为空时归入未分组 |
| `account_kind` | 是 | 现金、银行卡、信用卡、借贷、投资、虚拟账户等类型键 |
| `currency_code` | 是 | 账户币种 |
| `opening_balance_minor` | 是 | 初始余额，使用账户币种最小单位整数 |
| `opened_on` | 否 | 开户或启用业务日期 |
| `closed_on` | 否 | 关闭业务日期 |
| `is_hidden` | 是 | 是否默认隐藏 |

规则：

1. 账户创建后不建议直接修改币种；如必须修改，应走新建账户或迁移流程。
2. 有历史交易的账户不能物理删除，只能隐藏、关闭或软删除。
3. 关闭账户仍可在历史流水、报表和冲突详情中展示。
4. 常用记账只能选择未关闭且未归档账户，除非正在编辑历史记录。
5. 余额由分录重建，不允许 UI 直接改写当前余额。
6. 组合账户、一本通或多成员账户的主账户、子账户、组详情和期初事件必须同事务提交；任一成员失败整体回滚。
7. 期初余额从既有账户转入时必须生成双边平衡分录；外部期初、既有账户转入和组合账户期初必须用不同来源类型记录。
8. 非人民币、负余额、余额不足、关闭账户和多成员账户必须有结构化校验结果，不能由 UI 静默修正。

## 6. 分类

分类用于表达收入和支出方向。

字段要求：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `category_id` | 是 | 分类 ID |
| `parent_category_id` | 否 | 父分类 ID |
| `direction` | 是 | income、expense 或 first-version explicitly supported value |
| `name_path` | 否 | 分类完整路径 |
| `is_system` | 是 | 是否系统内置或迁移保留分类 |

规则：

1. 收入命令只能引用收入分类，支出命令只能引用支出分类。
2. 分类方向创建后不允许直接从收入改支出或从支出改收入。
3. 父分类归档后，子分类不能从选择器中消失，应展示归档路径或要求用户重选。
4. 已被历史交易引用的分类不能物理删除。

## 7. 标签

标签用于灵活筛选和辅助归类，不改变财务事实。

字段要求：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `tag_id` | 是 | 标签 ID |
| `color` | 否 | 展示颜色 |
| `description` | 否 | 账本内说明 |
| `display_order` | 否 | 同一账本内自定义显示顺序 |
| `is_home_pinned` | 否 | 是否显示在首页或常用入口；属于显示偏好，不改变交易事实 |

规则：

1. 同一交易不能重复引用同一标签。
2. 标签归档后，历史记录继续展示标签名称。
3. 标签重命名应通过对象版本同步到三端；历史交易显示当前名称还是历史快照，需要由交易展示层明确。
4. 手机第一版可以使用已有标签；离线轻量新增标签可后置，不阻塞常用记账。
5. 标签设为首页只影响 PC/Web 的展示入口或筛选快捷入口，不改变交易、资产、预算、报表或同步事实。
6. 标签拖放排序必须保存稳定 `tag_id` 顺序和对象版本；取消拖放零写入，失败回滚到拖放前顺序。
7. 标签批量加入、移出、转移和导入必须固定选择快照、目标标签版本和影响预览；有历史记录时不得物理删除标签。
8. 旧标签排序、设为首页、导出打印和批量关系校准证据只保存在 PC 本地；云端只同步新系统标签对象、关系对象、排序偏好和脱敏审计。

## 8. 往来方

往来方用于记录人员、机构或联系人。

字段要求：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `party_id` | 是 | 往来方 ID |
| `party_kind` | 否 | person、organization、merchant 或自定义 |
| `display_name` | 是 | 展示名称 |
| `note` | 否 | 账本内备注 |
| `birthday_calendar` | 否 | 人员生日历法：gregorian、lunar；机构不使用 |
| `birthday_year` | 否 | 原始生日年份，可为空；用于周年和年龄规则 |
| `birthday_month` | 否 | 原始生日月份 |
| `birthday_day` | 否 | 原始生日日期 |
| `birthday_leap_month` | 否 | 农历闰月标记，可为空 |

规则：

1. 往来方可被交易、计划、提醒或应收应付对象引用。
2. 有历史引用的往来方不能物理删除。
3. 手机第一版只做选择和展示；完整管理放在 PC/Web。
4. 联系方式、身份证件或敏感备注第一版不进入同步主线，除非后续补隐私字段定义。
5. 生日字段只对人员类往来方有效，财务日历读取人员真相生成只读投影，不另建可独立编辑的生日事件。
6. 公历、农历、闰月和 `2月29日` 规则必须版本化；旧生日验证证据、旧路径、旧原始行、迁移审计、迁移报告和脱敏摘要只保存在 PC 本地。

## 9. 币种和汇率快照

币种和汇率要求以 `amount-currency-exchange-rate-plan.md` 为准，本计划补充生命周期口径：

1. 账本本位币创建账本时必须明确。
2. 已被账户、交易或汇率引用的币种不能物理删除。
3. 汇率快照按账本保存，不作为全局可变汇率覆盖历史交易。
4. 修改汇率快照必须产生新版本，并触发相关报表重算或缓存失效。

## 10. 三端行为

### 10.1 PC

PC 端支持：

1. 未登录创建和管理本地账本基础资料。
2. 账户组、账户、分类、标签、往来方、币种和汇率快照的完整管理。
3. 旧 MoneyHome8 迁移生成新系统基础资料。
4. 开启同步后上传新系统基础资料对象。
5. 资料管理入口在无账本状态只能展示创建/打开账本入口或只读说明，不得保存游离基础资料。
6. 跨类型切换、关闭资料管理或切换账本时，未保存草稿必须提示保存、放弃或继续编辑；取消不得写入。

PC 端禁止：

1. 把旧来源完整路径作为云端对象字段。
2. 把旧原始行、旧字段值、迁移审计、迁移报告或脱敏摘要上传云端。
3. Flutter 直接写 SQLite 或旧账本文件。
4. 把旧账户组、组合账户、期初分录或资料入口草稿校准证据上传云端。

### 10.2 Web

Web 端支持：

1. 登录后读取云端账本基础资料。
2. 管理账户组、账户、分类、标签、往来方、币种和汇率快照。
3. 在创建交易前实时校验基础资料版本和权限。
4. 解决基础资料冲突。

Web 端禁止：

1. 读取 PC 本地 SQLite。
2. 读取旧 MoneyHome8 原始文件。
3. 展示旧迁移审计、迁移报告、脱敏摘要、旧路径或旧原始行。

### 10.3 手机

手机端支持：

1. 拉取最近账本所需基础资料缓存。
2. 在离线草稿中引用已缓存账户、分类、标签和往来方。
3. 上传队列时由云端校验引用对象仍有效。
4. 当基础资料缺失、归档或权限不足时保留草稿并提示 PC/Web 处理。

手机端第一版不承担完整基础资料管理。

## 11. 同步和冲突

基础资料属于可并发修改对象，必须进入对象级多主同步。

规则：

1. 创建基础资料必须带幂等键。
2. 修改必须带预期版本。
3. 删除或归档必须产生墓碑或归档版本。
4. PC 离线修改基础资料后上传，云端必须校验账本成员角色、对象版本和引用关系。
5. Web 在线修改基础资料时直接校验云端当前版本。
6. 手机队列上传交易时，如果引用对象版本过旧，应返回字段级错误或冲突提示。

需要显式冲突的场景：

| 场景 | 处理 |
| --- | --- |
| 同一账户名称、分组或关闭状态并发修改 | PC/Web 展示字段级差异 |
| 分类方向被修改或归档后仍被交易引用 | 阻止提交或要求重选 |
| 标签被删除后手机离线交易仍引用 | 保留草稿，要求移除或恢复标签 |
| 往来方被归档后仍被新对象引用 | 根据对象类型提示重选或确认继续 |
| 汇率快照并发修改 | 展示本币折算影响 |
| 组合账户成员并发失效 | 整体拒绝提交，保留草稿 |
| 账户组批量迁移部分失败 | 整体回滚并返回逐项原因 |

## 12. 权限

基础资料管理按账本角色控制：

| 操作 | Owner | Editor | Viewer |
| --- | --- | --- | --- |
| 读取基础资料 | 允许 | 允许 | 允许 |
| 创建基础资料 | 允许 | 允许 | 禁止 |
| 修改基础资料 | 允许 | 允许 | 禁止 |
| 归档基础资料 | 允许 | 允许 | 禁止 |
| 删除账本本位币 | 禁止 | 禁止 | 禁止 |
| 物理删除被引用资料 | 禁止 | 禁止 | 禁止 |

Viewer 的本地草稿可以保留在设备上，但不得上传成功。PC 本地未开启同步的账本没有云端成员概念。

## 13. 查询和选择器

选择器必须只展示当前账本内对象。

规则：

1. 账户选择器默认排除关闭账户，编辑历史记录时可显示被引用账户。
2. 分类选择器按收入/支出方向过滤。
3. 标签选择器默认排除归档标签，但历史记录继续展示。
4. 往来方选择器支持关键字查找和最近使用。
5. 币种选择器必须展示 `currency_code`、名称和小数位。
6. 手机选择器必须展示缓存状态，避免用户误以为资料完整。
7. 选择器提交必须携带候选对象版本或候选列表版本；候选在提交前被归档、删除、改名、移权或跨账本失效时，命令必须拒绝并保留草稿。
8. 内联新增候选成功后必须返回稳定 ID 和对象版本；取消或失败不得污染宿主草稿。
9. 选择器键盘焦点、搜索关键字、过滤范围和空结果状态不能绕过账本、权限、归档和状态过滤。

## 14. 错误模型

基础资料错误码至少包括：

| 错误码 | 含义 | 三端处理 |
| --- | --- | --- |
| `master_data_not_found` | 引用对象不存在或不属账本 | 标记字段并要求刷新 |
| `master_data_archived` | 引用对象已归档或关闭 | 要求重选或确认历史编辑 |
| `master_data_version_conflict` | 对象版本冲突 | PC/Web 进入冲突解决，手机保留草稿 |
| `category_direction_mismatch` | 分类方向不匹配 | 标记分类字段 |
| `account_currency_mismatch` | 账户币种和输入币种不匹配 | 标记账户或币种字段 |
| `master_data_permission_denied` | 当前角色无权管理 | 保留本地草稿或阻止提交 |
| `master_data_referenced` | 对象已有历史引用，不能物理删除 | 提示改为归档 |
| `master_data_group_invalid` | 账户组或组合账户成员失效 | 保留草稿并要求刷新 |
| `master_data_atomic_failed` | 组合账户或批量迁移原子提交失败 | 整体回滚并返回逐项原因 |

错误响应不得包含旧 MoneyHome8 原始路径、旧原始行、旧字段值、迁移审计、迁移报告、脱敏摘要或 PC 机器环境诊断。

## 15. 验收要点

1. PC 未登录可以创建账户组、账户、分类和标签，并用于本地记账。
2. PC 开启同步后，新系统基础资料同步到云端，旧迁移证据不上传。
3. Web 登录后可以管理同一账本的基础资料。
4. 手机能读取基础资料缓存并用于离线草稿。
5. 手机上传引用已归档分类的草稿时不会丢失草稿。
6. Viewer 不能上传基础资料变更。
7. 有历史交易的账户、分类、标签和往来方不能物理删除。
8. 分类方向错误、账户币种错误和版本冲突都有字段级错误。
9. 基础资料冲突只能由 PC/Web 完整处理。
10. 多账本之间不能互相读取或引用基础资料对象。
11. 标签设为首页和拖放排序只改变显示偏好或排序对象，不改变财务事实；取消、失败和候选版本失效必须零写入或回滚。
12. 选择器候选版本失效、并发归档、跨账本引用和权限变化必须拒绝提交并保留草稿。
13. 组合账户、一本通、多成员账户和组批量迁移必须原子提交；失败时不得留下半个主子结构或半批成员关系。
14. 无账本状态、跨类型切换和关闭资料管理时，未保存草稿不能静默写入或丢失。

## 16. 当前无需人工确认
