# 显示、本地化与可访问性需求计划

本文档承接 `three-client-ui-navigation-plan.md`、`settings-preferences-notification-plan.md`、`amount-currency-exchange-rate-plan.md`、`date-time-period-semantics-plan.md`、`domain-validation-invariants-plan.md` 和 `investment-advanced-assets-calibration-plan.md`，定义 Finance Own 第一版三端在显示格式、本地化消息、错误表达、键盘操作和基础可访问性方面的需求边界。

## 1. 核心原则

1. 存储和 API 使用稳定业务字段，显示层负责本地化格式。
2. 持久化键、命令 ID、错误码和对象类型不得使用中文菜单文本作为唯一标识。
3. 金额、日期、时间、币种、状态和错误消息在三端展示口径一致。
4. 基础可访问性不能依赖颜色、悬停或鼠标操作作为唯一信息来源。
5. 旧 MoneyHome8 缓存中的中文字段协议未确认前，不得编造成新系统业务名称。

## 2. 稳定键和展示文本

必须使用稳定键：

| 类型 | 稳定键 |
| --- | --- |
| 命令 | `command_id` 或命令枚举 |
| 菜单 | `route_id`、`action_id` 或页面族 ID |
| 错误 | `error_code` + `message_key` |
| 状态 | 状态枚举 |
| 对象类型 | 新系统对象类型枚举 |
| 快捷键 | 稳定命令 ID |

规则：

1. UI 文案可以本地化，但不能成为业务逻辑判断依据。
2. 快捷键、最近页面、默认页面和用户偏好都保存稳定键。
3. 导入和迁移预览必须展示字段来源状态，不能把未知旧字段直接显示为已确认业务含义。
4. Web、PC、手机同一状态应使用同一 `message_key`，允许端侧文案长度不同。

## 3. 金额和币种显示

金额显示规则：

1. 真相字段使用最小单位整数和币种代码。
2. UI 根据 `currency_code` 和 `minor_unit` 格式化小数。
3. 输入框可以显示小数，但提交时必须转回整数金额。
4. 负数、流入、流出和转账方向必须通过符号、颜色之外的文本或图标表达。
5. 缺汇率、本币折算缺失和待校准投资结果必须有明确状态文本。

三端必须一致：

1. 同一对象显示同一币种代码。
2. 同一余额口径不能在 PC、Web、手机用不同舍入规则展示。
3. 跨币种汇总不得把不同币种名义金额直接相加后显示为单一币种。

## 4. 日期和时间显示

日期显示规则：

1. 交易列表优先显示 `business_date`。
2. 审计、同步、冲突和设备状态显示时间戳。
3. 今日提醒、预算当前期和计划下一次发生按账本时区解释。
4. 移动端可以使用更短日期格式，但不能隐藏业务日期和同步状态的区别。
5. 导出和打印必须带期间参数、生成时间和数据版本。

## 5. 错误消息和字段提示

错误显示要求：

| 错误层级 | 展示方式 |
| --- | --- |
| 字段错误 | 定位到字段，并保留用户输入 |
| 对象错误 | 展示对象名、类型和可处理动作 |
| 权限错误 | 展示当前角色和限制，不伪装成普通校验失败 |
| 同步错误 | 展示可重试、需登录、设备撤销或冲突摘要 |
| 存储错误 | 展示可恢复动作，不暴露本地完整路径 |
| 校准错误 | 展示待校准、输入-only 或不支持状态 |

规则：

1. 错误响应必须使用稳定 `error_code`。
2. UI 根据 `message_key` 展示本地化文案。
3. 字段错误必须能映射到表单、导入预览、批量结果或冲突详情。
4. 错误消息不得包含密码、令牌、PC 完整本地路径、旧原始行、迁移审计、迁移报告、脱敏摘要或 PC 机器环境诊断。

## 6. 可访问性

第一版基础可访问性要求：

1. 主要写入命令、保存、取消、删除确认和冲突处理可通过键盘触达。
2. 表单字段有可读标签、错误描述和必填状态。
3. 只读、禁用、冲突、失败和待同步状态不能只靠颜色表达。
4. 图标按钮必须有可访问名称。
5. 表格或列表必须有稳定行焦点和选择状态。
6. 删除、覆盖恢复、开启同步和上传附件等高风险确认不能只依赖悬停提示。
7. 手机端按钮触达区域必须适合触控，且状态提示不能只靠短暂 toast。

## 7. 三端差异

PC：

1. 支持快捷键和菜单命令。
2. 支持密集列表、批量选择和可键盘操作的表格。
3. 旧迁移预览显示字段来源、校验状态和阻塞原因。

Web：

1. 支持浏览器键盘导航和焦点管理。
2. Viewer 看不到可成功提交的写入入口。
3. 在线错误必须区分认证、权限、字段校验、同步冲突和服务不可用。

手机：

1. 使用简短状态文案和摘要。
2. 离线、待上传、失败和冲突状态必须在草稿列表可见。
3. 不承担复杂字段级冲突合并或高级批量操作。

## 8. 旧数据中文字段边界

旧 MoneyHome8、缓存或参考库中的中文字段处理规则：

1. 已确认编码和字段语义后，才可映射为新系统显示名称。
2. 未确认 GBK/ANSI 长度前缀协议时，只能作为 PC 本地诊断候选，不写成业务名称。
3. 未识别片段、旧字段值和旧类别码诊断只保存在 PC 本地。
4. 云端、Web 和手机不得展示旧迁移诊断或旧字段原文。
5. 迁移后的新系统对象名称可同步，但必须来自用户确认或可靠映射结果。

## 9. 隐私和安全显示

不得显示或导出：

1. 密码、访问令牌、刷新令牌和密钥材料。
2. PC 完整本地路径。
3. 旧 MoneyHome8 原始文件、旧原始行和旧字段值。
4. 迁移审计、迁移报告、脱敏摘要或 PC 机器环境诊断。
5. 附件下载短期授权链接的敏感签名部分。

可以显示：

1. 账本名称、对象名称、同步状态和角色。
2. 脱敏设备名称和最近同步时间。
3. 用户确认同步后的新系统对象字段。
4. 校准状态和不支持原因。

## 10. 验收要点

1. 同一错误码在 PC、Web、手机都能展示可理解文案。
2. 字段错误能定位到表单字段并保留用户输入。
3. 金额显示符合币种小数位，提交仍使用整数金额。
4. 业务日期和审计时间在 UI 上可区分。
5. 只读、失败、冲突、待同步状态不只靠颜色表达。
6. 图标按钮有可访问名称。
7. 快捷键使用稳定命令 ID，不使用中文菜单文本持久化。
8. 未确认的旧缓存中文片段不会进入新系统业务名称。
9. 错误和导出不泄露 PC 本地完整路径或旧迁移证据。
10. 手机离线草稿列表能明确展示待上传、失败和冲突状态。

## 11. 当前无需人工确认

本计划没有引入新的产品取舍；它细化的是已确认的三端 Flutter UI、稳定命令 ID、金额日期显示、字段错误、本地化消息、旧迁移隐私和基础可访问性边界。
