# 三端需求分析

本文档承接 `technical-architecture-proposal.md`、`source-document-traceability-plan.md` 和 `docs/adr/` 中已确认的架构决策，用于把 Finance Own 第一版的 PC、手机和 Web 三端需求拆成可验证边界。本文属于进行中工作计划，后续实施完成后再把稳定结论回填到长期架构和产品文档。

## 1. 已确认产品边界

- 第一版 UI 统一采用 Flutter：PC 为 Flutter Desktop，手机为 Flutter Mobile，Web 为 Flutter Web。
- PC 端必须支持完全离线可写，本地账本采用 SQLite。
- Rust 仅作为 PC 客户端内置本地核心，不要求用户单独安装 Rust。
- Flutter PC 通过稳定 PC 本地 API/FFI 调用 Rust；Flutter 不直接访问 SQLite、不拼 SQL、不读取旧账本文件。
- .NET 是第一版云端服务端主技术，云端数据库采用 PostgreSQL。
- Web 端第一版在线为主，必须登录后使用。
- 手机端可记账、上传、下载同步数据，可支持离线草稿和待同步队列，但不保存完整本地账本。
- 三端都可以产生财务记录，也都可以上传到云端并同步下载其它端提交的数据。
- 同步采用对象级多主同步，云端保存完整新系统财务对象副本并协调冲突。
- PC 和 Web 支持完整冲突解决；手机端只提示冲突并允许延后处理。
- 旧 MoneyHome8 原始文件迁移第一版仅在 PC 端本地执行，旧文件不上传云端。
- 支持多账本，且多账本数据必须隔离。

## 2. PC 端需求

PC 端是完整本地账本、旧账本迁移和高级维护能力的主要承载端。

第一版必须支持：

1. 未登录状态下创建、打开和维护本地账本。
2. 完全离线新增、修改、删除和查询本地财务记录。
3. 账户中心、记账、流水、基础报表、预算、提醒、计划和财务目标的基础闭环。
4. 旧 MoneyHome8 数据本地迁移、预览、校验和导入。
5. 登录后由用户显式确认开启同步，确认前不得自动上传本地账本。
6. 上传本端变更、下载其它端变更，并展示同步状态。
7. 完整冲突列表、差异对比和冲突解决流程。
8. 备份、恢复、导入导出、附件和高风险文件操作。

PC 端第一版不要求：

- 写回旧 MoneyHome8 原始账本。
- 手机端或 Web 端内置 Rust。
- 复杂账本成员细粒度权限配置。

## 3. 手机端需求

手机端强调随手记账、查询和轻量同步。

第一版必须支持：

1. 登录后选择账本并查看云端同步下来的数据。
2. 在线新增收入、支出、转账等常用财务记录。
3. 离线保存记账草稿和待同步队列。
4. 联网后上传手机端变更并下载其它端变更。
5. 查看基础账户余额、最近流水、预算或提醒摘要。
6. 提示存在冲突，并允许延后到 PC 或 Web 处理。
7. 保存最近查询缓存、同步状态和附件临时缓存。

手机端第一版不要求：

- 保存完整本地账本。
- 执行旧 MoneyHome8 迁移。
- 完整冲突解决。
- 批量治理、复杂投资录入和高级备份恢复。

## 4. Web 端需求

Web 端第一版在线为主，承担在线记账、查询和冲突处理。

第一版必须支持：

1. 登录后访问账本。
2. 在线新增、修改、删除常用财务记录。
3. 查询账户、流水、预算、提醒和基础报表。
4. 直接通过 .NET API 写入云端对象副本。
5. 查看同步状态和设备变更来源。
6. 完整冲突解决。
7. 多账本切换和账本级权限校验。

Web 端第一版不要求：

- 浏览器离线主账本写入。
- 旧 MoneyHome8 原始文件迁移。
- 本地 SQLite 账本。

## 5. 云端与同步需求

.NET 云端服务需要支撑三端共同写入和同步。

第一版必须支持：

1. 自有账号、会话、刷新令牌和设备列表。
2. 多账本和账本成员模型，至少区分所有者、可编辑成员和只读成员。
3. PostgreSQL 保存完整新系统财务对象副本。
4. 对象级 push/pull 同步，不上传整个 SQLite 文件。
5. 稳定对象 ID、版本、墓碑、同步批次和冲突记录。
6. 非冲突变更自动双向合并。
7. 同一对象同一字段并发编辑、删除与修改并发等真正冲突进入显式解决流程。
8. 附件元数据、附件存储、权限校验和审计日志。
9. HTTPS、静态加密、密钥管理、账本级权限隔离和敏感字段保护。

第一版不要求完整端到端加密；但不能把这个决定理解为弱化安全要求。

| 登录后使用 | 支持 | 支持 | 支持 | 三端共用自有账号体系 |
| 离线新增记录 | 支持完整本地写入 | 支持草稿和待同步队列 | 不支持 | Web 第一版在线为主 |
| 离线修改/删除记录 | 支持 | 暂不作为完整能力 | 不支持 | 手机端优先离线新增，复杂修改删除后置 |
| 在线新增记录 | 支持 | 支持 | 支持 | 三端都可产生财务记录 |
| 在线修改/删除记录 | 支持 | 支持常用记录 | 支持 | 高风险批量操作优先 PC/Web |

| 旧账本迁移 | 支持 | 不支持 | 不支持 | 旧原始文件只在 PC 本地 |

| 账本成员管理 | 支持基础能力 | 查看/接受邀请可后置 | 支持基础能力 | 细粒度权限后置 |

### 手机端第一版能力边界

手机端“离线”只表示可以保存未同步的用户输入，不表示手机端拥有完整账本真相。手机端离线队列必须保存足够的幂等信息，避免联网后重复创建记录。

手机端第一版离线队列建议只覆盖：

1. 新增收入。
2. 新增支出。
3. 新增转账。
4. 新增备注、标签和附件临时引用。

手机端第一版不建议离线覆盖：

1. 删除已同步记录。
2. 修改已同步记录的关键金额、账户或日期。
3. 批量修改。
4. 复杂投资、计划自动执行、迁移导入和冲突合并。

## 7. 同步对象范围

第一版同步按对象和批次传输，不同步 SQLite 文件。同步对象必须带 `ledger_id`、稳定对象 ID、版本、更新时间、来源设备和删除墓碑信息。

### 第一批必须同步

| 对象 | 说明 | 三端写入范围 |
| --- | --- | --- |
| 账本 | 账本名称、本位币、基础设置 | PC/Web 创建与管理，手机选择和查看 |
| 账本成员 | 所有者、可编辑成员、只读成员 | PC/Web 管理，手机查看或接受邀请后置 |
| 币种 | 账本内币种和精度 | PC/Web 管理，手机读取 |
| 账户组 | 账户树分组 | PC/Web 管理，手机读取 |
| 账户 | 账户资料、币种、隐藏/关闭状态 | PC/Web 管理，手机常用读取 |
| 分类 | 收入/支出分类及层级 | PC/Web 管理，手机读取和选择 |
| 标签 | 标签名称、颜色、归档状态 | 三端可使用，管理优先 PC/Web |
| 往来方 | 人员、机构、联系人 | PC/Web 管理，手机选择和轻量新增后置 |
| 交易 | 收入、支出、转账和原子分录 | 三端都可新增常用交易 |
| 交易附件引用 | 附件和交易关系 | 三端可新增，云端做权限和审计 |
| 预算 | 预算定义和预算项 | PC/Web 管理，手机摘要和轻量查看 |
| 提醒 | 提醒规则和状态 | PC/Web 管理，手机查看和提示 |
| 计划 | 计划模板和执行状态 | PC/Web 管理，手机提示 |
| 财务目标 | 目标定义、账户范围和进度口径 | PC/Web 管理，手机查看 |
| 同步冲突 | 冲突对象、字段差异、解决状态 | PC/Web 解决，手机提示 |

### 第一版可后置同步

| 对象 | 后置原因 |
| --- | --- |
| 复杂投资成交 | 公式和费用口径仍需真实样例校准 |
| 投资成本批次和收益率结果 | 不能在校准前固化计算结论 |
| 高级报表定义 | 第一版先保证基础报表和查询 |
| 自动计划执行任务 | 需要任务幂等、重试和后台恢复机制 |
| 复杂权限策略 | 第一版只预留账本成员和粗粒度角色 |
| 旧迁移原始行 | 旧原始文件不上传云端，迁移审计和迁移报告只在 PC 本地保存 |

## 8. 关键用户流程

### 8.1 PC 本地新用户流程

1. 用户安装 Flutter PC 客户端。
2. 客户端内置 Rust 本地核心，用户不需要安装 Rust。
3. 用户未登录也可以创建本地账本。
4. 用户离线录入账户、分类和财务记录。
5. 用户选择登录。
6. 系统展示本地账本名称、数据范围、附件规模和隐私提示。
7. 用户显式确认开启同步。
8. PC 端把新系统对象上传到云端，云端创建对象副本和同步批次。
9. 手机和 Web 登录后可同步查看该账本。

### 8.2 PC 旧账本迁移流程

1. 用户在 PC 端选择旧 MoneyHome8 文件。
2. Flutter PC 调用 Rust 本地迁移 API。
3. Rust 只读探测旧文件、参考库、内置库和缓存。
4. Rust 输出迁移预览、无法识别项、认证阻塞项和风险提示。
5. 用户确认导入。
6. Rust 把新系统对象写入 PC SQLite，并记录迁移映射和审计信息。
7. 用户确认开启同步后，系统只上传新系统对象，不上传旧原始文件。

### 8.3 手机随手记账流程

1. 用户登录手机端并选择账本。
2. 手机端拉取最近账户、分类、标签和同步状态。
3. 用户在线或离线新增收入、支出或转账。
4. 离线时记录进入本地待同步队列。
5. 联网后手机端上传队列。
6. 云端校验对象版本、账本权限和幂等键。
7. 非冲突变更合并，冲突则标记待处理。
8. 手机端展示同步成功或冲突提示。

### 8.4 Web 在线记账流程

1. 用户登录 Web。
2. Web 端选择账本并加载云端对象副本。
3. 用户新增、修改或删除常用财务记录。
4. Web 端通过 .NET API 写入云端。
5. 云端生成对象版本和同步批次。
6. PC 和手机下次同步时拉取变更。

### 8.5 冲突解决流程

1. 云端发现同一对象同一字段并发编辑，或删除与修改并发。
2. 云端记录冲突，不静默覆盖任何一端。
3. PC/Web 展示冲突列表、来源设备、时间、字段差异和可选处理方式。
4. 用户选择保留本端、保留云端、字段级合并或另存副本。
5. 系统生成新的解决版本，并把冲突标记为已解决。
6. 手机端只提示冲突数量和处理入口，不提供复杂字段级合并。

## 9. 需求验收口径

每个三端需求进入实施计划前，必须满足以下验收口径：

1. 明确端：PC、手机、Web、云端或 Rust 本地核心。
2. 明确联网状态：在线、离线、待同步或冲突。
3. 明确账本范围：所有对象必须限定 `ledger_id`。
4. 明确权限：未登录、本地账本、账本成员、只读成员或可编辑成员。
5. 明确数据来源：PC SQLite、手机队列、云端 PostgreSQL、旧 MoneyHome8 原始文件或缓存。
6. 明确失败状态：输入校验失败、权限失败、版本冲突、网络失败、迁移阻塞或存储失败。
7. 明确是否同步：本地-only、可同步、必须同步或禁止上传。

## 10. PC 首屏本地 API 需求

PC 首屏本地 API 是 Flutter Desktop 与 Rust 本地核心之间的第一条正式边界。它必须以业务 DTO 和结构化错误表达页面所需状态，不暴露 SQLite 表结构。

### 10.1 账本会话 API

| API 能力 | 输入 | 输出 | 失败状态 |
| --- | --- | --- | --- |
| 创建本地账本 | 账本名称、本位币、首个账户、创建时间 | 账本 ID、首个账户 ID、会话状态 | 输入无效、文件创建失败、SQLite 初始化失败 |
| 打开本地账本 | 本地账本路径或最近账本 ID | 账本信息、会话状态、完整性检查摘要 | 文件不存在、格式不识别、外来 SQLite 标识、版本不支持、权限失败 |
| 关闭账本 | 当前账本 ID | 关闭状态 | 后台写入未完成、备份阻塞 |
| 读取会话状态 | 无或当前上下文 | 无账本、打开中、已打开、关闭中、失败 | 无 |

账本会话 API 必须保护以下场景：

1. Flutter 不直接判断 SQLite 文件头或迁移版本。
2. 打开失败必须返回可展示原因，不能让页面猜测失败类型。
3. 未登录账本必须能长期本地使用。
4. 登录后开启同步必须经过用户显式确认。

### 10.2 账户中心 API

首屏账户中心应复用当前 `WorkspaceHomeViewModel` 方向，并继续细化：

| 数据块 | 字段范围 | 说明 |
| --- | --- | --- |
| 账簿信息 | `ledger_id`、账簿名、本位币 | 所有查询必须显式限定账本 |
| 工作区状态 | 当前工作区、加载状态、错误状态 | Flutter 只绑定状态，不自行触发底层读取 |
| 账户组树 | 组 ID、父组、名称、类型、排序、子组 | 父组缺失时提升到根级，不能让账户消失 |
| 账户行 | 账户 ID、组 ID、名称、类型、币种、余额、资产/负债、隐藏、关闭日期 | 余额使用最小单位整数 |
| 币种汇总 | 币种、资产合计、负债合计 | 不在 Flutter 端重新计算财务口径 |
| 最近流水 | 日期、账户、分类、金额、币种、主题、标签、附件状态 | 默认不包含作废记录 |

### 10.3 常用记账 API

第一版 PC 首屏至少需要收入、支出和转账三类命令。命令必须走 Rust 本地核心校验，不允许 Flutter 直接写入本地数据库。

| 命令 | 必填输入 | 关键校验 | 输出 |
| --- | --- | --- | --- |
| 新增收入 | 账本、日期、账户、金额、币种、分类或主题 | 金额大于零、账户属于账本、币种匹配、分类方向允许收入 | 交易 ID、分录 ID、更新后的余额提示 |
| 新增支出 | 账本、日期、账户、金额、币种、分类或主题 | 金额大于零、账户属于账本、币种匹配、分类方向允许支出 | 交易 ID、分录 ID、更新后的余额提示 |
| 新增转账 | 账本、日期、转出账户、转入账户、金额、币种、可选手续费 | 两侧账户属于账本、不能缺任一方向、手续费分录独立表达 | 交易 ID、转出/转入/手续费分录 ID |

命令失败必须返回字段级错误或结构化业务错误，例如账户不存在、分类不可用、金额非法、币种不匹配、并发版本冲突或存储失败。

### 10.4 同步入口 API

PC 首屏只需要表达同步入口状态，不要求一次完成完整同步实现。

| 状态 | 页面含义 | 可用操作 |
| --- | --- | --- |
| 未登录 | 当前账本只在本地 | 登录 |
| 已登录未开启同步 | 登录不等于上传账本 | 查看隐私提示、确认开启同步 |
| 同步中 | 正在上传或下载对象变更 | 查看进度、取消非关键任务后置 |
| 已同步 | 本地和云端无待处理变更 | 手动同步、查看设备变更 |
| 有待上传 | 本地存在未上传变更 | 上传 |
| 有待下载 | 云端存在其它端变更 | 下载/合并 |
| 有冲突 | 存在显式冲突 | 打开冲突列表 |
| 同步失败 | 网络、权限、版本或服务端错误 | 重试、查看诊断 |

### 10.5 当前 Rust 基础与缺口

| 需求块 | 当前基础 | 待补缺口 |
| --- | --- | --- |
| 账本会话 | `src/app/workspace_shell.rs` 已有 `LedgerSessionState`、`WorkspaceShellState` | 需要形成 FFI 友好的 DTO 和打开/关闭账本 API 包装 |
| 账户中心首屏 | `src/app/ui.rs` 已有 `WorkspaceHomeViewModel`、账户组树、未分组账户和币种汇总 | 需要补分页、筛选、最近流水数量限制和 Flutter 序列化边界 |
| 基础资料读取 | `ReferenceDataRepository` 已覆盖账簿、账户组、账户、分类、标签、往来方 | 需要整理成 PC 本地 API 的查询命名和错误码 |
| 报表读取 | `ReportReadRepository` 已覆盖流水、余额、标签和投资输入投影 | 需要定义首屏使用的默认筛选、分页和空状态 |
| 常用交易写入 | `TransactionWriteRepository` 和 `create_transaction` 已有通用交易校验与写入入口 | 需要补面向 Flutter 的收入、支出、转账命令 DTO，避免页面构造底层分录细节 |

| 旧迁移 | `legacy_source`、`mh8`、缓存和参考库探测已有结构化状态 | 需要补迁移预览、确认导入和迁移审计 API |

### 10.7 Flutter PC 本地 API 错误模型

错误模型必须区分用户可修复错误、权限/同步错误和本地存储错误，且不得把完整敏感路径、密钥或旧原始数据放入错误消息。

| 错误类型 | 示例 | Flutter 展示要求 |
| --- | --- | --- |
| `ValidationError` | 金额为空、日期格式错误、缺少账户 | 标到字段或表单顶部 |
| `NotFoundError` | 账户不存在、账本不存在 | 提示刷新或重新选择 |
| `ConflictError` | 本地版本冲突、同步冲突 | 引导进入冲突或重试流程 |
| `PermissionError` | 云端角色变为只读 | 提示权限变化 |
| `StorageError` | SQLite 初始化失败、文件权限失败 | 展示脱敏原因和诊断入口 |
| `LegacySourceError` | 旧账本格式不识别、认证失败、对象不可见 | 展示迁移阻塞和下一步 |
| `NetworkError` | 云同步失败 | 保留本地可写，提示稍后同步 |

## 11. .NET API 第一版需求

.NET API 是 Web 在线端的主写入口，也是 PC 和手机同步的协调入口。第一版 API 不直接解析旧 MoneyHome8 原始文件。

### 11.1 认证与设备

| 能力 | 需求 |
| --- | --- |
| 注册/登录 | 第一版优先支持邮箱、密码和昵称；手机号登录后置 |
| 会话 | 支持访问令牌和刷新令牌 |
| 设备列表 | 记录设备 ID、设备类型、最后同步时间和可撤销状态 |
| 退出登录 | 当前设备令牌失效，不删除本地账本 |
| PC 未登录 | 不调用云端 API，仍可本地使用 |

邮箱优先的依据是旧版同步注册页已确认包含电子邮箱、密码、确认密码和昵称字段；当前没有同等强度证据要求第一版必须支持手机号登录。新系统可以在账号模型中预留手机号字段，但不把短信验证码接入作为第一版阻塞项。

### 11.2 账本与成员

| 能力 | 需求 |
| --- | --- |
| 账本列表 | 返回当前账号可访问账本，包含角色和同步摘要 |
| 创建云端账本 | Web 可创建；PC 本地账本开启同步时也可绑定或创建云端账本 |
| 账本成员 | 预留所有者、可编辑成员、只读成员 |
| 权限校验 | 所有对象读写必须校验 `ledger_id` 和成员角色 |
| 数据隔离 | 不同账本对象、附件、同步批次和报表缓存不得串账 |

### 11.3 对象同步

| 能力 | 需求 |
| --- | --- |
| Push | PC/手机上传对象变更批次，Web 在线写入也生成同类对象版本 |
| Pull | 三端按账本、游标、对象类型拉取变更 |
| 幂等 | 每个客户端变更必须携带幂等键，重复提交不得重复创建业务对象 |
| 墓碑 | 删除用墓碑同步，不能让其它端误恢复已删除对象 |
| 版本 | 对象必须有可比较版本，用于并发判断和冲突定位 |
| 审计 | 记录来源设备、来源端、用户、时间和变更摘要 |

### 11.4 冲突 API

| 能力 | 需求 |
| --- | --- |
| 冲突列表 | PC/Web 按账本查询冲突，手机只查询数量和摘要 |
| 冲突详情 | 返回对象、字段差异、来源版本、来源设备和操作类型 |
| 解决冲突 | 支持保留本端、保留云端、字段级合并或另存副本 |
| 解决审计 | 记录处理人、处理时间、处理方式和生成的新版本 |

### 11.5 附件 API

| 能力 | 需求 |
| --- | --- |
| 上传 | 三端都可上传附件，必须绑定账本和业务对象 |
| 下载 | 按账本权限控制下载 |
| 元数据 | 保存文件名、大小、内容哈希、MIME、上传设备和引用对象 |
| 敏感保护 | 附件 URL 不能长期裸露，必须有权限或短期授权机制 |

### 11.6 API 资源路径草案

第一版 API 采用账本作用域路径，避免跨账本串数据。路径命名用于需求分析，不等于最终 OpenAPI 定稿。

| 资源 | 路径草案 | 说明 |
| --- | --- | --- |
| 登录 | `POST /auth/login` | 获取访问令牌和刷新令牌 |
| 刷新令牌 | `POST /auth/refresh` | 更新访问令牌 |
| 当前用户 | `GET /me` | 当前用户和设备摘要 |
| 设备 | `GET /me/devices` | 设备列表和最后同步时间 |
| 账本列表 | `GET /ledgers` | 当前用户可访问账本 |
| 账本详情 | `GET /ledgers/{ledger_id}` | 账本基础信息和角色 |
| 账本成员 | `GET /ledgers/{ledger_id}/members` | 成员和角色 |
| 对象拉取 | `GET /ledgers/{ledger_id}/sync/changes` | 按游标拉取对象变更 |
| 对象推送 | `POST /ledgers/{ledger_id}/sync/batches` | 上传对象变更批次 |
| 冲突列表 | `GET /ledgers/{ledger_id}/sync/conflicts` | PC/Web 完整列表，手机可只取摘要 |
| 冲突解决 | `POST /ledgers/{ledger_id}/sync/conflicts/{conflict_id}/resolve` | 提交解决方式 |
| 附件上传 | `POST /ledgers/{ledger_id}/attachments` | 上传附件内容和元数据 |
| 附件下载 | `GET /ledgers/{ledger_id}/attachments/{attachment_id}/content` | 权限校验后下载或短期授权 |

### 11.7 分页、游标和错误模型

| 项目 | 第一版需求 |
| --- | --- |
| 分页 | 普通列表使用 `limit` 和 `cursor`，避免大 offset |
| 同步游标 | 每个账本、设备和对象类型可维护独立游标 |
| 幂等键 | Push 批次和客户端变更都必须携带幂等键 |
| 错误响应 | 统一返回错误码、可展示消息、诊断 ID 和字段错误 |
| 诊断 ID | 服务端日志使用诊断 ID 关联，响应不得包含敏感内部细节 |
| 权限失败 | 明确区分未登录、令牌过期、无账本权限和只读角色 |
| 冲突失败 | 返回冲突 ID 和建议处理端，而不是普通 500 |

## 12. 云端对象副本映射需求

PostgreSQL 云端对象副本不要求逐表复刻 PC SQLite，但必须能表达同一组业务对象、版本和同步状态。PC SQLite 的内部视图、索引和本地迁移审计不应直接暴露给云端。

### 12.1 映射原则

1. 云端对象以业务对象族组织，例如账本、账户、交易、预算、提醒，而不是照搬所有 SQLite 表。
2. 每个云端对象必须包含 `ledger_id`、对象 ID、对象类型、版本、最后修改时间、来源端和来源设备。
3. 删除必须用墓碑表达，不能只做物理删除。
4. 金额仍使用最小单位整数和币种代码，不使用浮点数。
5. 投影视图、报表结果和本地运行缓存不作为同步真相。
6. 旧 MoneyHome8 原始行、旧文件路径、迁移审计、迁移报告和脱敏摘要都不上传云端。

### 12.2 对象族映射

| 云端对象族 | PC SQLite 来源 | 同步口径 |
| --- | --- | --- |
| Ledger | `ledgers`、`currencies` | 账本基本信息、本位币和账本级设置 |
| LedgerMember | 云端主表，PC 仅缓存授权摘要 | 账号、角色、邀请和权限 |
| AccountCatalog | `account_groups`、`accounts`、`account_tags` | 账户树、账户资料、隐藏/关闭状态和标签关系 |
| MasterData | `categories`、`tags`、`parties`、`exchange_rate_snapshots` | 分类、标签、往来方和汇率快照 |
| Transaction | `transactions`、`transaction_entries`、`transaction_tags`、`transaction_attachments` | 交易头、原子分录、标签和附件关系必须同批次一致 |
| Attachment | `attachments`、`transaction_attachments` | 附件元数据、内容哈希、对象引用和云端文件位置 |
| Planning | `budgets`、`budget_items`、`reminders`、`financial_goals`、`financial_goal_accounts` | 预算、提醒和目标基础对象 |
| Schedule | `transaction_templates`、`transaction_template_entries`、`schedules`、`schedule_occurrences`、`reminder_occurrences` | 计划模板、发生实例、提醒实例和执行状态 |
| SyncState | `sync_profiles`、`sync_batches`、`sync_object_results`、`sync_conflicts`、`sync_tombstones` | PC 本地同步记录与云端协调状态互相映射 |
| LegacyMap | `legacy_id_map`、迁移批次和迁移预览 | 仅 PC 本地保存；云端不保存迁移审计、迁移报告或脱敏摘要 |

### 12.3 不进入第一版云端对象副本的内容

1. PC 本地 SQLite 视图和索引。
2. 旧 MoneyHome8 原始文件、旧库完整路径、未脱敏原始行、迁移审计、迁移报告和脱敏摘要。
3. 未校准的投资成本、收益率和复杂公式计算结果。
4. 手机端临时缓存和未提交草稿内部字段。
5. Rust 本地探测过程中的机器路径、锁文件线索和可能包含隐私的诊断细节。

## 13. 手机端离线队列需求

手机端离线队列是用户输入的暂存和上传机制，不是完整账本引擎。它必须保证联网后可以幂等提交，并能向用户解释每条记录当前状态。

### 13.1 队列项状态

| 状态 | 含义 | 用户可见操作 |
| --- | --- | --- |
| Draft | 用户尚未提交的本机草稿 | 编辑、删除、提交到待同步 |
| PendingUpload | 已提交但尚未上传 | 查看、撤回、等待同步 |
| Uploading | 正在上传 | 查看进度，避免重复提交 |
| Synced | 云端已接受并返回对象版本 | 查看结果 |
| Failed | 上传失败，未进入云端 | 重试、编辑、删除 |
| Conflict | 云端检测到冲突 | 查看摘要，延后到 PC/Web 处理 |

### 13.2 队列项最小字段

| 字段 | 说明 |
| --- | --- |
| local_queue_id | 手机端本地队列标识 |
| client_change_id | 幂等键，重复上传必须返回同一处理结果 |
| ledger_id | 目标账本 |
| object_type | 交易、附件引用等对象类型 |
| operation | create、update_draft、delete_draft 或 attach_local_file |
| payload | 用户输入的业务字段快照 |
| created_at | 本地创建时间 |
| updated_at | 本地更新时间 |
| last_attempt_at | 最近一次上传尝试时间 |
| attempt_count | 上传尝试次数 |
| error_code / error_message | 最近失败原因，必须脱敏 |

### 13.3 手机端离线草稿规则

1. 手机端允许离线编辑或删除尚未上传成功的本机草稿。
2. 手机端不允许离线直接修改已同步成功的云端对象；这类修改必须在线提交或进入后续版本再评估。
3. 同一个本机草稿多次编辑只保留最新 payload，但必须保留本地更新时间。
4. 上传失败后，用户可以编辑后重试；重试仍使用同一个 `client_change_id` 或生成明确的新修订 ID。
5. 附件离线时只保存临时引用，上传成功前不得假定云端已有附件。
6. 队列错误必须可解释，例如网络失败、权限失败、账本不可访问、字段校验失败或云端冲突。

## 14. 冲突解决需求

冲突解决第一版只在 PC 和 Web 提供完整能力。手机端只展示冲突数量、冲突对象摘要和建议处理入口。

### 14.1 冲突类型

| 冲突类型 | 示例 | 默认处理 |
| --- | --- | --- |
| 同字段编辑 | PC 离线把金额改为 100，Web 同时把金额改为 120 | 进入显式解决 |
| 删除与修改 | Web 删除交易，PC 离线修改备注 | 进入显式解决 |
| 关联对象缺失 | 手机上传交易引用了已被删除的分类 | 进入显式解决或要求重选 |
| 权限变化 | 用户离线编辑后被移出账本 | 阻止合并，提示权限变化 |
| 附件引用失败 | 交易已同步但附件上传失败 | 标记部分失败，允许重试附件 |

### 14.2 冲突详情字段

| 字段 | 说明 |
| --- | --- |
| conflict_id | 冲突稳定标识 |
| ledger_id | 所属账本 |
| object_type / object_id | 冲突对象 |
| base_version | 两端共同基线版本 |
| local_version | 本端或上传端版本 |
| cloud_version | 云端当前版本 |
| local_device / cloud_source | 来源设备和来源端 |
| field_diffs | 字段级差异列表 |
| conflict_kind | 同字段编辑、删除修改、关联缺失、权限变化等 |
| created_at | 冲突产生时间 |
| resolution_status | 未处理、已解决、已忽略或无法处理 |

### 14.3 PC/Web 解决操作

| 操作 | 适用场景 | 结果 |
| --- | --- | --- |
| 保留本端 | 用户确认本端版本正确 | 生成新云端版本并同步其它端 |
| 保留云端 | 用户确认云端版本正确 | 本端拉取云端版本 |
| 字段级合并 | 同对象不同字段都有有效修改 | 生成合并版本 |
| 另存副本 | 删除/修改都需要保留证据 | 创建新对象或补充记录 |
| 暂不处理 | 用户需要稍后判断 | 保持冲突状态，不继续覆盖 |

冲突解决必须保留审计记录：处理人、处理端、处理时间、处理方式、输入版本和生成版本。

## 15. 账本成员需求

第一版必须避免把数据模型写死成单人单账本，但不做复杂细粒度权限。

### 15.1 角色

| 角色 | 权限范围 |
| --- | --- |
| Owner | 管理账本、同步、成员、删除/转让账本、完整读写 |
| Editor | 新增、修改、删除常规财务对象，查看同步状态 |
| Viewer | 只读查看账本数据和基础报表，不可写入 |

### 15.2 成员流程

| 流程 | 第一版需求 |
| --- | --- |
| 邀请成员 | PC/Web 可发起邀请，手机端可后置 |
| 接受邀请 | Web 必须支持，手机可支持或后置，PC 可支持 |
| 移除成员 | Owner 可移除 Editor/Viewer |
| 修改角色 | Owner 可在 Editor 和 Viewer 之间调整 |
| 转让账本 | 第一版后置；Owner 退出前必须先移交或删除账本的规则保留为模型约束 |
| 退出账本 | 非 Owner 可退出；Owner 退出前必须转让或删除账本 |

### 15.3 隔离规则

1. 每个 API 请求必须校验用户对 `ledger_id` 的访问权限。
2. 手机端本地缓存必须按账本和账号隔离。
3. PC 本地账本未开启同步时没有云端成员概念。
4. PC 本地账本开启同步后，云端账本成员权限不得自动删除 PC 本地文件，但会影响后续云端同步能力。
5. 只读成员不得上传变更；如果本地存在待上传变更但云端权限变为只读，必须进入同步失败或冲突提示。

## 16. 附件需求

附件属于敏感财务资料。第一版必须支持交易附件的基础上传、下载、引用和权限控制，但不要求复杂全文检索或云端 OCR。

### 16.1 附件来源

| 来源 | 第一版需求 |
| --- | --- |
| PC 本地文件 | Flutter PC 选择文件，Rust 计算哈希、复制到受管目录并写入 SQLite 元数据 |
| 手机拍摄/选择 | 手机保存临时文件，上传成功后获得云端附件 ID |
| Web 上传 | Web 直接通过 .NET API 上传，云端生成附件元数据 |
| 旧账本迁移附件 | 只在 PC 本地迁移；默认本地保存，用户开启同步并确认附件隐私提示后才上传新系统附件对象 |

### 16.2 附件状态

| 状态 | 含义 |
| --- | --- |
| LocalOnly | 仅 PC 本地存在，尚未开启同步或用户选择不上传 |
| PendingUpload | 已绑定业务对象，等待上传 |
| Uploaded | 云端已保存内容和元数据 |
| DownloadPlaceholder | 本端只知道元数据，内容尚未下载 |
| Downloaded | 本端已有可打开内容 |
| Failed | 上传或下载失败 |

### 16.3 附件规则

1. 附件必须绑定 `ledger_id` 和业务对象，不能跨账本引用。
2. 附件内容使用哈希去重时，权限仍按账本和对象校验，不能只按哈希公开。
3. 附件 URL 必须是短期授权或经权限校验的访问入口，不能长期裸露。
4. PC 本地附件受管目录必须保存相对路径和内容哈希，避免移动账本后路径失效。
5. 手机端离线附件上传前只能作为临时引用，不能假设其它端可见。
6. 删除业务对象时第一版先解除附件引用并保留受管内容，物理清理交给后续清理任务。

## 17. 删除与撤销需求

删除财务对象会影响三端同步、报表和审计。第一版不能在 Web 或手机端做无提示的静默硬删除。

### 17.1 删除规则

| 对象 | 第一版删除口径 |
| --- | --- |
| 交易 | 使用作废、撤销或墓碑同步，不直接物理删除事实 |
| 账户 | 有历史交易时隐藏或关闭，不删除历史事实 |
| 分类/标签 | 使用归档，历史记录继续可展示 |
| 预算/提醒/计划 | 可停用或归档；已产生实例保留审计 |
| 附件引用 | 先解除业务引用，内容清理后置 |
| 账本 | Owner 二次确认；云端进入删除流程，本地 PC 文件是否删除由用户单独确认 |

### 17.2 Web 删除体验

1. Web 端删除交易、账户、账本或附件引用时必须二次确认。
2. 删除确认必须展示影响范围，例如是否影响余额、报表、同步到其它设备、附件引用。
3. 删除操作生成对象版本或墓碑，下发给 PC 和手机。
4. 删除与其它端修改并发时进入冲突解决，不自动覆盖。
5. 高风险删除需要可审计记录，至少包含用户、时间、端、对象和操作原因。

## 18. 已确认的隐私边界

### 18.1 迁移审计只保存在 PC 本地

旧 MoneyHome8 迁移审计和迁移报告只保存在 PC 本地，不上传云端，即使是脱敏摘要也不上传。云端只接收用户确认同步后的新系统财务对象。

PC 本地可以保存：

1. 迁移批次 ID。
2. 迁移时间。
3. 旧 ID 映射。
4. 迁移对象数量和失败数量。
5. 未识别项、认证阻塞项和迁移诊断。
6. 迁移预览和导入确认记录。
7. 迁移报告文件。

云端禁止保存：

1. 旧 MoneyHome8 原始文件。
2. 旧文件完整路径。
3. 旧原始行。
4. 旧字段值。
5. 迁移审计或迁移报告的脱敏摘要。
6. 可能包含隐私或机器环境信息的迁移诊断。

## 19. 下一步建议

下一步优先把 `PC 端 Flutter 首屏 + Rust 本地 API` 细化为接口清单：

1. 账本会话：无账本、打开中、已打开、关闭中、失败。
2. 账户中心：账户组树、未分组账户、资产/负债币种汇总。
3. 最近流水：筛选、分页、空状态、错误状态。
4. 常用记账命令：收入、支出、转账。
5. 同步入口：未登录、本地账本未开启同步、同步中、冲突待处理。
