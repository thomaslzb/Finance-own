# 计划、提醒与实例执行边界需求计划

本文档承接 `reporting-planning-plan.md`、`date-time-period-semantics-plan.md`、`command-form-lifecycle-plan.md`、`settings-preferences-notification-plan.md`、`runtime-reminder-calendar-contract.md` 和 `implementation-backlog.md` 中的计划提醒模型任务，定义 Finance Own 第一版计划模板、提醒、发生实例、今日待办、财务日历投影、跳过、执行、自动入账后置和三端展示的需求边界。

## 1. 核心原则

1. 第一版支持计划、提醒和发生实例的基础定义、列表、状态展示和手动处理。
2. 完整后台自动执行、幂等重试和失败补偿不作为第一版阻塞项。
3. 计划是否显示在今日待办、是否可执行、是否可跳过必须由领域层或 API 返回，不由 Flutter 页面猜测。
4. 已生成或已处理的实例必须保留审计，不因规则修改静默删除历史。
5. 手机端第一版只展示摘要和提示，不承担复杂计划配置或完整执行闭环。

## 2. 第一版范围

第一版支持：

| 能力 | PC | Web | 手机 |
| --- | --- | --- | --- |
| 计划模板查看 | 完整 | 完整 | 摘要 |
| 提醒查看 | 完整 | 完整 | 摘要和提示 |
| 今日待办 | 完整 | 完整 | 摘要 |
| 手动执行计划 | 可支持 | 可支持 | 后置 |
| 跳过实例 | 可支持 | 可支持 | 后置 |
| 停用/归档计划 | 支持 | 支持 | 后置 |
| 自动入账后台闭环 | 后置 | 后置 | 不支持 |
| 复杂周期编辑 | PC/Web 优先 | PC/Web 优先 | 不支持 |

第一版不承诺：

1. 后台无人值守自动入账完整闭环。
2. 自动执行失败后的完整补偿队列。
3. 手机端复杂计划编辑。
4. 旧 MoneyHome8 全部计划执行策略完全兼容。

## 3. 对象模型

计划相关对象包括：

| 对象 | 用途 |
| --- | --- |
| `TransactionTemplate` | 交易模板，定义执行时生成的交易草案 |
| `Schedule` | 计划定义，保存周期、状态和执行策略 |
| `ScheduleOccurrence` | 计划发生实例，表达某次计划是否进入今日、可执行或可跳过 |
| `Reminder` | 提醒定义，可绑定计划、预算、账户、交易或手工事项 |
| `ReminderOccurrence` | 提醒发生实例，表达触发、已读、忽略或归档状态 |
| `ExecutionPolicy` | 执行策略版本，表达手动、仅提醒、可执行、可跳过或自动入账候选 |

所有对象必须包含 `ledger_id`、稳定对象 ID、版本、状态、创建时间和更新时间。

## 4. 关键状态字段

计划实例必须显式返回：

| 字段 | 说明 |
| --- | --- |
| `occurrence_id` | 发生实例 ID |
| `schedule_id` | 所属计划 |
| `business_date` | 实例业务日期 |
| `status` | pending、executed、skipped、failed、archived |
| `show_in_today_inbox` | 是否显示在今日待办 |
| `can_execute` | 当前用户和当前实例是否可执行 |
| `can_skip` | 当前用户和当前实例是否可跳过 |
| `execution_policy_version` | 执行策略版本 |
| `generated_transaction_id` | 已执行后生成的交易 ID |
| `last_error_code` | 最近失败原因 |

提醒实例必须显式返回：

| 字段 | 说明 |
| --- | --- |
| `reminder_occurrence_id` | 提醒实例 ID |
| `reminder_id` | 所属提醒 |
| `target_date` | 提醒业务日期 |
| `status` | pending、triggered、dismissed、archived |
| `show_in_today_inbox` | 是否进入今日提醒 |
| `can_dismiss` | 是否可忽略 |
| `source_type` | reminder、schedule、budget、sync、conflict、security |

## 5. 执行策略

执行策略至少区分：

| 策略 | `show_in_today_inbox` | `can_execute` | `can_skip` | 说明 |
| --- | --- | --- | --- | --- |
| `manual_action` | 是 | 是 | 是 | 普通计划，用户可执行或跳过 |
| `reminder_only` | 是 | 否 | 是 | 只提醒，不生成交易 |
| `auto_post_candidate` | 可配置 | 后置 | 可配置 | 自动入账候选，第一版不完整执行 |
| `hidden_automation` | 否 | 否 | 否 | 固定账户或系统内部计划不进今日 |
| `unsupported` | 否 | 否 | 否 | 第一版不支持的旧计划策略 |

规则：

1. 不能把全部计划固定投影为可执行或可跳过。
2. 普通计划可以进入今日待办并允许执行/跳过。
3. 保险仅提醒类计划可以显示提醒，但不能直接生成交易。
4. 固定账户自动计划第一版不得默认进入今日提醒。
5. 不支持策略必须给出可展示原因，不得静默消失。

## 6. 周期和实例生成

周期规则以 `date-time-period-semantics-plan.md` 为准，本计划补充实例要求：

1. 实例按账本时区和业务日期生成。
2. 月末、闰年和不存在日期必须返回标准化结果或不支持错误。
3. 修改计划规则只重算未来未处理实例。
4. 已执行、已跳过、已失败或已归档实例保留原业务日期和审计。
5. 两缴费年度等跨期修改场景，只能重算未来实例，不能静默改历史实例。

## 7. 手动执行

手动执行计划要求：

1. 必须校验当前用户角色，Viewer 不能执行。
2. 必须校验 `occurrence_id`、`schedule_id` 和实例版本。
3. 必须读取交易模板并生成可预览交易命令。
4. 执行前必须通过领域校验：金额、账户、分类、币种、业务日期和附件引用。
5. 执行成功后生成交易对象、对象版本和审计。
6. 执行失败不得生成半笔交易，实例进入 failed 或保留 pending 并带错误码。

自动入账完整后台闭环后置；如果第一版显示 `is_auto_post`，必须明确它只是配置或候选状态。

## 8. 跳过和忽略

跳过计划实例：

1. 必须校验实例版本和角色权限。
2. 已执行实例不能跳过。
3. 跳过必须留下审计。
4. 跳过后不得生成交易。

忽略提醒实例：

1. 只影响该提醒实例或用户已读状态。
2. 不得删除提醒定义。
3. Viewer 可以忽略自己可见范围内的提醒，但不能改变账本级写入对象，具体状态必须由 API 返回。

## 9. 三端行为

PC：

1. 完整查看计划、提醒、今日待办和实例状态。
2. 支持 PC 本地未登录账本的本地计划和提醒。
3. 可执行或跳过计划实例，但必须走 Rust 本地核心。
4. 开启同步后只同步新系统计划、实例和执行结果。

Web：

1. 登录后在线查看和管理计划、提醒和实例。
2. 可执行或跳过已授权实例。
3. 通过 .NET API 校验权限、版本和领域规则。

手机：

1. 查看今日提醒、同步失败、冲突摘要和计划摘要。
2. 不承担复杂计划编辑、完整执行或字段级冲突合并。
3. 离线状态只显示已缓存摘要，不把本地提示当作已执行事实。

## 10. 同步和冲突

规则：

1. 计划、提醒和实例都必须带对象版本。
2. 执行、跳过、忽略和归档生成新版本。
3. PC 离线执行后上传，云端必须校验实例是否仍可执行。
4. Web 已跳过实例而 PC 离线执行同一实例时进入冲突。
5. 修改计划规则和执行实例并发时进入显式冲突或要求重新预览。
6. 手机只展示摘要并提示到 PC/Web 处理。

## 11. 审计和隐私

必须审计：

1. 创建、修改、停用和归档计划。
2. 创建、修改、忽略和归档提醒。
3. 生成实例。
4. 执行、跳过和失败。
5. 自动入账候选状态变化。
6. 冲突解决。

审计不得包含密码、令牌、PC 完整本地路径、旧 MoneyHome8 原始行、旧字段值、迁移审计、迁移报告、脱敏摘要或 PC 机器环境诊断。

## 12. 错误模型

错误码至少包括：

| 错误码 | 含义 | 三端处理 |
| --- | --- | --- |
| `schedule_occurrence_not_found` | 实例不存在或不属账本 | 刷新列表 |
| `schedule_occurrence_not_executable` | 当前实例不可执行 | 展示原因 |
| `schedule_occurrence_not_skippable` | 当前实例不可跳过 | 展示原因 |
| `schedule_policy_unsupported` | 执行策略第一版不支持 | 标记不支持 |
| `schedule_version_conflict` | 计划或实例版本冲突 | PC/Web 冲突解决 |
| `schedule_permission_denied` | 当前角色无权处理 | 阻止提交 |
| `schedule_execution_failed` | 执行失败 | 保留实例和错误码 |
| `recurrence_rule_unsupported` | 周期规则不支持 | 要求调整规则 |

错误响应不得包含旧 MoneyHome8 原始路径、旧原始行、旧字段值、迁移审计、迁移报告、脱敏摘要、PC 完整本地路径或 PC 机器环境诊断。

## 13. 验收要点

1. 普通计划实例可进入今日待办并允许执行或跳过。
2. 保险仅提醒类实例能提醒但不能直接执行生成交易。
3. 固定账户自动计划默认不进入今日待办。
4. 所有实例显式返回 `show_in_today_inbox`、`can_execute` 和 `can_skip`。
5. 修改计划规则只重算未来未处理实例。
6. 手动执行失败不产生半笔交易。
7. Web 跳过与 PC 离线执行并发进入冲突。
8. Viewer 不能执行或跳过会改变账本对象的计划实例。
9. 手机只展示摘要，不把缓存提示当作执行事实。
10. 自动入账完整后台闭环后置，不能在发布说明中宣称已完整支持。
11. 今日提醒按稳定 `occurrence_id` 和 `[eligible_from_date, occurrence_date]` 资格窗口投影实例；同日交易、生日和日记来源独立保留。
12. MoneyHome8 兼容日历按稳定 `schedule_id` 把活动普通提醒定义投影在 `start_date`，不随 `next_occurrence_date` 迁移；最终实例处理使定义完成后才退出。
13. `start_date`、`occurrence_date` 与 `eligible_from_date` 分别建模；逐实例日历若作为改进能力提供，必须与旧版兼容投影明确区分。

## 14. 当前无需人工确认

本计划没有引入新的产品取舍；它细化的是已确认的预算提醒、计划模板、今日待办、实例状态、执行能力标志、自动入账后置、三端同步和旧迁移隐私边界。
