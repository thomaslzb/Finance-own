# 日期、时间、账期与周期需求计划

本文档承接 `three-client-requirements-analysis.md`、`flutter-pc-local-api-plan.md`、`flutter-web-online-plan.md`、`mobile-offline-queue-plan.md`、`reporting-planning-plan.md`、`list-query-filter-pagination-plan.md` 和 `settings-preferences-notification-plan.md`，定义 Finance Own 第一版在 PC、Web、手机和云端之间统一日期、时间、账期、预算周期、提醒周期和排序的需求边界。

## 1. 核心原则

1. 财务归属优先使用业务日期 `business_date`。
2. 审计、同步、冲突和设备状态使用带时区或 UTC 语义的时间戳。
3. 预算、报表、提醒和计划必须基于明确账期和账本时区计算。
4. 三端展示可以本地化，但提交给 Rust 核心或 .NET API 的字段必须使用稳定格式。
5. 手机离线队列不能用本机当前时区静默改写已选择的业务日期。

## 2. 时间字段分类

| 字段 | 用途 | 格式 | 是否影响财务口径 |
| --- | --- | --- | --- |
| `business_date` | 交易、预算、报表归属日期 | `YYYY-MM-DD` | 是 |
| `occurred_at` | 真实发生时间或用户记录时间 | ISO 8601 | 否，除非业务明确使用 |
| `created_at` | 对象创建时间 | ISO 8601 / UTC | 否 |
| `updated_at` | 对象更新时间 | ISO 8601 / UTC | 否 |
| `deleted_at` | 删除或墓碑时间 | ISO 8601 / UTC | 否 |
| `client_created_at` | 客户端命令创建时间 | ISO 8601，带端侧时区线索 | 否 |
| `server_received_at` | 云端接收时间 | UTC | 否 |
| `last_synced_at` | 最近同步成功时间 | UTC 或明确时区 | 否 |
| `triggered_at` | 提醒触发时间 | UTC + 账本时区口径 | 视提醒规则 |

规则：

1. `business_date` 不携带时间和时区，用账本时区解释。
2. `created_at`、`updated_at`、`server_received_at` 和审计时间不得用于替代业务日期。
3. 同一天内排序必须使用稳定排序键，不能只按时间戳猜测用户意图。
4. 导入和迁移必须保留可确认的业务日期；无法确认时进入预览校验错误或校验阻塞状态。

## 3. 账本时区

每个账本必须有明确 `ledger_time_zone`。

规则：

1. 创建账本时默认使用创建端当前时区，并保存为账本设置。
2. PC 本地未登录账本也必须保存 `ledger_time_zone`。
3. Web 和手机读取云端账本时使用云端账本的 `ledger_time_zone` 解释业务日期、今日提醒和账期。
4. 修改账本时区属于高风险设置，第一版可以后置；如果提供，必须展示对预算、提醒、报表和计划实例的影响。
5. 云端不得用服务器部署时区解释用户账本的业务日期。

## 4. 业务日期

交易业务日期规则：

1. 收入、支出、转账、投资成交和手工调整都必须有 `business_date`。
2. `business_date` 是报表、预算、筛选和余额归属口径。
3. 用户粘贴或复制交易到“今天”时，只替换 `business_date`，不改变来源交易事实。
4. 修改 `business_date` 是高风险修改，必须重新校验预算、报表、提醒和冲突影响。
5. 手机离线新增时保存用户选择的 `business_date`，上传时不得被云端接收时间替换。

跨端规则：

1. PC、Web、手机显示同一交易时，业务日期必须一致。
2. 云端返回对象时必须保留原 `business_date`。
3. 若设备本地日期与账本时区的今日不同，UI 必须按账本时区展示“今日”相关状态。

## 5. 发生时间和审计时间

`occurred_at` 用于记录真实发生时间或用户记录时间，但第一版财务汇总不依赖它。

规则：

1. `occurred_at` 可以为空。
2. 如果页面收集时间，必须带明确时区或可解释的本地时间来源。
3. 审计必须记录创建、修改、删除、恢复、冲突解决和同步接收时间。
4. 审计时间用于追溯，不改变财务归属。
5. 冲突详情必须展示来源端、来源设备、版本和时间字段差异。

## 6. 账期和报表期间

报表期间使用闭区间业务日期：

| 字段 | 说明 |
| --- | --- |
| `date_from` | 业务日期起点，包含 |
| `date_to` | 业务日期终点，包含 |
| `period_kind` | monthly、quarterly、yearly、custom |
| `ledger_time_zone` | 解释期间边界的账本时区 |

规则：

1. 流水、余额、预算、提醒和报表筛选必须明确 `date_from` 和 `date_to`。
2. 月度、季度和年度按账本时区下的自然日解释。
3. 自定义期间必须保存起止业务日期。
4. 导出和打印必须记录期间参数、生成时间和数据版本。
5. 期间跨年、跨月、闰日和月末日期不得由 UI 自行猜测，必须由领域层或 API 返回标准化结果。

信用卡账单、还款日和类似业务账期也必须复用日期层规则：

1. 账单日规则使用 fixed_day、last_day_of_month、days_after_statement 或 custom 表达，不用 UI 文案持久化。
2. 固定日遇到短月份不存在日期时，必须按业务对象保存的 `short_month_policy` 标准化，或返回 `billing_day_missing_in_month`。
3. 已生成账单冻结规则快照、交易版本集合和账本时区；后续规则修改不得重算历史账单。
4. 账期闭区间必须满足 `period_start <= period_end`，同账户、同币种已出账账期不得重叠。
5. 手机离线不能自行推导复杂账单日，只能展示已同步账单、还款摘要或要求联网刷新。

## 7. 预算周期

预算周期字段：

| 字段 | 说明 |
| --- | --- |
| `budget_id` | 预算 ID |
| `period_kind` | monthly、quarterly、yearly、custom |
| `start_date` | 起始业务日期 |
| `end_date` | 结束业务日期 |
| `rollover_policy` | 第一版可为空或 none |
| `ledger_time_zone` | 账本时区 |

规则：

1. 预算项统计以交易 `business_date` 归属期间。
2. 预算起止日期必须合法且 `start_date <= end_date`。
3. 手机只展示当前预算摘要，当前期间由云端或 PC 本地核心按账本时区计算。
4. 修改预算周期必须使预算摘要缓存失效。
5. 跨币种预算仍按金额和汇率计划的口径处理，不在时间层隐式折算。

## 8. 提醒和计划周期

提醒和计划必须保存明确周期定义。

字段：

| 字段 | 说明 |
| --- | --- |
| `recurrence_kind` | none、daily、weekly、monthly、yearly、custom |
| `recurrence_rule` | 结构化周期规则，第一版可用 JSON 合同表达 |
| `start_date` | 起始业务日期 |
| `end_date` | 可选结束业务日期 |
| `next_occurrence_date` | 下一次发生业务日期 |
| `ledger_time_zone` | 账本时区 |

规则：

1. 今日提醒按账本时区判断，不按服务器时区。
2. 计划实例生成后必须保留实例日期，不因规则修改静默改历史实例。
3. 修改计划规则只重算未来实例，已执行或已跳过实例保留审计。
4. 自动执行完整闭环第一版后置，但实例日期和状态模型必须保留。
5. 月末、闰年和不存在日期必须有可解释策略；第一版如果未实现复杂策略，必须返回不支持或要求用户选择。

## 9. 同步和冲突

时间字段同步规则：

1. 时间字段必须进入对象版本。
2. 修改 `business_date`、预算期间、提醒周期或计划周期属于高风险修改。
3. 同一对象日期字段并发修改进入显式冲突。
4. 手机离线队列上传时必须带端侧 `client_created_at` 和用户选择的 `business_date`。
5. 云端接收时间只能作为 `server_received_at`，不能覆盖业务日期。

冲突展示要求：

| 字段类型 | 展示 |
| --- | --- |
| 业务日期 | 展示本端值、云端值和影响期间 |
| 发生时间 | 展示本端时间、云端时间和时区 |
| 预算期间 | 展示起止日期差异和预算影响 |
| 提醒周期 | 展示下一次提醒变化 |
| 计划周期 | 展示未来实例变化 |

## 10. 三端 UI

PC：

1. 完整日期范围、账期、预算周期和计划周期管理。
2. 未登录本地账本按账本时区解释今日和期间。
3. 修改高风险日期字段前展示影响范围。

Web：

1. 登录后使用云端账本时区展示今日、预算和提醒。
2. 在线查询和导出绑定明确期间参数。
3. 冲突详情展示日期和时间字段差异。

手机：

1. 默认展示账本时区下的今日。
2. 离线草稿保存用户选择的业务日期。
3. 不承担复杂计划周期编辑。
4. 时区变化或缓存过期时提示同步状态。

## 11. 错误模型

日期、时间和周期错误码至少包括：

| 错误码 | 含义 | 三端处理 |
| --- | --- | --- |
| `business_date_required` | 缺少业务日期 | 标记日期字段 |
| `date_range_invalid` | 起止日期非法 | 标记期间字段 |
| `period_overlap` | 同一对象范围内期间重叠 | 阻止生成或要求影响预览 |
| `billing_day_missing_in_month` | 固定日规则在短月份不存在 | 按规则标准化或返回字段错误 |
| `period_rule_version_stale` | 提交使用陈旧期间或账单规则版本 | 保留草稿并要求刷新 |
| `ledger_timezone_missing` | 账本缺少时区 | 阻止期间计算并提示修复 |
| `recurrence_rule_invalid` | 周期规则非法 | 标记周期配置 |
| `recurrence_rule_unsupported` | 第一版不支持该复杂周期 | 要求调整规则 |
| `date_version_conflict` | 日期字段版本冲突 | PC/Web 冲突解决 |
| `client_time_untrusted` | 客户端时间异常 | 保留业务日期，标记审计诊断 |

错误响应不得包含 PC 完整本地路径、旧 MoneyHome8 原始路径、旧原始行、旧字段值、迁移审计、迁移报告、脱敏摘要或 PC 机器环境诊断。

## 12. 验收要点

1. PC、Web、手机看到同一交易的 `business_date` 一致。
2. 手机离线新增后，云端接收时间不会覆盖用户选择的业务日期。
3. 报表查询使用闭区间 `date_from` 和 `date_to`。
4. 预算当前期间按账本时区计算。
5. 今日提醒按账本时区判断。
6. 修改交易业务日期会重新校验预算、报表和冲突影响。
7. 修改计划规则不会静默改写已执行实例。
8. 导出报表记录期间参数、生成时间和数据版本。
9. 服务器部署时区不影响账本业务日期解释。
10. 错误和审计不泄露旧迁移证据或 PC 本地完整路径。
11. 信用卡账单日短月份处理由领域层返回标准化结果或结构化错误，三端 UI 不自行猜测。
12. 已生成账单冻结规则快照和账本时区，修改未来规则不改写历史账单。

## 13. 当前无需人工确认

本计划没有引入新的产品取舍；它细化的是已确认的业务日期、发生时间、审计时间、账本隔离、三端同步、预算提醒和手机离线队列边界，并把账本时区作为避免跨端日期漂移的必要字段。
