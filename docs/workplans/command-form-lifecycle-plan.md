# 命令、表单与批量操作状态需求计划

本文档承接 `three-client-requirements-analysis.md`、`flutter-pc-local-api-plan.md`、`flutter-web-online-plan.md`、`mobile-offline-queue-plan.md`、`security-audit-error-handling-plan.md`、`list-query-filter-pagination-plan.md`、`runtime-command-and-state-evidence.md`、`runtime-transactions-and-ledger-contract.md` 和 `runtime-destructive-and-file-operation-contract.md`，定义 Finance Own 第一版新增、修改、删除、表单草稿、批量操作、模板执行、复制粘贴和高风险命令状态的三端需求边界。本文只定义需求口径，不进入具体 Flutter 表单组件或后端实现。

## 1. 目标

第一版必须支持：

1. 三端新增收入、支出、转账的统一命令状态。
2. PC/Web 修改和删除常用财务对象的版本校验、确认和审计。
3. 手机离线草稿、待上传队列和失败重试。
4. PC 优先承载批量操作、模板、复制粘贴、导入预览和高风险文件流程。
5. Web 支持在线常用新增、修改、删除和冲突相关命令。
6. 所有写命令必须携带账本范围、权限、幂等键或对象版本。
7. 表单失败时保留用户输入，不产生半写入或静默覆盖。

第一版不要求：

1. 手机端完整批量操作模式。
2. 手机端复杂模板执行。
3. Web 离线批量导入。
4. 投资复杂交易模板完整兼容。
5. 复制旧 MoneyHome8 的所有旧窗体事件启用条件。

## 2. 命令统一模型

写命令必须显式表达：

| 字段 | 说明 |
| --- | --- |
| `command_id` | 本次命令幂等标识 |
| `ledger_id` | 所属账本 |
| `actor_user_id` | 登录用户；PC 未登录本地命令可为空 |
| `device_id` | 来源设备；PC 未登录本地命令使用本地设备标识 |
| `object_type` | 交易、账户、分类、附件、预算、提醒等 |
| `object_id` | 修改或删除时的对象 ID；新增时可由客户端预分配或服务端生成 |
| `expected_version` | 修改、删除或高风险命令的预期版本 |
| `payload` | 业务输入 |
| `client_created_at` | 客户端创建时间 |

命令结果必须返回：

| 字段 | 说明 |
| --- | --- |
| `status` | applied、queued、failed、conflict、partial_success、cancelled |
| `object_versions` | 成功写入或影响的对象版本 |
| `field_errors` | 字段级错误 |
| `business_errors` | 业务规则错误 |
| `diagnostic_id` | 诊断 ID，不包含敏感内容 |
| `retry_hint` | 是否可重试、是否需刷新或是否需冲突处理 |

## 3. 表单状态

表单状态必须统一表达：

| 状态 | 含义 |
| --- | --- |
| `draft` | 用户正在编辑，尚未提交 |
| `validating` | 本地或服务端校验中 |
| `submitting` | 正在提交 |
| `submitted` | 已提交成功 |
| `failed` | 提交失败，可修正或重试 |
| `conflict` | 版本或权限变化导致冲突 |
| `cancelled` | 用户取消，未写入 |

规则：

1. 用户取消表单不得写入财务对象。
2. 校验失败必须保留草稿和字段定位。
3. 网络失败必须保留可重试状态。
4. 权限变化必须提示角色变化，不得伪装成普通校验失败。
5. 提交成功后，页面刷新使用命令结果中的对象版本或同步游标。

### 3.1 保存并继续

保存并继续用于连续录入同类业务，不是重复提交上一笔命令。

规则：

1. 保存成功后必须生成新的 `command_id`、草稿 ID 和对象预分配 ID。
2. 保留字段必须由业务类型声明，例如交易方向、常用账户、业务日期或钱包账户；金额、手续费、标签、附件和备注默认清空，除非宿主计划明确要求保留。
3. 保存失败、校验失败或版本冲突时不得进入下一条草稿，必须保留当前输入和字段错误。
4. 已提交字段不得在下一条草稿中作为“陈旧账面”再次提交；下一条草稿必须重新读取账户版本、余额提示和候选版本。
5. 旧程序保存并继续缺陷、陈旧草稿证据、旧路径、旧原始行和迁移诊断只保存在 PC 本地。

## 4. 常用记账命令

第一版三端都支持常用收入、支出和转账。

收入/支出：

1. 输入正金额、币种、账户、分类或主题、业务日期和可选备注、标签、附件。
2. 分类方向必须和交易方向一致。
3. 账户必须属于当前账本。
4. 金额使用 `amount_minor + currency_code`。
5. 成功后生成交易头、原子分录和对象版本。

转账：

1. 必须选择转出账户和转入账户稳定 ID。
2. 两侧账户必须属于当前账本。
3. 本金和手续费必须独立表达。
4. 跨币种转账或货币兑换必须进入明确跨币种流程，不由普通转账表单隐式猜测。

## 5. 修改、删除与撤销

修改规则：

1. 修改必须携带 `expected_version`。
2. 版本不匹配进入冲突或提示刷新。
3. 修改金额、账户、币种、业务日期等高风险字段后必须重新执行领域校验。
4. 修改成功后生成新对象版本和审计。

删除规则：

1. 删除交易使用作废、撤销或墓碑，不直接物理删除事实。
2. 删除账户、分类、标签、预算、提醒等对象前必须返回影响预览或引用阻断。
3. 删除确认必须展示影响范围。
4. 删除与其它端修改并发时进入冲突解决。
5. 手机第一版不承担高风险删除或复杂删除确认；在线常用删除可后置或限制。

撤销和取消：

1. 表单取消是零写入。
2. 已提交业务撤销必须生成可审计命令，不等同于取消。
3. 删除失败不得误报成功。

## 6. 批量操作和模板

PC 第一版优先支持批量和模板能力。

批量操作规则：

1. 批量操作进入明确选择模式。
2. 批量命令必须固定选择快照和每条对象版本。
3. 提交前展示对象数量、影响范围和不可执行项。
4. 执行结果返回成功、失败、跳过和冲突数量。
5. 任一对象版本变化时，必须拒绝该项或返回逐项冲突，不能对当前可见行重新取样后继续。

模板规则：

1. 模板定义和模板执行分离。
2. 保存模板只写模板头和模板行。
3. 执行模板生成独立交易命令批次。
4. 同名模板覆盖必须确认。
5. 空模板不能保存或执行。
6. 执行失败不得生成半笔交易。
7. 批量模板必须声明执行策略：`all_or_nothing`、`valid_rows_only` 或 `preview_only`；第一版默认要求用户在提交前确认策略。
8. 零金额模板行、无效账户、关闭账户、跨账本引用和重复行必须在预览中逐行标记，不得静默吞掉。
9. 批量转账手续费归属必须逐行明确，不能用页面显示文本推断账户身份。
10. 幂等重试不得重复生成批量交易；每一行需要稳定 `template_line_id` 或 `client_row_id`。

复制粘贴：

1. 复制交易必须生成新对象 ID。
2. 粘贴到今天只替换业务日期，不改变来源交易。
3. 复制来源 ID 可作为审计或追溯字段。
4. 粘贴失败返回字段级错误。
5. 复制粘贴不得复制旧迁移证据、附件本地路径、旧原始行或迁移诊断；附件只复制新系统附件引用或要求用户重新确认。
6. 改变交易类型必须进入显式转换预览，展示分类方向、账户、分录、标签、附件、计划和报表影响；不能直接复用旧表单字段。
7. 转计划必须生成计划或模板对象，不修改原交易事实；从交易转计划时必须保存来源对象版本和用户确认。

退款、冲销和分期：

1. 退款和冲销必须引用原交易或说明外部来源，生成可审计的反向或调整对象，不能直接改写原交易金额。
2. 退款、冲销和原交易在报表中必须可追溯，并避免重复抵扣。
3. 分期必须拆分协议、计划期次和实际入账事实；首期入账、重算、提前结清和已入账期次保护按领域计划执行。
4. 分期重算不得重写已入账期次；提前结清必须展示剩余本金、费用、利息、附件和计划影响。

## 7. 导入预览与提交

导入预览属于命令准备阶段，不得直接写财务真相。

规则：

1. 文件、剪贴板和交割单导入先进入原始行暂存。
2. 预览必须显示字段错误、重复候选和可提交行。
3. 用户确认提交后才生成业务命令批次。
4. 导入提交必须有批次幂等键。
5. 取消导入不得改变交易、余额、附件或同步对象。
6. 旧 MoneyHome8 原始文件和旧迁移证据仍只在 PC 本地处理。

## 8. 三端行为

### 8.1 PC

PC 必须支持：

1. 完整本地常用记账。
2. 修改、删除、作废和高风险确认。
3. 批量模式、模板执行、复制粘贴和导入预览。
4. 离线写入和后续同步上传。
5. 本地命令结果进入同步队列或本地对象版本。

PC 不得：

1. 让 Flutter 直接写 SQLite。
2. 把旧原始行、旧路径、迁移审计或迁移报告上传云端。
3. 执行批量操作时绕过影响预览和版本校验。

### 8.2 Web

Web 必须支持：

1. 在线新增、修改和删除常用财务记录。
2. 服务端字段校验和业务错误展示。
3. 幂等提交和版本冲突提示。
4. 删除二次确认和影响范围提示。
5. Viewer 禁止写入。

Web 不要求：

1. 离线写主账本。
2. 本地批量导入。
3. 旧账本迁移入口。

### 8.3 手机

手机必须支持：

1. 新增收入、支出、转账草稿。
2. 离线保存本机草稿和待上传队列。
3. 队列重试、撤回和失败保留。
4. 权限失败、设备撤销和冲突摘要提示。

手机不要求：

1. 完整批量操作。
2. 完整删除和字段级冲突合并。
3. 旧账本迁移或导入预览。

## 9. 权限、幂等与审计

权限规则：

1. Owner/Editor 可以写常规财务对象。
2. Viewer 只能查看，写命令返回 `ledger_readonly`。
3. 成员移除后返回 `ledger_forbidden`。
4. 设备撤销后返回 `device_revoked`。

幂等规则：

1. 网络重试不得重复创建交易。
2. 手机队列重复上传返回原处理结果或同一业务对象版本。
3. PC 本地命令同步上传时保留本地命令 ID 与云端批次结果映射。
4. Web 重复提交同一 `command_id` 返回幂等重放结果。

审计规则：

1. 新增、修改、删除、批量、模板执行、导入提交和冲突解决必须可审计。
2. 审计包含用户、设备、账本、对象、版本、命令类型、时间和结果。
3. 审计不得包含密码、令牌、旧原始行、旧完整路径、迁移审计或迁移报告。

## 10. 错误模型

| 错误码 | 场景 |
| --- | --- |
| `validation_failed` | 字段校验失败 |
| `business_rule_failed` | 分类方向、账户币种、金额守恒等业务规则失败 |
| `version_conflict` | 修改或删除版本不匹配 |
| `ledger_readonly` | Viewer 写入 |
| `ledger_forbidden` | 无账本权限 |
| `device_revoked` | 当前设备已撤销 |
| `idempotency_replay` | 幂等重放 |
| `partial_success` | 批量操作部分成功 |
| `storage_failed` | 本地或云端存储失败 |
| `network_unavailable` | Web/手机网络不可用 |
| `stale_continue_draft` | 保存并继续草稿基于过期对象版本 | 保留草稿并要求刷新候选 |
| `batch_strategy_required` | 批量执行策略未确认 | 返回预览并要求选择策略 |
| `type_conversion_preview_required` | 改变交易类型需要影响预览 | 阻止直接提交 |
| `installment_recalculation_required` | 分期计划变更需要重算预览 | 保留草稿并展示影响 |

错误响应必须脱敏，且不能包含旧 MoneyHome8 原始路径、旧原始行、迁移审计、迁移报告、脱敏摘要或 PC 机器环境诊断。

## 11. 验收口径

1. 收入、支出、转账提交成功后生成对象版本和可追溯分录。
2. 表单校验失败保留用户输入。
3. 表单取消不写入。
4. 重复提交同一幂等键不会重复创建交易。
5. 修改和删除必须校验对象版本。
6. 删除必须展示影响范围并留下审计。
7. PC 批量操作固定选择快照和逐项版本。
8. 导入预览取消不改变账本事实。
9. Viewer 写命令被拒绝。
10. 手机离线失败保留草稿，不静默丢弃。
11. 云端响应和审计不包含旧迁移证据或 PC 本地敏感路径。
12. 保存并继续成功后进入全新草稿，失败时保留原草稿；陈旧账户版本不能再次提交。
13. 批量模板预览必须逐行展示成功、失败、跳过和冲突，并明确执行策略。
14. 复制粘贴、改变类型、转计划、退款、冲销和分期都必须生成可审计命令，不得直接改写原事实或复制旧迁移证据。

## 12. 当前无需人工确认

本计划没有引入新的产品取舍；它细化的是已确认的常用记账、PC 高级维护、Web 在线写入、手机离线队列、显式删除确认、幂等、审计、权限变化和旧迁移隐私边界。
