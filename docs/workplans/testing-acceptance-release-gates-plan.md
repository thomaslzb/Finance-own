# 测试、验收与发布门禁需求计划

本文档承接 `three-client-acceptance-scenarios.md`、`three-client-implementation-slices.md`、`domain-validation-invariants-plan.md`、`security-audit-error-handling-plan.md`、`operations-observability-support-plan.md`、`runtime-validation-scenarios.md` 和所有三端需求计划，定义 Finance Own 第一版进入开发、联调、验收和发布前必须满足的质量门禁需求。本文只定义需求级门禁，不绑定具体 CI、测试框架或发布平台。

## 1. 核心原则

1. 发布前必须能证明 PC、Web、手机和云端的主链路符合需求。
2. 隐私和安全边界是发布阻断项，不是后置优化。
3. 文档中标记为后置、待校准或 input-only 的能力不得在发布说明中宣称已完整兼容。
4. 旧 MoneyHome8 原始文件、旧路径、旧原始行、旧字段值、迁移审计、迁移报告和脱敏摘要只保存在 PC 本地的边界必须被验收覆盖。
5. 验收证据必须说明覆盖范围和未覆盖缺口。

## 2. 门禁分层

| 门禁 | 目标 |
| --- | --- |
| 文档门禁 | 需求、实施切片、验收场景和 ADR 一致 |
| 单端门禁 | PC、Web、手机各自核心能力可用 |
| 云端门禁 | .NET API、PostgreSQL 对象副本、权限和同步合同可用 |
| 跨端门禁 | 三端同步、冲突、权限变化和离线队列闭环 |
| 隐私门禁 | 旧迁移证据、PC 路径、令牌和附件内容不外泄 |
| 数据门禁 | 金额、日期、账本隔离、对象版本和墓碑正确 |
| 运行门禁 | 诊断 ID、脱敏日志、告警和支持入口边界可验证 |
| 发布门禁 | 已知缺口、后置能力和风险对用户可解释 |

## 3. 文档门禁

发布前文档检查要求：

1. `three-client-requirements-analysis.md` 的后续技术设计输入包含当前需求计划。
2. `three-client-implementation-slices.md` 的端到端链路覆盖当前需求计划。
3. `implementation-backlog.md` 当前最高优先级引用当前需求计划。
4. 每个 workplan 没有悬空的需求人工决策标记。
5. ADR 和 workplan 不冲突，例如 Flutter/.NET/Rust 边界、PC 本地迁移、云端对象副本、多账本隔离和旧迁移证据 PC-only。

## 4. PC 门禁

PC 发布前必须覆盖：

1. 未登录创建、打开、关闭和继续使用本地账本。
2. 本地新增收入、支出、转账，并能读取余额和最近流水。
3. Flutter PC 不直接写 SQLite，不直接读取旧账本文件。
4. Rust 本地核心执行领域校验和原子写入。
5. PC 登录后未显式开启同步不上传本地账本。
6. 开启同步只上传新系统对象。
7. 旧 MoneyHome8 迁移入口只在 PC 本地出现。
8. 迁移审计、迁移报告、脱敏摘要、旧路径和旧原始行只保存在 PC 本地。
9. PC 本地备份恢复、导入导出和诊断包不泄露默认禁止内容。

## 5. Web 门禁

Web 发布前必须覆盖：

1. 未登录不能进入账本数据页。
2. 登录后读取账本列表、角色和同步摘要。
3. 在线新增、修改和删除常用财务对象。
4. Viewer 不能写入、删除或解决冲突。
5. Web 不读取 PC 本地 SQLite 或旧 MoneyHome8 文件。
6. Web 冲突解决支持完整字段差异和显式处理。
7. Web 错误展示字段错误、权限错误、认证错误和同步错误。
8. Web 日志、错误和诊断不包含令牌、PC 路径或旧迁移证据。

## 6. 手机门禁

手机发布前必须覆盖：

1. 必须登录后选择云端账本。
2. 能拉取最近账本数据、账户、分类、标签和同步状态。
3. 离线新增草稿并保留业务日期、金额、币种、账户和幂等键。
4. 恢复网络后上传队列，云端重新校验权限、版本和引用。
5. 上传失败、权限变化、设备撤销和冲突时保留草稿。
6. 手机只展示冲突摘要，不承担复杂字段级合并。
7. 手机不保存完整本地账本。
8. 手机诊断不包含令牌、附件内容、PC 路径或旧迁移证据。

## 7. 云端和同步门禁

云端发布前必须覆盖：

1. .NET API 所有读写校验 `ledger_id` 和成员角色。
2. PostgreSQL 保存完整新系统对象副本、对象版本、同步批次、冲突、墓碑和审计。
3. 同步批次按对象传输，不上传整个 SQLite 文件。
4. PC 和手机上传同一对象并发修改时生成冲突，不静默覆盖。
5. 删除与修改并发进入显式冲突。
6. 设备撤销后刷新令牌和同步上传失效。
7. 成员移除或降级为 Viewer 后，本地待上传数据保留但不能静默上传。
8. 云端响应、审计和日志不包含旧迁移证据。

## 8. 财务数据门禁

财务数据发布前必须覆盖：

1. 金额真相字段不是 `float` 或 `double`。
2. 收入、支出和转账均使用正金额和明确方向。
3. 转账保存转出、转入和手续费独立分录。
4. 账户余额由分录重建，不由 UI 直接改写。
5. 跨币种汇总不能直接相加名义金额。
6. 业务日期、发生时间、审计时间和服务器接收时间可区分。
7. 报表期间使用闭区间业务日期。
8. 预算和提醒按账本时区计算。
9. 多账本之间不能互相引用基础资料、附件或交易对象。
10. 未校准投资公式不进入正式报表结论。

## 9. 隐私和安全门禁

隐私安全发布前必须覆盖：

1. 密码、访问令牌、刷新令牌和密钥材料不进入普通日志、错误响应、导出或 Rust 核心领域表。
2. PC 完整本地路径不进入云端响应、审计、日志、告警或支持入口。
3. 旧 MoneyHome8 原始文件、旧路径、旧原始行、旧字段值、迁移审计、迁移报告和脱敏摘要不进入云端。
4. 附件下载经过账本权限校验或短期授权。
5. 运维指标和告警不包含财务明细。
6. 支持入口不能查看旧迁移证据或直接无审计修改财务对象。
7. 诊断 ID 脱敏，不能反推出用户财务数据。

## 10. 发布说明门禁

发布说明必须说明：

1. 已支持的三端能力。
2. PC 本地-only 能力。
3. Web 在线为主和必须登录边界。
4. 手机轻量离线队列边界。
5. 投资公式、复杂计划自动执行、手机号登录、第三方登录、完整 E2EE 等后置能力。
6. 旧 MoneyHome8 迁移证据只保存在 PC 本地。
7. 已知未校准或 input-only 的结果状态。

禁止在发布说明中宣称：

1. 复杂投资公式已完整兼容，除非通过校准门槛。
2. Web 或手机可迁移旧 MoneyHome8 原始文件。
3. 手机保存完整本地账本。
4. 云端保存旧迁移审计或迁移报告。
5. 完整端到端加密已实现，除非后续另行设计并验收。

## 11. 验收证据

每个门禁需要保留：

| 证据 | 要求 |
| --- | --- |
| 场景 ID | 对应验收场景或需求计划 |
| 端 | PC、Web、手机、云端或运维 |
| 数据范围 | 账本、对象族、权限角色 |
| 执行方式 | 自动化、手工、脚本或代码检查 |
| 结果 | 通过、失败、跳过或受限 |
| 缺口 | 未覆盖内容和原因 |
| 隐私检查 | 是否涉及旧迁移证据、PC 路径、令牌或附件内容 |

## 12. 错误和阻断

以下情况必须阻断发布：

1. 旧迁移证据进入云端对象、日志、审计、错误响应、支持入口或诊断包。
2. Viewer 可成功提交写入。
3. Web 或手机未登录可访问账本数据。
4. PC 登录后未开启同步却自动上传本地账本。
5. 设备撤销导致 PC 本地文件或手机草稿被删除。
6. 金额使用浮点真相字段。
7. 同步冲突被静默覆盖。
8. 迁移或导入失败产生半写入且无回滚。
9. 发布说明把后置或待校准能力描述为已完整支持。

## 13. 当前无需人工确认

本计划没有引入新的产品取舍；它把已确认的三端需求、同步、隐私、安全、校准、运维诊断和发布说明边界整理成第一版测试、验收与发布门禁。
