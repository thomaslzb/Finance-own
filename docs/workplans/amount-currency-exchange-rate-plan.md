# 金额、币种与汇率需求计划

本文档承接 `three-client-requirements-analysis.md`、`sqlite-schema-and-query-contract.md`、`runtime-calculation-and-report-projections.md` 和 `runtime-transactions-and-ledger-contract.md`，定义 Finance Own 第一版金额、币种、汇率、本币折算、余额和报表展示的三端需求边界。本文只定义第一版产品和接口口径，不固化尚未动态校准的投资成本、收益率或旧程序缺陷。

## 1. 目标

第一版必须支持：

1. 所有财务金额使用最小单位整数和明确币种代码。
2. 每个账本有明确本位币。
3. 每个账户有明确账户币种。
4. 常用收入、支出、转账、手续费和附件相关金额在三端使用一致字段。
5. 汇率使用定点值和汇率快照，不使用浮点数写回财务事实。
6. 本币折算结果必须能追溯所用汇率快照或明确为空。
7. PC、Web、手机展示余额、流水和报表时，不在页面侧重新发明财务口径。

第一版不要求：

1. 自动联网抓取实时汇率。
2. 完整外汇交易高级策略。
3. 投资成本法、收益率和复杂公司行动最终兼容。
4. 用当前汇率静默补写历史交易本币金额。

## 2. 数据表达

金额字段第一版统一使用：

| 字段 | 说明 |
| --- | --- |
| `amount_minor` | 主金额，币种最小单位整数 |
| `currency_code` | ISO 4217 或账本内约定币种代码 |
| `minor_unit` | 币种小数位，例如 CNY 为 2 |
| `amount_sign` | 展示方向由交易类型和分录方向决定，不要求用户输入负数 |

定点数统一使用：

| 类型 | 字段口径 |
| --- | --- |
| 汇率 | `rate_units + rate_scale` |
| 价格 | `price_units + price_scale` |
| 数量 | `quantity_units + quantity_scale` |
| 比例 | `ratio_units + ratio_scale` |

规则：

1. SQLite、.NET API、Flutter DTO 和手机离线队列都不得把财务金额作为 `float` 或 `double` 真相字段。
2. 页面可以按本地语言格式化显示金额，但提交给核心或 API 时必须恢复为整数金额和币种代码。
3. 金额输入允许展示小数，但提交前必须按币种 `minor_unit` 转为整数。
4. 金额舍入必须由领域层或 API 合同集中处理，页面不得自行决定尾差归属。

## 3. 币种和本位币

币种对象第一版至少包括：

| 字段 | 说明 |
| --- | --- |
| `currency_code` | 币种代码 |
| `display_name` | 展示名称 |
| `minor_unit` | 金额小数位 |
| `symbol` | 展示符号，可为空 |
| `is_base_currency` | 是否为账本本位币 |
| `status` | active、archived |

账本规则：

1. 创建账本时必须选择本位币。
2. 账本本位币用于资产汇总、报表汇总和跨币种折算展示。
3. 修改账本本位币属于高风险设置，第一版可后置；若提供，必须展示影响范围并保留审计。
4. 账户币种创建后不建议直接修改；如必须修改，应走迁移或新建账户流程。
5. 本位币在旧程序列表中可能不显示币种名，但新系统事实层仍必须保存明确币种代码。
6. 本位币切换若在第一版提供，必须先预览账户余额、报表、预算、目标、投资估值和历史折算影响；确认后生成账本级设置版本并触发相关投影重算。
7. 已被账户、交易、汇率或报表快照引用的币种不得物理删除；自定义币种代码必须做大小写、空白和 Unicode 规范化校验。

## 4. 汇率快照

汇率快照用于历史交易折算、报表基准日折算和跨币种汇总。

汇率快照字段第一版至少包括：

| 字段 | 说明 |
| --- | --- |
| `exchange_rate_snapshot_id` | 汇率快照稳定标识 |
| `ledger_id` | 账本范围 |
| `from_currency_code` | 报价来源币种 |
| `to_currency_code` | 报价目标币种 |
| `rate_units` | 定点汇率整数 |
| `rate_scale` | 汇率小数位 |
| `effective_at` | 生效时间或业务日期 |
| `source` | manual、imported、migration 或 system |
| `created_at` | 创建时间 |

汇率规则：

1. 同一账本内汇率必须限定 `ledger_id`。
2. 汇率方向必须明确保存，展示层可以派生反向报价。
3. 历史交易使用的汇率快照不能被原位覆盖；修改应生成新快照或新版本。
4. 汇率缺失时，本币折算金额为空，并向用户展示可补录汇率的状态。
5. 禁止用当前汇率静默覆盖历史交易的已折算金额。
6. 迁移旧数据时，只能把可确认的新系统汇率快照写入本地账本；旧迁移诊断仍只保存在 PC 本地。
7. 在线牌价更新必须先形成暂存批次，记录来源、方向、现汇/现钞口径、日期、成功数、失败数和状态；失败或中止不得覆盖已发布快照。
8. 同一账本、币种对、报价方向、业务日期和来源口径重复时必须返回 upsert 预览或版本冲突，不能静默覆盖。
9. 反向报价可以展示和用于录入辅助，但持久层必须保留规范方向、未舍入规范牌价和显示舍入差异。

## 5. 交易与转账金额

收入和支出：

1. 用户输入正金额。
2. 交易类型和分类方向决定流入或流出。
3. 页面不得允许“支出 + 负数金额”形成双重反转。
4. 账户币种和输入币种不一致时，必须返回字段级错误或进入明确的跨币种交易流程。

同币种转账：

1. 保存转出本金分录。
2. 保存转入本金分录。
3. 手续费使用独立费用分录。
4. 来源账户列表可以合并展示本金加手续费，但事实层必须保留本金和手续费组成。

跨币种转账或货币兑换：

1. 保存卖出币种、卖出金额、买入币种、买入金额。
2. 保存报价方向、规范汇率、显示汇率和舍入差异。
3. 两侧金额都必须大于零。
4. 换出账户和换入账户必须是稳定账户 ID，不能只提交显示名称。
5. 缺少汇率或币种身份时阻止提交，并保留草稿。

## 6. 余额和本币折算

余额规则：

1. 账户余额由已提交分录重建，不直接写可漂移余额。
2. 同一业务日期内排序必须使用稳定排序键，至少包含业务日期、创建顺序和交易标识。
3. PC 本地、Web 云端查询和手机摘要必须读取同一对象版本或同步游标范围内的余额口径。
4. 页面只展示 DTO 结果，不自行按列表求和生成权威余额。

本币折算规则：

1. 交易分录可保存原币金额、本币金额、本位币和汇率快照 ID。
2. 没有汇率快照时，本币金额为空，报表应展示缺汇率状态。
3. 报表按交易日汇率或报表基准日汇率折算时，必须在查询参数和结果中明确。
4. 跨币种汇总必须先按同一折算口径折成本位币，不能把不同币种名义金额直接相加。
5. 旧程序可能存在不同币种直接合计的显示缺陷，新系统不得复制该缺陷。

## 7. 三端行为

### 7.1 PC

PC 必须支持：

1. 本地账本币种列表和本位币读取。
2. 常用记账金额、币种和手续费校验。
3. 本地汇率快照读取和手动补录入口。
4. 缺汇率时仍保存原币交易，但本币折算为空并提示。
5. 旧迁移后只同步新系统金额、币种、交易和可确认汇率快照，不同步旧迁移证据。

### 7.2 Web

Web 必须支持：

1. 在线读取云端币种、账户余额和基础报表。
2. 在线提交金额字段时使用 `amount_minor + currency_code`。
3. 查询缺汇率对象并提示用户补录或到 PC/Web 处理。
4. Viewer 只能查看金额和报表，不能补录汇率或提交写入。

Web 不得：

1. 读取 PC 本地 SQLite。
2. 用浏览器本地计算覆盖云端余额。
3. 上传或展示旧迁移审计、迁移报告、脱敏摘要、旧路径或旧原始行。

### 7.3 手机

手机必须支持：

1. 常用记账金额输入。
2. 离线队列保存 `amount_minor + currency_code`。
3. 上传时由云端校验账户币种、金额范围和角色权限。
4. 最近余额和报表摘要只展示同步下来的结果或明确缓存状态。

手机不要求：

1. 完整汇率管理。
2. 复杂跨币种交易录入。
3. 投资复杂收益率校准。

## 8. 同步与冲突

金额、币种和汇率都属于高风险字段。

同步规则：

1. 金额、币种、本位币、账户币种和汇率快照都必须带对象版本。
2. 同一对象同一金额字段并发修改必须进入显式冲突。
3. 汇率快照被历史交易引用后不得原位覆盖；后续修正使用新版本或新快照。
4. PC 离线新增金额对象后上传，云端必须校验金额范围、币种存在、账户属于账本和权限角色。
5. 手机队列上传遇到币种、汇率或权限失败时保留草稿，不静默丢弃。

冲突解决要求：

1. PC/Web 冲突详情必须展示金额、币种、汇率快照和本币影响。
2. 字段级合并后必须重新执行领域校验。
3. 手机只展示冲突摘要，不提供金额字段级合并。

## 9. 验收口径

1. 收入、支出、转账和手续费均使用整数金额和明确币种提交。
2. 页面输入小数后，领域层按币种精度统一转换和校验。
3. 账户余额由分录重建，UI 不能直接修改余额。
4. 缺汇率时，本币折算为空并提示，不用当前汇率补写历史交易。
5. 跨币种汇总不能直接相加名义金额。
6. 汇率快照有方向、精度、生效时间和账本范围。
7. 金额或币种并发修改进入显式冲突。
8. 手机离线队列保留金额、币种和幂等键，失败时不丢草稿。
9. 云端不保存旧迁移审计、迁移报告、脱敏摘要、旧路径或旧原始行。
10. 投资成本、收益率和复杂公式在样例校准前不得标记为已兼容。
11. 本位币切换必须有影响预览和设置版本，不能静默重写历史交易本币金额。
12. 在线牌价更新批次失败或中止不得发布半批次；旧牌价协议、旧截图、旧路径和旧诊断证据只保存在 PC 本地。

## 10. 当前无需人工确认

本计划没有引入新的产品取舍；它细化的是已确认的整数金额、明确币种、本位币、定点汇率、汇率快照、PC 本地迁移隐私和三端同步边界。
