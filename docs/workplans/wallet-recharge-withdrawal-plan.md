# 第三方钱包充值与提现需求计划

本文档承接 `three-client-requirements-analysis.md`、`command-form-lifecycle-plan.md`、`master-data-lifecycle-plan.md`、`amount-currency-exchange-rate-plan.md`、`domain-validation-invariants-plan.md`、`runtime-transactions-and-ledger-contract.md`、`runtime-validation-scenarios.md`、`functional-ledger.md` 和 `acceptance-criteria.md`，定义 Finance Own 第一版第三方钱包充值、提现、本金手续费组成、保存并继续、修改删除、内联账户新建和三端同步边界。本文只定义新系统需求口径，不把尚未校准的费用报表分类、提现费用修改差额、附件/标签/内联账户保留和技术失败回滚标记为已兼容。

## 1. 目标

1. 支持 PC/Web 对第三方钱包账户执行充值和提现。
2. 使用显式业务动作区分 `wallet_recharge` 与 `wallet_withdrawal`，不依赖窗体标题、字段显示文字或金额正负。
3. 保证本金、手续费、来源账户、接收账户、费用承担账户、交易版本和审计同事务提交。
4. 保证资金发出侧承担手续费，接收侧只取得本金。
5. 保证旧 MoneyHome8 钱包充值/提现证据、旧路径、旧原始行、迁移审计、迁移报告和脱敏摘要只保存在 PC 本地。

## 2. 非目标

1. 第一版不承诺财付通、全部提供方专属字段和旧版所有异常路径完全兼容。
2. 第一版不把钱包充值/提现实现为普通单边收入或支出。
3. 第一版不在手机端提供复杂钱包交易修改、删除和冲突解决。
4. 第一版不上传旧钱包交易验证证据。
5. 第一版不允许手续费与本金混成不可区分的单一金额事实。

## 4. 分录规则

### 4.1 充值

充值方向：

```text
counterparty_account -= principal + fee
wallet_account += principal
net_worth -= fee
```

规则：

1. 资金来源账户承担手续费。
2. 钱包账户只增加本金。
3. 全局流水可显示等额本金流入和流出，手续费作为费用组成可追溯。
4. `Cash-CNY -> 微信钱包` 本金 `2.00 CNY`、手续费 `0.00` 时，来源 `-2.00`、钱包 `+2.00`、净资产不变。
5. 本金 `1.00 CNY`、手续费 `0.10 CNY` 时，来源 `-1.10`、钱包 `+1.00`、净资产 `-0.10`。

### 4.2 提现

提现方向：

```text
wallet_account -= principal + fee
counterparty_account += principal
net_worth -= fee
```

规则：

1. 钱包账户承担手续费。
2. 资金去向账户只增加本金。
3. `微信钱包 -> Cash-CNY` 本金 `1.00 CNY`、手续费 `0.00` 时，钱包 `-1.00`、目标 `+1.00`、净资产不变。
4. 本金 `1.00 CNY`、手续费 `0.10 CNY` 时，钱包 `-1.10`、目标 `+1.00`、净资产 `-0.10`。

### 4.3 通用约束

1. 本金必须大于零。
2. 手续费不得为负。
3. 钱包账户与对方账户必须属于同一账本。
4. 账户币种必须与命令币种兼容；跨币种钱包交易必须走明确换汇命令。
5. 来源余额不足、账户关闭、账户归档或版本冲突时阻止提交并保留草稿。
6. 提交成功后的刷新失败不得导致重复创建；重试必须返回原结果或可查询提交状态。

## 5. 修改、删除和保存并继续

修改规则：

1. 修改必须按稳定 `wallet_transfer_id` 和预期版本执行。
2. 修改手续费时按原组成与新组成计算差额，不得重复本金。
3. 修改本金、账户、日期、标签、备注或附件时必须重建完整影响预览。
4. 修改失败保留草稿，不留下部分分录。

删除规则：

1. 删除前必须显式确认。
2. 删除必须完整撤销本金、手续费、标签、附件关系和所有账户投影。
3. 删除可使用可审计冲正、墓碑或软删除，不得静默物理抹除审计。
4. 删除确认选择否时零写入。

保存并继续规则：

1. 必须先原子提交当前交易，再创建新草稿。
2. 充值和提现都保留当前钱包账户与业务日期。
3. 对方账户、金额、手续费、标签、备注和附件必须重置。
4. 新草稿必须有新的草稿 ID，不能复用已提交命令对象。

## 6. 内联账户新建

1. 钱包账户和对方账户选择器可进入共享新建账户流程。
2. 新建成功后必须返回稳定账户 ID 和版本，并回填当前草稿。
3. 新建取消、校验失败、权限失败或并发冲突必须返回原草稿。
4. 内联新建账户成功但钱包交易提交失败时，账户保留为独立主数据，交易草稿可重试。

## 7. 三端职责

| 能力 | PC | Web | 手机 |
| --- | --- | --- | --- |
| 新增充值/提现 | 支持 | 支持 | 简化后置 |
| 修改和删除 | 支持 | 支持 | 不支持 |
| 保存并继续 | 支持 | 支持 | 后置 |
| 内联账户新建 | 支持 | 支持 | 后置 |
| 冲突解决 | 支持 | 支持 | 摘要 |
| 旧验证证据 | PC 本地支持 | 不支持 | 不支持 |

手机端第一版可以提交简单钱包充值/提现草稿或只显示摘要；复杂修改、删除、手续费差额和冲突解决引导到 PC/Web。

## 8. 同步与冲突

1. 钱包交易、交易头、本金分录、手续费分录、标签、附件关系、审计和墓碑作为新系统对象同步。
2. 用户未开启同步时，PC 钱包交易只保存在本地 SQLite。
3. 云端只保存新系统钱包交易对象和版本，不保存旧 MoneyHome8 验证证据。
4. PC/Web 处理同一钱包交易的修改、删除和附件标签冲突。
5. 手机只展示冲突摘要，不能静默覆盖 PC/Web 修改。

## 9. 隐私与安全

1. 错误响应、日志、导出、同步批次和支持包不得包含密码、令牌、PC 完整本地路径、旧原始行或迁移审计。
2. 钱包备注可能包含敏感信息，普通日志只记录脱敏摘要。
3. 旧 MoneyHome8 钱包充值/提现证据、迁移审计、迁移报告、脱敏摘要、旧路径和旧原始行只保存在 PC 本地。
4. 内联账户新建过程不得把账户密码、卡号或提供方敏感字段写入普通审计。

## 10. 错误模型

| 错误码 | 场景 | 处理 |
| --- | --- | --- |
| `wallet_operation_invalid` | 业务动作不是充值或提现 | 阻止提交 |
| `wallet_account_required` | 缺少钱包账户 | 定位字段 |
| `wallet_counterparty_required` | 缺少对方账户 | 定位字段 |
| `wallet_principal_required` | 本金为空或不大于零 | 阻止提交 |
| `wallet_fee_invalid` | 手续费为负 | 阻止提交 |
| `wallet_currency_mismatch` | 币种不兼容 | 阻止提交 |
| `wallet_balance_insufficient` | 发出侧余额不足 | 保留草稿 |
| `wallet_version_conflict` | 版本冲突 | 进入 PC/Web 冲突解决 |
| `wallet_permission_denied` | 权限不足 | 阻止写入 |

## 11. 验收场景

1. 充值本金 `2.00`、手续费 `0.00` 时，资金来源减少 `2.00`、钱包增加 `2.00`、净资产不变。
2. 提现本金 `1.00`、手续费 `0.00` 时，钱包减少 `1.00`、目标账户增加 `1.00`、净资产不变。
3. 充值或提现本金 `1.00`、手续费 `0.10` 时，发出侧减少 `1.10`、接收侧增加 `1.00`、净资产减少 `0.10`。
4. 充值手续费 `0.10 -> 0.20` 修改只追加手续费差额，不重复本金。
5. 删除确认后本金、手续费、账户投影和全局流水完整恢复；删除选择否零写入。
6. 保存并继续后只保留钱包账户和业务日期，新草稿重置对方账户、金额、手续费、标签、备注和附件。
7. 内联新建账户成功后返回稳定 ID；交易提交失败不回滚已创建且可独立使用的账户。
8. 旧钱包验证证据、迁移审计、迁移报告、脱敏摘要、旧路径和旧原始行只保存在 PC 本地。

## 12. 当前无需人工确认

本计划没有引入新的产品取舍；它细化的是已确认的第三方钱包充值、提现、本金手续费组成、保存并继续、修改删除、内联账户新建、三端职责、同步冲突和旧迁移证据 PC 本地保存边界。
