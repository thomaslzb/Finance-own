# 日记、富文本与财务日历需求计划

本文档承接 `three-client-requirements-analysis.md`、`reporting-planning-plan.md`、`list-query-filter-pagination-plan.md`、`backup-import-export-plan.md`、`localization-accessibility-display-plan.md`、`security-audit-error-handling-plan.md`、`runtime-diary-contract.md` 和 `runtime-birthday-calendar-contract.md`，定义 Finance Own 第一版日记、富文本正文、搜索、导出、删除、财务日历投影、生日投影和三端同步边界。本文只定义新系统需求口径，不把尚未完成真实操作验证的旧版导出格式、跨年月搜索范围、生日下钻、公历周年重复或农历换算行为标记为已兼容。

## 1. 目标

1. 支持 PC/Web 创建、修改、删除、查询和导出日记。
2. 支持安全、可迁移的受限富文本正文和纯文本搜索投影。
3. 支持按账本本地自然日投影到财务日历。
4. 保证日记列表、月度计数、搜索结果、查看全部和财务日历读取同一日记真相。
5. 支持人员生日按财务日历只读投影，生日真相仍归人员主数据。
6. 保证旧 MoneyHome8 日记和生日日历证据、旧路径、旧原始行、迁移审计、迁移报告和脱敏摘要只保存在 PC 本地。

## 2. 非目标

1. 第一版不承诺完整复刻旧版日记导出文件名、扩展名、编码或覆盖策略。
2. 第一版不承诺旧版跨年月搜索、大小写、分词和排序规则完全兼容。
3. 第一版不把富文本保存为任意 HTML、脚本、外部对象或可执行内容。
4. 第一版不在手机端提供复杂富文本编辑器。
5. 第一版不上传旧 MoneyHome8 日记原始证据。

## 3. 领域对象

### 3.1 `DiaryEntry`

| 字段 | 说明 |
| --- | --- |
| `diary_id` | 日记稳定 ID |
| `ledger_id` | 账本 ID |
| `diary_date` | 账簿本地自然日 |
| `rich_text_body` | 受限富文本正文 |
| `rich_text_format_version` | 富文本格式版本 |
| `plain_text_projection` | 从正文派生的规范化纯文本 |
| `summary` | 用于列表、搜索和日历的安全摘要 |
| `status` | 草稿、已保存、已删除 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |
| `row_version` | 乐观并发版本 |
| `source_type` | 手工、导入、迁移 |

### 3.2 富文本格式范围

第一版受限富文本必须覆盖已验证能力：

1. 字体。
2. 字号。
3. 粗体。
4. 斜体。
5. 下划线。
6. 左、中、右对齐。
7. 项目符号。
8. 文字颜色。

规则：

1. 富文本格式必须是可迁移结构化表示。
2. 搜索只使用 `plain_text_projection`，不得匹配格式控制标记。
3. 摘要必须剥离格式控制、外部链接和不可见字符。
4. 导入旧富文本时，无法映射的格式作为 PC 本地迁移诊断保存，不进入云端。

## 4. 命令生命周期

### 4.1 保存

保存规则：

1. 正文为空时阻止保存并返回字段错误。
2. 保存必须在同一事务中写入正文、格式版本、纯文本投影、摘要、更新时间和审计事件。
3. 修改已有日记必须核对 `row_version`。
4. 同一自然日是否允许多篇，由目标模型显式字段和唯一约束表达；如果第一版按单日单篇实现，冲突必须返回清晰错误。
5. 系统 UTC 日期不得静默改变账簿本地自然日。

### 4.2 脏草稿关闭

1. 修改后关闭必须提示保存或放弃。
2. 选择放弃只丢弃页面草稿，不修改已保存日记。
3. 选择保存必须走与保存按钮相同的校验、事务和错误处理。
4. 保存失败保留草稿并定位错误字段。

### 4.3 删除

1. 删除前必须二次确认。
2. 删除以状态、墓碑或可审计删除记录实现。
3. 删除提交后，月度计数、搜索结果、查看全部和财务日历必须同时反映删除结果。
4. 删除不得影响同日交易、计划、提醒、生日或其它日历事件。

## 5. 查询、搜索和导出

### 5.1 月度列表

月度列表字段：

| 字段 | 说明 |
| --- | --- |
| `ledger_id` | 账本 ID |
| `year_month` | 账簿本地年月 |
| `entries` | 日记摘要列表 |
| `entry_count` | 当前年月可见日记篇数 |
| `query_version` | 查询快照版本 |

### 5.2 搜索

搜索规则：

1. 搜索必须限定账本和用户权限。
2. 搜索范围必须显式表达：当前月、全部、指定日期范围。
3. 无匹配时返回空结果，不弹出异常。
4. 大小写、分词和跨年月行为使用新系统规则，并在 UI 中保持一致。
5. 搜索结果返回稳定 `diary_id`、日期、摘要和版本。

### 5.3 导出

`DiaryExportRequestDto` 字段：

| 字段 | 说明 |
| --- | --- |
| `ledger_id` | 账本 ID |
| `export_scope` | current_month、all、date_range、selected_entries |
| `date_from` | 起始业务日期；范围导出时必填 |
| `date_to` | 结束业务日期；范围导出时必填 |
| `entry_ids` | 指定日记集合；选择导出时必填 |
| `format` | markdown、html、pdf、txt |
| `include_formatting` | 是否包含受限富文本格式 |
| `target_directory` | 用户明确选择的 PC 本地目录；Web 导出时为空 |
| `client_request_id` | 幂等请求 ID |

`DiaryExportResultDto` 字段：

| 字段 | 说明 |
| --- | --- |
| `export_id` | 导出任务 ID |
| `query_version` | 冻结的查询快照版本 |
| `entry_count` | 导出日记数量 |
| `file_label` | 脱敏文件名或下载名 |
| `manifest_hash` | 导出清单哈希 |
| `state` | previewed、exporting、completed、failed、cancelled |
| `failure_code` | 失败原因 |

导出规则：

1. 导出开始时冻结查询范围、排序和筛选。
2. 只能写入用户明确选择的目录。
3. 文件名必须清理路径分隔符、保留名和控制字符。
4. 导出失败不得误报成功，也不得留下被认为成功的半成品。
5. 导出不得包含旧迁移审计、迁移报告、脱敏摘要、旧路径或旧原始行。
6. 导出必须生成清单，记录日记数量、范围、排序、格式版本、富文本格式版本和生成时间。
7. PC 导出采用临时文件完成后原子替换；取消或失败必须清理临时文件。
8. Web 导出只能使用云端新系统 `DiaryEntry` 对象，不读取 PC 本地日记缓存或旧迁移证据。
9. HTML 导出必须使用受限标签和转义策略，禁止脚本、外部对象、远程图片和内联事件。
10. PDF 或 HTML 导出如遇不支持格式，必须降级为纯文本或返回 `diary_export_format_unsupported`，不得丢失正文。

## 6. 财务日历投影

财务日历是只读投影，不保存第二份日记正文。

规则：

1. 日历按 `ledger_id + diary_date` 查询日记事实和删除状态。
2. 同日交易、计划实例、提醒、生日和日记必须以来源类型区分。
3. 日记摘要点击后按稳定 `diary_id` 打开详情或编辑页。
4. 删除日记后，日历日记摘要立即消失，同日财务记录标记保持。
5. 日历页面只保存页面年月、选中日期和查看偏好，不写财务真相。

### 6.1 生日投影

生日属于人员主数据，不是独立可编辑的日历事实。财务日历只生成临时 `BirthdayOccurrence` 投影。

`BirthdayOccurrenceDto` 字段：

| 字段 | 说明 |
| --- | --- |
| `party_id` | 人员稳定 ID |
| `ledger_id` | 所属账本 |
| `display_name` | 当前人员名称 |
| `occurrence_date` | 投影到财务日历的账本本地自然日 |
| `calendar_type` | gregorian、lunar |
| `source_birthday_year` | 原始生日年份，可为空 |
| `source_birthday_month` | 原始生日月份 |
| `source_birthday_day` | 原始生日日期 |
| `leap_month` | 农历闰月标记，可为空 |
| `rule_version` | 周年重复、农历换算和闰日规则版本 |
| `can_open` | 是否支持下钻到人员详情 |
| `source_version` | 人员对象版本 |

规则：

1. 公历生日按账本本地自然日投影；历史年份周年重复、年龄显示和跨年边界必须由规则版本表达。
2. 农历生日必须保留原始年月日和闰月标记；农历换算库、时区和大小月策略必须可测试。
3. `2月29日` 在非闰年的显示策略必须结构化，不能由 UI 猜测。
4. 人员改名、隐藏、删除或修改生日后，日历投影按人员对象版本刷新。
5. 同日多个人员生日按稳定排序返回独立来源项；生日与交易、计划、提醒和日记互不覆盖。
6. 旧生日日历验证证据、迁移审计、迁移报告、脱敏摘要、旧路径和旧原始行只保存在 PC 本地。

## 7. 三端职责

| 能力 | PC | Web | 手机 |
| --- | --- | --- | --- |
| 新增和编辑日记 | 支持 | 支持 | 简化后置 |
| 富文本编辑 | 支持 | 支持 | 纯文本或只读摘要 |
| 月度列表 | 支持 | 支持 | 摘要 |
| 搜索 | 支持 | 支持 | 简单搜索 |
| 导出 | 支持 | 支持受限导出 | 不支持 |
| 财务日历投影 | 支持 | 支持 | 摘要 |
| 生日日历投影 | 支持 | 支持 | 摘要 |
| 旧日记迁移预览 | PC 本地支持 | 不支持 | 不支持 |

手机端第一版可以显示摘要、日期、同步状态和简单纯文本草稿；复杂富文本样式、批量导出和旧日记迁移不进入手机端。

## 8. 同步与冲突

1. 用户未开启同步时，PC 日记只保存在本地 SQLite。
2. 用户显式开启同步后，云端只接收新系统 `DiaryEntry` 对象、对象版本、墓碑和脱敏审计。
3. 云端不保存旧 MoneyHome8 日记原始证据、旧路径、旧原始行、迁移审计、迁移报告或脱敏摘要。
4. PC/Web 可处理正文、日期、删除和格式版本冲突。
5. 手机只显示冲突摘要，并引导到 PC/Web 处理复杂富文本冲突。
6. 富文本冲突必须提供纯文本差异摘要和格式版本差异，不能静默覆盖。

## 9. 隐私与安全

1. 日记正文属于敏感财务生活内容，日志、错误响应、诊断包和支持工单不得包含正文全文。
2. 云端审计只记录对象 ID、版本、操作、来源设备、时间和脱敏摘要。
3. 旧 MoneyHome8 日记证据、旧路径、旧原始行、迁移审计、迁移报告、脱敏摘要和自动化诊断只保存在 PC 本地。
4. 富文本不得加载脚本、外部对象、任意 HTML 或未经许可的远程资源。
5. 导出必须经过账本权限校验，并使用用户明确选择的范围。

## 10. 错误模型

| 错误码 | 场景 | 处理 |
| --- | --- | --- |
| `diary_body_required` | 正文为空 | 阻止保存并定位正文 |
| `diary_date_invalid` | 日期不在允许范围或无法映射到账本自然日 | 阻止保存 |
| `diary_version_conflict` | `row_version` 冲突 | 进入 PC/Web 冲突解决 |
| `diary_format_unsupported` | 富文本格式不受支持 | 保留草稿并提示降级 |
| `diary_export_target_invalid` | 导出目录无效 | 阻止导出 |
| `diary_export_format_unsupported` | 导出格式或富文本片段不支持 | 要求改格式或降级 |
| `diary_export_snapshot_stale` | 导出前查询快照已变化 | 要求重新预览 |
| `diary_export_failed` | 导出失败 | 返回结构化错误并清理半成品 |
| `diary_permission_denied` | 无账本权限 | 阻止读写 |

## 11. 验收场景

1. 空正文保存被拒绝。
2. 保存粗体正文后，重新打开仍能保留正文和格式。
3. 修改后关闭选择放弃，重新打开仍是已保存版本。
4. 搜索命中返回 `1` 条，无匹配返回空列表且不报错。
5. 查看全部清除搜索模式并返回全部可见日记。
6. 删除日记后二次确认，确认后月度计数、搜索结果和财务日历同时更新。
7. 财务日历只投影日记摘要，不复制正文；删除日记不影响同日账务记录。
8. 导出只能写入用户明确选择目录，失败不得误报成功。
9. 导出清单记录范围、排序、格式版本、富文本格式版本和生成时间；查询变化后必须重新预览。
10. HTML/PDF 导出禁止脚本、外部对象、远程图片和内联事件；不支持格式必须降级或返回结构化错误。
11. 人员生日投影来自人员主数据；删除人员或清除生日后，财务日历生日摘要消失，同日交易和日记保持。
12. 农历生日、闰月和 `2月29日` 使用规则版本或结构化不支持状态，不由 UI 自行猜测。
13. 旧日记和生日日历迁移证据、迁移审计、迁移报告、脱敏摘要、旧路径和旧原始行只保存在 PC 本地。

## 12. 当前无需人工确认

本计划没有引入新的产品取舍；它细化的是已确认的日记、富文本、搜索、导出、财务日历只读投影、三端职责、同步冲突和旧迁移证据 PC 本地保存边界。
