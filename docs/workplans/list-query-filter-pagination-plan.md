# 列表查询、筛选与分页需求计划

本文档承接 `three-client-requirements-analysis.md`、`dotnet-sync-api-plan.md`、`flutter-pc-local-api-plan.md`、`flutter-web-online-plan.md`、`mobile-offline-queue-plan.md`、`reporting-planning-plan.md` 和 `runtime-transactions-and-ledger-contract.md`，定义 Finance Own 第一版三端列表查询、筛选、排序、查找、分页、缓存和导出前置状态的需求边界。本文只定义需求口径，不进入具体索引设计或 Flutter 组件实现。

## 1. 目标

第一版必须支持：

1. PC、Web 和手机使用一致的账本范围、权限和对象版本口径查询列表。
2. 流水、账户、基础资料、附件、冲突、预算、提醒和报表列表支持稳定分页。
3. PC 和 Web 支持完整筛选、排序和查找；手机支持最近列表和轻量筛选。
4. 列表结果必须携带查询参数、游标、数据版本或同步游标。
5. 筛选变化后，导出、打印和批量操作不能复用旧结果。
6. 大数据量查询不得依赖无限制全表加载或大 offset 分页。

第一版不要求：

1. 手机端复杂组合筛选构造器。
2. 全文搜索引擎。
3. 跨账本全局搜索。
4. 离线 Web 主账本查询。

第一版不得：

1. 对旧 MoneyHome8 原始库执行云端查询。

## 2. 统一查询模型

列表查询必须显式表达：

| 字段 | 说明 |
| --- | --- |
| `ledger_id` | 查询所属账本 |
| `object_scope` | transactions、accounts、attachments、conflicts、budgets、reminders 等 |
| `filters` | 日期、账户、分类、标签、金额、状态、关键字等筛选 |
| `sort` | 排序字段和方向 |
| `limit` | 返回数量上限 |
| `cursor` | 上一页游标；第一页为空 |
| `data_version` | PC 本地数据版本、云端对象版本或同步游标 |
| `role` | 当前用户对账本的角色摘要 |

规则：

1. 每个查询必须限定 `ledger_id`，不能跨账本串数据。
2. Viewer 可以查询有权限列表，但不能触发写入、导出敏感数据或冲突解决。
3. 查询结果必须返回实际生效筛选条件，避免页面状态和服务端口径不一致。
4. 空筛选表示该列表的默认范围，不表示全库无边界扫描。
5. 查询错误必须区分权限失败、筛选无效、游标失效、网络失败和存储失败。

## 3. 筛选范围

流水列表第一版筛选：

| 筛选 | PC | Web | 手机 |
| --- | --- | --- | --- |
| 日期范围 | 完整 | 完整 | 最近范围 |
| 账户 | 完整 | 完整 | 常用账户 |
| 分类 | 完整 | 完整 | 常用分类 |
| 标签 | 完整 | 完整 | 可后置 |
| 金额范围 | 支持 | 支持 | 可后置 |
| 交易状态 | 正常、作废、归档 | 正常、作废、归档 | 正常为主 |
| 关键字 | 主题、备注、对象名 | 主题、备注、对象名 | 简单关键字 |
| 附件状态 | 支持 | 支持 | 摘要 |

基础资料列表筛选：

1. 账户：类型、币种、隐藏、关闭状态。
2. 分类：收入/支出方向、归档状态、父级。
3. 标签：归档状态、名称关键字。
4. 往来方：人员、机构、隐藏状态、名称关键字。

冲突列表筛选：

1. 冲突状态：open、resolved、deferred。
2. 对象类型：交易、账户、附件、预算、提醒等。
3. 风险等级。
4. 来源端或设备。
5. 创建时间范围。

附件列表筛选：

1. 附件状态：LocalOnly、PendingUpload、Uploaded、Failed。
2. 业务对象类型。
3. 上传端或设备。
4. 文件名关键字。
5. 时间范围。

## 4. 排序与游标

排序必须稳定，不能因分页或刷新造成重复或漏行。

默认排序：

| 列表 | 默认排序 |
| --- | --- |
| 流水 | 业务日期倒序、创建顺序倒序、交易 ID 倒序 |
| 账户 | 账户组排序、账户排序、账户 ID |
| 分类 | 父级排序、分类排序、分类 ID |
| 标签 | 自定义排序、名称、标签 ID |
| 附件 | 更新时间倒序、附件 ID |
| 冲突 | 风险等级、创建时间倒序、冲突 ID |
| 预算/提醒 | 状态、周期或触发日期、对象 ID |
| 报表明细 | 报表定义排序、业务日期、对象 ID |

分页规则：

1. 普通列表使用 `limit + cursor`。
2. 游标必须包含排序锚点和数据版本信息。
3. 游标失效时返回 `cursor_invalid` 或等价错误，页面提示刷新。
4. 大 offset 分页不作为第一版默认方案。
5. 手机最近列表可以使用较小固定 limit，但仍要知道是否还有更多。
6. 报表钻取生成的列表查询必须继承来源报表的筛选、排序、对象版本和权限范围；来源版本过期时返回 `report_drill_version_stale` 或等价错误。

## 5. 查找与关键字

查找和筛选是不同能力：

1. 筛选返回一个结果集合。
2. 查找定位当前结果集中的下一条或匹配项。
3. 筛选条件变化、排序变化或数据版本变化后，旧查找游标必须失效。
4. 关键字匹配范围必须明确，例如主题、备注、对象名、账户名、分类名。
5. 查找不得绕过当前账本和权限范围。

第一版 PC/Web 可支持“查找下一条”。手机第一版只要求简单关键字筛选或最近列表内搜索。

## 6. 三端行为

### 6.1 PC

PC 查询来源是本地 SQLite 和本地同步状态。

PC 必须支持：

1. 完整流水列表筛选、排序、分页和查找。
2. 账户、分类、标签、往来方等基础资料列表。
3. 附件、冲突、备份/导入导出批次等维护列表。
4. 本地离线查询。
5. 同步开启后展示本地版本和云端同步摘要。

PC 不得：

1. 用 Flutter 页面直接拼 SQL。
2. 查询旧 MoneyHome8 原始文件作为常规列表数据源。
3. 把旧迁移审计、旧路径或旧原始行暴露给云端列表。

### 6.2 Web

Web 查询来源是 .NET API 和 PostgreSQL 云端对象副本。

Web 必须支持：

1. 在线流水、账户、预算、提醒、附件和冲突列表。
2. `limit + cursor` 分页。
3. 角色权限控制后的列表动作。
4. 服务端返回实际筛选、排序和下一页游标。
5. 游标失效、权限变化和网络失败的结构化错误展示。

Web 不得：

1. 读取 PC 本地 SQLite。
2. 查询或展示旧迁移审计、迁移报告、脱敏摘要、旧路径或旧原始行。
3. 使用浏览器缓存结果作为权威财务真相。

### 6.3 手机

手机查询强调最近数据、轻量筛选和可解释缓存。

手机必须支持：

1. 最近流水列表。
2. 最近账户余额摘要。
3. 待上传队列列表。
4. 冲突摘要列表。
5. 网络失败时展示缓存状态和最近同步时间。

手机不要求：

1. 完整组合筛选。
2. 大批量导出。
3. 完整冲突字段列表。
4. 完整本地账本查询。

## 7. 缓存和离线状态

缓存规则：

1. PC 本地账本查询结果来自本地 SQLite，不需要云端缓存才能工作。
2. Web 第一版在线为主，浏览器缓存只用于体验，不作为可离线写入或权威查询。
3. 手机可缓存最近列表、常用账户、分类和同步摘要。
4. 手机缓存必须按账号和账本隔离。
5. 退出登录、设备撤销或成员移除后，缓存必须进入不可继续同步或需重新登录状态。
6. 缓存结果展示时必须标明最近同步时间或缓存状态。

## 8. 批量操作、导出和打印前置状态

筛选结果常用于导出、打印或批量操作，第一版必须避免旧结果误用。

规则：

1. 导出和打印必须绑定明确查询参数、数据版本和生成时间。
2. 筛选条件变更后，结果状态进入 `Dirty`，导出和打印禁用直到重新查询。
3. 批量操作必须固定选择快照和每条对象版本。
4. 执行期间对象版本变化时，冲突项必须拒绝或返回逐行结果。
5. 手机第一版不提供大批量导出或批量治理。
6. 列表导出和打印不得包含 PC 本地完整路径、旧 MoneyHome8 原始行、旧查询证据、迁移审计、迁移报告或脱敏摘要。
7. PC 本地为了校准旧功能而保存的旧查询结果、旧排序样例、旧打印样例和旧导出样例只保存在 PC 本地，不能作为云端列表缓存。

## 9. 错误模型

| 错误码 | 场景 |
| --- | --- |
| `query_validation_failed` | 筛选条件无效 |
| `cursor_invalid` | 游标过期或不匹配当前筛选 |
| `ledger_forbidden` | 无账本访问权限 |
| `ledger_readonly` | 只读角色触发写入型列表动作 |
| `network_unavailable` | Web/手机网络不可用 |
| `storage_failed` | PC 本地读取或云端查询失败 |
| `result_too_large` | 请求范围超过第一版限制 |

错误响应不得包含旧 MoneyHome8 原始路径、迁移审计、迁移报告、脱敏摘要、旧原始行或 PC 机器环境诊断。

## 10. 验收口径

1. 流水列表查询必须限定 `ledger_id`。
2. 普通列表使用 `limit + cursor`，不依赖大 offset。
3. PC/Web 筛选变化后，导出和打印不能使用旧结果。
4. PC/Web 查找游标在筛选、排序或数据版本变化后失效。
5. 手机最近列表展示缓存状态和最近同步时间。
6. Viewer 可以查询但不能执行写入型列表动作。
7. 跨账本附件引用、冲突查询和批量操作被拒绝。
8. Web 不读取 PC 本地 SQLite。
9. 云端列表不包含旧迁移审计、迁移报告、脱敏摘要、旧路径或旧原始行。
10. 大数据量列表有明确上限和可解释错误。
11. 列表导出和打印结果能追溯查询参数、排序、游标版本和生成时间，且不上传旧查询校准证据。

## 11. 当前无需人工确认

本计划没有引入新的产品取舍；它细化的是已确认的三端查询、Web 在线为主、手机轻量缓存、PC 本地 SQLite、账本隔离、权限控制、导出打印前置状态和旧迁移隐私边界。
