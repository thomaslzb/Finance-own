# 待摊费用与摊销需求计划

本文档承接 `three-client-requirements-analysis.md`、`deposits-debts-credit-amortization-plan.md`、`runtime-accounts-and-master-data-contract.md`、`runtime-debts-credit-and-amortization-contract.md`、`acceptance-criteria.md`、`functional-ledger.md` 和 `sqlite-schema-and-query-contract.md`，定义 Finance Own 第一版待摊费用创建、资金事实、期次摊销、计划重算、删除影响和三端同步边界。本文只定义需求口径，不把未经过真实到期执行校准的 MoneyHome8 自动摊销旧公式标记为已兼容。

## 1. 目标

1. 支持 PC/Web 创建和维护待摊费用主体、初始资金事实、确定金额期次和摊销交易。
2. 明确无资金账户和有资金账户两种初始入账模式，所有资金影响必须可追溯、可回滚。
3. 使用版本化尾差策略保证全部期次金额合计逐分等于原始金额。
4. 自动摊销命令以待摊费用和期次作为幂等身份，重复执行不得重复入账。
5. 已入账期次不得被普通资料修改无痕重写，涉及金额、币种、分类、首次日期、频率或总期次的变化必须走计划重算。
6. 删除或关闭前返回账户、初始交易、摊销交易、计划、标签和附件影响预览。
7. 旧 MoneyHome8 待摊费用验证证据、迁移审计、迁移报告、脱敏摘要、旧路径和旧原始行只保存在 PC 本地。

## 2. 非目标

1. 第一版不承诺 MoneyHome8 旧自动摊销公式、特殊日历边界或历史尾差策略完全兼容。
2. 第一版不在手机端提供待摊费用复杂创建、计划重算、删除影响处理或冲突解决。
3. 第一版不把待摊费用简化为普通资产账户备注、一次余额调整或报表缓存。
4. 第一版不上传旧待摊费用原始证据、旧库路径、迁移审计、迁移报告、脱敏摘要或 PC 机器环境诊断。

## 4. 创建校验

创建待摊费用必须校验：

1. `party_id` 属于当前账本且未被禁止引用。
2. 名称非空，且保存后用于账户和列表展示。
3. 原始金额大于零。
4. 支出分类属于当前账本，方向允许费用摊销。
5. 币种存在且与资金账户、待摊账户和账本精度兼容。
6. 摊销频率为正数，首次日期可按账本日期规则解释。
7. 总摊销期数为正数。
8. 兼容导入传入已摊次数时，已摊次数不得大于总期数；普通手工创建从零个已入账期次开始。
9. 幂等键重复提交时返回第一次创建结果，不重复创建账户、初始交易或期次。

创建命令必须原子写入待摊费用主体、主体账户、初始资金事实、全部计划期次、审计和引用关系。任一对象写入失败时整体回滚。

## 5. 初始资金事实

无资金账户规则：

1. `funding_account_id` 为空时，系统创建待摊费用主体账户。
2. 初始金额作为外部期初或单边余额事件进入主体账户。
3. 该模式不当场生成普通项目支出。
4. 审计必须标明资金来源为外部期初，避免报表把它误认为真实现金流入。

有资金账户规则：

1. 来源资金账户减少 `original_amount_minor`。
2. 待摊费用主体账户增加 `original_amount_minor`。
3. 两侧分录和待摊主体必须在同一事务提交。
4. 来源账户、币种或权限校验失败时，不得留下半成品主体账户或期次。

## 6. 期次金额与自动摊销

期次规则：

1. 期次数量等于 `total_installment_count`。
2. 各期 `planned_amount_minor` 合计必须等于 `original_amount_minor`。
3. 第一版目标尾差策略为：前 `n-1` 期使用最小货币单位整数除法结果，最后一期吸收全部余数。
4. 尾差策略必须写入 `formula_version` 和 `tail_difference_strategy`，便于未来与旧样例校准或升级。
5. MoneyHome8 真实到期执行完成校准前，旧公式状态保持 `pending_calibration`。

自动摊销规则：

1. 每期摊销生成普通费用交易，引用 `prepaid_expense_id` 和 `installment_no`。
2. 幂等身份使用 `prepaid_expense_id + installment_no` 或等价稳定键。
3. 重复执行已入账期次时返回原交易结果，不重复生成费用。
4. 已入账期次不得通过普通资料编辑改金额、日期、分类或状态。
5. 到期扫描只选择 `planned` 且到期日满足账本业务日期规则的期次。
6. 自动任务失败必须保存脱敏错误、可重试状态和审计，不得吞掉失败。

## 7. 修改、重算与删除

普通概况修改只允许：

1. 名称。
2. 人员或往来方。
3. 业务日期。
4. 备注。

以下字段必须走计划重算命令：

1. 原始金额。
2. 币种。
3. 支出分类。
4. 首次摊销日期。
5. 摊销频率。
6. 总摊销期数。

计划重算规则：

1. 必须携带主体版本，避免覆盖其它端或其它窗口的修改。
2. 必须返回已入账期次、未来期次替换、金额差异和报表影响预览。
3. 已入账期次保持锁定，只能替换未来未入账期次或生成调整命令。
4. 用户取消重算时不得写入新期次、不得修改主体版本。

删除或关闭规则：

1. 删除前必须返回主体账户、初始交易、已入账摊销交易、未来期次、计划、提醒、标签和附件影响。
2. 用户确认后，主体、账户、交易、期次、引用和投影必须在同一事务版本达到一致状态。
3. 第一版优先采用作废、关闭、归档或冲销策略保留审计；确需物理清理时必须受引用约束保护。
4. 删除选择否、关闭窗口或取消命令必须零写入。

## 8. 三端职责

| 能力 | PC | Web | 手机 |
| --- | --- | --- | --- |
| 创建待摊费用 | 支持 | 支持 | 后置 |
| 查看待摊费用列表 | 支持 | 支持 | 摘要 |
| 查看期次和剩余金额 | 支持 | 支持 | 摘要 |
| 手动执行摊销 | 支持 | 支持 | 后置 |
| 计划重算 | 支持 | 支持 | 不支持 |
| 删除影响预览 | 支持 | 支持 | 不支持 |
| 冲突解决 | 支持 | 支持 | 摘要和稍后处理 |
| 旧待摊迁移证据 | PC 本地支持 | 不支持 | 不支持 |

PC 未登录时可完整维护本地待摊费用。Web 在线维护云端对象副本。手机端只展示摘要、到期提示、同步状态和冲突提示，不承担复杂配置。

## 9. 同步、冲突与隐私

同步规则：

1. 待摊费用主体、初始资金事实、期次、摊销交易、审计引用和删除墓碑作为新系统对象同步。
2. 云端保存新系统对象副本，用于 Web 在线查询和三端同步。
3. PC 未开启同步前，待摊费用只保存在 PC 本地账本。
4. 同一待摊费用主体、资金事实、未来期次或删除状态并发修改时进入冲突解决。
5. 手机端遇到待摊费用冲突只展示摘要，并引导到 PC 或 Web 处理。

隐私规则：

1. 旧 MoneyHome8 待摊费用原始证据、旧库路径、旧原始行、旧字段值、迁移审计、迁移报告、脱敏摘要和 PC 机器环境诊断只保存在 PC 本地。
2. 云端、Web、手机、日志、导出、支持包和 AI 请求不得保存或发送旧待摊迁移证据。
3. 同步只上传用户已确认同步后的新系统待摊费用对象，不上传旧证据本身。
4. 错误响应不得包含 PC 完整本地路径、旧原始行、旧字段值、令牌或密码。

## 10. 错误码

| 错误码 | 含义 | 行为 |
| --- | --- | --- |
| `prepaid_amount_invalid` | 原始金额不大于零 | 阻止保存 |
| `prepaid_party_required` | 缺少人员或往来方 | 返回字段错误 |
| `prepaid_category_invalid` | 支出分类不可用于摊销 | 阻止保存 |
| `prepaid_frequency_invalid` | 频率或总期数不合法 | 返回字段错误 |
| `prepaid_posted_count_invalid` | 兼容导入已摊次数超过总期数 | 阻止导入 |
| `prepaid_funding_account_invalid` | 资金账户不可用或币种不兼容 | 阻止保存 |
| `prepaid_installment_total_mismatch` | 期次金额合计不等于原始金额 | 阻止保存 |
| `prepaid_installment_replay` | 摊销期次幂等重放 | 返回原结果 |
| `prepaid_recalculation_blocked` | 已入账期次阻止无痕重算 | 返回影响预览 |
| `prepaid_delete_reference_blocking` | 删除受到交易、附件或计划引用阻止 | 返回影响预览 |
| `prepaid_version_conflict` | 对象版本冲突 | 进入冲突解决 |

错误响应必须脱敏，不得包含旧 MoneyHome8 原始路径、旧字段值、旧原始行、迁移审计、迁移报告、脱敏摘要、PC 完整本地路径、令牌或密码。

## 11. 验收场景

1. PC/Web 创建 `100.01 CNY / 3` 期待摊费用时，三期期次合计精确等于 `100.01`，最后一期吸收尾差。
2. 无资金账户创建时生成待摊主体账户和外部期初余额事件，不生成普通现金流出。
3. 有资金账户创建时来源账户流出、待摊账户流入和全部期次同事务提交；任一失败整体回滚。
4. 重复提交创建命令不重复创建主体账户、初始交易或期次。
5. 同一期次自动摊销重复执行只返回原交易，不重复入账。
6. 普通概况页只能修改名称、人员、业务日期和备注。
7. 修改金额、币种、分类、首次日期、频率或总期数时必须先返回计划重算预览。
8. 删除前展示账户、初始交易、摊销交易、未来期次、计划、标签和附件影响；取消零写入。
9. Web 与 PC 并发修改同一待摊费用规则时进入冲突解决。
10. 手机只展示待摊费用摘要、到期提示和冲突摘要。
11. 旧待摊费用验证证据、迁移审计、迁移报告、脱敏摘要、旧路径和旧原始行只保存在 PC 本地。

## 12. 当前无需人工确认

本计划没有引入新的产品取舍；它细化的是已确认的待摊费用创建、摊销期次、分录平衡、幂等执行、三端职责和旧迁移证据 PC 本地保存边界。
