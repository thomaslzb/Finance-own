# 三端 UI 信息架构与导航需求计划

本文档承接 `three-client-requirements-analysis.md`、`flutter-pc-local-api-plan.md`、`flutter-web-online-plan.md` 和 `mobile-offline-queue-plan.md`，定义 Finance Own 第一版 PC、Web、手机三端 UI 信息架构、导航、首次使用和通用页面状态边界。本文只定义需求，不进入视觉设计稿或 Flutter 组件实现。

## 1. 目标

第一版 UI 必须支持：

1. PC、Web、手机三端一致的账本、账户、流水、记账、预算、提醒、报表、同步和冲突入口。
2. PC 未登录本地使用和登录后显式开启同步。
3. Web 必须登录后使用。
4. 手机端登录后轻量记账、查询、同步队列和冲突摘要。
5. 统一页面状态：加载中、空状态、只读、离线、失败、冲突待处理。
6. 旧 MoneyHome8 迁移入口只出现在 PC 端。
7. 备份恢复、导入导出和高级维护能力优先在 PC 端承载。
8. PC/Web 工作台概况布局支持可配置显示区块、图表摘要和排序偏好。

第一版不要求：

1. 手机端完整账本管理台。
2. Web 端离线写主账本。
3. 复杂投资录入、高级报表设计器和自动计划执行完整后台闭环。

第一版不得：

1. Web 或手机端读取 PC 本地 SQLite、旧账本文件或迁移审计。

## 2. PC 信息架构

PC 是完整本地账本、旧账本迁移和高级维护入口。

PC 顶层导航：

| 区域 | 第一版页面 |
| --- | --- |
| 财务数据 | 账户中心、基础资料、流水列表、附件管理 |
| 记账 | 收入、支出、转账、常用模板入口 |
| 财务报表 | 收支报表、账户余额、标签流水、基础导出 |
| 财务分析 | 预算、提醒、计划、财务目标 |
| 同步与冲突 | 同步入口、同步状态、冲突列表、冲突详情 |
| 迁移与维护 | 旧 MoneyHome8 迁移、备份、恢复、导入导出 |
| 设置 | 本地账本设置、账号登录、设备摘要、隐私提示 |

PC 首次使用流程：

1. 启动 Flutter PC。
2. 用户选择创建本地账本、打开本地账本或迁移旧账本。
3. 未登录用户可继续完整本地记账。
4. 用户登录后，同步入口展示隐私提示和显式开启同步确认。
5. 开启同步前不得自动上传本地账本、旧原始文件、迁移审计或迁移报告。

PC 页面状态必须覆盖：

| 状态 | 说明 |
| --- | --- |
| `no_ledger` | 未创建或未打开账本 |
| `local_only` | 本地账本未开启同步 |
| `sync_available` | 已登录但未开启同步 |
| `syncing` | 正在上传或下载新系统对象 |
| `conflict_pending` | 存在待处理冲突 |
| `legacy_migration_ready` | 可进入旧账本迁移 |
| `maintenance_required` | 备份、恢复或导入导出需要用户处理 |

### 2.1 工作台概况布局

概况布局用于承接旧版六类图表、四个显示区块和拖动排序能力。第一版不复刻旧界面的像素级布局，但必须保存用户能感知的显示偏好。

`DashboardLayoutPreferenceDto` 字段：

| 字段 | 说明 |
| --- | --- |
| `ledger_id` | 所属账本 |
| `user_id` | 云端账号下的用户；PC 未登录时使用本地用户范围 |
| `client_scope` | pc、web、mobile |
| `visible_sections` | 资产摘要、最近流水、预算提醒、图表等区块 |
| `section_order` | 区块排序 |
| `chart_types` | 启用的图表摘要类型 |
| `version` | 偏好版本 |

规则：

1. 概况区块排序只改变 UI 偏好，不改变财务对象、报表结果或同步事实。
2. PC 本地未登录时偏好只保存在本地账本或本地设置中。
3. 登录同步后，PC/Web 可同步新系统布局偏好；旧布局证据、截图和自动化输出只保存在 PC 本地。
4. 手机端只使用轻量首页摘要，不要求复刻 PC/Web 的多区块拖动排序。
5. 区块隐藏不能绕过权限；Viewer 即使显示区块也不能提交写命令。

## 3. Web 信息架构

Web 是在线记账、在线查询和冲突解决入口。

Web 顶层导航：

| 区域 | 第一版页面 |
| --- | --- |
| 账本 | 账本列表、账本详情、成员基础管理 |
| 工作台 | 账户摘要、最近流水、同步摘要 |
| 记账 | 收入、支出、转账 |
| 查询 | 账户中心、流水列表、预算、提醒、基础报表 |
| 冲突 | 冲突列表、冲突详情、解决动作 |
| 附件 | 上传、下载、引用管理 |
| 设置 | 当前用户、设备列表、退出登录 |

Web 首次使用流程：

1. 用户打开 Web。
2. 未登录时进入登录页。
3. 登录成功后进入账本列表。
4. 无账本时允许创建云端账本。
5. 有账本时进入最近使用账本或账本选择页。

Web 页面状态必须覆盖：

| 状态 | 说明 |
| --- | --- |
| `unauthenticated` | 未登录或刷新令牌失效 |
| `loading` | 正在调用 .NET API |
| `ready` | 数据已加载 |
| `readonly` | 当前用户为 Viewer |
| `offline` | 浏览器无网络或 API 不可达 |
| `conflict_pending` | 当前账本有冲突 |
| `error` | 结构化错误 |

Web 不得展示：

1. 旧 MoneyHome8 迁移入口。
2. PC 本地 SQLite 路径。
3. 迁移审计、迁移报告、脱敏摘要、旧路径或旧原始行。

## 4. 手机信息架构

手机端强调随手记账、最近查询和同步状态。

手机底部导航：

| 区域 | 第一版页面 |
| --- | --- |
| 首页 | 当前账本、资产摘要、最近流水、同步摘要 |
| 记一笔 | 收入、支出、转账快速表单 |
| 流水 | 最近流水和基础筛选 |
| 队列 | 离线草稿、待上传、失败、冲突摘要 |
| 我的 | 账号、设备、账本切换、缓存清理 |

手机首次使用流程：

1. 打开手机端。
2. 用户登录。
3. 选择账本。
4. 拉取最近数据、常用账户、分类、标签和同步摘要。
5. 网络不可用时允许创建离线草稿，但不允许完整本地账本维护。

手机页面状态必须覆盖：

| 状态 | 说明 |
| --- | --- |
| `unauthenticated` | 未登录 |
| `ledger_required` | 已登录但未选择账本 |
| `online` | 可同步 |
| `offline_draft` | 可保存本机草稿 |
| `pending_upload` | 有待上传队列 |
| `upload_failed` | 队列上传失败 |
| `conflict_summary` | 云端存在冲突，建议 PC/Web 处理 |
| `readonly` | 当前用户为 Viewer |

手机不得提供：

1. 旧账本迁移。
2. 高级备份恢复。
3. 批量导入导出。
4. 字段级冲突合并。
5. 完整本地账本维护。

## 5. 跨端一致性

三端必须一致：

1. 同一个账本使用同一 `ledger_id`。
2. 同一对象类型使用一致名称和状态。
3. 金额使用最小单位整数和币种代码。
4. 日期区分业务日期和发生时间。
5. 只读角色不能出现可提交成功的写入入口。
6. 冲突数量、同步状态和设备来源来自 .NET API 或 PC 本地同步入口，不由页面猜测。

## 6. 页面族与旧界面追溯

第一版不复刻旧 `460` 个 Delphi 窗体，而是使用目标页面族承接旧能力。

页面族要求：

1. 每个目标页面族必须记录覆盖的旧 `execution_id`。
2. 合并旧页面时必须保留业务命令边界。
3. 投资、预算、提醒、导入导出等尚未完全校准的页面族必须标记验证状态。
4. 页面族不能把旧 MoneyHome8 私有路径、旧字段名或迁移诊断暴露给 Web 或手机。

## 7. 验收口径

1. PC 未登录可创建本地账本并进入完整本地工作台。
2. PC 旧账本迁移入口不会出现在 Web 或手机。
3. Web 未登录不能进入账本页面。
4. Web Viewer 看不到可成功提交的写入、删除或冲突解决入口。
5. 手机可离线保存草稿，但不展示完整本地账本维护入口。
6. 三端都能进入账本切换或当前账本摘要。
7. 同步状态、冲突数量和只读状态在三端展示一致。
8. 目标页面族可追溯旧页面覆盖范围。
9. PC/Web 概况布局排序、显示区块和图表摘要作为偏好保存，不改变报表和账务事实。

## 8. 当前无需人工确认

本计划没有引入新的产品取舍；它把已确认的 Flutter 三端、PC 本地优先、Web 在线为主、手机轻量同步、旧迁移仅 PC 和页面族合并边界整理成 UI 信息架构需求。
