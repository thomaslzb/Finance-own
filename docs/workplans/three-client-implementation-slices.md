# 三端实施切片索引

本文档承接 `three-client-requirements-analysis.md`，把已经确认的 Finance Own 三端需求整理成可进入实现拆分的切片索引。本文只记录已确认范围，不引入新的产品取舍。

## 1. 总体顺序

第一版实施应按以下依赖推进：

1. 先稳定 PC 本地账本和 Flutter PC 本地 API，因为 PC 端承担离线完整账本、旧 MoneyHome8 迁移和本地 SQLite 真相源。
2. 再定义 .NET 同步 API 和 PostgreSQL 云端对象副本，因为 Web、手机和 PC 同步都依赖统一对象、版本、冲突和附件合同。
3. 再实现 Web 在线端，因为 Web 端在线为主、必须登录，是云端 API 和冲突解决能力的直接验证面。
4. 再实现手机端轻量同步，因为手机端依赖云端对象副本、幂等队列和冲突摘要机制。
5. 最后补齐跨端附件、审计、删除确认和异常恢复的端到端验收。

## 2. PC 本地切片

对应计划：`flutter-pc-local-api-plan.md`。

### 2.1 账本会话

范围：

1. 打开、创建、关闭 PC 本地账本。
2. 暴露 `NoLedger`、`Opening`、`Opened`、`Closing`、`Failed` 等会话状态。
3. 未登录用户可以完整使用 PC 本地账本。
4. 用户登录后，必须显式确认才把本地账本绑定账号并开启同步。

验收：

1. Flutter PC 不直接访问 SQLite 或旧账本文件。
2. 本地 API 错误不包含完整路径、旧原始行、密钥或未脱敏迁移诊断。
3. 关闭账本和打开失败时，页面能回到明确可恢复状态。

### 2.2 工作台首屏

范围：

1. 复用 Rust 侧 `WorkspaceHomeViewModel` 或等价 DTO。
2. 展示资产负债汇总、账户组、最近流水和待办状态。
3. 提供空账本、加载中、读取失败和数据正常四类状态。

验收：

1. DTO 能被 Flutter 序列化消费。
2. 页面不依赖数据库内部表名、视图名或索引名。
3. 金额、币种和时间字段有稳定格式。

### 2.3 常用记账

范围：

1. 收入。
2. 支出。
3. 转账。
4. 基础校验和命令状态。

验收：

1. Flutter 只提交业务命令，不拼底层分录。
2. Rust 本地核心负责原子写入、余额影响和错误归一。
3. 失败时返回字段级错误或可恢复的存储错误。

### 2.4 旧账本迁移

范围：

1. 旧 MoneyHome8 文件只读探测。
2. 迁移预览。
3. 用户确认导入。
4. 迁移审计、迁移报告和旧 ID 映射只保存 PC 本地。

验收：

1. 旧 MoneyHome8 原始文件不上传云端。
2. 迁移审计、迁移报告、脱敏摘要、旧路径、旧原始行和旧库诊断不上传云端。
3. 迁移结果写入 PC 本地 SQLite 后，只有新系统对象可在用户确认同步后进入云端。

## 3. .NET 云端切片

对应计划：`dotnet-sync-api-plan.md`。

### 3.1 账号与设备

范围：

1. 邮箱密码登录。
2. 刷新令牌。
3. 当前用户。
4. 设备列表和撤销。

验收：

1. Web 必须登录后使用。
2. PC 未登录不影响本地记账。
3. 令牌、密码和刷新凭据不进入 PC 核心领域表。

### 3.2 多账本与成员

范围：

1. 账本列表。
2. 账本详情。
3. Owner、Editor、Viewer 基础角色。
4. 多账本数据隔离。

验收：

1. 每个云端对象必须携带 `ledger_id`。
2. 跨账本查询、附件引用和同步批次必须被权限校验阻断。
3. PC 本地未开启同步的账本没有云端成员概念。

### 3.3 同步 Push/Pull

范围：

1. PC、手机、Web 均可创建新系统财务对象。
2. PC 和手机可以上传本端变更并下载其它端变更。
3. Web 直接写云端对象副本。
4. 同步按对象、版本、墓碑和批次传输。

验收：

1. 不上传整个 SQLite 文件。
2. 不要求云端静默覆盖 PC 本地对象。
3. 真冲突进入冲突列表，由用户确认解决。

### 3.4 云端对象副本

范围：

1. PostgreSQL 保存完整新系统财务对象副本。
2. 保存同步版本、冲突记录、墓碑、附件元数据和云端审计。
3. 不复刻 PC SQLite 内部视图和本地迁移审计。

验收：

1. 云端对象能支撑 Web 在线查询和三端同步。
2. 云端不保存旧 MoneyHome8 原始文件、迁移审计、迁移报告、脱敏摘要或 PC 完整本地路径。

## 4. Web 在线端切片

对应计划：`flutter-web-online-plan.md`。

范围：

1. 登录后账本列表和账本切换。
2. 在线新增、修改和删除常用财务记录。
3. 账户、流水、预算、提醒和基础报表查询。
4. 完整冲突列表和字段级差异展示。
5. 删除二次确认和影响范围提示。

验收：

1. Web 不读取 PC 本地 SQLite。
2. Web 不保存旧迁移审计或迁移报告。
3. Web 删除通过对象版本或墓碑同步到其它端。
4. Web 冲突解决必须留下云端审计。

## 5. 手机端切片

对应计划：`mobile-offline-queue-plan.md`。

范围：

1. 登录和账本选择。
2. 最近数据缓存。
3. 收入、支出、转账的快速记录。
4. 离线草稿和待同步队列。
5. 冲突摘要提示。

验收：

1. 手机端不保存完整本地账本。
2. 手机端不承担旧账本迁移。
3. 队列项必须有幂等键、状态、重试次数和脱敏错误。
4. 复杂冲突引导用户到 PC 或 Web 处理。

## 6. 冲突解决切片

对应计划：`conflict-resolution-plan.md`。

范围：

1. 对象级冲突检测。
2. 字段级差异展示。
3. PC/Web 完整解决。
4. 手机端只展示摘要和延后处理。
5. 解决结果生成新版本并同步下发。

验收：

1. 不允许静默执行 PC 覆盖云端或云端覆盖 PC。
2. 用户必须能选择本端值、云端值或可合并值。
3. 审计不得包含旧 MoneyHome8 迁移审计、迁移报告、完整本地路径或附件原始内容。

## 7. 附件与隐私切片

对应计划：`attachment-privacy-plan.md`。

范围：

1. PC 本地附件受管保存。
2. 手机端临时附件缓存。
3. Web 在线上传附件。
4. 云端附件元数据和内容存储。
5. 附件权限、短期授权和删除引用。

验收：

1. 附件必须绑定账本和业务对象。
2. 附件下载必须经过账本成员权限校验或短期授权。
3. 旧迁移审计、迁移报告和旧原始来源必须始终只保存在 PC 本地。
4. 迁移后的新系统附件对象只有在用户开启同步并确认附件隐私提示后才上传。

第一版最小端到端链路应按以下顺序验收：

1. PC 未登录创建本地账本并新增收入、支出、转账。
2. PC 登录后显式确认开启同步，把新系统对象上传云端。
3. Web 登录后看到同一账本和 PC 同步上来的记录。
4. Web 新增一条记录，PC 同步下载后可见。
5. 手机离线新增一条记录，恢复网络后上传云端。
6. PC 和 Web 均能看到手机新增记录。
7. PC 与 Web 制造同一对象并发修改，进入冲突解决。
8. 用户在 Web 或 PC 完成冲突解决，结果同步到三端。
9. PC 执行旧 MoneyHome8 迁移预览和确认导入，迁移审计和迁移报告只留 PC 本地。
10. 用户确认同步后，仅迁移生成的新系统对象进入云端。
11. Owner 调整成员角色后，Web、PC 和手机按新角色限制写入，未上传数据保留且不静默上传。
12. PC/Web/手机新增金额对象后，余额、币种、本币折算和缺汇率状态在三端展示一致。
13. PC/Web 使用同一筛选条件查询流水列表，分页、排序、导出前置状态和权限限制一致；手机显示最近列表和缓存状态。
14. 设备撤销、同步失败、今日提醒和冲突摘要在三端以通知或状态提示表达，且不泄露令牌、PC 本地路径或旧迁移证据。
15. PC/Web/手机提交常用记账命令时，表单失败保留草稿、重复提交不重复创建、修改删除校验版本并留下审计。
16. PC/Web 管理基础资料并同步到三端，手机引用缓存资料提交草稿时遇到归档、权限或版本问题必须保留草稿并提示处理。
17. PC 未登录创建本地账本、登录后显式开启同步、设备撤销后保留本地文件、删除本地账本必须本机二次确认。
18. PC/Web 展示投资输入和校准状态，未校准收益率、成本和复杂公式不得作为正式报表结论，手机只显示摘要和状态。
19. PC/Web 删除、归档或恢复对象时生成版本、墓碑和审计；手机删除未上传草稿只影响本机，远程动作不得删除 PC 本地文件。
20. PC/Web/手机展示同一交易业务日期一致，报表和预算按账本时区与闭区间账期计算，手机离线上传不能用云端接收时间覆盖业务日期。
21. 绕过 Flutter 前端校验提交非法对象时，Rust 本地核心或 .NET API 仍必须按统一不变量拒绝，并返回可映射字段错误或业务错误。
22. PC/Web/手机同一错误码、金额、日期、状态和只读权限展示一致，键盘和基础可访问性不能绕过权限或高风险确认。
23. Web/手机登录、刷新、退出和设备撤销流程不会泄露令牌或删除本地数据；PC 未登录本地可用且登录后未显式开启同步不上传账本。
24. 云端错误、告警、客户服务入口、支持入口和数据修复只使用脱敏诊断 ID、聚合指标、受控链接和受控审计，不暴露财务明细、旧迁移证据或 PC 本地完整路径。
25. 发布前验收证据覆盖三端主链路、隐私安全、财务不变量、运维诊断和后置能力说明，阻断项不得带入发布。
26. 计划实例显式返回今日待办、可执行和可跳过状态；普通计划、仅提醒计划和自动入账候选不能被统一误投影为同一执行能力。
27. PC/Web 创建财务目标和规划输入时必须返回公式版本、进度状态和引用影响预览；手机只展示摘要，旧迁移证据只保存在 PC 本地。
28. PC/Web 创建限额提醒和预算提示规则时必须校验条件范围、定点精度、条件版本和幂等触发键；当前告警进入今日提醒后不可执行、不可跳过。
29. PC/Web 维护存款、债务、信用卡和分期对象时必须区分合同、计划、实际交易和派生投影；账单日/还款日规则必须版本化处理固定日、月末、相对偏移、短月份策略、账单生成幂等和历史账单冻结；所有资金流保持分录平衡，敏感卡号不得进入日志或导出。
30. PC/Web 维护保险现金价值、社保项目、重大资产估值和分期对象时必须区分事件、资金交易、估值快照和派生投影；旧迁移证据和敏感身份信息不得进入云端或导出。
31. PC/Web 维护证券、基金、债券和融资融券对象时必须使用稳定工具身份、代码历史、新股流程 ID、费用或净值快照、估值批次和成本批次；未校准收益和风险公式不能作为正式结论。
32. 三端共享 UI 组件不得直接提交业务事务；金额计算器取消不回填，AI 适配器默认关闭且不能发送旧迁移证据，内部控制台只在诊断构建启用。
33. PC/Web 维护工资收入时必须使用稳定账户、分类、人员和社保账户 ID；收入、扣款、个人社保、公司社保、税务快照、现金流入和社保权益必须原子提交，旧工资迁移证据只保存在 PC 本地。
