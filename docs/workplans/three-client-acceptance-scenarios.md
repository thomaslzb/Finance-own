# 三端需求验收场景索引

本文档承接 `three-client-implementation-slices.md`，把 Finance Own 第一版三端需求整理成可执行验收场景。本文只定义需求验收口径，不绑定具体自动化测试框架。

## 1. 验收原则

1. 每个场景必须明确端：PC、Web、手机或云端。
2. 每个场景必须明确联网状态：离线、在线、待同步或冲突。
3. 每个场景必须明确账本范围和权限角色。
4. 每个场景必须明确是否允许上传云端。
5. 涉及旧 MoneyHome8 的场景必须确认旧原始文件、迁移审计、迁移报告、脱敏摘要、旧路径和旧原始行不会上传云端。
6. 涉及金额、余额或报表的场景必须能追溯业务日期、币种和对象版本。
7. 除场景明确禁止上传外，云端只允许接收用户已开启同步后的新系统对象、对象版本、同步状态和脱敏审计；旧 MoneyHome8 证据、PC 本地完整路径、旧原始行、迁移审计、迁移报告和脱敏摘要始终只保存在 PC 本地。

## 2. PC 本地基础场景

### AC-PC-001 未登录本地记账

前置条件：

1. PC 未登录账号。
2. 已创建或打开 PC 本地账本。

步骤：

1. 新增收入。
2. 新增支出。
3. 新增转账。
4. 打开工作台首屏和最近流水。

验收：

1. 三笔交易写入 PC 本地 SQLite。
2. Flutter PC 不直接访问 SQLite 或旧账本文件。
3. 本地账本未自动绑定云端账号。
4. 同步入口显示未登录或未开启同步。

### AC-PC-002 PC 显式开启同步

前置条件：

1. PC 已登录账号。
2. 本地账本存在未上传的新系统交易。

步骤：

1. 用户打开同步入口。
2. 系统展示账本名称、对象数量、附件规模和隐私提示。
3. 用户显式确认开启同步。
4. PC 上传新系统对象。

验收：

1. 只有新系统对象进入云端。
2. 不上传整个 SQLite 文件。
3. 不上传旧 MoneyHome8 原始文件、迁移审计、迁移报告、脱敏摘要、旧路径或旧原始行。
4. 云端生成同步批次和对象版本。

## 3. Web 在线场景

### AC-WEB-001 登录后在线记账

前置条件：

1. 用户可登录 Web。
2. 用户对目标账本拥有 Editor 或 Owner 权限。

步骤：

1. 登录 Web。
2. 选择账本。
3. 新增收入、支出和转账。
4. 查询流水列表。

验收：

1. Web 通过 .NET API 写入云端对象副本。
2. 每个写入生成对象版本。
3. 流水列表使用 `limit + cursor`。
4. Web 不读取 PC 本地 SQLite，不调用 Rust 本地核心。

### AC-WEB-002 Viewer 只读权限

前置条件：

1. 用户对账本拥有 Viewer 权限。

步骤：

1. 登录 Web。
2. 打开账本。
3. 尝试新增、修改、删除或解决冲突。

验收：

1. 查询可用。
2. 写入、删除和冲突解决不可用或被 API 拒绝。
3. 错误码表达为权限错误，不伪装成普通校验错误。

### AC-WEB-003 删除二次确认

前置条件：

1. Web 用户拥有 Editor 或 Owner 权限。
2. 目标交易已同步。

步骤：

1. 用户发起删除交易。
2. 系统展示影响范围。
3. 用户确认删除。

验收：

1. 删除请求包含对象版本、确认令牌和幂等请求 ID。
2. 云端生成墓碑、作废或归档版本。
3. 删除审计包含用户、时间、端、对象和操作原因。
4. 并发修改时进入冲突，不静默覆盖。

## 4. 账号、设备与成员场景

### AC-AUTH-001 Web 登录与设备登记

前置条件：

1. 用户已有自有账号。

步骤：

1. Web 使用邮箱和密码登录。
2. 服务端登记当前浏览器设备。
3. 用户查看设备列表。

验收：

1. 登录响应包含访问令牌、刷新令牌、用户资料和设备摘要。
2. 设备列表包含设备类型、设备名、最近活跃时间和撤销状态。
3. 密码、刷新令牌和访问令牌不进入普通日志或错误响应。

### AC-AUTH-002 设备撤销

前置条件：

1. 用户至少有两个已登录设备。

步骤：

1. 用户撤销其中一个设备。
2. 被撤销设备尝试刷新令牌。
3. 被撤销设备尝试上传同步批次。

验收：

1. 刷新令牌失败。
2. 上传同步批次返回 `device_revoked` 或等价权限错误。
3. 撤销设备不删除 PC 本地账本文件。

### AC-AUTH-003 PC 本地账本密码与换密钥恢复

前置条件：

1. PC 打开一个启用账本密码或本地加密的本地账本。
2. 该账本未开启同步或已开启同步但本地密钥材料只在 PC 本地。

步骤：

1. 连续输入错误账本密码。
2. 触发本机冷却后再次尝试打开。
3. 发起 KDF 升级或换密钥。
4. 在换密钥过程中模拟中断或失败。
5. 使用恢复入口重新打开账本。

验收：

1. 连续失败触发本机冷却，失败样例、密码输入和 KDF 探测证据不进入日志、云端、Web 或手机。
2. 换密钥前创建 PC 本地恢复点。
3. 中断或失败后账本能回到旧密钥可打开状态，或明确进入只读恢复状态。
4. 云端只接收脱敏状态或新系统对象版本，不保存密钥材料、恢复点路径、旧密码诊断或 PC 机器环境信息。

### AC-MEMBER-001 Owner 邀请 Editor

前置条件：

1. 用户 A 是账本 Owner。
2. 用户 B 有自有账号。

步骤：

1. 用户 A 邀请用户 B 成为 Editor。
2. 用户 B 接受邀请。
3. 用户 B 登录 Web 新增一条交易。

验收：

1. 成员列表显示用户 B 为 Editor。
2. 用户 B 可以新增、修改和删除常规财务对象。
3. 用户 B 不能修改成员角色或删除账本。

### AC-MEMBER-002 Viewer 隔离写入

前置条件：

1. 用户 B 是账本 Viewer。

步骤：

1. 用户 B 查询账户和流水。
2. 用户 B 尝试新增交易。
3. 用户 B 尝试上传附件。
4. 用户 B 尝试解决冲突。

验收：

1. 查询可用。
2. 新增交易、上传附件和解决冲突被拒绝。
3. 错误码明确为 `ledger_readonly` 或等价只读角色错误。

### AC-MEMBER-003 Editor 降级为 Viewer

前置条件：

1. 用户 B 原为 Editor。
2. 用户 B 的手机端存在待上传队列。

步骤：

1. Owner 将用户 B 降级为 Viewer。
2. 用户 B 手机端尝试上传待同步队列。

验收：

1. 上传失败或进入权限冲突提示。
2. 手机本地草稿不被静默删除。
3. 云端不接受 Viewer 写入。

### AC-LEDGER-001 多账本隔离

前置条件：

1. 同一用户拥有账本 A 和账本 B。
2. 两个账本都有交易和附件。

步骤：

1. 查询账本 A 流水。
2. 查询账本 B 流水。
3. 尝试把账本 A 的附件引用绑定到账本 B 的交易。

验收：

1. 账本 A 和账本 B 的流水、附件、同步批次和冲突互不串账。
2. 跨账本附件引用被拒绝。
3. 所有云端对象和 API 请求都限定明确 `ledger_id`。

### AC-LEDGER-002 PC 账簿结算预览与回滚

前置条件：

1. PC 本地账本存在多账户、多币种和历史交易。
2. 用户拥有本机账本写入权限。

步骤：

1. 选择结算截止日期。
2. 生成结算预览。
3. 模拟缺汇率或未校准公式阻断项。
4. 修正阻断项后执行结算。
5. 使用同一截止日和对象版本重复执行一次。
6. 模拟结算写入失败并执行恢复。

验收：

1. 结算预览展示截止日、对象版本、汇率快照、公式状态、恢复点和将生成的余额调整。
2. 有阻断项时不写入正式对象。
3. 成功结算同事务生成新系统结算对象和余额调整，失败整体回滚。
4. 重复执行不重复生成余额调整。
5. 旧结算校准证据、旧路径、旧原始行、迁移审计、迁移报告、脱敏摘要和 PC 机器环境诊断只保存在 PC 本地。
6. Web 和手机只能查看已同步的新系统结算摘要，不能保存或读取 PC 本地旧证据。

## 5. 手机轻量同步场景

### AC-MOB-001 离线新增后上传

前置条件：

1. 手机已登录并选择账本。
2. 手机临时离线。

步骤：

1. 离线新增收入。
2. 确认队列状态为 `PendingUpload`。
3. 恢复网络。
4. 手机上传队列。

验收：

1. 队列项有稳定 `client_change_id`。
2. 重复上传不会创建重复交易。
3. 云端接受后队列项变为 `Synced`。
4. 手机不保存完整本地账本。

### AC-MOB-002 手机冲突摘要

前置条件：

1. 云端已存在当前账本未解决冲突。

步骤：

1. 手机同步冲突摘要。
2. 用户打开同步状态页。

验收：

1. 手机显示冲突数量、高风险数量和最近冲突时间。
2. 手机提示到 PC 或 Web 处理。
3. 手机不加载字段级差异，不提供字段级合并。

### AC-MOB-003 手机快查和远程通知摘要

前置条件：

1. 手机已登录并选择账本。
2. 账本已开启同步，且用户拥有查看权限。

步骤：

1. 开启手机快查。
2. 查询账户摘要、最近流水摘要和提醒摘要。
3. 触发一条远程通知。
4. Owner 撤销设备或将用户降级为 Viewer。

验收：

1. 手机快查只读取摘要，不保存完整本地账本。
2. PC 本地未开启同步的账本不可被手机快查读取。
3. 远程通知只包含标题、严重级别、来源类型和脱敏对象摘要。
4. 通知不得包含完整交易备注、附件内容、旧迁移证据、PC 本地完整路径或令牌。
5. 设备撤销或权限变化后，手机快查和远程通知停止使用旧权限。
6. 手机快查失败必须区分网络失败、设备撤销、成员移除、角色降级、账本未同步和缓存过期。
7. 远程通知投递失败、重试和权限抑制使用幂等键去重，不创建重复通知。

## 6. 双向同步场景

### AC-SYNC-001 PC 到 Web 到手机

前置条件：

1. PC、Web、手机使用同一账号或同一账本成员权限。
2. PC 本地账本已显式开启同步。

步骤：

1. PC 新增一条交易并上传。
2. Web 查询账本流水。
3. 手机同步最近数据。

验收：

1. Web 能看到 PC 上传的交易。
2. 手机能看到 PC 上传的交易摘要。
3. 云端对象版本、来源设备和同步游标可追溯。

### AC-SYNC-002 Web 到 PC

前置条件：

1. Web 用户拥有写权限。
2. PC 已开启同步。

步骤：

1. Web 新增一条交易。
2. PC 执行同步下载。

验收：

1. PC 能看到 Web 新增交易。
2. PC 本地同步记录保存对象版本和来源设备。
3. 非冲突变更自动应用，无需额外确认。

### AC-SYNC-003 手机到 PC/Web

前置条件：

1. 手机端有 `PendingUpload` 队列项。

步骤：

1. 手机上传队列。
2. Web 查询流水。
3. PC 同步下载。

验收：

1. Web 和 PC 均能看到手机新增交易。
2. 云端幂等处理不会重复创建。
3. 失败时手机保留可重试或可编辑草稿。

### AC-SYNC-004 断点续传、取消和墓碑传播

前置条件：

1. PC 账本已显式开启同步。
2. 账本存在一批可分片上传的对象变更和一条可删除交易。

步骤：

1. PC 分片上传同步批次并在中途断开网络。
2. 网络恢复后使用续传令牌继续上传。
3. 对另一个尚未写入的批次发起取消。
4. Web 删除一条已同步交易。
5. PC 和手机拉取变更。
6. 使用同一 `client_batch_id` 重复上传一次。

验收：

1. 续传从最后检查点继续，服务端校验分片序号、哈希、总 payload 哈希和续传令牌。
2. 取消只对未进入不可取消阶段的批次生效，取消后不发布未完成对象版本。
3. Web 删除生成墓碑对象版本；PC 和手机拉取后删除或隐藏本地投影，不用旧缓存复活对象。
4. 重复上传返回原批次和逐项结果，不重复创建对象或冲突。
5. 查询批次能返回 applied、replayed、rejected、conflict_created、cancelled 和 failed 的真实结果。
6. 同步错误、批次状态和诊断 ID 不包含旧迁移证据、PC 完整本地路径或旧原始行。

## 7. 冲突解决场景

### AC-CONFLICT-001 同字段编辑

前置条件：

1. PC 和 Web 同时基于同一交易版本编辑金额或备注。

步骤：

1. Web 先提交成功。
2. PC 随后上传基于旧对象版本的修改。
3. 云端创建冲突。
4. 用户在 PC 或 Web 解决冲突。

验收：

1. 云端不静默覆盖任何一端。
2. 冲突详情包含基线、本端、云端和字段差异。
3. 解决结果生成新对象版本。
4. 冲突审计不包含旧迁移审计、迁移报告、脱敏摘要、完整本地路径或旧原始行。

### AC-CONFLICT-002 删除与修改并发

前置条件：

1. Web 删除交易。
2. PC 离线修改同一交易。

步骤：

1. Web 删除生成墓碑或作废版本。
2. PC 恢复网络并上传修改。

验收：

1. 云端创建 `DeleteVsEdit` 冲突。
2. 用户可选择保留删除、保留修改或另存副本。
3. 解决后同步到三端。

## 8. 附件与隐私场景

### AC-ATT-001 PC 本地附件不自动上传

前置条件：

1. PC 本地账本未开启同步。

步骤：

1. 用户给交易添加本地附件。
2. 打开同步入口但不确认附件上传。

验收：

1. 附件状态为 `LocalOnly`。
2. 附件受管目录只保存相对路径和内容哈希。
3. 云端没有附件内容和 PC 完整本地路径。

### AC-ATT-002 Web 附件上传和下载授权

前置条件：

1. Web 用户拥有目标账本写权限。

步骤：

1. Web 上传附件并绑定交易。
2. 另一个有权限成员下载附件。
3. 无权限用户尝试下载附件。

验收：

1. 有权限成员可通过短期授权或 API 流式下载。
2. 无权限用户被拒绝。
3. 附件 URL 过期后不能继续访问。
4. 附件引用不能跨账本复用。

### AC-ATT-003 旧迁移附件确认同步

前置条件：

1. PC 已完成旧 MoneyHome8 迁移预览和确认导入。
2. 迁移生成了新系统附件对象。

步骤：

1. 用户开启账本同步。
2. 系统单独展示附件隐私提示。
3. 用户选择允许上传部分迁移生成的新系统附件对象。

验收：

1. 仅用户选择的新系统附件对象上传云端。
2. 旧迁移原始来源不上传。
3. 迁移审计、迁移报告、脱敏摘要、旧路径、旧原始行和迁移诊断不上传。
4. 用户未选择上传的附件在其它端不显示假附件。

### AC-ATT-004 票据和支票簿凭证引用

前置条件：

1. PC/Web 用户拥有账本写权限。
2. 账本存在一条交易和一个本地票据或支票簿类附件。

步骤：

1. 创建票据或支票簿凭证引用并绑定交易。
2. 查询交易附件和凭证列表。
3. 尝试把该凭证引用到账本外交易。
4. 删除凭证并取消。

验收：

1. 凭证保存 `ledger_id`、脱敏票号、附件引用、业务对象引用和生命周期状态。
2. 凭证金额、票号和图片不直接生成资金分录，不改变账户余额。
3. 跨账本引用被拒绝。
4. 删除取消零写入；确认前必须展示关联交易、导入批次和附件影响。
5. 旧票据、支票簿和凭证证据、迁移审计、迁移报告、脱敏摘要、旧路径和旧原始行只保存在 PC 本地。

### AC-ATT-005 多附件引用和物理清理

前置条件：

1. PC/Web 用户拥有账本写权限。
2. 同一账本存在两条交易和一个受管附件。

步骤：

1. 把同一附件引用到两条交易。
2. 删除第一条交易上的附件引用。
3. 删除第二条交易上的附件引用。
4. 执行物理清理任务。
5. 分别模拟大文件、哈希不匹配、扫描失败、配额不足和权限变化。

验收：

1. 删除一个引用只减少该引用关系，不影响另一条交易继续下载或查看附件。
2. 最后一个引用删除后附件进入 `pending_cleanup`，不立即无审计物理删除。
3. 物理清理验证引用计数、哈希、受管存储位置、保留策略和幂等键；成功后只保留墓碑、哈希摘要和审计。
4. 清理失败不得恢复已删除引用，也不得删除仍被引用的内容或产生悬空引用。
5. 大文件、哈希不匹配、扫描失败、配额不足和权限变化返回结构化错误，不暴露 PC 完整本地路径、旧来源路径或旧迁移诊断。
