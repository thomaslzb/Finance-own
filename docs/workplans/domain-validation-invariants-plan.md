# 领域校验与业务不变量需求计划

本文档承接 `three-client-requirements-analysis.md`、`command-form-lifecycle-plan.md`、`amount-currency-exchange-rate-plan.md`、`master-data-lifecycle-plan.md`、`account-device-ledger-membership-plan.md`、`date-time-period-semantics-plan.md`、`attachment-privacy-plan.md` 和 `investment-advanced-assets-calibration-plan.md`，定义 Finance Own 第一版三端输入、Rust PC 本地核心、.NET 云端 API、手机离线队列和导入迁移之间统一的领域校验与业务不变量边界。

## 1. 核心原则

1. Flutter UI 可以做提前提示，但不能成为唯一校验层。
2. PC 本地写入必须由 Rust 本地核心执行领域校验。
3. Web 在线写入和三端同步上传必须由 .NET API 执行领域校验。
4. 手机离线队列可以做轻量本地校验，但上传时必须重新经过云端校验。
5. 字段级错误必须可映射到表单、导入预览、批量结果或冲突解决界面。
6. 校验、错误、日志和审计不得泄露旧迁移证据或 PC 本地完整路径。

## 2. 校验责任边界

| 层 | 职责 | 不能做 |
| --- | --- | --- |
| Flutter PC | 表单提示、字段格式、交互状态 | 直接写 SQLite、绕过 Rust 校验 |
| Rust PC 本地核心 | 本地账本权威校验、SQLite 原子写入、旧迁移预览校验 | 上传旧迁移证据 |
| Flutter Web | 在线表单提示、字段错误展示 | 浏览器自行计算权威余额或绕过 API |
| .NET API | 云端权威校验、权限、版本、同步批次、冲突 | 信任客户端校验结果 |
| Flutter Mobile | 离线草稿轻量校验、队列状态 | 把草稿视为已提交事实 |
| PostgreSQL/SQLite | 外键、唯一性、事务和存储约束兜底 | 用数据库约束替代业务错误说明 |

规则：

1. UI 校验失败不发起写命令。
2. 领域校验失败不产生半写入。
3. 数据库约束失败必须映射为可解释领域错误或存储错误。
4. 任何跨端同步上传都必须重新校验账本、权限、对象版本和引用关系。

## 3. 通用对象不变量

所有可同步对象必须满足：

| 不变量 | 说明 |
| --- | --- |
| `ledger_id` 必填 | 对象只能属于单一账本 |
| 稳定对象 ID | 创建后跨端不变化 |
| 对象版本 | 修改、删除、恢复和冲突解决都生成新版本 |
| 来源端和设备 | 审计和冲突必须可追溯 |
| 幂等键 | 新增、导入提交、同步上传和高风险命令防重复 |
| 软删除或墓碑 | 删除不能依赖物理消失 |
| 脱敏错误 | 错误不得包含秘密、旧迁移证据或 PC 完整路径 |

多账本不变量：

1. 账户、分类、标签、往来方、附件、预算、提醒和交易不能跨账本引用。
2. 切换账本后，表单草稿、选择器和列表缓存必须限定当前账本。
3. 云端 API 不能只靠对象 ID 判断权限，必须同时校验 `ledger_id` 和成员角色。

## 4. 交易不变量

收入：

1. 金额必须大于零。
2. 账户必须属于当前账本且未关闭，历史编辑例外必须明确。
3. 分类必须属于当前账本且方向允许收入。
4. 账户币种和交易币种必须一致，或进入明确跨币种流程。

支出：

1. 金额必须大于零。
2. 页面和 API 都不得允许“支出 + 负数金额”形成双重反转。
3. 分类必须属于当前账本且方向允许支出。
4. 账户币种和交易币种必须一致，或进入明确跨币种流程。

转账：

1. 转出账户和转入账户都必须明确。
2. 转出账户和转入账户不能相同。
3. 同币种转账必须保存转出分录和转入分录。
4. 手续费必须使用独立费用分录。
5. 跨币种转账必须保存两侧金额、币种、汇率快照或明确缺汇率状态。

通用：

1. 交易写入必须原子提交，失败时交易头、分录、标签和附件引用一起回滚。
2. 修改金额、账户、币种或业务日期后必须重新校验余额、预算、报表和冲突影响。
3. 删除交易使用作废、撤销或墓碑，不做无审计硬删除。

## 5. 金额、币种和汇率不变量

1. 金额真相字段必须使用最小单位整数或明确精度的定点数。
2. SQLite、PostgreSQL、.NET DTO、Flutter DTO 和手机队列不得把财务金额作为 `float` 或 `double` 真相字段。
3. 币种必须有 `currency_code` 和 `minor_unit`。
4. 账户币种创建后不建议直接修改；如果修改，必须走高风险流程。
5. 历史交易引用的汇率快照不得原位覆盖。
6. 跨币种汇总必须先按同一折算口径折成本位币。
7. 缺汇率时不得直接把不同币种名义金额相加。

## 6. 日期、账期和周期不变量

1. 交易必须有 `business_date`。
2. `server_received_at`、`created_at` 和 `updated_at` 不得替代业务日期。
3. 报表期间必须使用闭区间 `date_from` 和 `date_to`。
4. 预算、提醒和计划按账本时区计算。
5. 手机离线草稿上传时不得被云端接收时间覆盖业务日期。
6. 修改业务日期、预算期间或提醒周期属于高风险修改。

## 7. 基础资料不变量

1. 账户、分类、标签、往来方、币种和汇率快照必须属于当前账本。
2. 被历史交易引用的基础资料不能物理删除。
3. 账户关闭后不应出现在常用记账选择器中，但历史记录继续展示。
4. 分类方向创建后不得静默改变。
5. 标签归档后历史记录继续展示标签名称。
6. 往来方归档后历史对象继续可读。

## 8. 权限不变量

1. 未登录 Web 和手机不能访问账本数据。
2. PC 本地未登录账本可以完整本地使用。
3. Viewer 不能新增、修改、删除、上传或解决冲突。
4. 最后一个 Owner 不能被移除或降级。
5. 设备撤销后刷新令牌和同步上传失效。
6. 权限错误不得触发自动覆盖、自动删除或自动丢弃用户输入。
7. 云端成员变化不得自动删除 PC 本地账本文件。

## 9. 同步和冲突不变量

1. 创建对象必须带幂等键。
2. 修改、删除、恢复和冲突解决必须带预期版本。
3. 版本不匹配不得静默覆盖。
4. 删除与修改并发必须进入显式冲突。
5. 字段级合并后必须重新执行领域校验。
6. 手机只展示冲突摘要，不承担复杂字段级合并。
7. 同步批次不能上传整个 SQLite 文件。
8. 旧 MoneyHome8 原始文件、旧路径、旧原始行、旧字段值、迁移审计、迁移报告和脱敏摘要不能进入同步批次。

## 10. 附件不变量

1. 附件必须绑定账本和业务对象。
2. 附件下载必须通过账本权限校验或短期授权。
3. 附件内容哈希用于完整性校验和去重参考。
4. 解除附件引用不等于立即物理删除内容。
5. 旧迁移附件默认只保存在 PC 本地；只有用户确认同步的新系统附件对象可上传。
6. 附件错误不得泄露 PC 完整路径或旧迁移证据。

## 11. 投资和高级资产不变量

1. 未校准的投资成本、收益率和复杂公式不得标记为已兼容。
2. `pending_calibration` 结果不能进入正式报表结论。
3. 投资输入修改后，依赖它的已校准结果必须失效或重新进入待校准状态。
4. 手工确认结果必须记录确认人、时间、字段和版本。
5. 旧投资迁移证据只保存在 PC 本地。

## 12. 导入、迁移和批量不变量

1. 导入预览不得直接写财务真相。
2. 导入提交必须带用户确认、幂等键和批次 ID。
3. 批量操作必须固定选择快照和每条对象版本。
4. 批量执行结果必须逐项返回成功、失败、跳过和冲突。
5. 迁移旧 MoneyHome8 数据只能在 PC 本地只读处理。
6. 迁移审计、迁移报告、脱敏摘要、旧路径和旧原始行不能上传云端。

## 13. 错误模型

领域校验错误必须支持：

| 字段 | 说明 |
| --- | --- |
| `error_code` | 稳定错误码 |
| `message_key` | 可本地化消息键 |
| `field_errors` | 字段级错误列表 |
| `object_errors` | 对象级错误列表 |
| `retryable` | 是否可重试 |
| `conflict_id` | 触发冲突时返回 |
| `diagnostic_id` | 脱敏诊断标识 |

错误分类：

| 错误 | 示例 |
| --- | --- |
| 字段格式错误 | 金额为空、日期非法 |
| 领域规则错误 | 分类方向不匹配、账户币种不匹配 |
| 引用错误 | 账户不存在、对象不属账本 |
| 权限错误 | Viewer 写入、设备撤销 |
| 版本错误 | expected_version 不匹配 |
| 存储错误 | SQLite 或 PostgreSQL 约束失败 |
| 校准错误 | 投资公式未校准 |

错误响应不得包含密码、令牌、PC 完整本地路径、旧 MoneyHome8 原始路径、旧原始行、旧字段值、迁移审计、迁移报告、脱敏摘要或 PC 机器环境诊断。

## 14. 验收要点

1. Flutter 端绕过前端校验提交非法金额时，Rust 或 .NET 仍拒绝。
2. Web Viewer 构造写入请求时，API 返回权限错误且不写入。
3. 手机离线草稿上传时，云端重新校验账户、分类、币种、业务日期、权限和版本。
4. 交易写入中途失败时不会留下半笔交易。
5. 批量操作中单项失败不会被误报为全量成功。
6. 字段级冲突合并后重新执行领域校验。
7. 数据库约束失败能映射成可解释错误或存储错误。
8. 旧迁移证据不会进入错误响应、同步批次、云端审计或日志。
9. 未校准投资结果不会进入正式报表。
10. 多账本之间不能互相引用基础资料、附件或交易对象。

## 15. 当前无需人工确认

本计划没有引入新的产品取舍；它把已确认的金额、日期、基础资料、权限、同步、附件、投资校准、导入迁移和旧迁移隐私边界统一成领域校验与业务不变量需求。
