# 债权债务、信用卡与摊还运行合同

本文把 B04 动态观察转换为 Rust 重构约束。旧 Delphi 窗体和帧名称只用于证据追溯，不作为 Rust 模块、表名或 API 边界。

## 领域模型

### Party

`Party` 表达债权人、债务人、平台、机构或其他交易对象，至少包含稳定 ID、类型、显示名称、状态和可选联系方式。显示名称允许重复和变更，不能用人员名称、银行名称或平台 URL 作为外键。

### DebtAgreement

`DebtAgreement` 表达借入、借出、应收、应付、预收、预付、垫付或待摊合同，至少包含：

- 稳定合同 ID、方向和合同类型；
- 对手方、币种、初始本金和业务日期；
- 还款或收款方式、频率、期数、到期规则和利率规则；
- 当前状态、剩余本金、版本和审计信息；
- 可选账户组、标签、附件和备注关系。

方向必须由显式枚举表达。应收和应付、借入和借出、预收和预付不能只通过金额正负号互相转换。

### RepaymentSchedule

`RepaymentSchedule` 是合同的版本化计划，包含期次、计划日期、计划本金、计划利息、计划手续费、状态和来源规则版本。实际收款或还款通过交易引用计划项，计划值与实际值不得混为同一字段。

计划重算必须保存旧版本、变更原因、生效日期和已执行期次保护。已入账期次不能被无痕覆盖；未执行期次可在影响预览后由新版本替代。

### CreditCardAccount

`CreditCardAccount` 至少包含账户身份、币种集合、账单日规则、还款日规则、透支额度、额度提醒、最低还款比例、年费和免年费规则。卡号是可选敏感字段，必须加密或受保护存储，不能进入普通日志、截图或搜索索引。

双币信用卡共享账户身份、账单规则和持有人，但每个币种分别维护额度、已出账、未出账、还款和估值信息。

### CreditStatement

`CreditStatement` 表达一个明确账期，保存开始日、结束日、账单日、还款日、币种、期初、流入、流出、账单金额、最低还款金额和状态。账单生成后仍需保存与交易的稳定关联，不能仅按日期范围即时猜测归属。

### InstallmentAgreement

信用卡分期协议至少保存申请日、首次记账日、分期本金、总期数、已入账期数、手续费规则、利息规则、每期金额、自动扣减规则、备注和状态。每期入账交易引用协议与期次，提前结清或取消只能影响尚未入账期次。

### NetLoanAccount

`NetLoanAccount` 保存平台身份、平台名称、URL、账户币种和账户状态；`NetLoanPosition` 保存投资对象、投资日期、本金、利率、期数、收款方式、频率和剩余金额。平台元数据、投资对象、收款计划和实际交易必须分层建模。

## 金额与方向

本金、利息、手续费、罚息、奖励和坏账损失使用独立金额字段和分录分类。任何对外展示的“合计”均为派生值，不得成为唯一业务事实。

金额使用整数最小货币单位。利率、比例和汇率使用受控十进制定点值，并保存精度、舍入规则、计息基数和适用日期。

还款总额至少等于本金、利息和手续费的明确组合。资金账户流出、信用卡欠款减少、利息费用和手续费费用必须在同一数据库事务中提交。

## 合同命令

创建借入、借出、应收、应付、预收、预付、垫付或待摊时，领域服务必须同时校验方向、对手方、币种、金额、日期、账户和计划规则。页面不得直接写合同余额或期次表。

收回、返还、提前返还、信用卡还款和网贷收回应引用原合同或计划项，并返回本金、利息、手续费和剩余本金的分解结果。

坏账是显式终止或减值命令。它需要记录损失金额、原因、日期、剩余本金处理和审计信息，不能通过删除合同或把余额改为零实现。

变更还款方式、利率、频率、期数或到期日需要目标版本匹配和影响预览。并发修改时拒绝旧版本提交，不能用最后写入者覆盖计划。

## 信用卡账单与还款

信用卡交易先进入未出账集合，再由确定的账单规则归入账单。账单日调整必须定义对当前账期、下一账期和历史账单的影响，不能只修改账户上的一个日期字段。

最低还款、利息、逾期费和超限费需要独立规则版本。Rust 版在未验证旧公式前不得声称金额兼容；迁移时应保留旧账单结果并允许重新计算对比。

信用卡还款必须指定资金来源、币种、本金、利息、手续费、日期和幂等键。超额还款、跨币种还款、自动购汇和余额为零时的处理需要显式产品规则。

## 分期与摊还

计划生成应一次性创建完整期次，并验证各期本金合计等于协议本金。手续费和利息可以按首期、每期或一次性支付，但模式必须枚举化，不能依赖界面文案解析。

等额本息、等额本金、先息后本和自定义计划需要独立计算策略。每种策略必须固定：

- 日计息或期计息口径；
- 首尾期天数；
- 小数精度和尾差归属；
- 提前还款后的重算方式；
- 逾期、展期和利率变更的生效规则。

未通过旧软件真实样本验证前，这些公式只能标记为 Rust 新实现设计，不能标记为旧版兼容。

## 预收、预付、垫付与待摊

预收和预付先形成合同余额，后续通过收入、支出、退款或结算交易逐步核销。核销交易必须引用来源合同，并阻止超额核销或重复核销。

垫付记录实际资金流出和待收回权利；报销或收回时分别影响资金账户与剩余垫付金额。垫付明细选择必须固定选择快照，避免报销期间明细发生变化。

待摊费用需要摊销计划、已摊金额和剩余金额。每期摊销生成普通费用交易并引用待摊合同；修改计划不能改写已入账费用。

## 网贷

网贷借出创建投资对象和收款计划。奖励、转让、坏账和收回是引用投资对象的独立命令，不得只在账户总余额上记一笔无来源交易。

“计划到期自动执行”必须由可恢复任务驱动，保存计划项、预期执行时间、幂等键、执行结果和重试状态。桌面 UI 打开与否不能决定计划是否被重复执行。

债权转让需要保存原投资对象、转让价款、剩余本金、收益或损失和受让关系。坏账后是否允许继续收回应由状态机明确控制。

## 查询投影

债权债务合同列表、交易明细、构成图、还款表和概况使用统一 `DebtQueryContext`，至少包含合同范围、方向、类型、状态、是否包含已完成、日期、币种、排序和数据版本。

信用卡账单统计、交易明细、分期列表和账户概况使用统一 `CreditQueryContext`。已出账、未出账、分期未入账和普通账户余额必须有明确排除或包含规则。

所有列表和图表返回查询条件、数据版本和估值快照。切换“仅债权”“仅债务”或“忽略已完成”只改变查询参数，不写业务事实。

## 审计、冲突与幂等

创建、修改、删除、坏账、提前结清、计划重算、账单日调整和批量执行必须记录操作者、时间、目标版本、输入摘要、影响范围和结果。

删除前检查交易、账单、计划、附件和审计引用。存在已入账交易时优先使用关闭、冲销或替代版本，而不是物理删除。

所有写命令携带幂等键和期望版本。进程重启或任务重试不得重复生成还款、分期入账或自动收款。

## 本地持久化建议

SQLite 至少需要：

- `parties`、`debt_agreements`、`debt_agreement_versions`；
- `repayment_schedules`、`repayment_schedule_items`、`repayment_allocations`；
- `credit_card_accounts`、`credit_card_currencies`、`credit_statements`；
- `installment_agreements`、`installment_items`；
- `net_loan_accounts`、`net_loan_positions`；
- 与 B03 总账共享的交易头、分录、附件、标签和审计表。

剩余本金、账单金额和图表可以使用可重建投影或缓存，但不能成为唯一事实。数据库事务、外键、唯一约束、检查约束和乐观版本必须覆盖跨表命令。

## 验证要求

Rust 实现进入兼容声明前，至少覆盖：

- 借入、借出、应收、应付、预收、预付、垫付和待摊的有效、无效、取消和回滚路径；
- 本金、利息、手续费、罚息、奖励和坏账的分录平衡；
- 部分还款、超额还款、提前结清、逾期、展期和利率变更；
- 信用卡账单归属、最低还款、分期生成、还款和双币处理；
- 网贷计划、自动执行、奖励、转让、坏账和收回；
- 计划版本、已执行期次保护、并发冲突和幂等重试；
- 合同列表、交易明细、还款表、账户概况和图表口径一致；
- 敏感卡号和联系方式不进入普通日志、截图或导出。
