# MoneyHome8 重构验收标准

本文档把当前已分析出的功能范围转成验收标准，用于后续判断 Rust 版本在不同阶段是否真正达标。

## 1. 验收层级

### Level A：架构到位

满足：

- 四大工作区结构明确
- 数据源分层明确
- 领域模型明确
- 关键读取器可用
- SQLite 十三版迁移、应用文件标识、事务边界、查询投影和 `53` 类实体覆盖契约可重复验证
- `tools/run-rust-checks.ps1 -Action all` 能用项目内工具链完成格式、编译和 Rust 测试
- `460/460` 个旧运行时窗体均能追溯到业务域、交互角色和目标数据流，未分类数为 `0`
- `2000` 个按窗体去重事件处理器均有代码入口、真实父类归属、同名候选或无 VMT 边界状态；当前基线为 `1951` 个已定位代码、`8` 个同名候选、`41` 个无代码定位
- `2000` 个旧事件均映射为 Rust 应用命令、展示状态或人工复核项；写命令不得由 UI 直接操作 SQLite
- 全部 `460` 个窗体、`1407` 个可交互控件和 `2000` 个事件均进入可追踪动态执行队列；每条运行记录必须包含入口、状态、命令结果、数据前后差异、证据和需求回填结论
- 新 UI 可合并旧窗体，但每个被合并或移除的旧窗体必须保留命令、字段、状态和数据流映射
- `460` 个旧窗体必须唯一映射到 `11` 个目标分区和 `40` 个页面族；`1407` 个交互控件、`2000` 个事件和 `502` 个高风险候选在归并前后计数守恒
- 投资共享页面必须用类型化扩展与策略覆盖 10 个旧投资子域，不能以删减资产类型或使用全字段可空对象换取页面收敛
- `37/37` 个嵌入视图必须从已确认父窗体场景形成保留或合并决策；AI 作为默认关闭的外部适配器，控制台仅在开发/诊断构建中启用；金额计算器作为共享技术组件验收
- AI 关闭或断网时全部本地财务功能仍可用；不得使用明文 HTTP、客户端硬编码秘密或未同意的数据上传

### Level B：核心可用

满足：

- 旧数据可读
- 账户、流水、预算、提醒、参考库可用
- 基础查询与检索可用

### Level C：高频业务可替代

满足：

- 记账
- 账户浏览
- 投资品选择
- 基础报表
- 预算提醒

### Level D：高兼容

满足：

- 大部分扩展投资域
- 分析与报表中心
- 导入导出
- 同步与通知

## 2. Phase 1 验收标准

### 2.1 数据层

- 能读取：
  - `mhlink.mdb`
  - `MoneyHome8.cache`
  - `Investment.cache`
- 能尝试接入：
  - `test.mh8`
  - `MoneyHome8.data` 解压库

验收口径：

- 对每个数据源都能返回清晰的结果类型：
  - `success`
  - `locked`
  - `permission_denied`
  - `auth_failed`
  - `not_supported_yet`

### 2.2 领域模型

- 至少建好：
  - `AccountGroup`
  - `Account`
  - `Category`
  - `Currency`
  - `Person`
  - `Transaction`
  - `Budget`
  - `Reminder`
  - `Quote`
  - `FeeRule`
  - `RateRule`

验收口径：

- 字段命名与现有模式假设基本一致
- 领域对象间关系清楚可序列化

### 2.3 UI 壳层

- 有四个工作区骨架：
  - 财务数据
  - 记账
  - 财务报表
  - 财务分析

验收口径：

- 工作区能独立切换
- 子导航可加载空状态
- 主菜单保留账簿、资料管理、计划提醒、财务工具、设置、帮助和退出七个顶层入口
- 应用支持无账簿、打开中、已打开、关闭中和失败恢复；正常关闭等待后台任务进入可恢复状态后释放账簿锁
- 最近账簿、窗口位置和导航历史保存在应用会话层，不得通过改写账簿交易或财务事实保存
- 启动画面和首次引导可跳过；初始化失败时进入可操作错误页，不得停留在无响应过渡画面

## 3. Phase 2 验收标准

### 3.1 账户中心

Rust 版应能：

- 展示账户树
- 按类型筛选
- 展示资产/负债/净资产汇总
- 支持按账户类型和自定义分组查看，并显示账户组小计
- 同一估值快照下净资产严格等于资产减负债
- 概况与账户中心读取同一汇总服务，相同账簿和估值时点的净资产不得出现 `0.01` 差异
- 新增或编辑账户组时支持名称、联系电话、联系方式、密码和备注；详细资料作为父编辑器草稿的一部分
- 详细资料窗按账户或账户组上下文展示适用字段，账户组模式不得暴露不适用的联网账号入口
- 二级详细资料确认只更新草稿，父窗确认时一次事务提交；关闭任一层后不得留下部分账户组或详细资料写入
- 空名称的 `未命名` 只能作为编辑期展示回退，最终保存必须执行空名称和同级重名规则
- 账户组名称在校验和唯一索引前执行首尾空白裁剪、Unicode 规范化和明确大小写规则；`CASH`、` CASH ` 及其它规范化等价值不得形成两个视觉重名组
- 精确或规范化重名必须在任何业务写入前返回字段级错误并保留完整父子草稿；数据库唯一索引兜底并发竞争
- 修改账户组时按稳定组 ID 和预期版本原位更新名称、联系电话、联系方式、受保护密码、备注和版本；二级详细资料确认不得单独持久化
- 账户组资料在同会话和冷启动后完整往返；密码只允许遮罩回显，明文不得进入普通日志、遥测、导出或崩溃报告
- 添加账户以稳定账户 ID 集合提交关系差异；成功后目标组、原组和选择器从同一版本刷新，不得创建余额事件或改写交易、标签、附件和账户主数据
- 代表样例把 `Cash-CNY 608.00` 加入新组后，新组小计为 `608.00`、原 `CASH` 小计为 `8,887.70`，资产/负债/净资产仍为 `8,540,196.43 / 1,444,589.25 / 7,095,607.18`，冷启动逐分一致
- 单账户修改组归属时，对话框按稳定账户 ID 加载当前关系，选择其它组只修改草稿；取消或标题栏关闭后原关系、组投影和文件业务状态保持
- 确定时以可空目标组 ID 和预期版本原子替换关系，并从同一版本刷新账户概况、左侧导航、原组、目标组和小计；`<无>` 表示解除关系，不是删除账户或创建特殊组
- 代表样例 `H-Current: Halifax -> CASH` 保存后同会话重开和冷启动都读回 `CASH`，余额 `795.57`、交易数 `558`、开户银行 `Halifax` 及资产/负债/净资产均不变
- 选择器内新增账户组是独立命令；创建成功后刷新候选并显式选中，取消、重名、权限失败或持久化失败不得污染账户关系草稿
- 空名称保存必须在业务写入前失败并提示用户；提示关闭后保留原草稿供继续修改
- 密码字段必须遮罩显示、受保护存储，且不得出现在日志、导出或错误消息中
- 支持按账户类型和按自定义分组两种投影；切换投影后资产、负债和净资产总计保持一致
- 自定义分组显示组级汇总，空组显示 `0.00`；组选中后可修改、删除和在组内新增账户
- 左侧账户树提供“设置[自定义]显示”，可按稳定账户 ID 控制显示、执行全选/反选并调整导航顺序；编辑期间只修改草稿
- 确定后导航树立即从同一偏好版本刷新并跨冷启动保持；取消或标题栏关闭不写入，保存不改变账户组归属、余额、交易或资产负债汇总
- 自定义导航偏好以整份版本化草稿原子提交；并发冲突或持久化失败不得留下部分顺序、部分显示状态或重复序号
- 查看方式可独立控制已结清债权债务、到期、隐藏和注销账户的可见性；切换只能改变查询投影，不得改变账户状态、余额或汇总，偏好可跨冷启动保持并支持一键恢复默认值
- 修改账户按稳定账户 ID 和预期版本加载名称、日期、币种、所有者、备注和附件关系；关闭编辑器不得写入，校验失败必须保留完整草稿
- 账户名称必填且按明确的账簿范围、账户类型范围、大小写、首尾空白和 Unicode 规范化规则唯一；空名称与重名在任何业务写入前返回字段级错误，数据库唯一索引兜底并发竞争
- 已建立现金账户的币种默认只读；币种变化必须使用显式迁移或新账户转移流程，不得通过普通编辑改变历史交易金额语义
- 有效资料保存只更新同一账户主数据和版本，不重建账户、余额事件、交易、标签、附件或账户组关系；名称和备注变化不得改变余额、组小计或资产负债汇总
- 保存后账户中心排序、账户选择器、流水、报表、提醒和搜索从同一账户版本刷新；代表样例 `Cash-CNY -> Codex-Cash-CNY-Edit` 保持余额 `608.00`、`CASH 9,495.70` 和全部汇总，冷启动后字段完整往返
- 账户资料并发冲突保留用户草稿并展示当前值；每次成功修改记录变更前后值、操作者、时间和原因，备注不得进入普通日志或遥测明文
- 隐藏、取消隐藏、注销和取消注销必须作用于同一账户 ID，并保存带操作者、时间、原因和预期版本的状态事件；确认取消不得写入，冷启动后状态一致
- 隐藏账户不得改写余额或交易，只通过统一查询策略控制账户、交易、报表、选择器和后台任务的参与范围；恢复隐藏后原历史立即重新关联显示
- 注销前必须展示余额、未完成交易和计划影响；提交后账户进入 `written_off` 而非删除，历史交易永久保留。非零余额必须通过显式可审计分录处理，禁止静默归零
- 非零余额注销必须在同一事务中创建 `account_writeoff_balance_clear` 等额清零事件并写入 `written_off` 状态；事件保存原余额、币种、估值、原因和注销操作 ID，账户组、净资产、交易明细和记录数从同一版本刷新
- 取消注销只恢复账户状态且不得删除清零事件；界面必须明确余额不会自动恢复。余额恢复使用引用原事件的独立冲销命令，生成反向分录并保留原注销审计
- 账户标签必须使用稳定标签 ID 和独立关系表建模；外层编辑器提交目标标签集合差异，新增关系与解除关系原子完成，重复提交幂等
- 从账户标签选择器新增标签时，标签主数据成功和账户关联成功是两个明确提交结果；新增成功但关联失败时保留标签并允许重试，不得显示为已关联
- 解除账户标签关系不得删除标签主数据；冷启动后账户关系和标签候选分别保持，标签操作不得改变余额、交易、账户状态、账户组或资产负债汇总
- 标签选择器支持过滤、多选和受控新增；取消外层编辑器不得写账户关系，名称唯一性、权限和并发冲突必须给出可恢复错误
- 删除账户组必须二次确认并展示受影响账户数量；在单事务中删除组和组专属详细资料、清除账户关联并写入审计，但必须保留账户、余额事件、交易、附件和标签，原成员进入“无账户组”投影，冷启动后账户 ID、余额、交易数和全局汇总保持
- 永久删除账户前按稳定账户 ID 和版本展示影响快照，至少包含收支、转账双腿、兑换、计划、附件、标签和其它关系的数量与金额；选择取消时业务数据、投影和文件写入均保持
- 永久删除账户必须与隐藏、注销分离；提交时原子处理账户业务可见性、关联事实、转账双腿、计划关系、索引和审计，版本冲突或任一步失败整体回滚，重复幂等请求不得再次删除
- 删除完成后从剩余事实统一重算对手账户、账户组、资产、负债、净资产和全历史记录。代表样例 `Cash-CNY` 应满足记录数 `2,189 -> 2,180`、移除流入 `26,845.50`、移除流出 `30,708.00`、净资产增加 `3,862.50`，并在冷启动后逐分一致
- 现金、活期、金融产品和第三方储值等普通开户向导必须先形成完整草稿，再由最终确认一次提交账户、期初余额和资金来源
- 第三方储值的支付宝、微信钱包、财付通和其它储值入口必须复用通用账户模型，并以显式提供方类型区分；旧窗体标题、默认名称、图标和菜单位置不得作为业务键
- 第三方储值两页向导必须校验名称并保持跨页草稿。资金来源为空且金额为零时不生成余额事件；资金来源为空且金额大于零时生成外部期初事件；选择真实资金账户时原子生成来源流出和储值账户流入
- 代表样例 `CodexRT41Wallet / 12.34 CNY / 资金来源<无>` 必须产生一个账户和一条余额调整流入，使记录数增加 `1`、资产和净资产各增加 `12.34`、负债不变，并在响应或刷新失败后可通过幂等结果查询确认原提交
- `TThirdDepositsAcctDlgFm` 对既有账户只允许原位修改名称、所有者、备注和创建日期，币种只读且余额只能通过交易或显式调整变化；取消零写入，资料保存不得新增财务记录
- 现金开户第一页默认名称、币种、所有者、备注和账户组，第二页默认业务日期与零余额；上一步和下一步必须保留完整草稿，标题栏关闭或取消后相同名称仍可重新使用且不得存在账户、余额事件或组关系
- 账户名称为空或与规范化唯一范围内既有账户/账户组冲突时，必须在进入余额页前返回字段级错误并保留草稿；数据库唯一约束负责并发兜底
- 代表样例 `CodexCashDirect-1512 / 12.34 CNY` 提交后，账户、备注、期初余额、资产和净资产必须在同一版本可查询，负债不变；冷启动结果逐分一致
- 开户提交使用幂等键并返回稳定账户 ID、版本和明确提交状态。提交成功后的投影刷新或客户端响应失败不得产生模糊提交；重试必须查询或返回原结果，不能创建第二个账户
- 新增账户类型目录必须以稳定 `AccountCapability` 和显式路由表分派创建策略；显示名称、菜单位置和旧窗体类名不得作为业务键。目录打开、取消、未知类型或目标加载失败均不得写账户事实
- 多个入口复用同一向导时必须传递明确模式参数并显示对应默认值；菜单关闭、窗口销毁和应用退出不得访问已释放的路由或菜单对象
- 一卡通、一折通等组合账户必须原子创建主账户和全部子账户；取消、校验失败或任一子账户写入失败时不得留下半成品
- 活期一本通首次开户必须原子创建稳定类型的组合容器、首个活期子账户、归属关系和期初事件；标题栏关闭后组名与子账户名均可重新使用，且不得存在孤立容器或子账户
- 组合容器不保存独立余额。代表样例 `CodexCurrentPass-1537 / CodexCurrentSub-1537 / 7.89 CNY` 必须满足组小计 `7.89`、子账户余额 `7.89`、余额调整流入 `7.89`、记录数 `1`，资产和净资产各增加 `7.89`、负债不变，并在冷启动后逐分一致
- 组名和子账户名分别执行必填与规范化唯一校验；既有账户名不得被子账户复用。组合提交返回容器 ID、子账户 ID、版本和幂等结果，刷新失败重试不得创建第二套组合
- 普通活期账户两页向导的翻页、上一步和字段校验只修改 `CurrentAccountDraft`；第二页标题栏关闭后名称、账户、组关系和期初事件均不得残留
- 普通活期账户最终确认必须原子创建账户、可选账户组关系、期初余额事件和可选资金平衡分录；无账户组不得创建占位实体，无资金来源必须按外部期初处理
- 代表样例 `CodexCurrent-1604 / 23.45 CNY` 必须在即时刷新和冷启动后保持账户余额 `23.45`、一条余额调整流入 `23.45`、记录数 `1`，资产和净资产各增加 `23.45`、负债不变；提交返回稳定 ID、版本和幂等结果
- 定期一本通四页向导的翻页、上一步、期限联动和自动续存切换只修改组合草稿；第四页关闭后组名、子账户名、组合关系、条款和期初事件均不得残留
- 定期利率目录按币种、存款类型、期限和生效日提供默认建议；用户确认后必须固化利率规则版本和利率快照，后续利率更新不得重算既有存单
- 代表样例 `1200.00 CNY / 整存整取 / 3个月 / 0.80% / 2026-08-01` 必须生成到期日 `2026-11-01`、到期本息 `1202.40`、一条余额调整流入 `1200.00` 和记录数 `1`；组小计、子账户余额、资产和净资产增量均为 `1200.00`，冷启动逐分一致
- 首次定期一本通开户必须以幂等事务原子创建组合容器、首个定期子账户、关系、条款快照、自动续存规则、期初事件和可选资金分录；任一步失败不得留下孤立对象
- 公共开户向导宿主没有独立业务入口、领域实体或持久化表；具体向导注入步骤、草稿、逐页校验和最终命令，宿主只管理标题、提示、当前页和按钮状态
- 下一步仅在当前页校验通过后切页；完成期间禁用重复提交，取消和标题栏关闭只丢弃未提交草稿。跨步骤错误必须返回目标步骤和字段，宿主切页并聚焦，不得吞掉领域错误
- 期初余额必须明确区分外部期初、既有资金账户转入和其它可追溯来源，资金账户转入时必须生成平衡分录

### 3.1.1 基础资料

Rust 版应能：

- 用显式路由表维护资料入口、默认类型和页面组件；入口重开及冷启动按默认类型初始化，普通类型切换不得写业务数据
- 金融产品工作区共享导航框架时，证券、开放式基金、货币基金、债券、贵金属、银行理财、期货、贵金属 TD 和证券交易费率必须装载各自查询与命令组件；切换后旧组件释放且新组件完整刷新
- `其它金融产品` 旧入口必须确定性迁移到货币基金兼容路由，不得创建同名重复主数据或依赖显示文案猜测类型
- 跨资料类型切换和标题栏关闭必须处理未提交草稿；没有草稿时立即返回，存在草稿时按子页面策略丢弃、阻断或确认，任何取消都不得写入
- 分类区分收入与支出方向并支持层级；系统预置分类可限制删除，但不得仅依赖界面禁用保护引用完整性
- 往来方保存名称、类型、性别、联系方式、地址和可选生日，并通过稳定 ID 被账户、交易和计划引用
- 人物生日必须保存公历/农历和原始年月日分量；机构拒绝生日，人物修改或删除不得留下孤立的日历生日副本
- 币种保存名称、代码、显示精度及内置/自定义来源；账簿本币通过独立唯一关系保存，不得和人民币报价锚点混为一列或一个字段
- 本币切换必须按账簿版本原子替换唯一关系并展示影响预览；代表样例 CNY 切换到 CHF 后立即刷新且冷启动保持，历史交易、冻结报表和既有汇率快照不得被无痕改写
- 内置币种的修改删除必须由领域规则阻断，不能只依赖菜单禁用；自定义币种保存需校验规范化代码唯一性，删除前检查全部业务引用
- 汇率保存日期、货币对、报价方向和十进制汇率；反向展示必须由同一记录确定性计算，禁止无版本覆盖历史
- 手工汇率窗体提交稳定的第一币种 ID、第二币种 ID、有效日期和明确 `scale=4` 的十进制定点汇率；报价说明必须由有序币种对派生，不能作为独立可编辑或持久化字段
- 手工汇率保存前依次校验有效日期、第一币种、第二币种、币种不同和汇率大于零；任一失败必须定位字段、保留草稿，并保证报价事实、当前牌价和估值投影零变化
- 币种列表的当前牌价与汇率历史必须读取同一有效报价版本；代表样例 `2026-07-29 USD/CNY 6.7894 -> 6.7895` 保存后两个投影立即一致，冷启动后仍一致
- 修改汇率必须按稳定报价 ID 和预期版本提交；取消或并发失败不得改变原记录，也不得只刷新一个页面投影
- 删除汇率必须显示货币对、日期和值并要求确认；选择否零写入，选择是删除最新报价后，当前牌价和历史首行必须同时回退到下一有效记录。代表样例回退为 `2026-07-28 / 6.7829`
- 没有剩余有效报价时必须返回明确缺失状态；不得缓存或继续使用已删除报价，也不得静默改写历史成交、冻结报表或已保存估值快照
- `按日期显示全部汇率` 与按币种显示时间序列只能改变查询范围；切换、日期无结果和返回原视图不得创建、修改或删除汇率事实
- 存款利率按币种、存款类型、期限、生效时间、来源和批次版本化；人民币年利率单元格校验通过并提交后列表即时刷新，冷启动必须恢复同一有效版本。旧参考值只能作为迁移证据，不能固化为 Rust 常量
- 存款年利率使用整数加显式 scale 的百分比协议；允许 `0%`，拒绝负数、超过 `100%` 和超过 `12` 位小数。无效输入必须保留草稿并返回字段级错误，不得复制旧版仅数字解析、静默回退和浮点乘 `10000` 取整的协议
- 手工利率编辑和在线更新必须共用校验与版本发布服务；在线批次先暂存后原子发布，网络、解析或部分来源失败不得清空上一有效版本，也不得回写已入账利息和冻结报表
- 删除或合并已被账户、交易、预算、计划引用的基础资料前必须展示影响并阻断悬空引用；取消后不得发生写入

### 3.2 记账

Rust 版应能：

- 录入收入
- 录入支出
- 录入转账
- 浏览流水
- 使用模板或计划的基础入口
- 按记录范围和日期范围筛选，并同时返回结果条数、流入、流出和差额
- 列表、合计、图表、导出和打印共享同一查询 DTO；流入减流出必须等于差额
- 未选择、单选和多选状态正确控制修改、删除、退款、附件和批量命令
- `全部记录` 与 `仅收支记录` 切换后，记录集合、列标题、条数和汇总必须一次刷新；仅收支模式不得混入转账等非收支活动
- 查找至少覆盖日期、活动类型、流入、流出、资产账户、标签和备注；查找下一个只移动选择，重新开始只重置游标
- 筛选至少覆盖账户、活动类型、关键字、标签、金额大于等于、小于等于和闭区间；再次打开可编辑当前条件，清空条件恢复默认查询
- 行投影展示原币金额、汇总使用本位币时，必须携带汇率快照和折算金额；不得在 UI 中使用不可追溯的临时汇率
- 同一账本版本、查询 DTO、排序和汇率快照重复执行时，记录集合和所有汇总必须逐分一致；筛选应用、清空和重新应用不得产生 `0.01` 漂移
- 分组模式允许按可见列分组且不改变交易真相；批量模式必须显式进入和退出，空选择时写命令禁用
- 修改交易时按交易类型打开对应编辑策略；转账保存原子提交交易头、两侧分录、手续费、标签和附件关系
- 账户选择必须提交稳定账户 ID；只存在显示文本、账户已关闭或候选版本已失效时，保存必须阻止且不得产生任何分录
- 账户选择器由宿主规格控制单账户/多账户、允许空值、允许内联新增、账户类型、状态范围和排除集合；搜索只能过滤同一候选快照，不能绕过宿主范围
- 单账户选择立即返回稳定账户引用；多账户选择必须返回逐项 `账户 ID + 金额` 分配，零金额、重复账户、金额精度错误或合计不符合宿主规则时不得回填
- `<无>` 表示显式空引用，不得创建特殊账户；内联新增账户作为独立命令提交，取消或失败返回原选择草稿，成功后刷新候选并显式选中
- 同一转账的来源/目标相等、跨币种策略、余额、账户状态和提交版本由转账命令校验；选择器允许显示候选不等于该组合可以保存
- 同币种转账本金 `50.00`、来源账户手续费 `1.00` 后，来源余额减少 `51.00`、目标余额增加 `50.00`、净资产减少 `1.00`；来源流水、全局财务记录和冷启动重建必须逐分一致
- 普通收入和普通支出复用统一字段组件，至少包含收支项目、金额、收支账户、标签、日期、备注和附件；交易方向明确控制标题、金额语义和余额影响
- 编辑器分派依据交易种类或用户发起的业务动作，不得仅根据 `职业工资` 等收支项目名称推断专用编辑器
- 收支字段组件只更新父级草稿；父级取消不写入，父级保存原子提交交易头、单侧账户分录、项目、标签、备注和附件关系
- 日常收入与支出都接收正金额；`其它收入 3.00 CNY` 和 `教育培训支出 2.00 CNY` 的账户余额、CASH 分组、全局单边流入/流出及冷启动重建必须逐分一致
- 分类选择提交稳定分类 ID，交易头保存显式 `transaction_kind`；分类被改名、停用、删除或改变方向时，旧草稿提交必须重新校验并返回可定位错误
- 分类选择器由 `CategorySelectionSpec` 控制允许方向、默认方向、跨方向搜索、内联新增、管理入口、隐藏/系统项目、父项可选性和查询版本；宿主不得自行拼接另一套分类过滤规则
- 搜索结果必须返回稳定分类 ID、方向、层级路径和版本；同一搜索可同时出现收入和支出结果，空搜索结果不得回退到全部候选或创建占位分类
- 选择收入或支出分类后，父窗可更新标题和草稿方向，但最终交易种类必须显式保存；失焦、关闭、切换页签或无结果搜索不得改变原宿主分类
- 从选择器内联新增分类时默认方向必须继承当前上下文；若用户改变方向应显式确认。取消或失败返回原选择器和宿主草稿，成功后刷新候选并选中新分类
- 分类管理入口只有在宿主规格允许时显示；进入管理页和返回时必须保留宿主脏草稿，并对管理期间发生的改名、停用、删除和方向变化执行版本失效处理
- 标签选择器由 `TagSelectionSpec` 控制是否允许空集合、多选、内联新增、隐藏标签、最大选择数量、候选作用域、查询版本和失焦策略；宿主不得用分号字符串代替稳定标签引用
- 标签选择结果必须是有序且去重的 `TagRef` 集合；过滤只改变同一候选快照的投影，无匹配返回空集合，清空过滤不得丢失已选草稿
- 显式确定或宿主允许的失焦提交只回填父级草稿，不得直接写交易、账户或其它对象关系；父级取消必须保持业务关系零写入
- 内联新增标签是独立主数据命令；整体空输入在写入前阻断。批量输入过滤空分段、合并批次内重复，并返回 `created` 与 `existing` 标签引用；全部名称已存在时返回 `no_new_tags`。批量新增成功后必须返回全部新建标签并明确默认选中策略，不得静默只关联第一项
- 父级取消或关系提交失败不得删除已成功创建的标签；账户标签、交易标签及其它对象关系分别以稳定对象 ID、目标标签 ID 集合和预期版本原子提交差异
- 收支项目名称为空时必须在写入前阻止；规范化后的同账簿同方向同级名称必须唯一，失败时保留草稿并给出可定位错误
- 二级收支项目只能选择同方向父级，且不得形成自引用或层级环；保存后列表和冷启动必须按稳定 ID 重建一致的一级/二级关系
- `保存并新添` 每次只提交当前一个收支项目；成功后编辑器保持打开、保留方向并清空名称和父级，后续普通保存不得覆盖前一条记录
- 分类排序模式只能在 `use_frequency` 与 `manual` 中二选一；使用量模式下顺序编辑命令必须禁用，自定义模式下必须启用
- 自定义顺序拖动只更新预览；点击确定后按稳定分类 ID 和分类树版本原子提交，冷启动必须重建相同顺序。取消、冲突或写入失败不得留下部分排序
- 显示隐藏类别和显示系统类别只改变列表查询条件，不得改写分类记录、方向、父级或交易引用；系统预置分类必须由能力标志限制修改和删除
- 常用备注空白或规范化后为空时必须阻止保存并保留草稿；有效新增后列表立即出现，修改必须按稳定备注 ID 原位更新而不是新增重复对象
- 删除常用备注必须显式确认；选择否不写入，选择是后冷启动不得恢复已删除对象。历史交易保存备注快照，主档修改或删除不得回写历史记录
- 顶部记账入口按业务域注册命令并打开对应编辑器；普通收支、工资、存款、取款和转账不得错误落入同一个通用表单
- “保存并继续”每次只提交一个完整交易命令；成功后按明确规则重置草稿，失败时保留输入和错误定位，不得部分清空
- 批量记账和批量转账把模板视为版本化草稿，不得因模板修改回写历史交易；零金额行必须明确标记为跳过
- 批量生成前展示有效、跳过和错误行；默认整批校验并原子提交，若支持仅提交有效行，必须由用户显式选择并返回逐行结果
- 批量生成使用稳定幂等键；重复点击、进程重试或崩溃恢复不得重复生成收支、转账或手续费分录
- 批量转账的手续费显式从转出账户扣除并单独入账；跨币种行同时保存两侧金额、报价方向、汇率和舍入差异
- 分期协议、完整期次计划和实际入账交易分层保存；修改费率、期数或首期日期前展示重算影响，已入账期次不得无痕覆盖
- 复制或粘贴交易必须生成新交易 ID 并保存来源 ID；粘贴到今天只改变业务日期，同日排序只改变稳定显示顺序键
- 修改、删除、退款、改变类型、转为计划和批量设置必须校验目标版本并写审计事件；冲突项不得按刷新后的可见行静默重试
- 概况柱状图、分类构成图、账户流水、财务记录和底部汇总共享日期、转账排除、退款抵减、币种折算和估值快照口径
- 工资收入支持多条收入项目、普通扣款和按社保账户拆分的个人/公司缴费；目标实收现金逐分等于收入合计减普通扣款和个人缴费，社保账户权益增加逐分等于个人缴费加公司缴费，公司缴费不得混入收入账户现金
- 收款账户、收入/扣款分类、社保人员和社保账户选择器必须返回稳定 ID 与当前版本；只写显示文字不得被视为有效选择。缺少有效收入项目时必须在任何持久化前阻止提交；选择社保人员后必须按人员 ID 条件加载并显示社保账户、个人缴费和公司缴费编辑区
- 工资头、收入/扣款/社保组成、实收账户流入、社保账户权益、标签、附件、税务计算快照和审计必须单事务提交；任一失败不得只留下实收收入或孤立社保分录
- 个人所得税计算器必须保存税制版本、输入快照、舍入规则和结果；取消不得改变草稿，确认只显式回填草稿，不得绕过工资提交直接入账
- 取款支持取款账户、资金去向、可用资金、全部取完、手续费和手续费支出账户；全部取完基于同一余额快照计算
- 取款本金、目标入账和手续费在同一事务内提交；验收样例 `顺德农行 -> Cash-CNY` 本金 `4.00 CNY`、来源手续费 `1.00 CNY` 必须产生来源 `-5.00`、目标 `+4.00`、净资产 `-1.00`，并在全局投影显示流入 `4.00`/流出 `5.00`
- 存款支持存款账户、资金来源和金额；存取款均以双边分录原子提交，任一侧失败时整体回滚
- 定期账户与存单是不同生命周期对象；账户资料、存单本金、期限、利率、起止日期和资金来源必须原子创建，取消或任一写入失败不得留下半成品
- 定期续存必须关闭原周期并创建可追踪的新周期；自动续存和手工续存使用稳定幂等键，重复执行不得重复确认本金或利息
- 正常到期和提前支取使用不同事件类型，按同一存单版本计算本金、利息、罚息或补息，并原子更新存单状态、资金分录和收益
- 余额调整显示基于稳定账户、可选币种、有效日期和余额版本的账面余额，差额逐分等于真实余额减账面余额，并通过显式调整事件和平衡分录而非直接覆盖余额完成修正

## 4. Phase 3 验收标准

### 4.1 投资域

Rust 版应能至少覆盖：

- 证券
- 开放式基金
- 外汇
- 定期与理财
- 债权债务

扩展目标：

- 债券
- 期货
- 黄金
- 贵金属
- 融资融券
- 保险
- 社保
- 重大资产

验收口径：

- 投资一览按账户分组显示名称、数量、均价、成本、市值、浮动盈亏和涨幅
- 列表、底部合计和投资构成图共享同一带估值时间的持仓快照
- 对任一快照，当前市值减投入成本必须等于浮动盈亏，金额精度和币种换算规则可追踪
- 投资构成图至少支持按当前市值和按持仓成本两种模式；切换模式只改变聚合指标，不刷新账簿版本、行情批次或汇率批次
- 任一构成图模式的全部图例金额合计必须逐分等于同一快照中对应的页面底部合计
- 历史盈亏行必须关联关闭交易、来源成本批次和分摊费用；盈利合计、亏损合计、总盈亏、列表、导出和打印共享同一查询结果
- 市值构成和变动明确区分今日市值、昨日市值、价格涨跌与当日净交易影响；缺失昨日行情或分母为零时按显式空值规则处理
- 行情更新覆盖成功、离线、失败、取消和重试，不得用部分刷新结果覆盖完整可用快照
- 最新行情覆盖股票、港股、美股、开放式基金、贵金属、期货、外汇、存款利率和证券交易费率九类来源；存款利率更新完成后必须记录批次接收数、更新数和上次更新时间。历史行情只覆盖前七类价格源并支持日期区间，不得错误展示存款利率或证券交易费率历史下载
- 证券全局费率必须按市场、证券类型和不可变模板版本保存，字段明确区分 `%`、`‰` 和带币种固定金额；手工提交后冷启动应恢复同一版本

- 选择资金账户缴费 `10.00` 时，保险事件和资金流出必须原子提交并稳定关联；期初 `100.00` 的支付账户余额变为 `90.00`，累计保费变为 `10.00`，现金价值保持 `0.00`，保险侧与资金侧均可追溯对方
- 保费返还 `4.00` 时，返还事件和领取账户流入必须原子提交并稳定关联；累计缴费保持 `10.00`、累计领取变为 `4.00`、记录数变为 `2`、现金价值保持 `0.00`，零期初领取账户余额变为 `4.00`，不得用负保费冲减累计缴费
- 保险分红 `2.00` 时，分红事件和领取账户流入必须原子提交并稳定关联；累计缴费保持 `10.00`、累计领取变为 `2.00`、记录数变为 `2`、现金价值保持 `0.00`，零期初领取账户余额变为 `2.00`；财务记录投影同一笔“保险分红”收入，不得复制第二份资金事实
- 退保 `5.00` 且不终止账户时，`surrender` 事件记录 `finish_account=false`，到账资金事实与事件原子关联；保单保持 `active`、账户继续可见，累计缴费保持 `10.00`、累计领取变为 `5.00`、记录数变为 `2`、现金价值保持 `0.00`
- 退保 `5.00` 且选择同时终止账户时，`surrender` 事件、到账账户流入 `5.00`、保单 `surrendered` 状态和账户关闭标记必须原子提交；原支付账户保持 `90.00`，保单退出活动账户查询，但稳定 ID 和历史事件保留，财务记录只能投影同一资金交易
- 未终止退保后仍可按活动保单规则执行后续缴费、返还、分红、再次退保或最终终止；命令权限不得只根据是否存在历史 `surrender` 事件判断
- 退保提交后所有绑定当前保单的账户列表、交易、汇总、现金价值和概况组件必须在同一提交版本清除选择或重新查询，不得像旧程序一样继续显示终止前的缴费行和旧汇总
- 社保参保人必须引用人员主数据 ID，不能只保存显示文本；总账户创建时至少选择养老、工伤、失业、医疗、生育或住房公积金之一
- 六类社保子账户分别保存期初余额和后续事件，但总余额必须逐分等于同一快照中全部有效子账户余额之和；创建和删除整组全成或全败
- 社保开户同时创建自动账户组、所选子账户和期初余额事件；删除最后一个子账户时必须按产品规则自动清理空组或明确保留为可管理对象，不得形成不可见孤立组
- 保险交易明细统一投影缴费、领取、分红和退保，并在同一快照展示现金价值、缴费总额、领取总额与记录数；空账户汇总均为零
- 现金价值按保单和日期保存版本化快照；已有同日 `0.00` 时添加 `8.00` 必须执行单行 upsert，再修改为 `9.00` 后账户余额、现金价值汇总和趋势图同步为 `9.00`，保险交易、缴费/领取汇总和记录数保持不变
- 删除唯一现金价值快照后，快照表为空，当前现金价值、账户余额、交易页汇总、趋势图和资产投影必须在同一提交版本统一为 `0.00`；保险交易、缴费/领取汇总和记录数保持不变，重新启动后仍为 `0.00`
- 存在 `2026-07-30 / 11.00` 和 `2026-07-31 / 13.00` 时删除最新快照，当前现金价值、账户余额、交易页汇总、趋势图和资产投影必须统一回退为 `11.00`，重新启动后仍为 `11.00`，不得回填已删除的 `13.00`
- 存在相同两日期快照时删除较早的 `11.00`，当前现金价值、账户余额、交易页汇总、趋势图和资产投影必须保持 `13.00`，重启后仍为 `13.00`；保险交易、缴费/领取汇总和记录数保持不变
- 存在历史 `2026-07-29 / 7.00`、当前 `2026-07-30 / 11.00` 和未来 `2026-08-01 / 15.00` 时，以 `as_of_date=2026-07-31` 查询必须返回 `11.00`；列表和完整趋势图保留三条快照，但余额、交易汇总、资产和报表不得提前计入 `15.00`
- 现金价值快照按 `[effective_from, effective_to_exclusive)` 生效；重新启动后使用相同 `as_of_date` 必须得到相同结果，不得因未来快照存在而归零，也不得读取脱离快照事实和查询日的当前值缓存
- 现金价值负数和空值必须阻止提交并返回字段级错误；数据库同样拒绝 `value_minor < 0`，不得静默夹取为零
- 金额按币种小数位和显式舍入模式转换为整数最小单位；人民币验收包含 `1.234 -> 1.23`、`1.235 -> 1.24`，并验证 `99,999,999,999.99` 可以精确保存或被明确上限拒绝，不能进位为 `100,000,000,000.00`
- 余额、资产、报表和趋势图聚合使用受检整数运算；`9,999,999,999.99` 在现金价值页、交易汇总、账户中心和重启后必须逐分一致
- 应用或账簿业务日期来源、跨月/跨年/时区、其它币种精度、科学计数法、千分位、本地化小数分隔符、精确上限、聚合溢出、并发版本冲突和失败回滚必须单独验收；保费收支统计开关的影响范围须有明确且可回溯的规则
- 社保现金价值命令按保费收支统计开关和产品类型启用；关闭时显示明确原因并引导到账户概况，不能执行隐藏写入
- 商业保险和社保可共享工作区、交易明细、现金价值和概况组件，但命令启用、字段和写入规则按产品类型分派，不得因旧窗体标题相同而串用业务逻辑

### 4.2 报表中心

Rust 版应至少支持：

- 全部 `25` 张已确认业务报表，并保留旧窗体到合并后报表定义的追溯关系
- 日常收支分组、明细、账户、标签、两期对比、月份矩阵、趋势、月平均和现金流
- 资产负债、可用资金、债权债务和资产/负债/净资产月趋势
- 投资、证券、开放式基金、外汇、网贷和银行理财的表格、趋势或明确空结果
- 公共日期与七类筛选条件；恢复默认、全选和反选必须可测试
- 查询成功后才能导出和打印；表格、图表、导出和打印必须共享同一查询快照
- 收益率与年化收益率按可版本化公式计算，并可追踪期间现金流和估值快照

### 4.3 财务分析中心

Rust 版应至少支持：

- 财务预算
- 财务诊断支持账簿统计和持久化手工输入两种来源，保存输入来源、修改时间和计算快照
- 财务诊断覆盖储蓄性支出占比、投资与净资产比率、资产负债率、紧急备用金系数、保费比率、财务自由度、储蓄率、工资收入占比、支出比率、消费率、贷款压力比率和失业保障系数
- 诊断年总支出按消费、还款和保费合计并排除储蓄支出；月收入/月支出按年值除以 `12` 后舍入到 `4` 位小数；资产性质切换只重分类流动/投资资产，不改变余额和净资产
- 指标结果展示公式、输入值、当前值、参考区间、健康状态和建议文案，并记录公式与阈值版本
- 财务目标
- 财务规划先保存家庭成员与寿命区间，再建立从当前年至家庭寿命终点的年度序列；支持无配偶和有配偶分支
- 当前财务情况覆盖工资、资产/其它收入、日常/调整/资产/其它支出、现金与存款、投资资产、债权债务、商业保险、资产增长和通胀
- 未来事件覆盖退休、普通重大支出、教育和资产购置；资产购置支持一次性付款、分期首付/期数/年利率/月供及购置后收入和支出
- 零增长样例中，年工资 `120000`、家庭年日常支出 `60000` 必须产生每年 `60000` 的净现金流增量，并在冷启动后保持相同年度结果
- 规划结果保留逐年数值、输入快照、账户/估值快照、公式版本和计算时间；图表缩放与健康文案不得替代可审计结果
- 目标名称、起止日期、目标金额、账户范围、初始值、标准进度和实际进度；初始值允许为负数
- 创建目标时保存初始总值、估值时间和逐账户输入的完整快照，余额或市值变化不得反向覆盖该基线
- 标准进度必须记录公式版本并可由起始日期、目标日期、目标金额和初始值重算；旧程序的期间内插值公式在动态校准完成前不得标记为已兼容
- 规划清除和目标删除均需确认，完成后不保留临时记录

## 5. Phase 4 验收标准

### 5.1 导入导出

应支持：

- 整账簿 21 类数据集的选择性导入与导出
- 来源选择、原始数据、规范化候选、逐行错误和选中提交
- 旧版交换读取器支持 `GB2312`/代码页 936、CRLF、无 BOM、`INOUTDATA VERSION=1.21`，未知数据段和字段返回可审计警告或错误
- 导入批次、来源哈希、业务指纹和重复检测；同一文件重复导入不得静默复制交易
- “删除并覆盖”明确账户、日期和数据集范围，执行前显示影响数量并自动备份
- 打开文件和生成预览不得修改主账簿；取消预览后数据库、余额、记录数和标签关系保持不变
- 无效 XML、编码错误、字段错误和适配器异常不得使进程崩溃；提交失败时批次、交易、持仓、费用和资金分录整体回滚
- 交割单 12 类交易、10 字段、制表符/空格/自定义分隔符、列头/列序号映射和含费口径
- 交割单预览、批量修改、申购关联以及投资成交/费用/资金分录的单事务提交
- 财务记录与报表导出共享屏幕查询 DTO；筛选变化后导出禁用，刷新成功后内容与合计一致
- HTML/XLS 导出成功以文件原子落盘和可重新读取为准；文件选择器取消、路径不可写或序列化失败必须分别返回取消或失败，不得统一提示成功
- 通用旧交换格式只有完成成功回导、重复检测、覆盖范围和结果比对后才能标记兼容；仅能导出或只能预览不算兼容完成

备份、还原与附件应支持：

- 使用 SQLite Online Backup API 或 `VACUUM INTO` 生成一致性快照，不复制活动数据库文件
- 完整性检查、文件哈希、模式版本、保留数量、压缩策略和附件包含策略可追踪
- 备份名称不能为空，扩展名由格式策略统一生成；目标已存在时必须显示规范化完整路径并显式确认覆盖，选择取消或“否”不得创建、截断或改写目标文件
- 备份运行中只写同目录临时文件；数据库、附件和清单全部校验成功后原子改名为最终文件，不能以最终文件已出现替代完成状态
- 旧 `.mh8k` 仅作为隔离的迁移输入；当前样本为加密 7z 且内部单条 `BOOK`，旧程序自身覆盖还原和冷启动成功不等于 Rust 兼容，只有 Rust 端完成解密、还原到新账簿、业务数据/附件/设置比对后才能标记兼容
- 还原默认新建账簿；覆盖还原执行前自动备份，失败时原账簿仍可打开
- 备份目标与活动 SQLite 文件相同时拒绝执行；备份完成后校验完整性、哈希和模式版本
- 附件保存受管副本、相对路径、SHA-256、MIME 和原文件名；移动整个账簿目录后仍可打开
- 附件解除关系与物理删除分离，仍有引用时不得删除内容文件
- 账户附件空态只启用添加；添加完成后文件名、预览、打开附件、打开文件夹、动态文件菜单和账户行附件计数从同一提交版本启用，关闭管理窗不撤销已提交附件
- 添加附件先在受管卷写暂存文件并校验 SHA-256，再原子提交附件元数据与业务关系并发布最终相对路径；文件复制、数据库提交或改名失败不得留下可见关系、孤立内容或未清理暂存
- 打开附件和预览必须读取受管副本而不是源路径；源文件被移动或删除后仍可用。未知 MIME、损坏内容或可执行文件不得自动预览，调用外部程序前展示明确文件信息
- 删除选中的附件必须确认；选择否时关系、文件、计数和账簿版本保持，选择是先解除关系，仅最后引用删除内容与空目录，重复提交幂等
- 删除提交后账户行计数、动态菜单、管理窗、账户概况和搜索投影必须立即一致，不得复制旧版需要冷启动才清除 `1个附件` 的陈旧状态
- 启动一致性检查报告元数据缺文件、孤立文件、哈希不匹配、越界相对路径和临时文件；备份还原清单同时校验附件文件数、关系数和逐文件哈希
- 新建账簿拒绝覆盖现有文件，先在同目录完成临时库迁移和完整性检查，再原子改名并切换上下文
- 结算执行前显示截止日、影响摘要和恢复点；完整历史默认仍可查询，同一范围不得重复结转
- 恢复点必须先于活动账簿写入完成并通过清单、哈希和可恢复性校验；提交后生成可审计 `settlement_batch` 和按账户/币种/标的拆分的期初投影
- 旧版真实样本会把原记录重写为同日余额调整并保持账户汇总；Rust 版不得要求还原外部备份才能查看完整历史，原交易必须继续在线可查询
- 账簿密码修改验证旧密码和两次新密码，通过临时副本、完整性检查和原子替换避免半加密状态
- 清除账簿密码必须是显式命令，要求旧密码和确认；不得依赖两个空新密码字段隐式触发
- 受保护账簿只有正确密码才能建立数据库会话；空值或错误密码保持锁定并受控退避，取消返回可操作的无账簿外壳
- 密码、派生密钥和秘密输入不得进入日志、截图、崩溃报告、遥测、剪贴板或 UI 自动化树
- 系统设置区分设备级、应用用户级、账簿级和授权级作用域；取消不提交，秘密进入操作系统安全存储
- 快捷键保存前检测重复、系统保留键和老板键冲突；全局热键注册失败时保留原配置
- 授权服务不得读取或上传账簿内容；序列号、保护信息、通行证和用户资料不得进入日志、截图、遥测或账簿备份

预算应支持：

- 创建命令原子保存预算名称、频率和分类范围；分类选择取消或失败不得留下有效半成品预算
- 预算额度按预算、期间、稳定分类 ID 和币种保存正的最小货币单位；收入/支出方向使用显式字段，不依赖金额正负
- 实际金额只从交易事实按业务日期、方向、分类层级、状态和汇率快照重建，不保存第二套不可追溯的已用值
- 月度执行率在预算大于零时按 `actual / budget * 100` 四舍五入为整数且不封顶；预算和实际均为零显示 `0%`，预算为零而实际大于零显示兼容值 `100%`
- 最近 12 个月导入以执行日前一个完整月份为结束点，读取连续 12 个完整月份，并按月份编号映射到目标预算年度
- 导入提交前必须展示来源年月、目标年月、旧额度和新额度；确认后原子替换目标范围并保存导入批次，失败时原额度保持
- 分类范围变更提交前展示受影响月份和额度；兼容旧版时移除分类删除其全部期间额度，重新加入从零初始化，不得伪装成可逆隐藏
- 收入和支出额度可共用编辑网格，但列表必须分别展示预算总收入和预算总支出；净额作为独立派生值显示，不得覆盖两侧总额
- 正常退出和冷启动后，预算名称、分类范围、十二个月额度及由交易事实重建的实际/执行率投影逐分一致

### 5.2 同步与通知

应支持：

- 用户登录/注册骨架
- 双向合并与单向上传两种模式，双向为默认
- 未同意用户条款时禁用开始同步；选择单向上传时明确提示远端覆盖范围和不可逆影响
- 关闭账簿自动同步具备超时、取消和明确结果，不得无限阻塞账簿关闭
- 同步批次、游标、对象结果、冲突、删除墓碑、重试和取消状态
- 同步重置必须创建新的同步代际并明确指定当前本地账簿为真相；其它设备只能显式回退到该代际，不能把旧代际未同步修改静默合并或覆盖回来
- 本地 SQLite 始终独立可写，断网或旧服务失败不得阻塞本地记账
- 远端 DTO 通过映射层进入领域命令，不得直接覆盖核心表或计算余额
- 同步凭据保存到操作系统安全凭据库，账簿、日志、截图、崩溃报告和 UI 自动化树均不得暴露明文
- 所有新同步与通知通信必须使用 HTTPS；旧 HTTP 服务只能通过默认关闭、显式告警的隔离适配器接入
- 预算/提醒/持仓/资产负债通知链路

计划、预测和账户生命周期还必须满足：

- 计划定义与每次应发生实例分开保存；实例至少记录应发生日、金额规则、自动或人工批准、待处理/已生成/已匹配/已跳过状态和最终交易 ID
- 金额规则支持精确值、近似值和区间值；匹配窗口、候选原因和人工选择必须可审计，不能只凭金额和日期静默绑定
- 从历史交易创建计划、识别周期模式或应用规则时，生成的是可审查草稿；规则不得直接改写已过账交易
- 现金流预测从当前余额、未完成计划实例和明确假设即时生成；预测表格、图表和导出共享同一查询快照，预测值不得写入账户余额
- 关闭账户必须显式处理非零余额，并原子提交余额转移或清零业务事件、关闭状态和审计；关闭后历史可查且允许重开，重开不得自动撤销关闭时的资金事件
- 永久删除、关闭、注销和隐藏是四种不同命令；批量操作和导入重复检测必须逐项返回结果，不能用单个成功提示掩盖部分失败

### 5.3 旧格式兼容

达到如下任一即可视为阶段性达标：

- 旧账本只读导入稳定
- 或旧账本直接读取稳定

不要求：

- 当前阶段必须原位写回旧 `mh8`
