# 普通提醒与财务日历运行合同

本文档记录 MoneyHome8 普通提醒在“今日提醒”和财务日历中的动态投影行为，并把已验证事实转换为 Rust 重构约束。旧版的两个页面采用不同口径：今日提醒按发生实例和提前资格窗口推进，财务日历则把仍活动的普通提醒定义投影在定义开始日。

## 1. 验证边界

- 目标程序：`C:\Program Files (x86)\MoneyWise\MoneyHome8\Program\MoneyHome8.exe`
- 唯一可写账簿：`C:\DCG-SZ\IT Manage\Private\Personal-Docs\test.mh8`
- 一次性提醒：`CodexRT15CalendarReminder`，日期 `2026-08-03`、一次性、提前 `3` 天。
- 未来重复提醒：`CodexRT15FutureDaily`，开始 `2026-08-04`、每天、共 `2` 次、结束 `2026-08-05`、提前 `3` 天。
- 本轮只创建、跳过并删除上述临时普通提醒；没有修改交易、日记、人物生日或历史提醒。
- 重复提醒在首次跳过后完成一次完整冷启动复核，排除了单纯页面缓存造成日历日期不迁移的可能。
- 最终账簿恢复到长度 `18,669,568`、SHA-256 `D8E4AE302231A7A9B99B06D28C4D83500F8CD32D95F003814039E91EB0E165AC`；MoneyHome8 进程、`~$test*` 和 `test001*` 均为 `0`。

## 2. 已验证交互

### 2.1 定义保存与今日提醒资格

- 普通提醒编辑器的默认日期为当前业务日，默认重复为一次性，默认提前量为 `3` 天。
- `CodexRT15FutureDaily` 保存后，计划列表显示开始日 `2026-08-04`、结束日 `2026-08-05`、下次日期 `2026-08-04` 和执行中状态。
- 在业务日 `2026-08-03`，今日提醒已经显示第一期 `2026-08-04`，相对文案为“1天后”。这证明提前量决定今日提醒的资格窗口，而展示日期仍是实例的实际发生日。
- 普通提醒实例执行禁用、跳过启用；命令能力属于当前实例，不能由“提醒”文本统一推断。

### 2.2 旧财务日历按定义开始日投影

- 在提前资格日 `2026-08-03`，财务日历没有 `CodexRT15FutureDaily` 图标或摘要。
- 在定义开始日 `2026-08-04`，日期格显示独立勾选图标，右侧摘要精确显示提醒名称。
- 同日交易、日记和生日是独立来源；普通提醒状态变化不得覆盖其它来源。
- 一次性样例也在开始日显示提醒，并在跳过后消失；但一次性提醒的开始日、唯一发生日和定义完成日重合，单独看该样例不能证明日历按待处理实例查询。

### 2.3 首次跳过、实例推进与冷启动

- 跳过第一期后，今日提醒立即推进到第二期 `2026-08-05`，相对文案为“2天后”；计划列表的下次日期也推进到 `2026-08-05`。
- 此时财务日历仍在原开始日 `2026-08-04` 显示提醒，在第二期发生日 `2026-08-05` 没有提醒标记或摘要。
- 完全关闭并重新打开 MoneyHome8 后，上述三个状态保持：今日提醒仍为第二期，日历仍只在开始日显示，第二期发生日仍为空。
- 因此旧日历不跟随 `next_occurrence_date`，也不逐期投影 `ReminderOccurrence`；它投影的是仍活动的普通提醒定义，并锚定 `schedule.start_date`。

### 2.4 最终跳过、完成与清理

- 跳过第二期后，今日提醒清空，计划定义进入完成态。
- 完成后，财务日历在 `2026-08-04` 和 `2026-08-05` 都不再显示该提醒。开始日标记消失的原因是定义不再活动，不是历史实例被物理删除。
- 显示已完成范围时，定义仍存在并统一显示“执行完毕”；领域事实必须保留两次真实 `skipped` 动作。
- 删除临时定义只用于清理受控数据；变更后业务副本和恢复侧文件已归档，随后用运行前备份恢复指定测试账簿。

## 3. Rust 领域合同

普通提醒至少分为三个层次：

- `ReminderSchedule`：保存稳定定义 ID、账簿 ID、名称、开始日期、重复规则版本、最大次数、提前提醒天数、状态和行版本。
- `ReminderOccurrence`：保存稳定实例 ID、定义 ID、定义版本、`occurrence_date`、`eligible_from_date`、状态、处理动作、处理时间、操作者和幂等键。
- `LegacyReminderCalendarProjection`：从活动定义派生的只读兼容投影，使用 `schedule_id` 作为来源键，并把事件日期固定为 `schedule.start_date`。

定义、实例和兼容日历投影不得合并为一行可变状态。`start_date`、`occurrence_date` 和 `eligible_from_date` 是三种不同业务日期，不能互相覆盖或从本地化显示文本反推。

旧版兼容日历来源至少输出：

- `source_kind=legacy_reminder_schedule`、`source_id=schedule_id` 和定义版本。
- `event_date=start_date`、摘要名称、图标类型和明确的 `can_open`。
- 当前定义状态与可见性；仅活动定义参与该兼容投影。

目标产品可以另行提供按每次发生实例展开的改进日历，但必须使用独立模式或明确的产品规则，不能把该改进标记为 MoneyHome8 旧版兼容行为。

## 4. 查询与事务边界

- 今日提醒按 `ledger_id + eligible_from_date + occurrence_date + occurrence_status` 读取实例；当前业务日位于 `[eligible_from_date, occurrence_date]` 时实例具备展示资格。
- 旧版兼容日历按 `ledger_id + schedule.start_date + schedule_state` 读取活动普通提醒定义；选中日期必须等于 `start_date`，不读取 `next_occurrence_date` 决定标记位置。
- 首期跳过原子写入 `occurrence_id`、实例版本、`skipped` 动作、处理时间和审计，再推进下次实例；定义仍活动时，兼容日历的开始日投影保持。
- 最终实例处理完成后，定义进入完成态，兼容日历不再返回该定义；历史实例审计仍保留。
- 重复提交不得产生第二个动作或错误推进规则。日历查询本身只读，不生成、修改或删除实例。
- 删除或修改定义前返回影响预览；删除或归档定义不得级联清除已处理实例审计。

## 5. 仍待验证

- 每周、每月、每年和自定义重复规则是否同样锚定定义开始日。
- 修改活动定义开始日后，旧日历标记是否迁移；暂停、停用、归档和删除对投影的精确影响。
- 同日多个普通提醒以及提醒与日记、生日、计划实例的稳定排序和容量上限。
- 提醒摘要的点击、下钻目标、返回行为和详情提示。
- 执行、忽略、失败和并发提交时的定义状态、实例审计与日历一致性。
- 改进型逐实例日历的产品取舍、迁移提示和与旧版兼容模式的切换边界。
