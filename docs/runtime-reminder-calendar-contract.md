# 普通提醒与财务日历运行合同

本文档记录 MoneyHome8 普通提醒实例到财务日历的动态投影行为，并把已验证事实转换为 Rust 重构约束。未来日期的提前提醒、重复提醒、多提醒排序和日历下钻尚未完成真实样例验证，不视为旧版兼容结论。

## 1. 验证边界

- 目标程序：`C:\Program Files (x86)\MoneyWise\MoneyHome8\Program\MoneyHome8.exe`
- 唯一可写账簿：`C:\DCG-SZ\IT Manage\Private\Personal-Docs\test.mh8`
- 受控提醒：`CodexRT15CalendarReminder`，日期 `2026-08-03`、一次性、提前 `3` 天。
- 本轮只创建、跳过并删除上述临时普通提醒；没有修改交易、日记、人物生日或历史提醒。
- 最终账簿恢复到长度 `18,669,568`、SHA-256 `D8E4AE302231A7A9B99B06D28C4D83500F8CD32D95F003814039E91EB0E165AC`；MoneyHome8 进程、`~$test*` 和 `test001*` 均为 `0`。

## 2. 已验证交互

### 2.1 定义保存与待处理实例

- 普通提醒编辑器的默认日期为当前业务日，默认重复为一次性，默认提前量为 `3` 天。
- 保存后计划列表立即显示类型“提醒”、名称、一次性、开始/结束/下次日期均为 `2026-08-03`，状态为“执行中”。
- 同日“今日提醒”立即出现该实例；执行禁用、跳过启用。该能力属于本期实例，不能由“提醒”显示文本统一推断。

### 2.2 待处理实例的日历投影

- 实例仍为待处理状态时，财务日历 `2026-08-03` 的日期格显示独立勾选图标，右侧摘要精确显示 `CodexRT15CalendarReminder`。
- 提醒摘要没有“提醒：”前缀，也没有观察到日记来源所带的“查看”入口；当前证据只确认展示，不确认点击或下钻能力。
- 同日原有金额图标和“有账务记录”保持，证明提醒与交易是两个独立来源项，不能互相覆盖。

### 2.3 跳过与完成态

- 在“今日提醒”点击跳过后，列表立即清空；没有生成交易。
- 重新打开同日日历后，提醒勾选图标和名称摘要同时消失，而金额图标和“有账务记录”保持。
- 启用“显示已完成的计划和提醒”后，定义仍存在，并显示一次性、`2026-08-03`、下次执行和状态均为“执行完毕”。
- 因此日历读取的是仍待处理的提醒实例，不是计划定义，也不是已跳过或已完成历史。旧版“执行完毕”只是兼容投影，领域事实必须保留 `skipped` 动作。

### 2.4 删除与清理

- 跳过后删除提醒定义会显示二次确认；确认后仅该临时提醒从已完成列表消失，历史提醒保持。
- 本轮没有用“删除定义”证明日历移除，因为实例在跳过后已经退出日历。删除只用于清理受控数据。
- 变更后业务副本和恢复侧文件已归档，随后用运行前备份恢复指定测试账簿。

## 3. Rust 领域合同

普通提醒至少分为两个层次：

- `ReminderSchedule`：保存稳定定义 ID、账簿 ID、名称、起始日期、重复规则版本、最大次数、提前提醒天数、状态和行版本。
- `ReminderOccurrence`：保存稳定实例 ID、定义 ID、定义版本、应发生自然日、提醒资格窗口、状态、处理动作、处理时间、操作者和幂等键。

财务日历按自然日生成只读 `CalendarEventProjection`，普通提醒来源至少输出：

- `source_kind=reminder_occurrence`、`source_id=occurrence_id` 和 `source_version`。
- `occurrence_date`、摘要名称、图标类型和明确的 `can_open`。
- 当前状态与可见性；兼容投影只包含仍应展示的 `pending` 实例。

定义、实例和日历投影不得合并为一行可变状态。跳过操作必须原子写入实例动作和审计，然后使当前日历查询不再返回该实例；不得删除定义、未来实例或同日其它来源。

## 4. 查询与事务边界

- 日历查询按 `ledger_id + occurrence_date + status` 读取普通提醒实例，并与交易、计划实例、生日和日记做只读并集。
- 当前兼容规则只确认 `pending` 普通提醒进入日历；`skipped` 不进入当前日期摘要。`executed`、`dismissed`、`failed` 和 `archived` 的日历规则仍需独立验证。
- “提前 3 天”已确认会影响今日提醒资格，但本轮应发生日就是当天，尚不能证明日历按应发生日还是提醒资格日显示未来实例。模型必须分别保存二者。
- 跳过使用实例 ID、实例版本和幂等键；重复提交不得产生第二个动作或错误推进重复规则。
- 日历刷新与跳过提交必须遵守提交版本边界，不能出现今日提醒已清空但日历仍长期显示旧实例的混合状态。
- 删除定义前返回影响预览；若产品保留历史实例，删除或归档定义不得级联清除已处理实例审计。

## 5. 仍待验证

- 未来应发生日进入提前提醒窗口时，日历标记落在应发生日还是提醒资格日。
- 每天、每周、每月、每年和自定义重复规则的多期日历投影。
- 同日多个普通提醒以及提醒与日记、生日、计划实例的稳定排序和容量上限。
- 提醒摘要的点击、下钻目标、返回行为和详情提示。
- 执行、忽略、失败、停用、归档和定义修改后的日历状态变化。
- 冷启动后待处理提醒日历投影，以及跳过与日历查询并发时的一致性。
