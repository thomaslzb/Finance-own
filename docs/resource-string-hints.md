# 资源二进制字符串线索

本文档记录对若干 Delphi 资源二进制导出文件的补充性字符串提取结果。

## 0. 结论修正

本文件后续章节保留的是早期磁盘导出样本的历史观察。2026-07-28 已确认 PE 资源目录中的 DFM 指向运行时解包后的虚拟内存；旧 `.bin` 并不是真实窗体载荷，因此对其做宽松字符串提取只会产生噪声。

当前已经直接从普通权限副本内存中提取并解析 `460` 个真实 `TPF0` DFM。记账、财务诊断、财务规划、财务目标和 `25` 张报表的控件、文案、字段与事件均已有直接证据。以下“不能补齐功能语义”的旧结论已被取代，当前权威证据见：

- [runtime-dfm-functional-evidence.md](C:\DCG-SZ\SZ-System-Docs\CodexWorkSpace\Finance-own\docs\runtime-dfm-functional-evidence.md)
- [runtime-dfm-control-catalog.md](C:\DCG-SZ\SZ-System-Docs\CodexWorkSpace\Finance-own\docs\runtime-dfm-control-catalog.md)

目的不是把这些结果当正式页面证据，而是回答两个问题：

1. 在无法直接点开页面时，资源二进制里还能不能榨出一点功能语义。
2. 哪些线索可以作为“补充支持”，哪些又太噪，不能拿来直接下结论。

## 1. 本轮处理对象

本轮检查对象：

- `artifacts/TMAINFORM.bin`
- `artifacts/TTRANSDLGFM.bin`
- `artifacts/TREPORTFM.bin`
- `artifacts/TFINANCIALPLANNINGCENTERFM.bin`
- `artifacts/TACCOUNTMANAGERFM.bin`

处理方式：

- 十六进制头检查
- ASCII 可打印串提取
- 宽松 UTF-16LE 片段提取

说明：

- 这些 `.bin` 明显不是直接明文 DFM 文本。
- 字符串提取结果噪声很大，只能作为弱证据或补充证据。

## 2. 可靠性判断

### 可作为补充支持的线索

在 `TTRANSDLGFM.bin` 中，本轮提取到了少数可直接辨认的中文词：

- `证券`
- `证券证券`
- `股票`
- `债券`

这些词虽然出现在噪声环境里，但方向与现有结论一致：

- `TTRANSDLGFM`
  - 不是单一“现金收支框”
  - 至少覆盖了证券/股票/债券等专项交易语义

这与已有多源证据一致：

- `TSecurityTransFm`
- `TOpenFundTransFm`
- `TNMarketBond*`
- 投资交易窗体家族

### 只能作为弱提示的线索

在 `TREPORTFM.bin`、`TMAINFORM.bin`、`TFINANCIALPLANNINGCENTERFM.bin` 中，本轮提取结果以噪声为主：

- 能看到零散英文片段
- 也能看到大量无法稳定解释的伪中文串

这些结果目前不足以支持下列结论：

- 顶层 `记账` 工作区真实导航项
- `财务报表 -> 投资类` 的具体子报表名
- `财务规划` 页面上的真实输入字段标题

因此本轮不把它们升级为正式功能点证据。

## 3. 当前可落地结论

### 结论 1：资源二进制仍然值得继续挖

虽然整体噪声较高，但 `TTRANSDLGFM.bin` 已经证明：

- 这类导出文件里确实还藏着可见业务词

如果后续拿到更好的解包方式，仍可能进一步补到：

- 专项交易按钮文案
- 报表名
- 规划页字段名

### 结论 2：不能把本轮提取结果当页面实测替代品

截至 `2026-07-28`，本轮字符串提取还不能替代：

- 真实页面截图
- 主账本正式表结构
- 可点击流程的实际观察

所以它更适合作为：

- “与现有结论一致”的补充说明
- “值得继续逆向”的方向信号

而不是独立的最终证据。

## 4. 对当前缺口的影响

本轮结果的实际作用主要有两点：

1. 进一步加强了“交易中心覆盖证券/股票/债券等专项交易”的判断。
2. 没有实质缩小以下 UI 级硬缺口：
   - `记账` 工作区真实页面
   - `财务分析` 诊断/规划/目标真实子页
   - `财务报表` 投资类真实子报表

## 5. 后续建议

如果继续沿这条线推进，优先级建议如下：

1. 先找到可稳定解包这些资源的方式，再继续提字符串。
2. 在此之前，不要把本轮字符串提取结果写成“已实测页面内容”。
3. 所有涉及 `TMAINFORM / TREPORTFM / TFINANCIALPLANNINGCENTERFM` 的功能结论，仍优先依赖：
   - 页面截图
   - 资源窗体家族
   - 主账本对象线索
   - 配置文件与参考库证据
