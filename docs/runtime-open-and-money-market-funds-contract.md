# 开放式基金与货币基金账本合同

本文把 B09 动态观察转换为 Rust 重构约束。新系统可以重新设计 SQLite 表结构和界面，但必须保留两类基金不同的交易语义、估值口径和账户边界。

## 1. 领域模型

基金目录、账户、交易、份额批次、价格和查询投影应分离：

```rust
/// 基金身份独立于当前代码，代码变更不能切断历史交易引用。
pub struct FundId(pub uuid::Uuid);

/// 产品类型决定允许的交易字段和估值策略。
pub enum FundKind {
    OpenEnded,
    MoneyMarket,
}

/// 每次估值都绑定不可变账簿、净值和汇率边界。
pub struct FundValuationRef {
    pub ledger_revision: i64,
    pub nav_batch_id: NavBatchId,
    pub fx_batch_id: FxBatchId,
    pub valued_at: chrono::DateTime<chrono::Utc>,
    pub reporting_currency: CurrencyCode,
}
```

旧窗体和 Frame 只是命令或查询边界，不应按窗体复制领域表。开放式基金与货币基金可以共享稳定身份、账户和交易基础设施，但不得共享一个忽略产品类型的换算函数。

## 2. 基金目录与账户

开放式基金目录至少保存代码、名称、币种、申购费率、赎回费率和名称锁定状态，并保存按日期、来源和批次版本化的净值。货币基金目录只要求代码、名称和币种；未经验证不得强迫其维护开放式基金式日净值。

基金账户至少保存账户名称、基金类型、币种、所有者、备注、创建日期、账户组、开户机构、账号、默认资金来源、标签和附件。货币基金账户还保存“投资/储蓄”资产性质。

- 基金类型和币种变更必须校验现有交易与持仓，不能只禁用 UI。
- 自身资金初始化生成账户初始余额事件；其它账户来源生成可追溯转账。
- 账户、初始资金和默认关系必须在一个事务中创建。
- 名称锁定、代码唯一性和删除限制必须由领域规则执行。

## 3. 开放式基金交易

开放式基金交易至少覆盖申购、赎回、转换、现金红利、分红再投资、新基金认购、认购确认和拆分。每笔交易保存原始输入、收费模式、费率来源、费用分项、舍入结果、资金分录、份额批次和成本分配。

建议把公式作为版本化策略实现，而不是散落在 UI：

```text
申购毛额、净申购额、费用、确认净值和确认份额分别保存
赎回毛额 = 确认份额 * 确认净值
赎回净额 = 赎回毛额 - 赎回费用 - 其它费用
已实现盈亏 = 赎回净额 - 已分配成本
市值 = 持仓份额 * 估值净值
浮动盈亏 = 市值 - 持仓成本
```

后端收费、其它金额/费率下的份额确认精度、尾差归属、成本批次分配和费率来源优先级尚未通过保存样例校准，必须可配置和审计，不能把单一代表性结果硬编码为全部兼容行为。

2026-08-03 的计划执行样例已校准一组前端收费保存结果：

```text
申购毛额 = 1.00
前端费率 = 1.00%
申购费用 = 0.01
净申购额 = 0.99
确认净值 = 1.0000
确认份额 = 0.99
含费持仓均价 = 1.00 / 0.99 = 1.0101
```

该样例证明费用从毛额中扣除后再换算份额，持仓成本仍保留毛额 `1.00`；财务记录只生成一条流出 `1.00` 的申购，不另造手续费支出行。以上只证明该金额、费率和四舍五入口径，不能外推到其它金额、后端收费或更高精度边界。

## 4. 货币基金交易

货币基金申购按金额录入，界面不要求净值、费率或手工份额；赎回区分赎回份额、赎回金额和利息；红利再投资按金额产生份额。Rust 端应使用独立的 `MoneyMarketFundPolicy`：

- 明确份额面值或万份收益等来源，不从开放式基金净值字段猜测。
- 分离本金、已结转收益、未结转收益和可用份额。
- 保存申购、赎回、收益结转和再投资的确认日期与资金在途状态。
- “投资/储蓄”资产性质影响分类与报表口径，但不得改变已提交事实。

真实面值、收益结转周期、赎回利息和在途规则仍待受控保存样例验证。

## 5. 基金转换

转换是一个原子复合命令：关闭来源份额和成本，计算赎回或转换费用，形成目标份额与成本，并处理可能的资金尾差。

- 开放式基金转开放式基金时保存来源净值、目标净值、收费模式和费用。
- 目标为货币基金时使用货币基金策略，不能补造隐藏的目标净值和转换费用。
- 来源与目标使用稳定 `FundId` 和账户 ID，代码或名称不得承担关系主键。
- 来源扣减、目标增加、费用、收益和审计事件必须同事务提交。
- 任一校验失败时，来源持仓和目标持仓都不得发生部分变化。

## 6. 认购、分红与拆分

- 新基金认购先保存资金冻结或支出，再由认购确认关联中签数量、价格、费用、利息和返款。
- 现金红利生成资金收入和收益分类；分红再投资同时生成收益事实和新份额批次。
- 基金拆分保存比例、原份额和新份额，原则上保持总成本不变并重算单位成本，但具体比例方向和零碎份额规则仍待校准。
- 认购、中签、返款、分红与再投资之间通过稳定关系 ID 关联，不依赖行号或备注文本。

## 7. 估值与查询投影

开放式基金样例验证了：

```text
市值 = 60,000.81 * 2.4195 = 145,171.96
均价 = 71,454.99 / 60,000.81 = 1.1909
浮动盈亏 = 145,171.96 - 71,454.99 = 73,716.97
总盈亏 = 73,716.97 + 132,594.11 = 206,311.08
```

同一次真实申购还确认：成交净值 `1.0000` 生成 `0.99` 份和成本 `1.00`，但交易完成后投资一览按独立最新行情显示市值 `1.10`、浮动盈亏 `0.10`。因此成交快照与估值快照必须分开保存，历史成本不能随行情变化，当前市值也不能永久使用成交净值。

同一个 `FundValuationRef` 必须驱动持仓、页脚、市值构成、昨日对比、历史盈亏、导出和打印。缺净值、净值日期落后、跨币种、零份额、负份额和并发更新必须显示明确状态，不得静默回退到零价格。

货币基金工作区的累计金额、实现盈亏、可用资金、总市值和总计也必须来自同一账簿修订；空账户返回明确空集合和零汇总，而不是缺失字段。

## 8. 原子性与审计

所有会改变基金事实的命令必须在单事务内覆盖：

- 交易事实及状态。
- 资金账户双边分录。
- 份额和成本批次。
- 费用、收益和税费分项。
- 标签、备注、附件关系。
- 估值失效标记和审计事件。

查询投影可重建，不得成为唯一业务事实。保存并继续、修改、删除和调整都必须执行相同领域校验，并使用乐观并发版本防止覆盖其它会话更新。

## 9. 当前验证缺口

- 开放式基金其它金额和费率的申购舍入，以及赎回、转换和红利再投资的金额、份额、费用与成本公式；货币基金真实申购仍待验证。
- 开放式基金后端收费和申购、赎回费率的来源优先级；前端收费目前只有 `1.00 / 1.00%` 的代表性样例。
- 货币基金面值、收益结转、赎回利息与资金在途规则。
- 新基金认购、确认、返款及未中签、部分中签状态机。
- 基金拆分比例方向、零碎份额和历史净值调整。
- 净值重复日期、批量更新失败、缺净值、跨币种和并发估值。
- 导出、打印、附件、搜索和大数据量分页。
