# MoneyHome8 破坏性操作与文件流程合同

本文档依据 [runtime-event-command-dataflow.json](C:\DCG-SZ\SZ-System-Docs\CodexWorkSpace\Finance-own\docs\runtime-event-command-dataflow.json) 中的事件代码字符串和精确入口地址，整理删除、覆盖、备份、还原、导入导出和模板生成的开发合同。字符串证明旧程序包含对应校验或提示，但最终影响行数和数据库副作用仍需按动态场景校准。

## 1. 删除与级联边界

| 旧处理器 | 代码证据 | 已确认规则 | Rust 合同 |
|---|---:|---|---|
| `TAccountManagerFm.actDeleteAccountExecute` | `0x3DFB78` | 动态确认删除会移除账户、相关收支、与其它账户的转账和关联财务计划；`Cash-CNY` 选择否零写入，选择是移除 9 条全历史记录并重算对手账户，净资产增加 `3,862.50`，冷启动保持 | 删除前返回带版本的数量和金额影响快照；账户业务可见性、收支、转账双腿、兑换、计划、索引和审计在一个事务中处理，再从剩余事实统一重算投影；取消、冲突或任一步失败必须整体回滚 |
| `TAccountManagerFm.actDeleteAccountGroupExecute` | `0x3DFD58` | 删除账户组会清除组与下挂账户的关联关系，提示未声明删除账户本身 | 账户组和账户使用独立关系；删除组默认解除关系，不级联删除账户 |
| `TCategoryListFm.actDeleteCategoryExecute` | `0x33EBC0` | 已使用的子收支项目不可删除；删除父项目时需确认是否包含全部子项目 | 分类删除必须检查交易引用和子树；支持阻止、迁移或显式级联策略，不能静默产生孤儿引用 |
| `TCurrListFm.actDelExecute` | `0x315E04` | 本币不可删除；已使用币种不可删除 | 基准币种受保护；存在账户、交易或汇率引用时使用 `RESTRICT` 语义 |
| `TPersonListFm.actDelExecute` | `0x336F90` | 已使用的人员或机构不可删除，并区分人员、机构、家庭成员确认文案 | 人员类型保留业务语义；存在交易或关系引用时禁止物理删除，可提供停用状态 |
| `TTransFrame.miBatchDeleteClick` | `0x350334` | 批量删除会显示选中记录数量并再次确认 | 命令必须携带稳定交易 ID 集合；提交前重新校验数量和权限，使用单事务删除 |
| `TWasteBookFm.actDeleteExecute` | `0x2BE7F4` | 财务记录删除同样按选中数量确认 | 流水页和其它入口复用同一删除命令，不得形成两套级联口径 |
| `TGoalCenterFm.miDeleteClick` | `0x2D0294` | 删除财务目标时显示目标名称并确认 | 目标删除与账户、进度快照或提醒关系在事务内处理 |
| `TLimitRemindDlg.miDeleteClick` | `0x375B88` | 删除提醒前确认 | 提醒删除保留审计信息；调度队列和持久化状态同步清理 |
| `TAccessoriesDlg.btnDeleteClick` | `0x2B2FB4` | 动态确认文案为“您确定删除选中的附件吗？”；选择否零变化，选择是删除账户关系、受管文件及最后空目录。旧版账户行 `1个附件` 计数延迟到冷启动刷新 | 先解除业务关系；只有最后一个引用解除后才能删除受管文件内容。文件、关系、计数和动态菜单从同一提交版本刷新，失败可重试且不得留下孤立文件或陈旧计数 |

价格历史删除还直接引用 `AssetObjID / ObjID / TransObjID / PriceDate` 等旧字段。新 SQLite 不要求沿用字段名，但应以“对象 ID + 价格日期”作为稳定唯一边界，并避免删除价格时误删持仓或交易。

## 2. 账簿、备份与还原

| 流程 | 直接证据 | Rust 合同 |
|---|---|---|
| 新建账簿 | `TNewBookFm.btnOKClick` (`0x2A4A48`) 使用 `.mh8`，文件已存在时报 `E_00303` | 新系统可使用自己的 SQLite 扩展名；目标路径必须规范化并拒绝覆盖，除非用户明确选择覆盖流程 |
| 备份账簿 | `TBackupBookFm.BtnOkClick` (`0x28E700`) 使用 `.mh8k`，检测已存在文件、源文件与备份路径相同、成功/失败及 `E_00603/E_00604/E_00605`；动态样本确认空名称阻断、目录选择取消、成功输出、完整路径覆盖确认和覆盖否零写入。成功文件是加密 7z，内部单条 `BOOK` 声明长度与源账簿一致 | 使用 SQLite Online Backup API 或 `VACUUM INTO` 创建一致快照；禁止活动库与目标同路径；覆盖前确认并记录哈希、模式版本和时间点；最终文件只在临时包完成校验后原子出现 |
| 还原账簿 | `TRestoreBookFm.RzButtonOkClick` (`0x28F840`) 提示关闭当前账簿并覆盖数据，也存在新账簿名和 `E_00701/E_00702` 代码线索；动态样本确认空来源 `00701`、文件选择取消、当前账簿覆盖确认取消、真实覆盖成功、重开和冷启动。当前可见入口固定目标为 `test.mh8`，未显示新账簿名控件；还原前未观察到自动 `.mh8k` 安全备份 | 默认还原到新账簿；覆盖当前账簿前自动备份，关闭连接后在隔离临时目标完成解密、迁移和完整性校验，再原子替换；失败时原账簿和恢复点必须仍可打开 |
| 结算账簿 | `TCheckBookDlg.RzButtonOkClick` (`0x291364`) 执行写入，`btnChangeClick` (`0x2919D8`) 选择 `.mh8k`；动态样本确认默认当天、固定结算备份名、保存取消零写入、先备份后结算、无独立二次确认、成功提示和余额调整重写。最近 1 月由 23 条原记录变为 78 条同日余额调整，汇总余额保持不变 | 结算前返回影响预览并二次确认；先验证恢复点，再以单事务创建 `settlement_batch` 和期初投影；原始交易保持在线可查询，重复范围、并发写入或任一跨域校验失败时整体回滚 |

`.mh8` 和 `.mh8k` 属于旧格式兼容证据，不要求新主库复制 Jet 或旧加密 7z 结构。Rust 版应把旧格式读取放在 `legacy_import`，把新备份定义为可验证的 SQLite 快照包。当前 `.mh8k` 样本已通过 MoneyHome8 自身覆盖还原并完成业务摘要与冷启动抽查，但仍不能据此推断密钥、内部数据库字节、附件范围或 Rust 迁移兼容性。

## 4. 模板与批量生成

`TTemplateDlgFm` 和 `TTransferTemplateDlgFm` 的代码字符串确认：

- 空交易列表或空转账列表不能保存为模板
- 保存模板需要名称
- 同名模板会请求覆盖确认
- 生成交易后提示成功生成的记录数量
- 删除模板时显示模板名称并确认

Rust 版应把模板定义和模板执行分离。保存模板只写模板头和模板行；执行模板必须生成独立交易命令批次，返回成功、失败和跳过数量，任何原子交易不能出现半写入。

## 5. 密码与敏感流程

`TPwdChangeFm.btnOkClick` (`0x29018C`) 区分旧密码错误、新密码确认不一致、修改成功、修改失败和 `E_00801`。新系统不得复制旧可逆配置或工作组口令实现，应使用现代密码哈希、独立盐、失败限速和敏感日志脱敏。

动态验证补充：无密码账簿的空新密码会被当作清除并提示成功；受保护账簿增加旧密码字段，旧密码错误时提示“旧密码输入错误”，正确旧密码配合空新密码可清除保护。冷启动空密码和错误密码会静默重建输入窗，取消退回文件选择器，正确密码才打开账簿。Rust 版必须把清除保护做成显式高风险命令，使用版本化 KDF、临时副本、完整性检查和原子替换；失败反馈、退避和审计不能依赖无限静默重试。

同步账号密码删除与修改存在独立主菜单命令，且旧修改入口访问明文 HTTP 页面。Rust 版同步认证必须经过安全适配器，不得继续使用明文 HTTP、客户端硬编码秘密或将账本凭据写入普通日志。

## 6. 统一实现规则

1. 所有新增、修改、删除、覆盖还原和模板生成都必须通过应用命令进入事务边界，UI 不直接操作 SQLite。
2. 破坏性命令先返回影响预览，至少包含对象类型、对象数量、关联记录数量和不可逆说明。
3. `RESTRICT`、解除关系、软删除和物理级联必须按实体分别定义，不能依赖数据库默认行为。
4. 文件写入采用“校验路径 -> 写临时文件 -> 完整性检查 -> 原子替换”的顺序。
5. 错误码可重新设计，但必须使用结构化错误类型，并保留可操作的用户提示和技术诊断上下文。
6. 动态验证按 [runtime-validation-scenarios.md](C:\DCG-SZ\SZ-System-Docs\CodexWorkSpace\Finance-own\docs\runtime-validation-scenarios.md) 执行，只操作授权的 `test.mh8` 测试库。
