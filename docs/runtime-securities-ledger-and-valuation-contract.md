# 上市证券账本、费率与估值合同

本文把 B08 动态观察转换为 Rust 重构约束。新系统可以重新设计 SQLite 表结构和 UI，但必须保留已验证的业务功能与数据边界。

## 1. 领域边界

上市证券至少拆分为以下聚合和投影：

1. 证券目录：稳定证券身份、市场代码、名称、类型、交易所和代码历史。
2. 证券账户：账户币种、所有者、机构、股东代码、资金来源和账户级费率。
3. 交易事实：买入、卖出、新股申购、中签、退款、配股、送股、缩股、现金红利和调整。
4. 持仓与成本批次：数量、成本基础、批次关闭和公司行为分配。
5. 行情与估值：按日期和批次保存价格，在同一快照生成市值与浮动盈亏。
6. 查询投影：交易明细、持仓统计、市值构成和历史盈亏。

旧窗体和 Frame 是输入或查询边界，不应逐窗体建立重复领域表。

## 2. 建议核心类型

```rust
/// 证券身份独立于当前代码，保护历史交易在代码变更后仍可追溯。
pub struct SecurityId(pub uuid::Uuid);

/// 交易保存时冻结实际采用的费率来源和参数。
pub struct AppliedSecurityFeeSnapshot {
    pub source: SecurityFeeSource,
    pub market: SecurityMarket,
    pub security_kind: SecurityKind,
    pub effective_at: chrono::DateTime<chrono::Utc>,
    pub parameters: SecurityFeeParameters,
}

pub enum SecurityFeeSource {
    ExplicitTransactionOverride,
    AccountSchedule,
    GlobalTemplateCopiedAtAccountCreation,
}

/// 列表、构成图和盈亏页必须引用同一个不可变估值边界。
pub struct SecurityValuationRef {
    pub ledger_revision: i64,
    pub quote_batch_id: QuoteBatchId,
    pub fx_batch_id: FxBatchId,
    pub valued_at: chrono::DateTime<chrono::Utc>,
    pub reporting_currency: CurrencyCode,
}
```

## 3. 证券目录与代码变更

证券代码不是主键。每个证券使用稳定 `SecurityId`，代码按市场和有效期保存。代码变更命令必须：

- 校验源证券、目标代码、市场和生效日期。
- 保留旧代码别名及有效期，避免历史交易失去引用。
- 原子迁移持仓、行情、交易选择和新股关系引用，或让这些对象继续引用稳定 ID。
- 检测目标代码冲突、循环别名和跨市场不兼容。
- 保存审计事件，支持查看变更前后值。

证券名称锁定属于目录规则，不得依靠 UI 禁用状态作为唯一约束。

## 4. 账户与资金来源

证券账户至少保存账户名称、证券类型、币种、所有者、创建日期、备注、账户组、深沪北股东代码、开户机构、托管银行、联系信息、附件和默认资金来源。

新建向导中的“自有余额”和“其它资金账户”是不同资金初始化模式：

- 自有余额生成账户初始余额事件。
- 其它资金账户生成可追溯的账户间资金转移。
- 账户建立、初始资金事件和费率模板复制必须在一个事务内完成。
- 账户类型决定允许币种时，应在领域校验中实现，不只锁定下拉框。

## 5. 费率继承与计算

全局费率是新账户模板，不是所有账户的实时引用。创建账户时应复制一个版本化账户费率表；后续修改全局模板不得改变已有账户。

RT-08-004 已真实验证模板编辑和在线发布生命周期：沪市股票卖出印花税 `0.1 -> 0.11`、沪市 B 股结算费 `0.05 -> 0.06` 均在单元格提交后即时持久化并通过冷启动复核；在线更新随后成功发布 `11` 条记录，把两个手工值分别覆盖回 `0.1` 和 `0.05`，并把深市 B 股买卖最低佣金从 `0.05` 更新为 `5`。因此在线更新必须按完整模板版本处理，不能实现成“只补空值”。

费率参数至少覆盖：

- 买入和卖出印花税率。
- 买入和卖出佣金率及最低佣金。
- 附加费和过户费。
- B 股结算费、结算费上限和交易规费。

字段必须显式保存量纲：印花税、佣金、结算费和交易规费使用百分比，过户费使用千分比，最低佣金、附加费和结算费上限使用带币种的固定金额。显示层转换不能改变领域值的单位。

手工编辑和在线更新都发布不可变 `SecurityFeeTemplateVersion`。在线发布前应展示 11 行逐字段差异并要求覆盖确认，保存来源、批次、操作者、发布时间和上一版本；抓取或校验失败时保留上一有效版本。旧程序在线更新期间还改写了账簿外 `mhlink.mdb` 的时间状态，Rust 版必须把应用级参考数据与账簿内账户费率快照分开，并明确账簿备份/还原是否包含全局模板。

每笔交易必须保存计算输入、分项结果、舍入规则、币种以及实际采用的费率快照。建议计算顺序为：

```text
成交毛额 = 价格 * 数量
比例费用 = 按费率和舍入规则计算
佣金 = max(比例佣金, 最低佣金)
费用合计 = 各分项费用之和
买入现金流 = -(成交毛额 + 费用合计)
卖出现金流 = 成交毛额 - 费用合计
```

具体税率、最小单位和舍入规则仍需真实样例校准，当前不得硬编码为已兼容结论。

## 6. 交易与持仓批次

买入创建证券数量、成本批次和资金流；卖出关闭可用数量并分配成本。保存必须原子覆盖：

- 交易事实和分项费用。
- 资金账户分录。
- 持仓批次新增或关闭分配。
- 已实现盈亏来源关系。
- 标签、备注、附件和审计信息。

成本分配方法必须显式配置并版本化，不能从列表顺序推断。余额不足、可卖数量不足、价格或数量非法、费率缺失和并发版本冲突都必须在提交前失败。

## 7. 公司行为与新股流程

送股、缩股、现金红利、配股和新股流程应保存独立事件类型：

- 送股/缩股改变数量和单位成本，但不应凭空改变总成本，除非规则明确要求。
- 现金红利生成资金收入，并关联持仓资格日期和税费。
- 配股同时生成认购资金流、新增数量和成本批次。
- 新股申购、中签确认和退款通过稳定关系 ID 关联，不能依靠三条记录的行号或备注文本长期维系。
- 未中签、部分中签、部分退款、跨日和取消场景必须保留状态机与审计轨迹。

`TRelationNewStockRecordsDlgFm` 暴露的申购、中签、退款三记录关系，在 Rust 中应建模为领域关联，不复制为 UI 行号字段。

## 8. 行情与估值

证券价格按证券、价格日期、来源和行情批次保存。重复价格必须有明确覆盖或拒绝策略。在线更新先写入暂存批次，整批校验成功后再发布。

同一 `SecurityValuationRef` 驱动持仓列表、页脚、市值构成图和历史盈亏查询。B08 样例满足：

```text
总浮动盈亏 = 15,860.00 - 16,424.30 = -564.30
成本构成合计 = 8,700 + 4,150 + 3,000 + 574.30 = 16,424.30
市值构成合计 = 8,700 + 4,150 + 3,000 + 10 = 15,860.00
```

缺行情、停牌、零价格、跨币种和昨日价格缺失必须显示明确状态，禁止悄悄使用零值制造虚假收益率。

## 9. 查询投影

- `TSecurityStatisticFrame` 映射为持仓估值查询。
- `TSecurityTransFrame` 映射为证券交易明细查询。
- `TMarketConstitutesFrame` 映射为当前与昨日市值构成查询。
- `THistoryProfitFrame` 映射为已关闭数量和成本分配生成的实现盈亏查询。
- `TStockViewFrame` 映射为证券账户概况查询。

筛选、列表、页脚、图表、导出和打印必须共享同一个查询快照。查询组件不得直接修改交易或持仓事实。

## 10. 当前验证缺口

- 账户级费率页的直接入口、保存和全局/账户覆盖优先级。
- 真实买卖交易的费用、舍入、成本批次和已实现盈亏公式。
- 新股申购、中签、退款三记录的关联与状态迁移。
- 证券选择对话框的候选范围、更新后刷新和返回语义。
- 代码变更后的历史交易、持仓、行情和报表迁移。
- 缺行情、跨币种、停牌和并发更新场景。
