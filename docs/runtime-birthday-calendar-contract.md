# 生日与财务日历运行合同

本文档记录 MoneyHome8 人物生日到财务日历的动态投影行为，并把已验证事实转换为 Rust 重构约束。公历历史年份的周年重复、农历换算、闰月和生日下钻尚未完成真实样例验证，不视为旧版兼容结论。

## 1. 验证边界

- 目标程序：`C:\Program Files (x86)\MoneyWise\MoneyHome8\Program\MoneyHome8.exe`
- 唯一可写账簿：`C:\DCG-SZ\IT Manage\Private\Personal-Docs\test.mh8`
- 复用人物样例：`CodexRT34Person`，家庭成员、男、农历 `1991-06-07`。
- 新增人物样例：`CodexRT15Bday`，家庭成员、男、公历 `2026-08-03`。
- 本轮只新增和删除上述公历临时人物；没有修改交易、计划、提醒或日记。
- 最终账簿恢复到长度 `18,669,568`、SHA-256 `D8E4AE302231A7A9B99B06D28C4D83500F8CD32D95F003814039E91EB0E165AC`；MoneyHome8 进程、`~$test*` 和 `test001*` 均为 `0`。

## 2. 已验证交互

### 2.1 人物生日源

- 人物列表明确展示生日类型和出生日期；农历样例显示 `农历 / 1991-06-07`，公历样例显示 `公历 / 2026-08-03`。
- 新增人物勾选生日后，默认历法为公历，默认日期为当前业务日 `2026-08-03`。
- 公历人物保存后立即进入人物列表；删除使用人员列表“操作 -> 删除”，确认后人物和生日字段一起消失。
- 生日属于人员主数据，不应另建一份可独立编辑的日历生日事实。日历只读取稳定 `party_id`、历法和原始年月日分量。

### 2.2 公历生日投影

- `CodexRT15Bday / 公历 2026-08-03` 保存后，财务日历 `2026-08-03` 右侧显示精确文案 `今天是CodexRT15Bday的生日`。
- 同日原有“有账务记录”继续显示，证明生日摘要与交易存在性是两个独立来源。
- 生日摘要没有观察到日记摘要所带的“查看”入口；当前证据只确认展示，不确认下钻能力。
- 删除 `CodexRT15Bday` 后重新打开日历，生日摘要立即消失，“有账务记录”保持，证明日历按人物真相实时投影。
- 该样例出生年份等于当前年份，只证明精确出生日期投影；历史公历生日是否每年重复仍待验证。

### 2.3 农历生日限制

对 `CodexRT34Person / 农历 1991-06-07` 分别检查：

- `2026-07-20`，页面农历卡片为六月初七；
- `2026-06-07`，按保存分量直接解释的月日；
- `1991-06-07`，保存年月日的精确日期。

三个日期均未出现生日摘要。该结果证明旧版在本样例下没有把农历生日投影到上述三种日期口径；不能进一步推断所有农历生日都永不投影，也不能据此删除农历生日支持。

## 3. Rust 领域合同

`PartyBirthday` 继续作为人物真相的一部分，至少包含：

- 稳定 `party_id` 和所属 `ledger_id`；机构不允许生日。
- `calendar`：公历或农历，不能由显示文本推断。
- 原始 `year`、`month`、`day` 分量；农历还需在产品规则确认后扩展闰月标记。
- 人物行版本和删除/隐藏状态；日历读取与人物列表使用同一提交版本。

日历查询生成临时 `BirthdayOccurrence` 投影，至少包含：

- `party_id`、显示名称、来源版本和 `occurrence_date`。
- 原始历法与生日分量、采用的重复/换算规则版本。
- `source_kind=birthday`、摘要文案和明确的 `can_open` 能力。

`BirthdayOccurrence` 不是独立可编辑真相，不应保存人物姓名副本或形成无法随人物修改、隐藏、删除而更新的孤儿记录。若为性能缓存实例，缓存必须带人物版本和规则版本并可完整重建。

## 4. 目标规则

- 公历生日按账簿本地自然日计算；历史生日周年规则需要代表性样例验证后再固化。
- 目标产品应明确支持公历和农历生日，而不是复制旧版已观察到的农历漏投影；农历换算库、时区、闰月和规则版本必须可测试、可迁移。
- 必须定义 `2月29日` 在非闰年的显示策略，以及农历闰月生日在无对应闰月年份的策略。
- 人物改名后摘要使用当前名称；修改生日后旧日期退出、新日期进入；隐藏是否排除由显式产品规则决定，删除必须立即排除。
- 同日多个人物生日按稳定排序返回独立来源项；生日与交易、计划、提醒、日记互不覆盖。
- 页面查询只读。查询失败不得写入人物或日历事件；并发修改通过来源版本刷新，不展示混合版本摘要。

## 5. 仍待验证

- 历史年份公历生日的年度重复、年龄显示和跨年边界。
- 农历生日是否存在其它触发条件，以及闰月、大小月和春节跨公历年的换算。
- 人物隐藏、改名和修改生日对日历投影的即时影响。
- 同日多人生日的排序、摘要布局和容量上限。
- 生日摘要是否可点击、下钻目标和返回行为。
- 提醒来源已确认活动定义锚定开始日并在定义完成后消失；提醒与生日、日记同时存在时的跨来源顺序仍待验证。
