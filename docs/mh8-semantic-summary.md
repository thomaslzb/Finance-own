## 1. `TBPerson` 的业务口径

当前能稳定看到的中文提示包括：

- `唯一标识符 标识 人员/机构表`
- `类型 属于 人员/机构表`
- `性别 属于 人员/机构表`
- `人员/机构表名称 属于 人员/机构表`

当前结论：

- `TBPerson` 高可信不只是自然人表。
- 更像：
  - 人员
  - 机构
  - 往来方
  的统一对象表。

这与现有样本中能看到大量银行、保险公司、机构名称是相互印证的。

## 2. `TBTransType` 的业务口径

当前能稳定看到的中文提示包括：

- `Name 属于 交易类型表`
- `资产的占有户头`
- `在设计视图中创建查询`
- `在设计视图中创建窗体`
- `在设计视图中创建报表`

当前结论：

- `TBTransType` 高可信是交易类型基础字典表。
- 主账本内部仍保存 Access 设计器级元对象信息，这说明库结构并没有完全被“黑盒化”。

## 3. `TBRemindSetting` 的业务口径

当前能稳定看到的字段组合包括：

- `RemindType`
- `ObjectID`
- `MinValue`
- `MaxValue`
- `IsRemind`

并且可见中文提示：

- `最大值`

当前结论：

- 提醒至少支持阈值型口径，而不只是日期型提醒。
- 很可能存在：
  - 最小值触发
  - 最大值触发
  - 启用/停用

## 4. `TBCurrency` / 账户类型相关中文项

当前在主账本片段中已经能直接看到多组中文类别项，例如：

- `现金`
- `实物资产`
- `应收款`
- `待摊费用`
- `上市证券`
- `货币基金`
- `国债`
- `贵金属`
- `集合理财`
- `银行理财产品`
- `非上市债券`

当前结论：

- 这些类别项强烈支持“账户类型 / 投资对象类型 / 币种映射”存在于数据库对象或其元数据中。
- 它们和我们从页面、资源窗体、参考库里看到的功能域是一致的。

## 5. `TBPreciousMetals` 的业务口径

当前能看到的字段组合包括：

- `PreciousMetalsName`
- `CurrType`
- `TransObjID`
- `SecuType`
- `SecuName`
- `AutoUpdateName`

当前结论：

- 贵金属对象本身兼具：
  - 名称
  - 计价币种
  - 交易对象引用
  - 自动更新名/行情更新名
- 这说明其在系统内的表现更接近“独立投资对象”，而不是证券表的一种简单别名。

## 6. 对重构的直接意义

### 6.1 `Person`

- 应建模为广义往来方，而不是只做联系人。

### 6.2 `Reminder`

- 应保留阈值提醒字段：
  - `min_value`
  - `max_value`
  - `enabled`

### 6.3 `Currency / ObjectType`

- 应准备支持：
  - 现金
  - 货币基金
  - 上市证券
  - 国债
  - 贵金属
  - 银行理财
  - 非上市债券
  - 待摊费用
  - 应收款
  - 实物资产

### 6.4 `PreciousMetal`

- 不应被视作证券对象的简单子类型别名。

## 7. 当前限制

- 这些线索来自未正式认证的主账本字节流，并非正式 SQL 查询结果。
- 因此它们适合：
  - 收窄建模方向
  - 约束命名
  - 提高后续表验证优先级
- 但不应替代正式字段枚举。
