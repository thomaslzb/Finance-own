# MoneyHome8 账簿生命周期、设置与授权合同

## 1. 边界

B01 覆盖应用外壳、账簿新建/备份/还原/结算、账簿密码、系统设置、快捷键、授权、关于和启动过渡。Rust 重构需要保留用户可见功能和迁移入口，但不得复制旧程序把会话状态、授权秘密和账务数据混在同一生命周期中的实现风险。

旧窗体名仅用于需求追溯。Rust 版至少拆分为 `ApplicationShell`、`LedgerLifecycleService`、`BackupService`、`RestoreService`、`LedgerSecurityService`、`SettingsStore`、`ShortcutRegistry` 和 `LicenseAdapter`。

## 2. 应用外壳

1. 支持无账簿、打开中、已打开、关闭中和失败恢复状态。
2. 主导航保留账簿、资料管理、计划提醒、财务工具、设置、帮助和退出七个顶层入口。
3. 最近账簿和窗口状态属于应用级会话数据，不得通过改写账簿财务表实现。
4. 应用关闭必须等待后台写入、备份、同步和导出任务进入可恢复状态，再释放账簿锁。
5. 启动画面只在初始化耗时足以需要反馈时显示；初始化失败必须进入可操作错误页，不能停留在无响应画面。

## 3. 新建账簿

1. 输入包含账簿名、保存位置和是否立即设置密码。
2. 目标路径必须规范化扩展名、拒绝目录穿越、拒绝覆盖现有文件，并在创建前检查父目录可写性和可用空间。
3. 先在同目录创建临时文件，完成数据库结构、默认数据和完整性检查后原子改名。
4. 创建失败必须删除临时文件，保留当前账簿上下文，不得切换到半成品账簿。
5. 可选密码设置是创建后的独立安全步骤；密码步骤失败时，新账簿仍需处于明确的未加密或待加密状态。

## 4. 备份

1. 备份输入包含名称、目标目录、压缩和优化策略。
2. 备份必须来自一致性快照，不允许直接复制仍有未检查点写入的活动数据库文件。
3. 输出先写临时文件，完成完整性检查、附件清单和 SHA-256 后再原子改名。
4. 清单至少记录格式版本、数据库版本、创建时间、源账簿标识、文件列表、长度、哈希和压缩方式。
5. 备份失败不得影响源账簿；取消和错误必须清理不完整输出。
6. 旧 `.mh8k` 兼容只有在真实样本通过恢复验证后才能标记完成。

2026-08-01 的旧程序动态样本确认：备份名称不能为空，扩展名固定为 `.mh8k`；目标已存在时显示规范化完整路径并要求“是/否”覆盖确认，选择“否”不改变既有文件。成功样本是加密 7z 容器，内部单条 `BOOK` 的声明长度与源账簿一致。该事实只用于 `legacy_import` 设计和追溯；未完成真实还原前，不得把旧格式标记为兼容。

旧程序提交后先能观察到最终目标文件，稍后才显示“备份成功”。Rust 版不得复制这一中间可见性：运行中只写同目录临时文件，完成快照、完整性检查、清单和哈希后再原子改名为最终目标。

## 5. 还原

动态校准确认旧程序当前账簿入口只显示备份来源和固定的当前 `test.mh8` 目标。来源为空时报 `00701`；有效 `.mh8k` 会请求关闭当前账簿并覆盖数据的二次确认，选择“否”返回页面，选择“是”可完成恢复、重开和冷启动。旧程序本次没有生成可见的还原前自动 `.mh8k` 安全备份，且成功后只报告备份文件名，不报告附件、设置、迁移或校验结果。

1. 默认还原到新账簿；覆盖当前账簿需要二次确认，并显示源、目标、版本和恢复点。
2. 读取备份后先验证清单、哈希、格式版本、数据库版本和可用空间，再允许提交。
3. 覆盖当前账簿前必须自动生成可验证安全备份，关闭数据库连接并释放锁。
4. 还原到临时目标，完成迁移和完整性检查后原子替换；任一步失败都恢复原文件。
5. 恢复报告必须列出数据库、附件、跳过项、迁移项和失败项，不能只显示“成功”。

## 6. 账簿结算

旧版结算在截止日前合并记录，并要求通过还原备份查看完整明细。Rust 版需要保留“降低活动账簿负担、形成期初余额、按截止日封存”的用户目的，但默认实现不得不可逆删除历史。

动态校准确认：旧程序默认截止日为当天，先生成 `.mh8k` 恢复点，再把当前范围重写为同日“余额调整”。最近 1 月从 `23` 条原始记录变为 `78` 条余额调整，账户资产负债汇总不变；记录把账面余额归零，以真实余额形成差额，零余额账户也可能生成记录。点击确定没有独立二次确认，成功报告只有“结算成功”。

1. 结算前显示截止日、影响记录数、账户数、币种数、未完成计划、附件和恢复点路径。
2. 先创建并验证完整备份，再在单一事务中生成结算批次、期初结转和归档标记。
3. 完整历史仍应在当前产品内可查询；为了旧格式兼容导出时，才生成旧版聚合结果。
4. 结算必须可重复检测，禁止同一范围重复结转。
5. 任意余额、外币、投资持仓、债权债务或跨期引用校验失败时整体回滚。
6. 使用 `settlement_batch` 保存范围、规则版本、恢复点和状态；使用 `opening_balance_entry` 保存账户、币种、投资标的和来源范围的期初投影。
7. 原交易在线保留并可按结算批次查询；活动视图可以默认折叠历史，但不能要求用户还原外部备份才能查看。

## 7. 账簿密码

2026-08-01 动态校准确认：无密码账簿只显示两次新密码；两个字段均为空时旧程序仍提示成功，表示清除或保持无密码。两次输入不一致时给出明确错误。一旦设置密码，冷启动进入单字段 `TpwdCheckFm`；空密码和错误密码不会显示独立错误，而是静默重建密码窗。关闭密码窗退回账簿文件选择器，正确密码才建立账簿会话。受保护账簿的修改页增加旧密码字段，错误旧密码提示“旧密码输入错误”；正确旧密码配合空新密码可清除保护，后续冷启动直接打开。

1. 设置或修改密码必须要求两次新密码一致，并在修改已有密码时验证旧密码。
2. 密码不得明文存储、记录、回显或进入崩溃日志；密钥派生参数必须版本化并支持未来升级。
3. 整库加密或换密钥必须采用临时副本、进度、取消边界、完整性检查和原子替换，禁止原地半加密。
4. 清除密码必须是显式命令并要求旧密码和确认，不得把两个空新密码字段作为唯一交互语义。
5. 错误密码需要统一失败反馈、进程内尝试计数、渐进退避、安全审计和明确取消；不得泄露密钥材料，也不得永久锁死仅存于本地的账簿。
6. 正确解锁前不得创建业务数据库连接、加载敏感投影或启动同步等后台任务；取消只中止当前打开请求并返回可操作的无账簿外壳。
7. `TPasswordDialog` 这类旧数据库驱动密码列表不作为产品功能复制；旧格式导入器在隔离进程中处理兼容密码。

## 8. 设置作用域

| 作用域 | 示例 | 存储规则 |
| --- | --- | --- |
| 设备级 | 任务栏/托盘、窗口状态、显示缓存、声音 | 本机用户配置，不随账簿复制 |
| 应用用户级 | 更新检查、离线模式、代理、快捷键、报表自动查询 | 用户配置；秘密部分进入系统秘密存储 |
| 账簿级 | 最小化保护、账簿备份策略、账簿密码状态 | 与账簿标识关联，但不混入交易事实 |
| 授权级 | 序列号、保护信息、许可令牌 | 独立加密授权存储，默认不导出到账簿备份 |

设置页必须区分即时生效、下次启动生效和需要重新打开账簿生效。取消时恢复打开前草稿，单项保存失败不得污染其它设置分区。

## 9. 快捷键

1. 命令使用稳定标识，不以中文菜单文本作为持久化键。
2. 保存前检测重复映射、系统保留组合键、输入法冲突和老板键冲突。
3. 全局热键注册失败要保留原映射并给出可操作错误。
4. F1-F12 快速记账和菜单快捷键共享同一命令注册表，隐藏或不可用命令不得执行。
5. 提供恢复默认和单项清除；取消不写配置。

## 10. 授权与关于

1. 授权适配器只接收产品标识、许可凭据和最少设备证明，不得读取或上传账簿内容。
2. 免费使用、在线激活、离线激活、购买和查看注册资料是独立状态机；网络失败不得阻止离线账务核心。
3. 序列号、保护信息、通行证和用户资料均按秘密或个人信息处理，默认遮罩且禁止进入截图、日志和遥测。
4. 许可服务和旧离线激活格式尚未验证，不得标记为兼容。
5. 关于页显示产品名、语义版本、构建标识、数据库格式版本、操作系统和版权；外部链接必须经用户显式触发。
