## 1. 目标定义

当前分析工作的目标不是泛泛“看懂一个财务软件”，而是为使用 Rust 重构 `财智8 8.50.0.0` 提供足够扎实的前期资料，使后续可以正式进入实现阶段。

具体目标包括：

1. 尽可能完整记录现有功能点。
2. 梳理主要数据源、权限链、缓存和参考库。
3. 建立领域模型与页面/数据的映射。
4. 给出可执行的实现路线与阶段性验收标准。

## 2. 当前总体结论

### 2.1 产品定位结论

`财智8` 不是“简单个人记账工具”，而是包含以下能力的大型本地财务管理桌面软件：

- 账本生命周期管理
- 账户体系与多资产账户
- 通用收支与流水
- 债权债务、信用、应收应付
- 外汇、证券、基金、债券、期货、黄金、贵金属、融资融券
- 保险、社保、重大资产
- 预算、提醒、财务规划、财务目标
- 导入导出
- 同步、远程通知、行情更新
- 报表与分析中心

### 2.2 顶层工作区结论

当前已经确认至少存在四个顶层工作区：

- `财务数据`

其中：

- `财务数据`

## 4. 数据源与结构结论

### 4.1 主账本 `test.mh8`

已确认：

- 文件头是 `Standard Jet DB`
- 主账本字节流中出现大量 `TB*` 表名
- 还能看到主键、索引、字段、中文语义提示

已看到的高价值结构线索：

- `TBTransaction_PK`
- `TBBudgetItem_INDEX_BudgetID_CategoryID_AmountBeginDate`
- `IDX_TBAcctDetail_AcctID`
- `IDX_TBPayModeHistory_AcctID`
- `IDX_TBPayModeHistory_ChangeDate`
- `IDX_TBStdTransObject_ObjName`

已看到的高价值字段语义：

- `TBPerson`
  - 人员/机构表
- `TBRemindSetting`
  - 支持阈值提醒
- `TBCurrency`
  - 兼具中文名、英文缩写、交易对象映射
- `TBPreciousMetals`
  - 更像独立投资对象而非证券别名

### 4.2 主账本认证现状

当前最关键的技术发现：

- ODBC / ADO：
  - 可以确认 Jet 与工作组认证存在
- `Access.Application`：
  - `OpenCurrentDatabase(...)` 已经能成功打开主账本
  - 但打开后：
    - `AllTables = 0`
    - `AllQueries = 0`
    - `TableDefs = 0`
    - `QueryDefs = 0`
    - `AllForms = 0`
    - `AllReports = 0`
    - `Properties.Count = 0`

这说明当前问题已经从“能不能打开数据库”收敛到：

- 对象是否可见
- 对象是否有读取权限
- 当前上下文是否仍缺工作组认证材料

### 4.3 共享参考库 `mhlink.mdb`

当前已正式读取：

- `HBRate`
- `TBSecuPrice`
- `TBTransFee`

其中：

- `HBRate`
  - 利率参数
- `TBSecuPrice`
  - 行情价格
- `TBTransFee`
  - 手续费率

类型码当前高可信推断：

- `ObjType = 4`
  - 场外基金 / 公募基金
- `ObjType = 3`
  - 交易型市场标的
- `ObjType = 10`
  - 贵金属
- `CurrType = 1`
  - 人民币
- `CurrType = 2`
  - 美元

### 4.4 内置库 `MoneyHome8.data`

当前已确认：

- 文件头为 `.MH8D`
- 偏移 `125` 可 `zlib` 解压出一份 Jet 数据库
- 解压后的内置库与主账本共享约 `103` 张表、`130` 个字段

这说明：

- 主账本和内置库高度共用同一业务模型
- Rust 中应围绕统一领域模型建模，再通过不同 repository 连接不同数据源

### 4.5 缓存层

#### `MoneyHome8.cache`

高可信语义：

- 代码 + 中文名 + 拼音/缩写检索索引

## 6. 当前最稳妥的重构路线

当前不建议直接承诺：

- 旧库原位写回
- 100% 旧格式兼容

当前最稳妥的路线是：

1. 旧数据可读
2. 新数据可写
3. 主账本优先作为只读导入/兼容源
4. 参考库和缓存单独建读取器
5. 认证打通后再决定是否补旧格式深兼容
