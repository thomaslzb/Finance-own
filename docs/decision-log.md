# MoneyHome8 重构决策日志

本文档记录当前阶段已经足够稳定、可直接指导实现的关键技术/产品判断，以及仍然只是阶段性推断的结论。

状态说明：

- `已确认`
  - 当前证据已足够稳定，可直接指导设计
- `阶段性推断`
  - 当前方向很强，但仍待后续实测或正式结构验证

## 1. 数据层决策

### 决策 1：不是单一数据文件产品

- 状态：`已确认`
- 结论：
  - 原软件至少包含以下数据层：
    - `test.mh8` 主账本
    - `mhlink.mdb` 共享参考库
    - `MoneyHome8.data` 压缩封装的受控 Jet 内置库
    - `MoneyHome8.cache`
    - `Investment.cache`
    - `mh.mdw`
    - `user.cfg` / `UseInformation.cfg`
- 影响：
  - Rust 不应设计成单一仓储适配器

### 决策 2：`mhlink.mdb` 是共享参考库

- 状态：`已确认`
- 结论：
  - 至少承载：
    - `HBRate`
    - `TBSecuPrice`
    - `TBTransFee`
- 影响：
  - 利率、行情、费率不应硬编码

### 决策 3：`MoneyHome8.data` 不是普通静态资源包

- 状态：`已确认`
- 结论：
  - 偏移 `125` 处可 `zlib` 解压为 Jet 数据库
  - 解压后仍受工作组认证控制
- 影响：
  - 需要 `builtin_repository`

### 决策 4：`test.mh8` 高概率依赖 `mhlink.mdb`

- 状态：`阶段性推断`
- 结论：
  - 主账本中多次出现 `mhlink.mdb` 路径
  - 且伴随 `Connect / Database / Tables / MSysRelationships`
- 影响：
  - 主账本读取器要预留外部依赖处理

## 2. 模型层决策

### 决策 5：主账本与内置库共享业务模型

- 状态：`已确认`
- 结论：
  - `test.mh8` 与解压后的内置库共享约 `103` 个核心表名
  - 共享约 `130` 个字段名
- 影响：
  - Rust 领域层可以围绕一套统一模型建模

### 决策 6：主账本是关系型结构而非扁平文件

- 状态：`已确认`
- 结论：
  - 已看到：
    - `TBTransaction_PK`
    - `TBBudgetItem_INDEX_BudgetID_CategoryID_AmountBeginDate`
    - `IDX_TBAcctDetail_AcctID`
    - `IDX_TBPayModeHistory_ChangeDate`
- 影响：
  - 查询层和报表层需要按数据库访问模式设计

### 决策 7：`Person` 更像“人员/机构/往来方”

- 状态：`阶段性推断`
- 依据：
  - `TBPerson` 周边中文语义
  - 银行、保险、机构名称样本
- 影响：
  - 不要只建模为自然人联系人

### 决策 8：`Reminder` 至少支持阈值提醒

- 状态：`阶段性推断`
- 依据：
  - `TBRemindSetting` 周边字段：
    - `MinValue`
    - `MaxValue`
    - `IsRemind`
- 影响：
  - 提醒模型不要只支持日期型提醒

### 决策 9：贵金属不应简单并入证券

- 状态：`阶段性推断`
- 依据：
  - `ObjType = 10`
  - `TBPreciousMetals*` 独立对象族
- 影响：
  - 保留独立实体或独立扩展对象

## 3. 缓存层决策

### 决策 10：`MoneyHome8.cache` 偏搜索索引

- 状态：`已确认`
- 结论：
  - 至少包含：
    - 代码
    - 中文名称
    - 拼音/缩写索引
- 影响：
  - 投资品选择器至少支持代码/名称/拼音缩写检索

### 决策 11：`Investment.cache` 偏投资品分类字典

- 状态：`已确认`
- 结论：
  - `_3 / _4 / _9` 具有高可信分类意义
  - 且与 `MoneyHome8.cache` 有交集但并非简单重复
- 影响：
  - 需要单独的投资品目录缓存读取器

### 决策 12：类型码含义可先按高可信推断实现

- 状态：`阶段性推断`
- 当前推断：
  - `_3` / `ObjType=3`：交易型市场标的
  - `_4` / `ObjType=4`：场外基金/公募基金
  - `_9`：货币基金/现金管理类
  - `ObjType=10`：贵金属
- 影响：
  - 可先作为 Rust 枚举初版
  - 后续保留 `Unknown(i32)` 兜底

## 4. UI 信息架构决策

### 决策 13：至少有四个顶层工作区

- 状态：`已确认`
- 工作区：
  - 财务数据
  - 财务报表
  - 财务分析
  - 记账
- 影响：
  - UI 壳层不要做成单一平铺页

### 决策 14：`财务数据` 与 `记账` 应分开

- 状态：`阶段性推断`
- 结论：
  - 财务数据偏浏览/管理
  - 记账偏录入/执行
- 影响：
  - 不建议合并成同一工作区

### 决策 15：`财务报表` 是报表导航中心

- 状态：`已确认`
- 结论：
  - 至少包含：
    - 日常收支类
    - 资产负债类
    - 投资类
- 影响：
  - 报表工作区需要左侧导航树 + 右侧报表内容区

### 决策 16：`财务分析` 是预算/规划/目标中心

- 状态：`已确认`
- 结论：
  - 至少包含：
    - 财务预算
    - 财务诊断
    - 财务规划
    - 财务目标
- 影响：
  - 预算、规划、目标应归同一工作区

## 5. 迁移路线决策

### 决策 17：优先“旧数据可读，新数据可写”

- 状态：`已确认`
- 结论：
  - 当前阶段最稳妥的路线是双轨：
    - 旧账本只读导入/兼容
    - 新系统写入新格式
- 影响：
  - 不应把项目第一阶段绑死在 `mh8` 原位写回上

### 决策 18：Phase 1 已可启动

- 状态：`已确认`
- 结论：
  - 虽然主账本认证未打通，但：
    - 参考库
    - 缓存
    - 领域模型
    - 页面结构
    - 功能目录
    - 场景数据流
    已足够支撑 Rust 架构与读取器建设
- 影响：
  - 可以开始搭建正式模块和读取骨架

### 决策 19：新系统不需要复刻旧 `mh8` 表结构

- 状态：`已确认`
- 结论：
  - 重构目标应是功能与业务口径对齐
  - 不要求内部数据库继续与旧 Jet 表结构一一对应
- 影响：
  - 可以围绕 Rust 领域模型重新设计主存储
  - 旧账本兼容主要通过导入映射实现

### 决策 20：新主账本默认选 `SQLite`

- 状态：`已确认`
- 结论：
  - `SQLite` 最符合本地桌面、离线可用、单文件账本、事务可靠、部署简单这几个核心条件
  - `libSQL / Turso Sync` 作为未来同步增强可选项
  - `DuckDB` 作为未来分析副存储可选项
- 影响：
  - Phase 1/2 的仓储、迁移、导出、备份都围绕 `SQLite` 设计
  - 不把同步和重分析能力提前耦合进主账本
