# 账户与基础资料运行合同

本文把 B02 动态观察转换为 Rust 重构约束。旧 Delphi 类名只用于追溯，不作为 Rust 模块边界。

## 领域边界

### Account

账户至少包含稳定 ID、账户类型、名称、币种、所有者、备注、账户组、状态和创建来源。账户类型专属字段应通过有类型的配置对象表达，不能依赖窗体标题或稀疏通用字段猜测。

账户状态至少区分正常、隐藏、注销、到期和债权债务结清。隐藏属于显示状态，注销和到期属于业务状态，不能混为一个布尔值。

### AccountGroup

账户组是账户导航和汇总维度，不拥有账户生命周期。删除账户组只解除关联，不得级联删除组内账户。活期一本通、定期一本通和一卡通虽在 UI 中表现为组合账户，也必须显式区分组身份与子账户身份。

单账户修改组归属必须使用稳定 `account_id`、可空 `account_group_id` 和双方预期版本提交独立关系命令。选择器只修改草稿，取消零写入；确定时原子替换关系并从同一提交版本刷新账户概况、左侧导航、原组、目标组和组小计。真实样例把 `H-Current` 从 `Halifax` 移到 `CASH` 后，余额 `795.57`、`558` 条交易和资产/负债/净资产 `8,540,196.43 / 1,444,589.25 / 7,095,607.18` 均不变并通过冷启动，证明组归属不是余额事实，也不能与开户银行文本混用。

### OpeningBalance

期初状态包含日期、原币金额和可选资金来源账户。若选择其它资金账户，创建账户和资金转移分录必须原子提交；若选择账户自身或不考虑资金来源，则应保存显式来源类型，不能用空账户 ID 推断。

### PrepaidExpense

待摊费用不是普通账户备注，也不是一次余额调整的别名。`PrepaidExpense` 至少保存稳定主体 ID、账簿、账户、人员或机构、支出分类、原始金额、币种、业务日期、首次摊销日期、月频率、总期次、状态和乐观版本；每一期使用独立 `PrepaidExpenseInstallment` 保存期次号、到期日、确定金额、状态和可选已入账交易 ID。

创建页运行态已确认人员、名称、正金额、支出项目、正频率、正总次数和“已摊次数不超过总次数”校验。新版正常创建必须从零个已入账期次开始；旧字段“已摊销次数”只允许在受审计的兼容导入中作为迁移输入，运行态计数由已入账期次查询派生，不能直接修改计数而没有对应交易。

无资金账户样例 `100.01 CNY / 3期` 保存后创建独立资产账户和一条余额调整流入，资产与净资产各增加 `100.01`，没有同步生成支出项目交易。这一行为在目标模型中表达为显式外部期初来源；若选择真实资金账户，则必须在同一事务创建来源账户流出、待摊账户流入和主体期次，任何失败都不得留下单边余额。

旧概况页只允许修改名称、人员、业务日期和备注，币种、支出项目、金额、频率、首次摊销日期、总期次和已摊期次均只读。目标系统应保留这个普通资料更新边界；需要改变金额、分类或计划参数时使用独立计划重算命令，按主体版本锁定已入账期次，只重建允许变化的未来期次。

Finance Own 采用明确的目标尾差策略：前 `n-1` 期使用最小货币单位整数除法结果，最后一期吸收全部余数，保证期次合计精确等于原始金额。该策略必须版本化并写入测试，但在 MoneyHome8 真实到期执行和旧数据样本完成校准前，不把它描述为旧公式兼容结论。自动执行以 `prepaid_expense_id + installment_no` 作为幂等身份，已存在已入账交易时返回已有结果。

删除确认必须先返回初始资金事实、已生成摊销交易、未来期次、计划、标签和附件影响。旧版确认后物理级联清理账户与余额调整；新版可以采用冲销和审计保留策略，但主体、账户、交易、期次和投影必须在同一事务版本内达到一致状态。

## 资料管理宿主合同

资料管理是表示层路由宿主，不是独立基础资料实体。Rust 版应使用类型化路由表声明 `入口命令 -> 默认资料类型 -> 页面组件 -> 查询/命令权限`，不能依赖菜单对象、HelpContext、窗口标题或旧 Delphi 类名推断业务类型。

- 收支项目入口默认支出，人员与机构入口默认家庭成员，存款利率入口默认人民币；同会话重开和冷启动都重新使用入口默认值，不继承临时左侧选中态。
- 左侧切换只更新路由状态。收支和人员在同一列表组件内切换查询口径；金融产品切换会替换证券、基金、债券、贵金属、理财、期货或费率组件。
- 上市证券、开放式基金、证券交易费率和其它金融产品共用金融产品导航框架，但领域模型、权限、查询和写命令必须独立。旧版 `其它金融产品` 实际默认到货币基金，应作为兼容别名迁移，不建立重复实体。
- 重大资产、家居物品、币种与汇率和常用备注虽复用宿主外壳，但隐藏左侧类型栏；目标 UI 可以直接路由到对应工作区。
- 宿主关闭只处理页面生命周期，不提交业务数据。跨类型切换若存在未提交草稿，必须由子页面声明丢弃、阻断或确认策略。

## 开户向导合同

账户类型目录使用稳定 `AccountCapability` 和显式路由表描述分组、排序、创建策略、模式参数与可用性条件。中文标题和旧 Delphi 窗体类名只用于显示与迁移追溯，不能作为领域分派键。目录只创建目标向导草稿并导航，不写账户、期初事件或关系；多个显示入口可以复用同一创建策略，但必须携带明确模式参数。

所有开户向导实现统一草稿协议：

1. 每一步只修改内存草稿，不直接创建账户或分录。
2. 上一步保留已输入值，切换账户类型时必须显式确认是否丢弃草稿。
3. 完成前执行跨步骤校验，包括名称唯一性、币种有效性、账户组兼容性、金额精度和资金来源可用性。
4. 完成在一个事务内创建账户、类型专属配置、期初状态、组合关系和必要分录。
5. 取消、标题栏关闭、校验失败和持久化失败均不得留下半成品。

目录取消、标题栏关闭、未知类型、目标加载失败或菜单生命周期异常都不得留下半成品。菜单和窗口销毁必须与应用退出安全解耦；旧版在自绘子菜单检查后的特定关闭序列触发过 `EAccessViolation`，Rust 版需要为路由表、菜单模型和窗口生命周期建立明确所有权。

`TNewAcctWizardDlgFm` 已确认只是公共向导宿主：DFM 只有提示区和 `TWizardCtrl`，默认 `PageIndex=-1`，没有领域字段、业务分页或数据集。Rust 版应使用组合式 `WizardShell` 和步骤协议复用上一步、下一步、完成、取消、帮助、错误聚焦和提交中状态；具体账户向导拥有草稿、逐页校验、最终领域命令和幂等结果。公共宿主不得成为领域实体、数据库表或隐藏事务边界。

现金账户向导已验证两页草稿、必填和重名校验、标题栏取消、直接与内联成功提交及冷启动。直接提交 `12.34 CNY` 后业务事实已经持久化，但旧程序在刷新账户中心时先报 `closed dataset`，再报 `C0000025` 并退出。目标命令必须使用幂等键返回稳定账户 ID、版本和提交状态；投影刷新失败只能进入可重试状态，不能把已提交事务表现成未知结果或诱导重复开户。

普通现金、活期、银行理财和第三方储值账户共享“账户资料 + 期初状态”结构。活期一本通、定期一本通和一卡通需要额外的组合账户聚合服务，不能在 UI 层串联多个独立保存命令。

活期一本通已验证三页草稿和首次组合提交：组 `CodexCurrentPass-1537`、子账户 `CodexCurrentSub-1537` 与 `7.89 CNY` 期初事件在冷启动后同时存在，组小计精确等于子账户余额。`CurrentPassbook` 必须是有稳定类型的组合容器，不能与普通账户组混同，也不能保存可直接调整的独立余额；首次开户原子创建容器、首个子账户、关系和期初事件，后续子账户通过兼容性校验加入。旧程序同样在提交后刷新阶段崩溃，因此组合命令必须返回容器和子账户的稳定 ID、版本与可查询幂等结果。

普通活期账户已验证两页草稿、统一名称校验、标题栏取消、无账户组且无资金来源的 `23.45 CNY` 提交及冷启动。成功样例立即形成账户和一条 `余额调整` 流入，资产与净资产各增加 `23.45`、负债不变，并且没有出现现金和活期一本通向导的提交后崩溃。`CurrentAccount` 仍必须通过幂等事务原子创建账户、可选组关系、期初事件和可选平衡分录；`<无>` 账户组表示可空关系，`<无>` 资金来源表示外部期初，均不得映射成伪业务实体。

银行理财产品账户已验证两页草稿、必填与统一重名校验、账户自身/其它账户模式切换、跨页保持、标题栏取消、`250.00 CNY` 账户自身余额提交和冷启动。成功样例 `CodexMoney-2213` 使无账户组小计、总资产和净资产各增加 `250.00`，负债不变；双击账户行打开的编辑器允许维护名称、所有者、备注、创建日期、开户机构和默认资金账户模式，但币种只读。开户余额属于账户可用现金，不得自动生成银行理财产品或持仓；`BankWealthAccount`、期初事实、产品目录、持仓和产品事件必须分层。零金额的其它账户模式在未显示来源时仍可完成是旧版宽松行为，Rust 版应按金额和来源模式执行明确校验，非零真实来源必须原子生成双边平衡事实。

定期一本通已验证四页组合草稿和整存整取首次提交。存期从 `1个月` 改为 `3个月` 时，默认年利率从 `0.25%` 更新为 `0.80%`；成功样例 `1200.00 CNY` 的起存日为 `2026-08-01`、到期日为 `2026-11-01`、到期本息为 `1202.40`，与单利 `本金 + 本金 * 年利率 * 3/12` 一致并通过冷启动。`DepositPassbook` 是无独立余额的组合容器；`FixedDepositTerms` 必须固化存款类型、期限、起止日期、利率快照、计息口径和自动续存规则。利率目录只提供默认建议，后续更新不得重算既有存单；首次提交原子创建容器、子账户、关系、条款、期初事件和可选资金分录。

一卡通已验证两页外层组合向导和内联活期子账户向导。成功样例 `CodexOneCard-2255 + CodexOneCardCurrent-2255 + 88.88 CNY` 在账户中心和冷启动后保持父子层级，组小计精确等于子账户余额；总资产和净资产各增加 `88.88`，负债不变，证明 `OneCard` 是无独立余额的有类型组合容器。旧程序的内联子向导完成时会立即独立提交子账户，随后关闭外层向导只取消组创建，却把 `CodexOneCardChildDraft-2252` 遗留在无账户组；这是已复现的非原子提交缺陷。Rust 版必须优先把组草稿、子账户草稿、关系和期初事实放进一次幂等事务，只有外层完成才持久化；若为兼容流程保留内层提前提交，则必须显式定义保留、删除或重新归属的补偿命令及失败恢复状态。组名只与组名校验，已存在的普通账户名 `Cash-CNY` 可作为组名继续下一步，迁移和唯一索引不得臆定账户与账户组共用命名空间。定期子账户、选择现有子账户、多成员和跨组迁移仍是验证缺口。

家居物品账户已验证单页默认值、空名称和统一重名校验、投资/自用切换、标题栏取消、零余额开户、账户概况、账户编辑器、冷启动和归档回放。成功样例 `CodexItem-2334` 创建后账户行、物品工作区、成本合计和市值合计均为 `0.00`，总资产、负债和净资产保持 `8,540,196.43 / 1,444,589.25 / 7,095,607.18`；开户没有期初金额页，也没有自动创建物品主档、持仓、价格或交易。`HouseholdItemAccount` 只保存账户身份、币种、所有者、组关系、创建日期、资金账户偏好和 `investment/personal_use` 性质，物品余额必须从持仓批次和估值快照派生。编辑器把性质从自用改为投资后即时和冷启动均保持，币种只读且零投影不变；性质更新不得重写历史成本、交易或估值。名称仍使用账户与账户组统一约束，最终提交需要唯一索引、幂等键和可查询结果。旧程序还会自动刷新预存 `~$test` 恢复旁文件，Rust 版必须用带账簿 ID、版本、原因、完整性校验和生命周期的显式恢复快照代替。

第三方钱包账户已验证支付宝、微信钱包和其它储值模式入口。各入口复用同一两页向导，但携带显式子类型；基线已有同类型账户时，支付宝和微信钱包默认名称分别避让为 `支付宝2` 和 `微信钱包2`。第一步维护账户资料，第二步维护创建日期、期初余额和可选资金来源；空名称在切页前阻断，跨页往返保持草稿。支付宝草稿标题栏关闭没有创建账户；微信钱包样例 `CodexWeChat-0018` 以 `0.00 CNY`、无资金来源提交后不生成余额事件或改变汇总。其它储值样例 `CodexRT41Wallet` 以 `12.34 CNY`、无资金来源提交后生成一条外部期初余额调整，资产和净资产各增加 `12.34`、负债不变。旧客户端随后在刷新阶段报 `closed dataset` 并退出，但冷启动可查询完整账户和余额事件，因此开户命令必须使用幂等键返回稳定账户 ID、版本和明确提交状态，刷新失败只能重试投影查询。`ThirdPartyWalletAccount` 必须保存显式 `wallet_kind`，不能从账户名、窗体标题或图标猜测支付宝、微信钱包、财付通和其它储值；四种提供方复用通用账户、关系和余额事件表。零余额无来源只创建账户和类型配置，非零无来源创建外部期初事件，既有账户资金来源必须在同一事务生成双边平衡事实。`TThirdDepositsAcctDlgFm` 已确认既有账户币种只读，名称、所有者、备注和创建日期按稳定账户 ID 与预期版本原位更新；资料取消零写入，资料保存不改变余额或交易。开户与 `wallet_recharge / wallet_withdrawal` 是独立命令边界。

## 分类合同

`Category` 必须保存稳定 ID、收入/支出方向、名称、可选父级、排序、可见状态和系统预置标记。

- 父子分类必须保持相同方向。
- 系统预置分类不可被普通用户修改或删除，但可按产品规则隐藏。
- 已被交易、预算、计划或报表筛选引用的分类不能静默物理删除。
- 排序应保存稳定顺序键，并在单事务内重排；不能依赖当前列表行号。

## 人员与机构合同

`Party` 统一表达家庭成员、往来人员和机构，但 `PartyKind` 必须保留这三个旧版业务类别，不能把家庭成员与往来人员合并成无法还原的通用自然人。记录包含稳定 ID、名称、类型、可选联系方式、可选地址，以及人员适用的性别和可选生日。业务引用只保存 `party_id`，展示名称通过查询投影取得。

名称必填；旧窗体静态上限为名称 `20`、联系方式 `20`、地址 `40` 个字符。空白联系方式和地址在命令边界转换为 `None`。机构模式隐藏性别和生日，领域校验必须拒绝机构携带残留人员字段；家庭成员和往来人员允许生日为空。

生日使用 `PartyBirthday { calendar, year, month, day }` 保存用户录入分量。运行态确认历法为公历或农历：公历显示单一日期控件，农历显示年份、12 个月份和 30 个日期。农历 `1991 / 六月 / 初七` 在列表中以生日类型 `农历`、出生日期 `1991-06-07` 投影，因此导入和兼容层不得在没有明确规则时把它自动换算成公历日期。

空名称提示后保持草稿；标题栏关闭零写入；家庭成员、往来人员和机构共享账簿级名称空间，任意两类完全同名新增都会被拒绝。新增和修改成功后列表立即刷新并通过冷启动。创建和修改应按稳定 `party_id` 原子提交，失败不能留下半条资料。首尾空白、大小写、Unicode 归一化，以及隐藏或删除后的名称复用范围仍需动态校准。

列表查询必须显式接收 `PartyKind`、是否包含隐藏记录和可选搜索关键字。家庭成员与往来人员投影名称、性别、生日类型、出生日期、联系方式和地址；机构投影名称、联系方式和地址。搜索对当前投影显示字段做即时子串匹配，切换类别会清空搜索。空结果仍允许新增，但修改、删除和隐藏等依赖当前行的命令必须不可执行。

人员隐藏不应破坏历史交易、债权债务、保险关系或账户所有者引用。默认列表排除隐藏记录；包含隐藏视图必须明确标记隐藏名称并提供取消隐藏。删除命令必须先返回引用影响：存在引用时在确认前直接阻断；只有无引用记录才进入按家庭成员、往来人员或机构生成的删除确认，再在单事务中物理删除。

列表导出目标为 HTML，打印使用系统打印对话框。旧程序在取消 HTML 保存后仍误报“导出成功”；Rust 版必须以临时文件写入、关闭和原子改名的真实结果决定成功状态，取消不得产生文件或成功提示。打印取消不得创建打印作业。

## 币种与汇率合同

`Currency` 至少包含代码、显示名、精度、内置/自定义来源和可见状态。账簿本币使用独立的 `LedgerDefaultCurrency` 唯一关系保存，不能把本币标记混入全局币种主档；代码需要唯一且稳定。

`ExchangeRateQuote` 必须包含：

- 生效日期；
- 基准币种和报价币种；
- 报价方向；
- 十进制定点汇率；
- 来源、抓取或录入批次；
- 创建时间、版本和替代关系。

汇率换算必须显式使用报价方向和舍入策略。不能只保存“对人民币牌价”后在各页面重复猜测乘除方向。

运行态把 CHF 设置为本币时没有确认框或独立保存步骤，列表立即切换勾选并在冷启动保持；与此同时列标题和数值继续采用“对人民币牌价”。因此本币切换属于账簿级默认值写入，人民币只是旧行情目录的报价锚点，两者必须分离建模。Rust 版应在提交前显示跨账户、报表、预算、规划、同步和估值缓存的影响，并按账簿版本原子替换唯一默认币种；历史交易、冻结报表和已保存估值不得被无痕重写。

当前测试库只显示七个内置币种，选中 CNY 或 CHF 时修改、删除都禁用，页面也没有新增币种入口。`TCurrDlg` 仍存在静态保存处理器，删除处理器也包含本币和引用保护文案，因此目标领域需要内置币种保护和引用检查，但自定义币种来源、字段校验和真实删除语义在取得可编辑样例前不得标记为已兼容。

运行态已确认币种列表中的当前牌价与日期化历史共享同一有效报价：`2026-07-29 / USD/CNY` 从 `6.7894` 修改为 `6.7895` 后两个投影即时同步并通过冷启动；删除该最新记录后，两个投影同时回退到 `2026-07-28 / 6.7829`。因此当前牌价必须由最新有效历史查询产生，不能另存一个可独立漂移的字段。

修改汇率应按稳定报价 ID 和预期版本提交；删除必须显式确认并记录审计。删除最新报价后，在同一提交版本内选择下一条有效报价；没有剩余记录时返回明确的缺失状态，禁止沿用已删除值。`按日期显示全部汇率` 与按币种显示时间序列只是同一查询服务的两种投影，不得写回业务数据。

汇率唯一性至少覆盖账簿、日期、基准币、报价币和报价方式。本币标记写入与冷启动已确认，但跨模块重估影响仍待校准；现汇、现钞、在线牌价真实更新和价格整理影响也不得提前固化为兼容结论。

## 存款利率合同

`DepositRateRule` 由币种范围、储蓄类型、期限区间、年利率、生效日期、来源和版本组成。旧程序页面当前显示的数值只属于参考数据快照，Rust 版不得硬编码。

旧 `TRateFm` 的事件处理器只验证输入能否解析为数字，解析失败时静默恢复旧值；提交时把浮点百分比乘 `10000` 后取整写入，没有发现非负、上限或精度约束。目标系统改用 `ScaledValue` 和数据库整数加 scale：允许明确的 `0%`，拒绝负数、超过 `100%` 和超过 `12` 位小数，错误保留草稿并显示字段级原因。手工提交创建不可变版本，不能原位覆盖或依赖二进制浮点舍入。

在线更新必须先写不可变抓取批次，完成格式、范围和重复校验后再原子发布。失败、取消或部分响应不得覆盖最近有效版本。

## 标签合同

标签使用稳定 ID 和多对多关系关联账户、交易或其它支持对象。新增、排序、隐藏、移动和批量设置关系应分开建模。

标签主数据至少保存规范化名称、隐藏状态和乐观版本。单个新增与半角分号批量新增共用解析、唯一性读取和原子事务；修改按稳定 ID 原位更新，取消不写。旧版批量输入会过滤空分段、合并批次内精确重复，并在存在新名称时创建全部新名称、跳过已有名称；只有批次没有任何新名称时才提示重复。Rust 版应以一次预检和单事务复现该可见结果，显式返回 `created`、`existing` 和默认选择，不能逐项提交。删除前必须读取账户、交易和其它对象的完整引用图；无引用标签可确认删除，有引用标签不得静默级联删除关系。

隐藏/取消隐藏是可逆领域状态，`显示隐藏标签` 是独立查看偏好，两者均可持久化但不得改写标签关系或财务事实。标签页的交易记录、资产账户、查找、筛选、批量关系命令、导出和打印必须共享同一查询 DTO 与范围快照。

标签顺序使用独立的版本化偏好保存完整稳定标签 ID 序列。拖动只修改编辑草稿，确定时原子替换整份顺序；取消、并发冲突或写入失败必须保留旧版本。固定的 `<无>` 筛选项不属于标签主数据，不进入排序集合。排序不得修改标签名称、隐藏状态、账户/交易关系或任何财务事实。旧控件已证明子组件视觉坐标可以变化而内部排序草稿不变，因此目标命令必须返回已提交版本，并由标签页、选择器和冷启动查询读回确认，不能依据动画结束或控件位置显示保存成功。

旧“主题”资源视为标签兼容层，不建立第二套平行领域模型。迁移时需要保留旧 ID 到新标签 ID 的映射和引用完整性。

## 选择器合同

账户、分类和标签选择器只返回稳定 ID、当前候选版本或明确的空选择，不直接提交宿主业务对象。账户选择器由 `AccountSelectionSpec` 配置单账户/多账户、是否允许空值、是否允许内联新增、账户类型、状态范围、排除集合和上下文提示，不能在通用控件中硬编码工资、转账或保险规则。

单账户结果为稳定 `AccountRef`；多账户结果为有顺序的 `AccountAllocation { account_id, amount }` 列表。旧版工资选择器点击账户后动态显示金额编辑器，零金额确认提示 `请输入账户金额`，证明多账户选择不是无金额的 ID 集合。金额必须使用币种最小单位或定点十进制，并由宿主声明合计口径。

搜索页复用打开选择器时的同一候选查询快照。过滤文字只改变投影，不扩大候选范围；空态由实际查询结果驱动，不能因为旧 DFM 中存在“没有可用账户”面板就判断为空。

选择器内新增资料通过独立命令完成，成功后刷新候选并显式选中；取消或失败返回原选择草稿。旧版从转入账户打开 `TNewAcctTypeDlgFm` 后取消，会回到原选择器并保留外层转账草稿。

候选查询必须统一处理隐藏、注销、到期、已结清、账户类型、币种提示和宿主排除范围，避免不同页面各自拼接条件。通用选择器只保证候选身份有效；转出等于转入、跨币种策略、余额不足、产品约束和提交时版本冲突由外层领域命令校验。旧版转账目标列表允许选择来源账户和外币账户，选择 `Cash-USD` 后转账币种仍为 CNY，不能把旧候选列表当作完整业务校验。

分类选择器由 `CategorySelectionSpec` 配置允许方向、默认方向、是否跨方向搜索、是否允许内联新增、是否显示管理入口、是否包含隐藏或系统项目、是否允许选择父项和查询版本。选择结果必须是 `CategoryRef { category_id, direction, parent_id, version }` 或等价强类型；显示名称只用于呈现，不能作为交易方向、编辑器路由或数据库关联键。

旧版日常收支选择器的支出页创建 `22` 个候选控件，收入页创建 `12` 个；搜索 `其它` 会同时返回 `其它收入 / 收入` 和 `其它支出 / 支出`。搜索因此必须读取同一分类树快照并显式返回方向和层级路径。选择收入或支出结果后，父窗分别切换为日常收入或日常支出，但提交仍应保存显式 `transaction_kind` 并重新校验分类版本。

分类内联新增是独立命令。旧版即使从收入页点击新增，`TEditCategoryFm` 仍默认支出，这是已确认的方向继承缺陷；Rust 版必须传入当前方向，或在方向变化时要求显式确认。取消或失败返回原选择器和宿主草稿，成功后刷新候选并显式选中新分类。`[收支项目管理]` 在日常收支宿主中隐藏，其可见宿主和返回草稿策略仍待验证。

标签选择器由 `TagSelectionSpec` 配置是否允许空集合、多选、内联新增、隐藏标签、最大选择数量、候选作用域、查询版本和失焦提交策略。结果必须是有序且去重的 `TagRef { tag_id, version }` 集合；显示名称和分号拼接文本只用于呈现，不能作为关系键或持久化协议。

账户标签外层 `TSelectTagDlgFm` 已验证空态、标题栏取消、内联新增后回填、外层确定关联、清空解除关系和双冷启动。选择器内新增标签是独立主数据提交，只有外层确定才按稳定账户 ID、账户版本和目标标签 ID 集合写 `account_tag` 差异；外层取消不得写关系，也不得回滚已成功创建的标签。提交空集合只解除全部关系，不能级联删除标签主数据。关系变更不得改写余额、交易、账户状态、账户组或资产负债汇总。

过滤复用打开选择器时的同一标签候选快照，只改变投影。无匹配返回空集合，不回退到全部标签或创建占位对象。旧版日常收支宿主在失焦时把当前集合回填父级草稿，显式确定也执行同一动作；两者均不得绕过父级保存直接写交易或其它对象关系。

标签内联新增是独立主数据命令。旧版分号批量创建两个标签后关闭下拉，只默认选中批次第一项；Rust 版必须明确返回全部新建标签及默认选择策略，避免用户误以为整个批次已关联。空输入在写入前阻断；混合批次中的已有名称作为幂等已有结果返回，批次内重复只保留一项，全部名称已存在时返回 `no_new_tags`。数据库失败和并发冲突仍必须整体回滚；取消保持原候选和宿主草稿。父级取消不得回滚已成功创建且可能被其它对象引用的标签主数据，关系提交失败时保留标签并允许重试。

## 查询与投影

账户中心支持按账户类型和按自定义账户组两种投影，两者必须读取同一余额与估值快照。切换投影、显示隐藏/注销/到期账户只改变查询范围，不改变业务数据。

自定义账户导航顺序和显示状态属于独立偏好，不是账户组成员关系、账户状态或余额事实。偏好至少包含稳定账户 ID、显示标志、顺序、作用域和版本；全选、反选、上移、下移和单项勾选只修改草稿，确定时原子替换整份偏好。保存后只刷新导航树，不得改写账户、账户组归属、交易、余额、标签、附件或资产负债汇总。

账户概况是组合投影：通用账户字段、类型专属字段、余额、附件、标签和统计结果应由独立查询服务组合。概况页不得触发隐式重算或写回。

## 删除与引用保护

高风险删除流程必须先查询并展示影响范围。账户删除至少考虑交易、转账、债权债务、计划、附件、标签、组合关系和期初分录；分类、人员、币种和标签删除必须考虑全部引用。

删除和关联清理必须在一个事务内完成。失败时保留原对象及全部引用，不能用文件大小是否回退判断成功。

## 验证要求

Rust 实现进入兼容声明前，至少覆盖：

- 每种账户向导的有效、无效、取消、成功和持久化失败路径；
- 非零期初余额及其它账户资金来源的平衡分录；
- 组合账户多子账户、重复归属和部分失败回滚；
- 分类、人员、币种和标签的引用中删除与停用；
- 汇率方向、精度、重复日期币种对和跨币种舍入；
- 删除最新汇率后的有效值回退、无剩余报价和历史冻结投影；
- 利率版本、生效日期、在线更新失败和旧版本重算一致性；
- 账户中心两种投影与底部资产、负债、净资产合计一致；
- 自定义导航的批量选择、单项显示、顺序调整、取消、冷启动、并发冲突和失败原子回滚。
- 单账户组归属的取消、保存、解除关系、冷启动、组失效、并发冲突和失败原子回滚。
- 资料管理入口默认值、同会话重开、冷启动、跨类型草稿保护、权限显隐和键盘焦点恢复。
