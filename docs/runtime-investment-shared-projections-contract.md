# 投资公共能力与查询投影合同

本文把 B07 动态观察转换为 Rust 重构约束。目标数据库和表结构可以按新系统需要设计，不要求复制旧 Delphi 窗体或旧账簿表结构。

## 1. 领域边界

投资公共能力至少分为四层：

1. 交易事实：买入、卖出、申购、赎回、开仓、平仓、公司行为、费用、利息和调整事件。
2. 持仓事实：按账户、产品和成本批次追踪数量、成本基础及关闭关系。
3. 估值快照：在明确行情批次、汇率批次和估值时间下计算市值、浮动盈亏与仓位。
4. 查询投影：投资一览、构成图、历史盈亏、市值构成和报表。

旧程序中的 `TInvestmentListFm`、`TInvestmentChartFrame`、`THistoryProfitFrame` 和 `TMarketConstitutesFrame` 都属于查询或展示边界，不是独立持久化聚合。

## 2. 建议核心类型

```rust
/// 投资查询使用的不可变版本边界，保护列表、图表和汇总读取同一份数据。
pub struct InvestmentSnapshotRef {
    pub ledger_revision: i64,
    pub valued_at: chrono::DateTime<chrono::Utc>,
    pub quote_batch_id: QuoteBatchId,
    pub fx_batch_id: FxBatchId,
    pub reporting_currency: CurrencyCode,
}

/// 构成图切换只改变聚合指标，不能隐式刷新快照。
pub enum InvestmentAllocationMetric {
    CostBasis,
    MarketValue,
}

/// 费用和利息共享编辑字段，但事件类型必须显式保存。
pub enum InvestmentCashEventKind {
    Expense,
    InterestIncome,
}
```

## 3. 持仓调整

`TAdjustHeldDlgFm` 输入账户或资产、产品、调整后总成本、调整后数量、日期、标签和备注。Rust 命令必须：

- 读取当前数量、当前成本基础和持仓版本。
- 保存调整前值、调整后值、数量差额、成本差额和业务原因。
- 使用乐观并发检查，拒绝按过期快照覆盖期间新增交易。
- 原子写入调整事件、成本批次影响和审计记录，再重建投影。
- 禁止直接修改投资一览或账户余额的汇总字段。

## 4. 投资费用与利息

`TInvestFeeDlgFm` 被证券、基金、外汇、银行理财、期货和融资融券等域复用。应用命令必须显式传入：

- `event_kind`：费用或利息收入。
- `product_domain`：证券、基金、外汇、理财、期货等。
- 资金账户、账户币种、金额、日期、标签和备注。
- 跨币种时使用的汇率批次和折算金额。

不得从窗口标题、菜单层级或金额正负推断业务方向。资金分录、收益或费用分类、汇率快照和审计事件必须单事务提交。

两个 CNY 正常路径已真实校准：银行存款入口保存 `2.00` 利息收入会生成单边资金流入，外汇入口保存 `1.25` 其它费用会生成单边资金流出；两次都选择 `Cash-CNY`、自动锁定人民币 CNY，并在冷启动后保持余额和全局记录。旧列表对本位币行隐藏币种文字，且外汇费用行不显示来源上下文，因此领域事实必须显式保存币种、`event_kind` 和 `product_domain/source_context`。该结果不等于证券、基金、理财、期货或融资融券上下文已经全部兼容。

## 5. 投资一览和构成图

同一个 `InvestmentSnapshotRef` 必须同时驱动：

- 账户分组与持仓行。
- 总投入成本、总当前市值和总浮动盈亏。
- 按资产类别的成本构成与市值构成。
- 投资报表与导出快照。

必须满足：

```text
总浮动盈亏 = 总当前市值 - 总投入成本
构成图分组金额合计 = 当前模式对应的页面底部合计
单行浮动盈亏 = 单行当前市值 - 单行持仓成本
```

B07 样例已证明按市值图例合计为 `6,997,592.58`，按成本图例合计为 `4,778,184.00`，分别与页面底部金额一致。

## 6. 历史盈亏

历史盈亏行应关联实际关闭事件、来源持仓批次和资金现金流，至少包含：

- 业务日期、产品、活动类型、价格、数量和交易金额。
- 移出成本、分摊费用、实现盈亏和盈亏比例。
- 来源交易 ID、关闭事件 ID 和成本分配版本。

盈利合计、亏损合计和总盈亏必须来自同一结果集。筛选、列表、页脚、导出和打印共享同一查询快照。

## 7. 市值构成和变动

市值变动投影按产品输出今日市值、昨日市值、涨跌额和涨跌幅，并聚合当前仓位与总额。规则为：

- 今日与昨日必须使用明确的两个行情日期和各自汇率快照。
- 涨跌额不能混入当日净买入、净卖出或外部资金流；若产品要求展示总资产变化，应使用另一个指标名称。
- 昨日市值为零时，涨跌幅按显式空值或产品定义处理，禁止产生无穷值。
- 查询失败时保留最后成功快照，并显示数据时间与失败状态。

## 8. 存储建议

新 SQLite 模型可以围绕以下对象设计，而不复制旧表：

- `investment_instrument`
- `investment_transaction`
- `position_lot`
- `lot_close_allocation`
- `position_adjustment_event`
- `quote_batch` 与 `quote_observation`
- `fx_rate_batch` 与 `fx_rate_observation`
- `valuation_snapshot` 与 `valuation_position`
- `realized_profit_projection`

交易与成本分配属于事实数据；估值、构成图和盈亏列表可以按版本化投影重建。不要把图表 JSON 或页面合计作为唯一真相写入交易表。

## 9. 当前验证缺口

- 持仓调整真实保存、并发冲突和失败回滚。
- 证券、基金、理财、期货、贵金属和融资融券上下文的产品关联，外币折算和收益报表刷新；银行 CNY 利息收入与外汇 CNY 其它费用正常路径已验证。
- 用卖出、赎回和平仓样例校准实现盈亏、费用分摊和比例公式。
- 市值变动在当日发生交易、跨币种和缺失昨日行情时的口径。
- 有数据状态下的历史盈亏导出、打印、排序和钻取。
