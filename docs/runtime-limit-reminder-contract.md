## 3. Rust 领域模型

领域层使用枚举承载类型化条件，不允许业务层直接解释任意 JSON：

```rust
pub enum LimitCondition {
    AccountBalance { currency: CurrencyCode, lower: Money, upper: Money },
    CreditOverdraft { currency: CurrencyCode, threshold: Money },
    SecurityPrice { quote_currency: CurrencyCode, lower: Price, upper: Price, scale: u8 },
    OpenFundPrice { quote_currency: CurrencyCode, lower: Price, upper: Price, scale: u8 },
}
```

规则至少保存稳定规则 ID、账簿 ID、类型、稳定目标 ID、类型化条件、条件版本、启用状态、创建/修改时间。账户、证券和基金规则保存 `lower < upper` 不变量；货币金额按最小单位保存，行情价格保存十进制定点值和领域精度，不使用二进制浮点数。

规则创建默认启用。修改条件必须递增条件版本；启停只改变评估资格，不删除规则。规则删除、启停和当前告警重算需要在同一事务或同一版本化提交中完成，避免列表与今日提醒看到不同版本。

## 4. 评估与告警投影

评估器读取启用规则和同一版本的目标快照，输出幂等触发结果。触发键至少包含 `rule_id + condition_version + target_snapshot_version + boundary_kind`，防止页面刷新或重启重复制造同一告警。

触发实例冻结条件快照、观测值、差额、行情/余额快照版本、评估时间和公式版本。当前告警视图只投影仍有效且当前越界的规则；审计表不能因规则修改、停用或删除而改写历史。今日提醒把它投影为 `can_execute=false`、`can_skip=false`，后续可提供查看详情、确认或停用规则等明确能力。

评估调度必须显式实现并可测试。旧版已证明冷启动会刷新告警徽标和列表，但尚未证明保存后即时评估、固定轮询间隔、行情更新回调或等于边界的精确语义，因此这些策略不能标记为已兼容。

## 5. 引用与删除

目标账户或投资品删除、关闭、隐藏时，应用服务必须先预览受影响规则，再明确执行 `restrict`、停用并保留审计，或经确认级联删除规则；不得留下孤儿引用。自动化尝试删除临时信用卡时，旧窗口选择上下文指向了其它基线账户，操作已选择“否”安全中止，因此旧版真实引用删除语义仍未验证。
