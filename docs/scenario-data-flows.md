## 1. 新建/打开/关闭账本

### 场景目标

- 创建新账本
- 打开已有账本
- 关闭当前账本
- 切换默认账本

### 当前数据流

```mermaid
flowchart TD
  A["主界面操作"] --> B["账本生命周期服务"]
  B --> C["主账本文件 test.mh8 或新账本"]
  B --> D["程序配置 Moneyhome.ini"]
  D --> E["DefaultBook / Recent Book List"]
```

### 涉及对象

- `Ledger`
- `LedgerRepository`
- `DefaultBook`
- `Recent Book List`

### 已确认数据源

- `Moneyhome.ini`
- `test.mh8`

### Rust 落地要点

- 账本切换逻辑不能只改 UI 状态，需要同步：
  - 当前连接上下文
  - 最近账本列表
  - 默认账本配置

### 备份动态校准

- 备份页面读取当前账簿名、源路径、系统日期和默认备份目录；用户输入逻辑名称，旧程序固定追加 `.mh8k`。
- 空名称在写文件前被拒绝；目录选择取消保持原草稿；同名目标显示规范化完整路径并要求覆盖确认，选择“否”不改变已有文件。
- 成功样本是加密 7z 容器，内部单条 `BOOK` 声明长度与源账簿一致。旧容器只作为迁移输入，不能作为新版数据库或主备份结构。
- 新版数据流应为“在线一致性快照 -> 临时目录/临时文件 -> 数据库完整性检查 -> 附件与清单哈希 -> 原子改名 -> 成功结果”，失败或取消必须删除临时输出并保持源账簿可用。

### 还原动态校准

- 当前账簿还原页读取备份来源、当前账簿名和完整目标路径；当前可见目标固定为 `test.mh8`，没有显示新账簿名或目标模式切换。
- 空来源在关闭账簿前以 `00701` 拒绝；文件选择取消不改变来源；有效 `.mh8k` 提交后显示关闭当前账簿并覆盖数据的二次确认，选择“否”返回页面。
- 选择“是”后旧程序关闭当前账簿、恢复加密 `.mh8k` 内的账簿内容、重新打开当前账簿并报告恢复成功；完全退出后的冷启动可再次打开，账户余额和资产摘要抽查与基线一致。
- 旧程序本次没有生成可见的还原前自动 `.mh8k` 安全备份，成功报告也没有附件、设置、迁移和校验明细。新版数据流必须为“来源预检 -> 自动安全备份 -> 隔离临时目标解密/迁移 -> 完整性与内容清单校验 -> 关闭连接 -> 原子替换 -> 重开验证 -> 详细报告”。

### 结算动态校准

- 结算输入为截止日和恢复点完整路径。默认截止日为当天，默认恢复点名包含账簿名、日期和“结算备份”，格式固定 `.mh8k`。
- 旧程序的数据流为“选择恢复点 -> 生成加密账簿备份 -> 重写活动账簿 -> 生成同日余额调整 -> 成功提示”。文件时间证明恢复点先于活动账簿写入。
- 最近 1 月基线 `23` 条原始收支/转账记录在结算后变为 `78` 条余额调整；调整记录把账面余额归零，以真实余额形成差额，账户与资产负债汇总保持不变。
- Rust 版改为“影响预览 -> 二次确认 -> 一致性恢复点校验 -> `settlement_batch` -> 原始历史归档标记 -> `opening_balance_entry` 投影 -> 余额/持仓/计划校验 -> 提交报告”。原交易继续在线可查询，不复制只能还原外部备份才能看历史的限制。

### 账簿密码动态校准

- 无密码账簿设置页读取当前保护状态，只显示新密码和确认密码；受保护账簿增加旧密码输入。两次新密码不一致或旧密码错误时不改变保护状态。
- 旧程序把两个空新密码解释为清除保护。Rust 版数据流改为“选择设置/修改/清除 -> 显式确认清除意图 -> 验证旧密码 -> 校验新密码策略与一致性 -> 创建加密临时副本 -> 完整性检查 -> 原子替换 -> 清理密钥材料 -> 返回结果”。
- 冷启动打开受保护账簿时，只有正确密码才创建已解锁会话。空或错误密码保持锁定并进入受控重试；取消返回可操作的无账簿外壳，不加载账户投影或后台任务。
- 错误尝试只写脱敏安全审计和进程内退避状态，不写入交易事实；密码、派生密钥和输入长度等可识别秘密不得进入普通日志、截图、遥测或崩溃报告。

## 2. 账户中心浏览

### 场景目标

- 浏览账户组与账户树
- 按账户类型筛选
- 查看资产/负债/净资产汇总

### 当前数据流

```mermaid
flowchart TD
  A["账户中心页面"] --> B["AccountGroup / Account 查询"]
  B --> C["主账本 test.mh8"]
  B --> D["账户类型定义 TBAcctType"]
  B --> E["币种与名称 TBCurrency"]
  B --> F["汇总计算"]
  F --> G["资产/负债/净资产"]
```

### 涉及对象

- `AccountGroup`
- `Account`
- `AccountType`
- `Currency`

### 已确认数据源

- `test.mh8`
- 主账本对象线索：
  - `TBAcctGroup`
  - `TBAcctDetail`
  - `TBAcctType`
  - `TBCurrency`

### 运行态校准

- 账户中心按账户类型分组显示账户和小计，当前可见现金组 `9,487.88`、活期（卡折）组 `978,715.76`。
- 页面汇总资产 `8,535,534.04`、负债 `1,444,074.57`、净资产 `7,091,459.47`，满足资产减负债等于净资产。
- 概况页显示同一账簿净资产 `7,091,459.48`，比账户中心高 `0.01`，证明旧程序至少存在两条舍入或聚合路径。
- 新增账户组使用父编辑器承载名称，`详细资料...` 再打开二级编辑器承载联系电话、联系方式、密码和备注；空名称在二级窗临时显示为 `未命名`。
- 父窗空名称点击确定会在写入前提示 `请输入账户组名称`；关闭提示后编辑上下文保留，`未命名` 不会作为默认名称入库。
- 依次关闭二级窗和父窗后账簿文件大小与最后写入时间不变，说明打开窗口和取消草稿不产生业务写入。
- 有效详细资料在二级窗确认后只回传父草稿，文件时间保持不变；父账户组确认后才写入账簿。
- 删除账户组会永久删除组及其专属详细资料；若组内有账户，只清除关联并保留账户。真实样例中 `Cash-CNY 608.00` 删除组后进入 `无账户组`，原 `9` 条交易、累计流入 `15,708.00`、流出 `15,100.00` 和全局汇总均不变，冷启动保持。
- 已结清债权债务、到期、隐藏和注销账户使用四个独立查询开关。已结清、隐藏和注销在当前测试库会增加可见历史账户，到期无可见样例；所有开关只改变投影，不改变汇总。“显示注销账户”跨冷启动保持，目标实现应把该偏好存入用户/账簿视图设置而非账户状态表。
- 自定义导航编辑的数据流为“读取账户组/账户树和当前偏好版本 -> 在草稿中全选、反选、勾选或调整顺序 -> 确定时校验稳定账户 ID 集合与版本 -> 原子替换显示和顺序偏好 -> 刷新左侧导航投影”。真实把 `Halifax` 下移并隐藏 `H-Current` 后，导航立即变化且底部汇总不变，冷启动保持；上移并重新显示同样通过冷启动。标题栏关闭丢弃草稿，保存不得触碰账户组关系、账户状态、余额或交易。
- 账户右键菜单按状态动态切换“隐藏账户 / 取消隐藏”和“注销账户 / 取消注销”。恢复命令立即把同一账户转回活动状态；隐藏确认声明账户和交易不参与统计且不在其它页面展示，注销确认声明余额清零但历史交易保留。两个状态和查看偏好都能跨冷启动保持，目标数据流应为“读取账户及版本 -> 预览状态影响 -> 可选确认 -> 写状态事件 -> 刷新统一投影”，不得改写历史交易身份。
- 非零余额注销的真实数据流为“读取当前余额 `608.00` -> 新增等额流出余额调整 -> 余额归零 -> 写已注销状态 -> 账户组和净资产减少 `608.00`”；原 9 条交易不改写，新增清零记录使交易数变为 10。取消注销只写回活动状态，不撤销清零记录。Rust 版应使用明确的注销清零事件和操作 ID；状态恢复与财务冲销是两个独立命令。
- 账户标签数据流分成两个提交点：“选择器内新增标签 -> 立即写标签主数据 -> 回填外层草稿”和“外层确定 -> 比较目标标签 ID 集合 -> 新增/删除账户标签关系 -> 刷新账户行标签投影”。解除关系后标签主数据仍保留。标签关系变化不触碰余额、交易、账户状态、账户组或资产负债汇总，关联和解除均通过冷启动保持。
- 第三方储值开户数据流为“入口提供显式钱包类型 -> 两页草稿收集账户资料、日期、金额和可选资金来源 -> 最终确认原子创建账户、类型配置、可选组关系和期初事实 -> 返回稳定账户 ID、版本及提交状态 -> 刷新账户中心与财务记录”。`CodexRT41Wallet / 12.34 CNY / 资金来源<无>` 生成单条外部期初流入，资产和净资产各增加 `12.34`；旧客户端在提交后刷新阶段报关闭数据集并退出，但冷启动确认原事务成功。目标系统必须用幂等结果查询消除模糊提交；真实资金来源分支改为来源流出与钱包流入的双边事务。
- 标签主数据流为“输入单个或分号名称列表 -> 过滤空分段并合并批次内精确重复 -> 读取现有名称 -> 原子新增全部新名称 -> 返回 created/existing 和默认选择”，以及“按稳定标签 ID 和版本读取 -> 修改名称或切换隐藏状态 -> 原位更新 -> 刷新标签条和选择器”。整体空值阻断；混合批次跳过已有项并创建新项，全部已存在时提示重复。修改关闭取消；无引用删除先显示目标名并支持否/是。隐藏状态与显示隐藏查看偏好分离且均能冷启动读回，固定 `<无>` 不进入主数据命令。
- 标签页查询与关系数据流为“选择标签 -> 读取同一范围的交易/资产投影 -> 应用日期、账户、活动类型、关键词、金额和标签条件 -> 对选中稳定交易 ID 集合执行加入、移出或转移标签关系”。空选择提示 `请选择记录`；导入记录到标签先查询候选，再选择目标标签提交。导出和打印复用当前查询快照；旧程序两类导出取消仍误报成功，目标实现必须以真实文件提交结果决定反馈。
- 标签排序数据流为“读取可排序稳定标签 ID 集合、当前完整顺序和版本 -> 拖动或键盘命令修改草稿 -> 确定时校验集合与版本 -> 原子替换顺序 -> 刷新标签页和选择器投影”。固定 `<无>` 筛选项不进入排序集合；取消、冲突或失败保留旧顺序。`RT-02-015` 已验证 `A -> C -> B` 初始顺序、`C -> B -> A` 视觉位置、确定、同会话重开和冷启动；完整消息拖放只改变子控件坐标，三个读回点仍为原顺序，证明视觉位置不能作为内部草稿或持久化结果。真实物理拖放仍待解锁交互桌面补测。
- 单账户组归属数据流为“从账户概况读取稳定账户 ID、当前组关系和候选组版本 -> 在选择器草稿中选择可空目标组 ID -> 取消则丢弃 -> 确定时校验账户、原组、目标组和预期版本 -> 原子替换关系 -> 从同一提交版本刷新概况、左侧导航、原组、目标组和小计”。`H-Current` 从 `Halifax` 改为 `CASH` 后同会话与冷启动都保持，余额 `795.57`、`558` 条交易、开户银行和全局汇总不变；`<无>` 应解除关系，内联新增账户组必须作为独立提交点处理。
- 永久删除账户的数据流为“读取账户 ID、版本及完整关系图 -> 生成收支/转账/兑换/计划等影响快照 -> 用户确认 -> 原子移除业务可见账户与关联事实 -> 从剩余事实重算对手账户和全部汇总 -> 冷启动重建投影”。`Cash-CNY` 样例删除后全历史记录 `2,189 -> 2,180`，移除流入 `26,845.50`、流出 `30,708.00`；被删除事实净额 `-3,862.50` 对应净资产增加 `3,862.50`。目标账户自身流水合计不足以表达级联范围，禁止按当前余额直接增减总账。
- 账户附件数据流为“选择账户和源文件 -> 复制到受管暂存并计算 SHA-256 -> 写附件元数据和账户关系 -> 原子发布受管文件 -> 刷新附件计数、动态菜单和预览”。旧版实际路径为 `test/Account/23/原文件名`，打开和文件夹命令均指向受管副本。删除流程为“选择附件 -> 确认 -> 解除关系 -> 最后引用删除内容文件 -> 清理空目录 -> 刷新全部投影”；旧版删除后账户行计数要到冷启动才更新，目标实现必须在同一提交版本立即刷新并对数据库/文件不一致提供启动审计。
- 账户资料修改数据流为“按稳定账户 ID 和版本读取字段 -> 编辑草稿 -> 必填与规范化名称唯一性校验 -> 原位更新名称/日期/所有者/备注和版本 -> 重建排序及跨页面账户投影”。`Cash-CNY` 改名并增加备注后仍保留 `608.00` 余额、`CASH 9,495.70` 和相同全局汇总，只因名称排序移动行位置；空名称和精确重名都在写入前阻断。现金账户币种在既有账户编辑态只读，换币种不得作为普通资料修改。

- 选择器规格至少包含模式、允许空值、允许新增、账户类型、状态范围、币种提示、排除集合和查询版本；不同业务页通过规格裁剪能力，不复制选择器逻辑。
- 单账户只返回稳定引用；多账户必须返回 `账户 ID + 金额`。旧版零金额确认提示 `请输入账户金额`，证明金额分配是选择结果的一部分。
- 搜索只改变候选投影。空态由查询结果决定；失焦、关闭或内联新增取消保留原宿主草稿。
- 转账目标列表允许来源账户和外币账户，选择 `Cash-USD` 后外层转账币种仍为 CNY。来源/目标相等、跨币种策略、余额不足和版本冲突必须由外层命令在提交前统一校验。

### 收支项目选择器数据流

```mermaid
flowchart TD
  A["宿主提供 CategorySelectionSpec"] --> B["读取版本化分类树快照"]
  B --> C["支出页 / 收入页 / 跨方向搜索"]
  C --> D["返回 CategoryRef"]
  D --> E["宿主更新分类引用和显式 transaction_kind"]
  E --> F["提交前校验方向 / 状态 / 版本"]
  C -->|"新增"| G["独立分类创建命令"]
  G -->|"成功"| H["刷新快照并显式选中"]
  G -->|"取消或失败"| C
  C -->|"失焦或关闭"| I["保留原宿主草稿"]
```

- `CategorySelectionSpec` 至少声明允许方向、默认方向、跨方向搜索、内联新增、管理入口、隐藏/系统项目、父项可选性和查询版本。
- `CategoryRef` 至少包含稳定分类 ID、收入/支出方向、可选父级和版本。搜索 `其它` 同时返回收入和支出结果，说明方向必须是结果字段，不能根据名称推断。
- 父窗可根据选择结果即时切换日常收入或日常支出展示，但持久化必须保存显式交易种类，并在提交时重新校验分类方向和版本。
- 内联新增使用当前方向作为默认值。旧版从收入页新增仍默认支出是已证实缺陷；取消或失败必须恢复原分类、页签和父窗草稿。
- 搜索、页签切换和高亮只修改选择器草稿；无匹配结果返回空集合，不创建占位分类。

### 标签选择器数据流

- 账户树与账户汇总必须共享同一批源数据，不应由 UI 端重复拼装。

### Rust 落地要点

- 交易写入必须联动余额更新与后续统计刷新。
- 交易模板、主题、类型是独立对象，不应硬编码在页面里。
- 财务记录应由一个不可变查询 DTO 驱动列表、合计、图表和导出；筛选改变后旧导出结果必须失效。
- 查询 DTO 需要包含范围、日期、账户、活动类型、关键字、标签、金额条件、排序、分组、原币和本位币口径。
- 查找游标、批量选择和分组状态属于页面会话状态，不写回交易真相；批量业务命令通过显式 ID 集合进入应用层。
- 普通收支字段组件只维护内存草稿；父窗确定时在单事务中写入交易头、单侧账户分录、项目、标签、备注和附件关系，取消或失败时整体回滚。
- 本币切换服务按账簿版本原子替换唯一 `LedgerDefaultCurrency`，提交前返回账户、报表、预算、规划、同步和估值缓存的影响预览，提交后使依赖投影失效。历史交易、冻结报表和已保存估值继续引用原币及原汇率快照。汇率命令服务使用稳定报价 ID、业务键和乐观版本；删除最新报价后在同一提交版本中重建当前牌价投影，没有下一有效记录时返回缺失状态。估值服务按日期和报价方式选择版本。
- 记账菜单只负责命令发现和上下文传递，工资、存取款、转账和专项交易的校验与事务由各自应用服务负责。工资应用服务还必须锁定币种、收入账户、人员和社保账户版本，使用受检整数汇总三组明细，并在任一组成失效时保留完整草稿。
- 同币种转账服务以一个业务命令写入来源本金、目标本金和手续费组成；来源账户投影可合并为总流出，但费用报表、审计和退款仍能单独定位手续费。
- 取款服务使用同一余额版本读取可用资金并提交来源本金、目标本金和费用；来源承担费用时来源总流出为 `本金 + 手续费`、目标只增加本金、净资产只减少费用。“全部取完”仍需独立验证后再固定计算规则。
- 余额调整使用 `account_id + currency_id + effective_date + balance_version` 执行乐观并发。默认策略把真实余额、基线账面余额和差额共同写入调整审计事件，修改使用稳定调整 ID 和预期版本，删除使用可审计撤销。`日常收支` 策略只在转换事务中读取基线和计算差额，随后按 `delta < 0` 创建显式普通支出，否则创建显式普通收入，并保存差额绝对金额和稳定对账分类；零金额事实仍须持久化并进入查询、审计、迁移和删除生命周期，金额投影忽略其数值影响。保存并继续必须提交后重新读取余额版本，不能沿用旧显示状态。对账分类和系统对手关系必须显式映射，不能从显示文字猜测。分拆收支由应用服务检查双集合平衡后再提交。
- 持仓调整使用持仓版本执行乐观并发，并保存调整事件后重建投影；钱包充值/提现、银行利息和货币兑换均按显式业务动作路由。钱包命令校验稳定账户 ID、账户状态、币种、正金额、可用余额、余额版本和幂等键，再在单事务中提交交易头、两侧本金分录和费用组成；费用分录归属资金发出侧账户，接收账户只取得本金，失败时保留草稿且不留下单边写入。
- 货币兑换和外汇买卖应在单事务中保存两侧分录、稳定账户与币对、报价展示方向、未舍入规范牌价、隐含或显式成交汇率、两侧最终金额、舍入结果和可选汇兑损益，禁止单边成功。货币兑换要求两侧账户 ID 和账户币种都不同；外汇账户内部买卖可保留同币种兼容草稿，两类命令不能共用错误的同币种规则。所有选择器必须提交稳定 ID 和版本，显示文本不参与身份解析。应用层使用明确的 `base_currency/quote_currency` 与 `sell_currency/buy_currency`；显示方向切换从同一规范十进制牌价生成双向显示，不能倒置已舍入文本，也不能改写交易腿。成交汇率只解释交易，账户组和报表使用带时间、来源和版本的估值汇率；跨币种合计必须按原币分组或统一折算，禁止直接累加名义金额。
- 报销应用服务必须锁定或版本校验垫付记录的未报销余额，并原子写入报销交易、收款分录、逐条核销关系、借款抵扣和债权余额投影；幂等键用于阻止重复提交。
- 导出先生成项目目录内临时文件，校验成功后原子替换目标文件；取消或失败时删除临时文件并返回准确状态。

### Rust 落地要点

- 债权债务不是普通收支的备注扩展，而是独立业务域。
- 借入/借出命令创建带方向的合同、本金和资金分录；预付/预收创建可核销或冲销的往来余额，不能在收支分类中直接抹平。
- 收回/返还把本金与利息分开：本金调整债权债务余额，利息进入收入或费用，资金账户按本息合计收付。
- 提前收回/返还必须以合同版本读取剩余本金、剩余期数和每期金额，并按处理方式重算未来计划；计划更新失败时结算交易也必须回滚。
- 债权坏账确认损失，债务坏账确认豁免收益；坏账金额受未结本金和版本约束。
- 垫付产生可报销来源明细，报销通过显式核销关系消费明细余额，预防重复报销和双重费用确认。
- 信用卡账单日、还款日和提醒属于独立规则流。
- 信用卡取现写入负债增加、目标账户流入和手续费；信用卡还款写入资金来源流出、本金减少和利息费用，并在同一事务刷新可用额度。
- 信用卡还款总额由本金与利息确定性计算，不能把利息混入本金或只更新页面显示值。
- 待摊费用应作为跨期费用子域处理：创建时写入主体、初始支出和计划，后续每期摊销命令必须幂等并留下来源关系。
- 垫付记录与报销不是备注关联：每条核销关系必须记录来源垫付、核销金额和报销交易；实收账户合计与借款抵扣共同平衡报销金额。

- `RT-14-005` 校准样例要求：费用金额必须大于零，支出项目默认 `资产费用` 但引用完整支出类别体系。`0.50` 外部支付只创建资产费用和绩效损益，不改变成本、市值、资金账户、资产或净资产；随后绑定 `Cash-CNY` 支付 `0.25`，同一业务事件必须同时减少资产累计收益、现金账户、全账簿资产和净资产 `0.25`，负债不变。资产页、现金账户页和全局财务记录必须引用同一费用事件。
- `RT-14-006/010` 校准样例要求：市值快照按稳定资产 ID 和估值日期唯一保存。跨日 `2026-08-03 / 0.00` 新增独立历史点；修改只改金额；同日再次添加从 `2.50` upsert 为 `3.00` 且不增加行数；删除最新点后回退到最近较早日期。估值从 `1.00` 变为 `2.50` 时，成本和累计收益不变，`Cash-CNY` 与负债不变，资产和净资产各增加 `1.50`。快照、当前值、趋势、构成、账户中心和净资产必须共享同一业务版本。
- 物品需要数量与成本批次，买卖改变数量和资金，价值变更只产生重估事件及未实现损益。
- 重大资产工作区的统计表、市值历史、趋势、成本/市值构成和概况必须读取同一资产选择与估值快照；同日 upsert 保存覆盖审计，删除最新值按日期回退；跨币种资产先按快照汇率折算，再生成总额和构成占比。
- 物品主数据流为 `分类 -> 物品主档 -> 价格快照`，账户与交易只引用稳定 ID。物品买入创建数量和成本批次，卖出结转数量与成本，价值变更新增估值事件，不得直接覆盖主档现价或历史交易。
- 物品账户永久删除会级联影响关联收支、转账和财务计划，目标系统必须先展示影响清单，再在单事务中删除或明确拒绝；取消和失败不得留下部分清理。
- 保险账户聚合保费、返还、分红、现金价值和退保结算；退保与保单终止共享事务但保持两个可审计动作。
- 证券成交统一拆为标的数量变化、成本批次、成交毛额、分项费用和资金净额；卖出再按成本分配生成已实现损益。
- 新股申购以申购聚合跟踪冻结、返款、中签和可分离债权证，任何结算步骤都引用同一业务标识和版本。
- 送股、缩股和现金红利属于公司行为：前两者重建数量与单位成本投影，后者生成资金收入；三者都保留除权/到账规则与来源证券。
- 权证行权、债转股和债券到期是跨标的转换或持仓终止事务，必须原子保存来源持仓减少、目标持仓增加、成本转移、现金尾差及收益。
- 投资费用、资金利息、债券利息和证券红利使用明确事件类型，报表层可聚合但交易真相层不得合并。
- 开放式基金成交由交易时净值、收费模式、费率、费用、金额和份额共同决定；净值与费率快照属于交易证据，不由最新行情或配置覆盖。
- 新基金认购聚合冻结本金、认购期利息、中签份额、费用和返款，并以状态机和幂等键完成结清。
- 基金拆分只改变份额和单位成本；现金分红生成资金收入；分红再投资确认收益并增加份额，三种事件使用不同现金流语义。
- 基金转换以单一事务连接来源持仓与目标持仓，保存两侧基金类型、净值/本金、份额、费用、成本转移和舍入尾差。
- 货币基金采用本金与累计收益投影，申购按金额、赎回拆分本金和利息、红利再投资结转收益；不套用开放式基金净值费率公式。
- 债券交易将净价资本流、应计利息流和费用流拆分；持仓成本不吸收购入应计利息，资本利得不混入卖出应计利息。
- 债券卖出、正常到期和提前兑取共享持仓结转能力，但使用不同条款、现金流和损益规则，并保留终止原因。
- 银行理财以产品条款与持仓本金为核心，申购增加本金，赎回以实际收回金额减本金形成收益，分红不减少本金。
- 债券利息与理财分红可共享编辑器和资金收入管道，但业务事件类型、产品引用和统计口径必须显式保存。

### 5.1 外汇账户与交易

运行态已确认外汇账户采用三步创建流程：先写账户名称、本位币、所有者、备注和账户组，再写期初余额、日期和资金来源，最后按币种补充初始持仓及各自资金来源。账户创建、期初资金分录和分币种持仓必须作为一个业务事务提交；任一步取消都不应留下半成品账户。

```mermaid
flowchart TD
  A["外汇账户向导"] --> B["账户主数据与固定本位币"]
  A --> C["期初余额与资金来源"]
  A --> D["附加币种与初始持仓"]
  E["外汇买卖/转账/费用/利息"] --> F["交易头与双边分录"]
  G["手工牌价/在线行情"] --> H["带方向和来源的牌价快照"]
  B --> I["外汇账户查询投影"]
  C --> I
  D --> I
  F --> I
  H --> I
  I --> J["余额/本位币折算/构成图"]
```

外汇买卖显式输入卖出币种、买入币种、交易汇率和两侧金额；`6.00 CNY × 0.1473 USD/CNY = 0.8838 USD` 在旧界面金额端显示为 `0.88 USD`，保存后全局记录以同一“外汇买卖”展示流入 `0.88`、流出 `6.00`。真实方向点击显示直接 `0.1473`、反向 `6.7894` 且交易腿不交换，说明两种四位显示必须来自同一未舍入规范牌价。CNY/CNY 被选择器接受并归一为 `1.0000`，零金额提交进入“卖出金额必须大于零”校验；正金额提交仍待验证。两侧金额都作为可编辑字段暴露，但不一致值能否保存仍待验证；规范牌价、成交汇率、两侧最终金额和舍入差额都属于交易证据，不能只保存界面汇率后重算，也不能被之后的市场牌价覆盖。手工市场牌价窗体只提交有效日期、有序的两个币种 ID 和四位汇率，报价说明由币种顺序派生；旧对象按 `rate * 10000` 保存整数，编辑时除以 `10000` 回填。目标模型用 `ExchangeRateVersion(quote_id, currency_1_id, currency_2_id, effective_date, rate_scaled, scale, source, quote_kind, version)` 承载事实，展示标签由查询层生成。当前持有与全部交易过币种是两个查询范围，余额、牌价、折算合计和构成图必须共享同一已发布估值快照。校准账户的统计投影显示 `0.88 USD / 6.7894 / 5.97 CNY` 与 `94.00 CNY / 1.0000 / 94.00 CNY`，合计 `99.97 CNY`；构成图直接复用两个折算金额。交易查询同时保留币种范围和日期范围，余额调整可映射为单侧腿，外汇买卖必须映射为双侧腿，修改或删除后按原查询参数原子刷新持仓、明细、合计和构成。

外汇账户资料修改数据流为“按稳定账户 ID 和预期版本读取 `Account + ForeignAccountProfile` -> 编辑名称、日期、固定币种、所有者、备注、开户银行和账号草稿 -> 校验名称、日期、唯一性及币种 -> 原子更新主档与扩展资料 -> 从同一版本刷新账户树、概况、选择器和工作区”。新增默认绑定账簿本币，编辑态禁用币种；银行和所有者使用可空稳定 ID，账号最长 50 字符。余额、分币种持仓、交易、牌价和估值不进入该命令，换币种必须走独立迁移流程。

持有外汇调整读取当前账面余额和版本，以真实余额减账面余额形成差额事件。删除账户先读取关联收支、转账、计划和其它关系，展示级联影响，确认后单事务删除或归档并刷新账户中心；本轮临时账户逻辑删除后 Jet 文件增长 `20,480` 字节，说明验证不能依赖文件长度回退，而应验证对象、关系和查询投影均已清理。

### 5.2 现货贵金属账户、产品与交易

现货贵金属账户先创建账户主数据和固定币种，再保存期初资金来源。产品目录与按日价格快照独立维护；买入或卖出通过产品 ID 引用目录，通过成交价格引用或固化交易证据，后续行情只能改变估值，不能覆盖历史成交。

### Rust 落地要点

- 规划域最好单独建子模块，不和普通预算/提醒揉成一团。
- 所有专题编辑器先修改规划草稿，最终统一生成年度结果；单个对话框取消不得留下部分输入。
- 资产购置必须同时表达一次性/分期资金流、首付、利率、月供及购置后收入和支出。
- 家庭资料决定规划年度范围。`1990` 年出生、预计寿命 `85` 的受控样例生成 `2026..2075` 共 `50` 个年度；有配偶时需并列保存配偶出生年份和预计寿命，并按家庭寿命边界生成结果。
- 零增长受控样例中，年工资 `120,000.00`、家庭年日常支出 `60,000.00` 使年度余额按每年净增加 `60,000.00` 递增，并在冷启动后保持；这只校准了基础年度收入减支出，不能外推通胀、退休、分期购置和资产增长的复利顺序。
- 年度图、健康状态和纵轴缩放属于可重算展示。目标实现必须保留逐年数值、输入快照、账户/估值快照、公式版本和计算时间。
- 目标进度读取账户余额或投资估值投影，不得把显示进度保存为不可追溯的真相值。
- 受控目标 `Codex-Goal-Probe-20260729` 的期间为 `2026-07-29..2026-10-29`，目标金额为 `1,000.00`，所选账户聚合值为 `-550,000.00`；在起始日，初始值、实际进度和标准进度均显示 `-550,000.00`，证明负初始值有效且创建时账户估值是三者共同起点。
- 创建时必须保存初始总值、估值时间和逐账户输入快照。标准进度可能由初始值向目标金额按期间推进，但目前只有起始日等值被动态确认，线性内插及舍入规则仍属于待校准推断。
- 诊断、规划和目标共享账户与估值服务，但公式版本、输入快照和计算时间必须可追踪。
- 财务诊断支持账簿统计和持久化手工输入两种来源。诊断年总支出为消费、还款和保费之和，排除储蓄支出；储蓄性支出为保费与储蓄支出之和；月收入和月支出按年值除以 `12` 后先舍入到 `4` 位小数。
- 定期和货币基金的资产性质只重分类流动资产和投资资产，不得改写账户余额、总资产、总负债或净资产。
- 十二项诊断结果是可重算投影；业务阈值、建议文案版本和图表缩放范围必须分开建模。

- 预算创建先确认名称和频率，再确认分类范围；目标命令必须原子保存两部分或使用不进入有效列表的显式草稿。

- 实际支出从交易事实重建。执行率在预算大于零时按 `actual / budget * 100` 四舍五入为整数且不封顶；零预算按实际是否为零显示 `0%` 或 `100%`。
- `2026-08-02` 的导入读取 `2025-08` 至 `2026-07` 共 12 个完整月份，按月份编号写入目标年度 2026 的 1 至 12 月列，并无确认覆盖手工额度。目标实现必须返回来源年月、目标年月和覆盖差异预览，再原子保存导入批次和新额度。
- 单元格复制只覆盖勾选月份的同一分类；整列复制覆盖勾选月份的全部分类；跨年度复制读取同一预算来源年度的逐月分类额度矩阵。没有当前单元格选择时，前两项命令禁用。
- 尚无额度的未来年度在旧版中以前一年度十二月分类额度铺满十二个月。复制子对话框只更新父级编辑草稿，父级确定后才持久化并跨冷启动保持。
- 分类移除会删除该分类全部月份额度，重新加入从零初始化；目标命令必须预览受影响月份和额度，不能把它实现成可逆隐藏。
- 收入和支出共用十二个月额度网格，但主页独立展示总收入和总支出；网格页脚净额是额外派生投影。受控样例为收入 `17.89`、支出 `43,660.70`、净额 `-43,642.81`，并已跨冷启动保持。
- 冷启动从预算持久化数据与交易事实重建同一投影。预算页面不得维护第二套实际支出真相。
