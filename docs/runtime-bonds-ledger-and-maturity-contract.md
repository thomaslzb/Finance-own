# 债券账本与到期合同

本文把 B10 动态观察转换为 Rust 重构约束。SQLite 表结构和界面可以重新设计，但必须保留债券资料、净价/全价、应计利息、账户资金来源和终止事件的业务边界。

## 1. 领域身份

债券、发行人、账户、交易和估值批次必须使用稳定 ID，债券代码和名称只用于展示与检索。

```rust
/// 债券身份不随代码或显示名称调整而变化。
pub struct BondId(pub uuid::Uuid);

/// 交易价格必须标明是净价还是全价，避免在 UI 或报表中重复计息。
pub enum BondPriceBasis {
    Clean,
    Dirty,
}

/// 债券结束方式决定收益确认和持仓关闭规则。
pub enum BondTerminalEvent {
    MarketSale,
    Maturity,
    EarlyRedemption,
}
```

旧窗体不是数据库实体。`TMarketDebtTransFm` 及其 Frame 应映射为命令和查询投影，而不是复制为多套事实表。

## 2. 债券目录

债券目录至少保存名称、代码、币种、发行人、发行日、到期日、票面年利率、债券类型、付息月日、面值和免税状态。当前版本面值只读为 `100`，但新模型不应把 `100` 写死到所有债券类型；应以产品规则或债券主数据版本约束。

- 名称必填，代码唯一性按业务市场规则校验。
- 发行日不得晚于到期日，付息日必须能映射到有效票息期间。
- 债券类型候选和免税适用范围尚未完整校准，不能凭推测硬编码。
- 被交易、持仓或计划引用的债券不得物理删除；更正主数据要保留版本和审计。
- 发行人、币种和日期规则必须由领域层校验，不能只依赖控件禁用。

## 3. 账户与资金来源

债券账户至少保存名称、币种、所有者、备注、创建日期、账户组、开户机构、账号、默认资金账户、标签和附件。创建后币种锁定；已有交易时不得通过后门改变币种。

“账户自身”表示债券账户维护独立可用资金；“其它账户”表示交易资金通过可追溯双边转账进入或流出。账户创建、初始余额、资金来源关系和审计事件必须同事务提交。

账户删除必须检查交易、持仓、转账、计划、标签和附件引用。旧软件会级联删除相关记录，新系统应默认采用软删除或显式级联预览，并把受影响对象、确认人和时间写入审计。

## 4. 买入与卖出

买入和卖出保存原始净价、应计利息、数量、金额、费用分项、资金账户、日期、标签和备注。建议使用不可变交易事实与独立资金分录：

```text
全价 = 净价 + 单位应计利息
结算价款 = 全价 * 数量 * 面值换算因子
买入资金流出 = 结算价款 + 买入费用
卖出资金流入 = 结算价款 - 卖出费用
已实现盈亏 = 卖出净收入 - 已分配资本成本 - 已分配费用
```

上式中的报价单位、面值换算因子、应计利息单位、舍入和税费仍未通过真实保存样例校准，必须作为版本化策略保存。购入应计利息不能直接并入资本成本后丢失，卖出应计利息也不能重复计入票息收益。

## 5. 利息与应计

债券利息事件至少保存债券、债券账户、资金账户、金额、日期、标签和备注，并关联票息期间。利息收入、购入应计、卖出应计和税费必须分开记账，以支持税务口径和收益归因。

- 同一债券、账户和票息期间的重复入账应被检测或明确标记为更正。
- 免税标记影响税费策略，不应覆盖原始毛利息。
- `TNMarketBondInterestDlgFm` 还会被银行理财分红上下文复用；Rust 端应复用收益命令基础设施，但以产品类型区分规则和文案。

## 6. 到期与提前兑取

正常到期、提前兑取和市场卖出是三种不同终止事件：

- 正常到期使用全价、数量和金额，通常关闭对应持仓并确认本金和最后一期利息。
- 提前兑取使用净价、应计利息、数量和金额，可能只关闭部分持仓，也可能适用独立罚息或费用策略。
- 市场卖出使用净价、应计利息和交易费用，收益来源是市场处置而非发行人兑付。

每种终止命令都必须原子更新交易事实、资金分录、持仓数量、成本批次、应计利息、收益和估值失效标记。任一校验失败时不得只关闭持仓或只增加资金。

`TStockBondMatureDlgFm` 属于上市证券账户中的债券到期入口；它可以共享到期领域命令，但必须携带证券账户前置条件和来源上下文，不能把纯债券账户与上市证券账户静默合并。

## 7. 持仓、估值与历史盈亏

持仓投影至少返回债券、数量、投资金额、面值、年利率、年限、到期日、市值和占比。交易投影必须保留净价、应计利息、数量、费用、金额、活动类型和余额。

同一个估值引用必须驱动持仓、页脚、成本市值构成、历史盈亏、导出和打印：

```rust
/// 防止持仓表、图表和盈亏页混用不同账簿或价格批次。
pub struct BondValuationRef {
    pub ledger_revision: i64,
    pub price_batch_id: PriceBatchId,
    pub fx_batch_id: FxBatchId,
    pub valued_at: chrono::DateTime<chrono::Utc>,
    pub reporting_currency: CurrencyCode,
}
```

缺行情、过期行情、到期未处理、负持仓、零面值、跨币种和部分兑付都必须显示明确状态。空账户返回空集合和零汇总，不得用缺失字段表示成功。

## 8. 原子性与审计

所有写命令必须在单事务内覆盖：

- 债券或账户聚合版本。
- 交易事实和资金双边分录。
- 持仓与资本成本批次。
- 应计利息、票息、费用和税费分项。
- 标签、备注和附件关系。
- 估值失效标记和审计事件。

“保存并继续”和“确定”必须调用同一个领域命令；前者只改变保存后的 UI 生命周期。修改、删除、余额调整和持仓调整也必须复用领域校验并使用乐观并发版本。

## 9. 当前验证缺口

- 债券类型完整候选、代码唯一性、发行人维护和主数据删除限制。
- 净价、全价、应计利息、面值换算、费用和舍入公式。
- 真实买入后持仓成本、卖出后已实现盈亏和票息归因。
- 正常到期、部分到期、提前兑取和最后一期利息的状态机。
- 免税债券、税费和跨币种资金账户规则。
- 行情来源、缺行情、历史价格和估值批次。
- 导出、打印、搜索、附件、并发修改和失败回滚。
