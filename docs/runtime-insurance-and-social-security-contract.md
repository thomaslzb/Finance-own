# 保险与社会保障 Rust 开发合同

## 1. 证据边界

本合同覆盖 B13 的商业保险、社会保险、现金价值、交易工作区、缴费计划和账户投影。页面结构、空状态、代表性账户创建/删除、取消路径，以及商业保险非零已缴保费开户、真实缴纳保费、真实保费返还、真实保险分红、真实退保并分别保留或终止账户、现金价值同日新增覆盖、修改保存、唯一快照删除、两日期删除最新值和删除非最新值、历史与未来估值日、仅提醒计划跳过、固定账户计划执行、独立计划修改、两缴费年度半年重算、冷启动自动入账及资金/保险双边投影已有动态证据；现金价值和自动缴费复测均暴露旧程序跨组件、跨重启的读模型不一致。业务日期来源、跨月/跨年/时区、收付异常、退保边界、其它频率边界、自动提交精确时点和公式仍属于待校准项。

`TInsureBalaInDlgFm` 与 `TInsureBalaOutDlgFm` 在 MoneyHome8 8.50.0.0 中没有发现用户可达入口，现行现金价值由 `TInsureCashValueFrame` 和按日期编辑器维护。Rust 不复刻两个不可达旧对话框，但迁移层必须能识别旧数据可能表达的价值增减事实。

## 2. 领域对象

- `InsurancePolicyAccount`：稳定 ID、账簿、名称、币种、险种、保单号、机构、投保人、被保险人、受益人、起止日、缴费统计口径和状态。
- `PremiumSchedule`：保单及条款版本、频率、应缴金额、资金账户、执行策略、开始/结束条件和版本；由保单拥有，中央列表只提供投影。
- `PremiumScheduleOccurrence`：计划版本、应期日、策略快照、金额和账户快照、状态、幂等键、处理动作、关联保险事件/资金交易及失败信息。
- `PremiumExecutionDraft`：从到期实例生成的可审阅草稿，冻结保单、支付账户、金额、日期、标签和来源备注；打开草稿本身不产生账务事实。
- `InsuranceCashValueSnapshot`：保单账户、估值日、现金价值、来源、录入批次和审计版本；同一账户同一日期只有一个有效值，重复新增按可审计 upsert 更新。
- `InsuranceEvent`：缴纳保费、保费返还、分红、退保、费用和迁移导入；事件类型不能由金额正负推断，退保还必须记录提交时的 `finish_account` 选择。
- `SocialSecurityAccount`：参保人、地区、社保编码、项目类型、币种、账户组和统计口径。
- `SocialSecurityEvent`：缴费、领取、调整和迁移导入，必须关联具体社保项目。

## 3. 账户与计划规则

1. 商业保险开户创建账户、保单条款和可选缴费计划时必须单事务提交。
2. “仅做提醒”允许不绑定资金账户，并生成不可执行、可跳过的计划实例；跳过只写实例动作，不生成保险事件或资金交易。
3. “固定账户定期扣款”必须绑定有效资金账户并生成自动计划。保存计划定义不得立即扣款；后台或手工执行都必须先原子领取唯一实例。手工路径生成可审阅草稿，后台路径使用同一校验和幂等提交命令，不依赖可见窗口。
4. 缴费年限和频率共同确定实例范围。真实单缴费年度年缴样例开始日和结束日相同；两缴费年度半年缴样例从 `2026-08-03` 开始，最后应期为 `2028-02-03`，共四个半年应期，保单终止日 `2028-08-03` 不额外生成实例。月缴、季度缴、一次性缴、月末和闰年规则仍待校准。
5. 零保费和无资金账户允许创建；向导填写“已缴保费”时，即使没有资金账户也会生成计入缴费汇总的初始余额调整事件，但不得据此虚构资金流水。
6. 人员、机构和资金账户使用稳定引用；被历史事件引用后不得通过物理删除破坏追溯。
7. 账户关闭、退保和删除是不同状态。存在业务事件时默认禁止物理删除，迁移清理必须记录来源和影响数量。
8. 社保账户由一个账户组和多个项目子账户组成；删除最后一个子账户后，空组是否保留由显式命令决定。
9. 缴费编辑器的支付账户选择器支持内联新建账户。真实样例确认完成现金开户后会返回同一编辑器、保留保单和日期并自动选择新账户；样例原金额为零，尚未证明非零金额、标签和备注的旧程序往返行为。Rust 仍必须暂存并恢复完整保费草稿；账户创建与保费保存不得合并成无法单独回滚的隐式操作。

## 4. 现金价值规则

1. 现金价值是按估值日保存的快照，不等同于账户资金余额，也不能由累计保费直接替代。
2. 当前值取不晚于显式 `as_of_date` 的最新有效快照；默认查询日来自应用或账簿业务日期。未来快照可保存并进入完整趋势图，但生效日前不得进入账户余额、交易汇总、资产和报表。
3. 新增、修改和删除快照必须保留审计版本；真实样例确认同一账户同一日期“新增”会无提示覆盖原有效值且不增加行数，Rust 使用唯一键和显式 upsert 复现该结果。删除唯一 `11.00` 快照后，旧程序表格与图表归零，但当前会话余额错误变为 `1.00`、重开后又回到 `11.00`；Rust 不复制该缺陷，删除后必须从剩余快照原子重算当前值，无剩余快照时统一投影 `0.00`。
4. 旧库若包含“价值增加/价值减少”交易，迁移时转换为显式迁移事件或重建快照，不恢复不可达旧 UI。
5. 现金价值变化不自动产生资金收入、支出或已实现收益，除非同时存在明确保险事件和资金分录。
6. 现金价值是非负估值；负数和空值必须阻止提交，不得像旧程序一样静默转换为 `0.00`。金额先按币种精度和明确舍入模式转换为整数最小单位，人民币实测 `1.234 -> 1.23`、`1.235 -> 1.24`。
7. 现金价值、余额、资产和报表不得使用二进制浮点保存账本事实。旧程序在十一位整数金额上将 `99,999,999,999.99` 错误进位为 `100,000,000,000.00`；Rust 使用受检 `i64` 最小单位并在输入及聚合时检测溢出。

## 5. 交易与状态规则

1. 正常缴纳保费在选择资金账户时原子写入保险事件和资金支出；真实样例确认现金账户期初 `100.00`、缴费 `10.00` 后余额为 `90.00`，保险交易和资金交易互相显示关联账户。开户“已缴保费”在无资金账户时保存为来源明确的初始调整事件，不生成资金分录。是否进入收支统计由账户口径决定。
2. 保费返还和保险分红必须保存不同业务类型。真实样例确认返还 `4.00` 和分红 `2.00` 均创建同额领取账户流入并进入累计领取，但财务记录仍分别显示“保费返还”和“保险分红”。编辑器未展示费用、税费和净额拆分，相关口径仍待确认，不得编造旧程序字段。
3. 退保资金事件与账户生命周期转换是两个可审计动作，必须在同一事务中按 `finish_account` 显式处理现金价值结转、资金到账、费用、损益、未执行计划和可选终止；重复提交不得重复到账。对照样例均在累计缴费 `10.00`、现金价值 `0.00` 的保单上退保 `5.00`：`finish_account=false` 时保单保持活动，交易新增领取 `5.00`，累计领取变为 `5.00`、记录数变为 `2`；`finish_account=true` 时保单退出活动列表，到账账户和财务记录均投影同一笔 `5.00` 流入。旧程序未展示独立损益、费用或税费行，不得据此臆测公式。
4. 社保缴费与领取必须关联参保人和项目，养老、医疗、失业、工伤、生育及住房公积金不得仅用显示名称区分。
5. 所有金额使用定点小数和币种精度；跨币种资金分录保存汇率方向、来源和快照时间。
6. 保险事件是业务真相，资金交易是可选结算关系。开户初始调整可以没有资金交易；选择支付或领取账户的缴费、返还、分红和退保必须通过稳定关联绑定对应资金交易。
7. 计划执行使用实例幂等键原子提交保险事件和资金交易。真实 `1.00` 样例使 `Cash-CNY 608.00 -> 607.00`、资金记录数 `9 -> 10`，保险侧新增缴费 `1.00`、累计保费 `1.00`、记录数 `1`；重复领取、重试或页面刷新不得再次扣款。
8. 独立修改从保单上下文创建新的 `PremiumSchedule` 版本，只替换尚未处理的实例。年缴 `1.00` 改为半年缴 `1.01` 后，中央列表、执行草稿和冷启动编辑器必须读取同一新版本。
9. 自动提交后账户中心、现金账户、保险工作区、计划列表和报表必须原子失效旧投影。旧程序在现金工作区已为 `606.99` 时账户中心仍显示 `608.00`，该刷新缺陷不进入兼容合同。

## 6. 查询投影

- 保险工作区的账户列表、交易明细、现金价值和账户概况必须绑定同一账户选择和查询时点。
- 空交易页返回零记录、零缴费、零领取和当前现金价值，不生成占位交易。
- 保险账户余额取当前有效现金价值，不取投保金额或累计缴费；快照保存后账户余额、现金价值汇总和趋势图使用同一提交版本刷新。
- 删除快照后，账户列表、交易页现金价值汇总、趋势图、资产汇总和报表必须查询同一已提交版本；删除唯一快照时全部现金价值投影为零，重新启动不得从缓存或恢复状态回填旧值。
- 删除最新快照时，当前值按估值日回退到上一有效快照；真实两日期样例在当前会话正确从 `13.00` 回退 `11.00`，但旧程序重启后余额和汇总错误回到已删除的 `13.00`，Rust 必须从剩余快照确定性重建为 `11.00`。
- 历史 `2026-07-29 / 7.00`、当前 `2026-07-30 / 11.00` 和未来 `2026-08-01 / 15.00` 可同时保存并进入趋势图；以 `2026-07-31` 查询时当前值仍为 `11.00`。每条快照形成左闭右开生效区间 `[effective_from, effective_to_exclusive)`，重启必须按同一 `as_of_date` 得到相同结果。旧程序重启后错误归零，不属于兼容目标。
- `9,999,999,999.99` 在现金价值页、交易汇总、账户中心和重启后保持一致；任何消费者都必须读取同一整数最小单位事实。输入或聚合溢出时整项查询或命令应返回明确错误，不能截断、进位或部分刷新。
- 删除非最新快照时只移除对应历史数据点；真实样例删除较早的 `11.00` 后，最新 `13.00` 快照、账户余额、交易页汇总和趋势图在当前会话及重启后均保持一致。
- 缴纳保费增加累计保费和保险记录数，并减少支付账户余额；不自动改变现金价值、投保金额或累计领取。真实样例保存后累计保费 `10.00`、记录数 `1`、现金价值 `0.00`、投保金额 `100.00`、累计领取 `0.00`。
- 仅提醒的待期实例进入今日提醒并投影 `can_execute=false/can_skip=true`；固定账户自动计划不进入同一待办列表，中央计划列表可触发类型化执行草稿。定义保存、实例领取、草稿打开和最终入账是独立边界；后台执行可无界面提交，但必须写同一审计和幂等关系。
- 单期实例被跳过或成功执行后，兼容列表均显示“执行完毕”，但领域事实必须分别保留 `skipped` 和 `executed`。中央计划列表对保单派生计划禁用直接修改和删除，修改命令必须回到保单上下文并生成新计划版本。
- 保费返还增加累计领取和保险记录数，并增加领取账户余额；真实样例返还 `4.00` 后累计缴费仍为 `10.00`、累计领取为 `4.00`、记录数为 `2`、现金价值为 `0.00`，领取账户从零变为 `4.00`。不得把返还实现为负保费或据此自动冲减累计缴费。
- 保险分红也增加累计领取和保险记录数，但必须保留独立收益类型。真实样例分红 `2.00` 后累计缴费仍为 `10.00`、累计领取为 `2.00`、记录数为 `2`、现金价值为 `0.00`，零期初领取账户变为 `2.00`，财务记录投影同一笔“保险分红”流入。
- 不勾选同时终止保险账户的退保保存后，保单保持 `active` 且继续出现在活动账户查询中；真实样例新增退保领取 `5.00` 后累计缴费保持 `10.00`、累计领取变为 `5.00`、记录数变为 `2`、现金价值保持 `0.00`，工作区立即刷新。后续命令权限必须读取当前保单状态，不能因存在 `surrender` 事件就一律禁用。
- 勾选同时终止保险账户的退保保存后，保单进入 `surrendered` 状态并退出活动账户查询，但稳定 ID、历史保费、现金价值快照、退保事件和资金关联必须保留。真实样例退保 `5.00` 后活动列表不再显示保单，到账账户和财务记录均显示同一笔 `5.00` 流入；终止后的旧工作区下方仍短暂显示保存前交易和汇总，Rust 必须使全部组件从同一提交版本清除选择或重新查询。
- 现金价值快照更新不得新增或改写保险交易，也不得改变缴费总额、领取总额和交易记录数。
- 现金价值趋势、账户概况、资产负债表和保险报表必须能追溯到同一有效快照。
- 导出和打印使用当前查询快照，不得在导出过程中重新读取并混入后续写入。

## 7. 验收缺口

- 旧程序删除后 `1.00/11.00/0.00` 分裂、未来快照重启后归零的具体数据库根因，以及既有恢复文件是否参与当前值重建。
- 应用或账簿业务日期的真实来源，以及跨月、跨年和时区切换时的 `as_of_date` 规则。
- 其它币种小数位、精确最大金额、科学计数法、千分位、本地化小数分隔符、聚合溢出、并发冲突和保存失败回滚。
- 保费计入全局收支统计的开关规则，以及返还/分红金额边界、候选账户过滤、收益报表和费用税务。
- 未终止退保后的再次缴费、返还、分红、再次退保和最终终止；金额与现金价值/累计保费/保障费用的公式、损益税费、未执行计划、重复提交、失败回滚和终止历史查询。
- 在非锁屏会话复拍未终止分支的到账账户余额和财务记录投影。
- 月缴、季度缴和一次性缴的多年度保存，月末/闰年规则，关闭未入账草稿到自动提交之间的精确时点，以及余额不足、账户失效、重复提交、失败补偿和并发修改。
- 社保六类项目的真实字段、缴费/领取公式和地区差异。
- 旧保险价值增减数据到快照模型的迁移样例。
- 缴费编辑器在非零金额、标签和备注下的完整草稿恢复，以及内联账户创建成功但保费取消时的账户保留策略。
